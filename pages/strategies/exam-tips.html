应试策略与技巧

一、选择题答题策略

时间分配

  • 总时间150分钟，75道题
  • 建议每题平均2分钟
  • 遇到不会的题先选一个标记，不要纠缠
  • 选择题目标：55-65分

答题技巧

  1. 排除法：排除明显错误选项，正确率提升50%
  2. 绝对化选项：含"总是""一定""所有"的通常是错误选项
  3. 相对化选项：含"通常""一般""大多数"的通常是正确选项
  4. 计算题：先估算范围，再精确计算
  5. 不会做的：相信第一直觉，不要轻易改答案

常见陷阱

  • 概念混淆：如进程与线程、同步与互斥
  • 条件遗漏：题目中的"除了""不包括"
  • 时间复杂度：注意最坏/平均/最好情况
  • 协议端口号：HTTP=80, HTTPS=443, FTP=21, SSH=22

二、大题答题策略（科目二）

时间分配

  • 总时间150分钟（14:00–16:30），5道大题（试题一~四必答 + 试题五/六二选一），每题15分
  • 建议每题平均25–28分钟，不要在一道题上花超过30分钟
  • 留10分钟检查漏空的题

答题原则

  1. 写满步骤：步骤分很重要，写出关键步骤就能拿分
  2. 先易后难：先做有把握的题
  3. 格式清晰：分步骤写，标清序号
  4. 不要空题：即使不会也要写相关内容

各题型答题模板

UML建模题

1. 识别参与者（Actor）
2. 识别用例（Use Case）
3. 画出用例图
4. 分析关系（包含/扩展/泛化）
5. 写出关键描述

设计模式题

1. 识别模式类型（创建/结构/行为）
2. 画出类图结构
3. 说明各角色职责
4. 写出适用场景
5. 结合题目需求说明

数据库设计题

1. 分析实体和属性
2. 画出E-R图
3. 转换为关系模式
4. 写出SQL查询
5. 分析范式级别

架构设计题

1. 分析系统需求
2. 选择架构风格
3. 画出组件图
4. 说明交互方式
5. 考虑非功能性需求

三、时间管理

考试当天时间表

时间 事项
考前30分钟 到达考场，准备物品
考前15分钟 调整心态，回忆框架
考试开始 先浏览试卷，了解题量
120分钟时 检查选择题是否完成
考前10分钟 检查答题卡是否涂完

答题顺序建议

  1. 先做有把握的选择题（快速拿分）
  2. 再做有疑问的选择题（标记后做）
  3. 最后做不会的选择题（猜一个）
  4. 大题按顺序做，先做简单的

四、高频考点速记

数据结构

  • 链表反转、树遍历、图算法
  • 排序算法稳定性：冒泡/插入稳定，快速/堆排序不稳定
  • 哈希冲突解决：链地址法、开放地址法

操作系统

  • PV操作：P申请资源，V释放资源
  • 死锁条件：互斥、占有且等待、不可剥夺、循环等待
  • 页面置换：LRU最近最少使用

网络

  • TCP三次握手建立，四次挥手释放
  • 子网划分：IP地址 & 子网掩码 = 网络地址
  • HTTP无状态，HTTPS = HTTP + TLS/SSL

数据库

  • SQL：GROUP BY + HAVING + ORDER BY 顺序
  • 范式：1NF→2NF→3NF 逐步消除依赖
  • 事务ACID：原子性、一致性、隔离性、持久性

软件工程

  • 敏捷开发：Scrum/Sprint
  • 测试：黑盒（等价类/边界值）/白盒（逻辑覆盖）
  • 耦合度（七级，由高到低）：内容 > 公共 > 外部 > 控制 > 标记 > 数据 > 非直接
  • 内聚度（七级，由低到高）：偶然 < 逻辑 < 时间 < 过程 < 通信 < 顺序 < 功能

五、心态调整

  1. 考试不是终点：即使这次不过，也是宝贵的经验
  2. 尽力而为：把会的题做对，不会的尽量写步骤
  3. 保持自信：30天的努力不会白费
  4. 正常发挥：考试时不要追求完美，发挥出80%就是成功
