Day 5（9/25）计算机网络② 练习题：TCP 连接管理 + 子网划分（20 道选择题）

说明：本题是 Day 5 的章节题。子网划分计算题（1–8）是本日核心，每题都给出完整手算步骤，做完必须能达到"换一组数字也能算对"。 题目分布：子网划分计算 8 题（1–8）、TCP 连接管理 6 题（9–14）、拥塞控制 3 题（15–17）、UDP 与综合 3 题（18–20）。 完整答案与解析在文件末尾。建议独立完成（约 40 分钟，计算题务必打草稿）再对答案。 做题纪律：计算题不许口算——写出掩码、块大小、网络地址再选答案。

附：Day 5 笔记「快速自测」速答

  1. 三次握手：SYN → SYN+ACK → ACK。
  2. 客户端发 SYN 后进 SYN-SENT；服务器收 SYN 后进 SYN-RCVD。
  3. 客户端先进入 ESTABLISHED。
  4. 被动关闭方收到 FIN 后先回 ACK，进入 CLOSE-WAIT。
  5. TIME-WAIT 等 2MSL：保证最后的 ACK 到达 + 清除网络残留报文。
  6. 慢开始：每 RTT 加倍（指数）。
  7. cwnd 达到 ssthresh 后转拥塞避免（线性 +1）。
  8. 3 个重复 ACK：ssthresh = cwnd/2，cwnd = ssthresh（不回 1）。
  9. 超时：cwnd = 1。
  10. TCP 首部 20 字节，UDP 8 字节。
  11. 流量控制由接收方（rwnd）限制，拥塞控制由发送方（cwnd）限制；实际窗口 = min(rwnd, cwnd)。
  12. 192.168.1.130/26 网络地址 = 192.168.1.128。
  13. /28 可用主机数 = 14。
  14. 每子网 25 台主机 → /27，C 类 /24 可划 8 个。
  15. 192.168.0.0/24 ~ 3.0/24 聚合 = 192.168.0.0/22。
  16. 跨网段时 ARP 求默认网关的 MAC。

答案与解析

第一部分：子网划分计算

1. C 用 5 步法：

① /26 → 掩码 255.255.255.192，块大小 = 256 − 192 = 64，h = 6
② 网络地址 = IP AND 掩码：
   前三段照抄 → 192.168.1；第四段：130 ÷ 64 = 2 余 2 → 2 × 64 = 128
   ∴ 网络地址 = 192.168.1.128

二进制验证：130 = 10000010，掩码第四段 192 = 11000000，AND = 10000000 = 128 ✓ （D 选项 192.168.1.192 是"下一个子网"的网络地址，是常见干扰项。） （知识点：网络地址 = IP AND 掩码；对应 day05-tcp.md §八 模板第 2 步、例题 1）

2. B /28 → 主机位 h = 32 − 28 = 4，可用主机数 = 2⁴ − 2 = 16 − 2 = 14。 易错点：C 选项 16 忘了减 2（网络地址与广播地址不可用）；A 选项 12 是把 16 减去了别的数。"可用主机数 = 2^h − 2"这一步永远不能忘。 （知识点：可用主机数；对应 day05-tcp.md §八 模板第 4 步、§7.3 对照表）

3. C 用 5 步法：

① /20 → 掩码 255.255.240.0，第三段块大小 = 256 − 240 = 16，h = 12
② 第三段：55 ÷ 16 = 3 余 7 → 3 × 16 = 48 → 网络地址 = 172.16.48.0
③ 广播地址：第三段 = 48 + 16 − 1 = 63；第四段（掩码为 0）全 1 → 255
   ∴ 广播地址 = 172.16.63.255

易错点：A 选项 172.16.55.255 是"把最后一段改成 255"的直觉错误；广播地址必须是主机位全部置 1，即网络地址 + 块大小 − 1。 （知识点：广播地址；对应 day05-tcp.md §八 模板第 3 步、例题 2）

4. A

① 先定主机位：要求 2^h − 2 ≥ 25。h=5 → 30 ≥ 25 ✓（h=4 只有 14，不够）
② 掩码：n = 32 − 5 = 27 → 255.255.255.224
③ 借用位数 b = 27 − 24 = 3 → 子网数 = 2³ = 8
   每个子网可用主机 = 2⁵ − 2 = 30（≥ 25 ✓）

易错点：C 选项（/26）虽然每个子网 62 台够用，但"最省"意味着刚好够用即可，/26 只能划 4 个，且浪费更多地址；D 选项的"6 个"是常见的瞎猜数字（误以为 254/30 ≈ 8 或用别的方法）。"给定主机数求掩码"先定 h，再得 n = 32 − h。 （知识点：给定主机数求掩码与子网数；对应 day05-tcp.md §八 例题 4）

5. B 用 5 步法分别算两台主机的网络地址：

① 同为 /26，块大小 = 64
② A：100 ÷ 64 = 1 余 36 → 1 × 64 = 64 → 网络地址 192.168.1.64
   B：200 ÷ 64 = 3 余 8  → 3 × 64 = 192 → 网络地址 192.168.1.192
④ 网络地址不同（.64 ≠ .192）→ 不在同一子网

易错点：A/D 选项"前三个字节相同就同一子网"是典型陷阱——/26 时第四段被切成 4 个子网（0/64/128/192）；判断是否同子网必须算网络地址。C 选项把 A 的网络地址算成 .0，是块大小取错（取 256 或没做 AND）的结果。 （知识点：同子网判断；对应 day05-tcp.md §八 例题 5）

6. B "最节省"= 可用主机数刚好 ≥ 需求的最小主机位：

h = 7 (/25) → 126 台（够，但浪费）
h = 6 (/26) → 62 台 ≥ 50 ✓，且 h=5 (/27) 只有 30 < 50 不够
∴ 选 /26，掩码 255.255.255.192

A 选项 /25 也能容纳，但不够节省；C 选项 /27 只有 30 台根本不够。关键在"最节省"三个字：找满足需求的最小 h。 （知识点：VLSM 按需定掩码；对应 day05-tcp.md §9.3 VLSM 例题）

7. B

4 个 /24 连续网络要聚合 → 需 2^k = 4 → k = 2 → 前缀 = 24 − 2 = 22
检查块对齐：第三段 0、1、2、3 = 00000(000/001/010/011)，前 6 位都相同（000000）
∴ 聚合后 = 192.168.0.0/22（掩码 255.255.252.0）

验证：/22 第三段块大小 = 256 − 252 = 4 → 覆盖 192.168.0.0 ~ 192.168.3.255，正好是 4 个 /24 ✓ 易错点：A 选项 /23 只能合并 2 个网络；C/D 前缀太短（合并 8 个/16 个）。聚合的规律：合并 2^k 个连续网络，前缀就减 k。 （知识点：CIDR / 路由聚合 / 超网；对应 day05-tcp.md §9.2）

8. A

① /30 → 掩码 255.255.255.252，块大小 = 256 − 252 = 4，h = 2
② 第四段：5 ÷ 4 = 1 余 1 → 1 × 4 = 4 → 网络地址 = 202.100.10.4
④ 可用主机数 = 2² − 2 = 2（即 202.100.10.5 和 202.100.10.6，恰好给链路两端）

/30 是点对点链路的经典用法：一个子网只有 2 个可用地址，正好分配给链路两端的两个接口，不浪费任何一个地址。D 选项把 IP 本身当网络地址，是最基础的错误。 （知识点：/30 点对点链路；对应 day05-tcp.md §7.3 对照表、§八 模板）

第二部分：TCP 连接管理

9. C 第二次握手是服务器对客户端 SYN 的确认 + 服务器自己的 SYN：SYN=1, ACK=1, seq=y（服务器随机初值）, ack=x+1（确认客户端的 SYN，SYN 占 1 个序号）。B 选项是第三次握手的内容（seq=x+1, ack=y+1）；A 缺少 ACK 与确认号；D 的 FIN 是挥手阶段才出现的控制位。 （知识点：三次握手报文内容；对应 day05-tcp.md §2.1、§2.4）

10. B 两次握手无法防止"已失效的连接请求"：若客户端的一个旧 SYN 因网络滞留迟到，服务器会回 SYN+ACK 并单方面建立连接、分配资源，而客户端根本没想建立这个连接，资源就白白浪费。第三次握手正是让服务器确认客户端确实收到了自己的 SYN 并在场。C 错——服务器可在第二次握手中确定自己的序号；A、D 与握手次数无关。 （知识点：三次握手必要性；对应 day05-tcp.md §2.3）

11. C 四次挥手中，被动关闭方收到对方 FIN 后，先回 ACK 并进入 CLOSE-WAIT（"关闭等待"——自己还有数据没发完，先别断）；等数据发完再发 FIN，进入 LAST-ACK。易错点：A（TIME-WAIT）是主动关闭方的状态；D（FIN-WAIT-2）也是主动关闭方的状态；B（LAST-ACK）是发完 FIN 之后的状态，不是收到 FIN 时。 （知识点：四次挥手状态变迁；对应 day05-tcp.md §3.1、§3.2）

12. C TIME-WAIT 等 2MSL 有两个目的：① 保证最后的 ACK（第 ④ 段）能到达对方——若丢失，对方会重传 FIN，本端在 2MSL 内还能收到并重发 ACK；② 让本连接的所有报文段都从网络中消失，防止迟到报文干扰同 socket 的新连接。A 错（数据在 CLOSE-WAIT 阶段已发完）；B 太笼统；D 没抓住要害。 （知识点：TIME-WAIT 与 2MSL；对应 day05-tcp.md §3.2）

13. D 确认号 = 期望收到的下一个字节的编号 = 本次数据的第一个字节编号 + 数据长度 = 1001 + 500 = 1501。即"1501 之前的所有数据（1001~1500，共 500 字节）我都收到了"。C（1500）是"最后一个字节的编号"，不是确认号；B（1001）等于没确认任何数据。 （知识点：序号与确认号；对应 day05-tcp.md §1、§2.4）

14. A 三次握手中，客户端发出第 ③ 段（对服务器 SYN 的确认）后即进入 ESTABLISHED；服务器必须收到第 ③ 段后才从 SYN-RCVD 进入 ESTABLISHED。所以客户端先建立连接。 （知识点：连接建立时序；对应 day05-tcp.md §2.2）

第三部分：拥塞控制

15. B 快重传/快恢复（收到 3 个重复 ACK）的处理是：ssthresh = cwnd / 2，cwnd = ssthresh（即 cwnd 减半但不回到 1），随后进入拥塞避免线性增长。易错点：A 选项的"cwnd = 1"是超时才有的处理——超时说明网络严重拥塞，要狠狠降；3 个重复 ACK 说明只是偶发丢一包，网络基本通畅，温和降即可。"超时回 1，重复 ACK 减半"。 （知识点：快重传与快恢复；对应 day05-tcp.md §6.1、§6.2）

16. B 慢开始阶段 cwnd 每经过 1 个 RTT 加倍（1→2→4→8→…，指数增长）。"慢开始"的"慢"指的是起点小（cwnd=1），而不是增长慢——恰恰相反，它增长得最快。A（线性 +1）是拥塞避免阶段的特征；D 是丢包后的反应。 （知识点：慢开始增长规律；对应 day05-tcp.md §6.1）

17. B

超时处理：ssthresh = cwnd / 2 = 24 / 2 = 12；cwnd = 1（重新慢开始）
此后：cwnd = 1 → 2 → 4 → 8 → 12（达到新 ssthresh）→ 转拥塞避免线性增长

A 选项（cwnd=12）是快恢复的处理（3 个重复 ACK 时的反应），不是超时的；超时必须把 cwnd 重置为 1。 （知识点：超时与快恢复的区分；对应 day05-tcp.md §6.3 完整演算）

第四部分：UDP 与综合

18. A TCP 首部固定 20 字节（含选项时最大 60 字节），UDP 首部固定 8 字节（源端口、目的端口、长度、校验和各 2 字节）。这正是"TCP 开销大、UDP 开销小"的直接来源。 （知识点：TCP/UDP 首部开销；对应 day05-tcp.md §四）

19. C 实时视频/语音会议要求低延迟、能容忍少量丢包，TCP 的确认/重传机制反而增加延迟，因此优先选 UDP。A（FTP）、B（SMTP）、D（Telnet）都要求可靠传输，用 TCP。 （知识点：UDP 的应用场景；对应 day05-tcp.md §四）

20. C 主机 A 用掩码算出目的服务器不在本网段（192.168.1.0/24），于是把数据包交给默认网关 192.168.1.1。以太网帧按 MAC 封装，因此 ARP 求的是默认网关（路由器本网段接口）的 MAC 地址，而不是目的服务器的 MAC。IP 头里的目的 IP 仍是服务器不变，只有链路层的目的 MAC 是网关的。易错点：A 是最典型的错误——跨网段时目的主机在另一个链路上，本网段的 ARP 广播根本到不了它。 （知识点：默认网关与 ARP 的关系；对应 day05-tcp.md §9.4）
