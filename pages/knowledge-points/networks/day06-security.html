Day 6（9/26）计算机网络③：网络安全 + 网络阶段收尾

考试定位：信息安全在科目一（75 道选择题）中约占 5% 分值（3–4 题），概念性为主、短期可速成——是"背熟就得分"的典型板块，性价比极高。计算题极少，几乎全是"概念辨析 + 归属判断 + 攻防配对"。 本日结构：Step 1 信息安全基础（§1–§15）→ Step 2 网络阶段知识框架图（§16，网络阶段收尾交付物，可单独打印冲刺）。 学习建议：先按 §1→§15 顺序学完并做完 day06-exercises.md 的 15 道安全题，再用 §16 的框架图把 Day 4–6 串成一张图；晚上按 reflection.md 的指引重做 Day 4–5 高混淆度题。

一、信息安全总览：CIA 三要素与 5 大安全服务

1.1 CIA 三要素（信息安全的目标）

┌─────────────────────────────────────────────────────────────────┐
│                    信息安全三大目标（CIA）                        │
├──────────────┬──────────────────────────────────────────────────┤
│ 机密性 C     │ 信息只被授权的人看到      → 靠【加密】实现         │
│ Integrity I  │ 信息不被篡改、完整无误    → 靠【摘要/数字签名】实现│
│ 可用性 A     │ 系统随时可用、不被搞瘫    → 靠【防火墙/抗 DDoS】   │
└──────────────┴──────────────────────────────────────────────────┘

扩展的两个常考点： - 真实性（身份认证）：确认"你是你声称的人" → 靠【数字签名 / 证书 / 口令】。 - 抗否认性（不可否认性）：发出后不能抵赖"我没发过" → 只有数字签名能做到（因为私钥只有你有）。

⚠️ 易错点：数字签名本身不提供机密性。签名只是"盖了个章"，报文仍是明文。要同时保密，必须先加密再签名（或用数字信封）。考题常出现"数字签名能保证机密性"的错项。

1.2 ISO 7498-2 定义的 5 大安全服务（OSI 安全体系，必背）

安全服务 作用 典型实现手段
认证服务 验证对等实体身份 / 数据来源真实性 数字签名、数字证书、口令、Kerberos
访问控制 决定谁能访问什么资源、有何权限 ACL、防火墙规则、RBAC
数据机密性 防止信息被窃听 对称/非对称加密
数据完整性 防止数据被篡改、重排、丢失 报文摘要、HMAC、数字签名
抗否认服务 防止发送方/接收方抵赖 数字签名 + 可信第三方（CA/时间戳）

记忆口诀：「认、控、保、完、否」——认证、访问控制、机密性、完整性、抗否认。

二、对称加密体制（DES / 3DES / AES / SM4）

核心特征：加密和解密用同一个密钥（或由一个推出另一个）。又叫"单钥/私钥/共享密钥"加密。

2.1 三大主流算法对比（必背表）

算法 有效密钥长度 分组长度 轮数 结构 现状与特点
DES 56 位（输入 64 位，其中 8 位是奇偶校验，实际只用 56 位） 64 位 16 轮 Feistel 网络 已被破解（穷举可破），速度极快；不再用于新系统，软考仍常作为"经典对称算法"出现
3DES 112 位（2 密钥）或 168 位（3 密钥，每把 56 位） 64 位 48 轮（3×16） Feistel 用 3 把 DES 密钥做"加密-解密-加密"（EDE）；安全但慢，是 DES→AES 的过渡方案；兼容单 DES（三把密钥相同时退化为 DES）
AES 128 / 192 / 256 位（三种规格，对应 AES-128/192/256） 128 位 10 / 12 / 14 轮 SP 网络（不是 Feistel） 当前主流国际标准；速度快、安全性高；分组长度固定 128 位，与密钥长度无关
SM4 128 位 128 位 32 轮 SP 网络 中国国家密码标准，用于无线局域网 WAPI 等

⚠️ 高频易错点（连考多年）： 1. AES 的分组长度固定是 128 位，不随密钥长度变化！密钥可以 128/192/256，但分组永远是 128 位。选项里"AES 分组长度可以是 192/256 位"是错的。 2. DES 密钥长度说 56 位（有效），不是说 64 位——64 位里有 8 位是校验位，不参与加密。 3. 3DES 密钥长度是 112 位或 168 位（3×56），不是"3×64=192 位"。 4. 轮数对应关系：AES-128 → 10 轮，AES-192 → 12 轮，AES-256 → 14 轮（密钥每长 64 位多 2 轮）。

2.2 对称加密的优缺点

优点 缺点
① 速度快（比非对称快 100–1000 倍），适合加密大量数据 ① 密钥分发困难：通信前必须安全地把密钥送给对方
② 算法公开、计算开销小、易于硬件实现 ② 密钥规模爆炸：n 个人两两通信需 n(n−1)/2 个密钥（10 人 = 45 个，100 人 = 4950 个）
③ 加密效率高，适合文件/硬盘/链路加密 ③ 无法实现抗否认（双方密钥相同，谁都能伪造）
④ 无法直接做数字签名（公钥体系才能签名）

三、非对称加密体制（RSA / ECC / SM2）

核心特征：使用一对密钥——公钥（公开）和私钥（保密），由数学难题保证"由公钥推不出私钥"。

3.1 两条用法（务必分清，这是全部考点的基础）

① 公钥加密 → 私钥解密   ⇒  实现【机密性】（谁都能加密，只有你能解密）
   场景：A 用 B 的公钥加密 → 只有 B 的私钥能解开

② 私钥加密 → 公钥解密   ⇒  实现【数字签名 / 身份认证 / 抗否认】（只有你能"签"，谁都能"验"）
   场景：A 用 A 的私钥"签名" → 所有人用 A 的公钥验证"这确实是 A 发的"

⚠️ 易错点："公钥加密"和"私钥签名"不是同一件事。问"如何保证机密性"选用对方公钥加密；问"如何实现数字签名/抗否认"选用自己私钥签名。

3.2 主流算法对比

算法 密钥长度 数学基础 特点与现状
RSA 1024 / 2048 / 4096 位（常用 2048） 大整数因子分解困难 事实标准，应用最广；速度慢，通常只加密小数据（如会话密钥）或做签名；可同时用于加密和签名
ECC 160–256 位（常用 256） 椭圆曲线离散对数困难 同等安全性下密钥更短（256 位 ECC ≈ 3072 位 RSA 的安全性），速度快、省带宽，适合移动端/物联网
DSA 1024 位 离散对数困难 只能用于数字签名，不能用于加密（软考常考的辨析点）
SM2 256 位 椭圆曲线 中国国家密码标准，替代 RSA/ECC 商用
Diffie-Hellman — 离散对数困难 密钥交换协议（协商对称密钥用），本身不加密数据

⚠️ 高频易错点： 1. DSA 只能签名不能加密；DH 只能交换密钥不能加密。 2. 非对称加密不适合加密大量数据——慢且有长度上限（RSA 加密明文长度不能超过密钥长度）。"用 RSA 加密整个文件"是错的。 3. ECC 不是"RSA 的缩写版本"，两者数学基础完全不同；ECC 的优势是"短密钥同等安全"。

3.3 非对称加密的优缺点

优点 缺点
① 密钥分发容易：公钥可公开，无需秘密通道 ① 速度极慢，不适合大量数据加密
② 密钥规模小：n 个人只需 2n 个密钥（每人一对） ② 计算复杂、消耗 CPU
③ 可实现数字签名、抗否认 ③ 需要可信机制（PKI）保证"这个公钥真的是那个人的"

四、对称 vs 非对称对比（必背表）

对比维度 对称加密 非对称加密
密钥数量 1 个（双方共享） 1 对（公钥 + 私钥）
密钥分发 困难（需安全通道） 容易（公钥可公开）
n 人通信密钥数 n(n−1)/2 2n
速度 快（适合大量数据） 慢（适合小数据/密钥/签名）
安全性 较低（密钥需保密传递） 较高（私钥不外传）
数字签名/抗否认 不能 能
典型算法 DES / 3DES / AES / SM4 RSA / ECC / DSA / SM2
典型用途 文件加密、链路加密、会话数据加密 密钥分发、数字签名、身份认证

一句话总结：对称加密负责"干活"（加密大量数据），非对称加密负责"分钥匙"和"签字"。这正是数字信封和 HTTPS 的设计思想。

五、数字信封：混合加密的标准玩法（必考）

问题背景：对称加密快但密钥送不出去；非对称加密能安全送密钥但太慢。数字信封把两者拼起来——用非对称加密保护对称密钥，用对称加密保护真正的数据。

5.1 流程图解

发送方 A                                     接收方 B
──────────                                  ──────────
① 随机生成一次性会话密钥 K（对称）
② 用 K 加密明文 M      →  密文 C
③ 用 B 的【公钥】加密 K →  数字信封 E
④ 发送  C + E  ────────────────────────→   ⑤ 用 B 的【私钥】解 E → 得到 K
                                           ⑥ 用 K 解 C → 得到明文 M

5.2 关键结论（看到就选）

  1. 会话密钥 K 是随机生成、用完即弃的——每次通信换一把，即使泄露也只影响一次会话。
  2. 数字信封 = 用接收方公钥加密的对称会话密钥。只有接收方的私钥能拆开信封，所以 K 不会泄露给第三方。
  3. 只有接收方能解开——保证了机密性。但数字信封不提供抗否认（A 可以否认"我没发过"），抗否认要靠数字签名（§7）。
  4. 传递顺序记牢：明文用对称密钥加密，对称密钥用接收方公钥加密。反过来（用对称加密传公钥）是错的。

六、报文摘要与消息认证码（MD5 / SHA / HMAC / SM3）

6.1 什么是报文摘要（Hash）

把任意长度的输入 M 压缩成固定长度的输出 H(M)，又叫散列值/哈希值/指纹。

四个必备性质（必考）： 1. 定长输出：无论输入多长，输出长度固定。 2. 单向性（不可逆）：由摘要无法反推出原文——这是摘要与加密的根本区别（加密是可逆的）。 3. 雪崩效应：输入改 1 个比特，输出"面目全非"。 4. 抗碰撞：找不到两个不同输入给出相同摘要（计算上不可行）。

用途：① 完整性校验（对比摘要就知道有没有被改）；② 数字签名（先摘要再签名，提高效率）；③ 口令存储（数据库存 hash 不存明文）；④ 文件去重/秒传。

6.2 常见摘要算法（输出长度必背！）

算法 输出长度 安全现状
MD5 128 位 已被破解（可构造碰撞，王小云 2004 年攻破）；不能用于安全签名/数字证书，但仍广泛用于文件完整性校验、网盘去重（不抗攻击但够用）
SHA-1 160 位 已不安全（2017 年 SHAttered 实际碰撞），主流系统已弃用
SHA-256 256 位 安全，当前主流（SHA-2 家族，TLS/区块链广泛使用）
SHA-512 512 位 安全（SHA-2 家族）
SM3 256 位 中国国家密码标准，配合 SM2/SM4 使用

⚠️ 必考数字记忆法：MD5 = 128，SHA-1 = 160，SHA-256 = 256。题目最爱问"MD5 的摘要长度是多少"，答案 128 位；"SHA-1 比 MD5 长多少"，160 − 128 = 32 位。

6.3 报文摘要 vs 消息认证码 HMAC（高频辨析）

报文摘要（如 MD5） HMAC（如 HMAC-SHA256）
有密钥吗 无密钥 有密钥
防篡改 能检测意外损坏 能检测恶意篡改（攻击者无密钥，伪造不出正确值）
防伪造 不能（谁都能算） 能
身份认证 不能 能（证明消息来自持有该密钥的人）

结论：单纯摘要只能防"改"，不能防"伪造"——任何人都能算 MD5。要证明"这消息确实是我发的且没被改过"，需要 HMAC（有密钥的摘要） 或 数字签名（用私钥签摘要）。

七、数字签名（原理 + 完整流程）

7.1 原理

发送方用自己的私钥对报文（或其摘要）加密，得到"签名"；接收方用发送方的公钥验证。因为私钥只有发送方有，所以：

  • 身份认证：能验过，说明确实是用那个私钥签的 → 证明身份。
  • 抗否认：发送方事后不能说"这不是我签的"——只有他的私钥能签出来。
  • 完整性：签名是对摘要做的，报文被改一个字，验证必然失败。

7.2 完整流程（签名 + 加密，混合方案，重点）

实际系统（如 HTTPS、PGP）中，签名与加密同时使用：

发送方 A                                          接收方 B
──────────                                       ──────────
1. 生成会话密钥 K（对称，随机）
2. 密文 C = E_K(M)                  ← 对称加密，保机密
3. 摘要 D = H(M)
4. 签名 S = E_SKa(D)                ← A 用【A 的私钥】签摘要
5. 信封 E = E_PKb(K)                ← 用【B 的公钥】加密会话密钥
6. 发送  C + S + E  ─────────────────────────→  7. K = D_SKb(E)      ← B 用【B 的私钥】拆信封
                                                  8. M = D_K(C)        ← 对称解密
                                                  9. D' = H(M)         ← 重算摘要
                                                 10. D = D_PKa(S)      ← 用【A 的公钥】验签名
                                                 11. D' == D ? 验证通过 : 被篡改

三把钥匙各管一件事，务必分清： - A 的私钥 → 签名（证明"A 发的"） - B 的公钥 → 加密会话密钥（保证"只有 B 能看"） - B 的私钥 → 拆信封（B 才能读） - A 的公钥 → 验签名（B 验证 A 的身份）

7.3 常考辨析

需求 用什么
机密性（别人看不懂） 对称加密 + 数字信封（B 的公钥加密 K）
完整性（没被改过） 报文摘要 / HMAC
身份认证（确认是 A） 数字签名（A 的私钥）
抗否认（A 不能赖账） 只有数字签名

八、PKI / CA 与数字证书

8.1 为什么需要 CA（解决什么问题）

非对称加密的公钥是公开的，但你怎么知道"这个公钥真的是张三的"？ 攻击者可以把自己的公钥冒充张三的公钥发给你（中间人攻击）。PKI 就是为了解决"公钥与身份的绑定可信"问题。

PKI（Public Key Infrastructure，公钥基础设施） = 硬件 + 软件 + 人员 + 策略 + 规程的集合，功能是创建、管理、保存、发放和吊销数字证书。

8.2 PKI 的组成部分

组件 作用
CA（证书颁发机构） 核心。负责签发证书——用自己的私钥对"身份 + 公钥"签名
RA（注册机构） 受理证书申请、审核身份（不签发，只初审）
证书库/目录 存放已签发证书，供公开查询
CRL（证书吊销列表） 记录提前作废的证书（私钥泄露、换公司等）。现代系统用 OCSP 实时查询
密钥管理中心 生成/备份/恢复/销毁密钥

8.3 数字证书是什么

数字证书 = CA 用自己私钥签名过的"（持有者身份 + 持有者公钥 + 有效期）"（X.509 标准格式）。

┌──────────────── X.509 证书（简化）──────────────────┐
│ 版本号 / 序列号                                     │
│ 持有者：CN=www.example.com（身份标识）              │
│ 持有者公钥：<RSA 2048 位公钥>                       │
│ 有效期：2026-01-01 ~ 2027-01-01                     │
│ 签发者：CN=Let's Encrypt CA                         │
│ CA 的签名：<用 CA 私钥对以上内容的摘要加密>          │
└─────────────────────────────────────────────────────┘

验证链（信任的传递）：你预先信任根 CA（浏览器/操作系统内置根证书）→ 用根 CA 的公钥验证中间 CA 的证书 → 用中间 CA 的公钥验证终端证书。这就叫证书链。

核心结论：信任 CA，就信任 CA 签发的证书。你不需要认识张三，你只需要认识 CA——CA 用它的信誉担保"这个公钥是张三的"。

8.4 证书验证的 4 个步骤（HTTPS 实际在做）

  1. 验证签名：用 CA 公钥验证证书上的签名（证书没被伪造）。
  2. 检查有效期：当前时间在"有效期起止"之内。
  3. 检查吊销状态：查 CRL / OCSP，证书是否已被作废。
  4. 域名匹配：证书里的持有者名称（CN/SAN）与访问的域名一致。

⚠️ 易错点：CA 签发证书用的是 CA 自己的私钥，不是用申请人的私钥；申请人验证证书用的是 CA 的公钥，不是申请人自己的公钥。

九、安全协议与层级归属（层级判断题专用）

协议/技术 工作层次 用途与要点
IPSec 网络层（IP 层） 对所有 IP 报文加密/认证，与上层应用无关（VPN 主力）
SSL / TLS 传输层之上、应用层之下（OSI 中对应表示层/会话层位置） 为应用层数据加密；HTTPS = HTTP over TLS，端口 443
SSH 应用层 安全远程登录（替代 Telnet），端口 22
HTTPS 应用层（底层用 TLS） HTTP + TLS，端口 443
PGP 应用层 邮件加密（混合加密 + 数字签名，Web of Trust）
SET 应用层 安全电子交易（信用卡支付，国内少用）
S/MIME 应用层 安全邮件（配合 X.509 证书）
WPA2/WPA3、802.11i 数据链路层 无线接入加密（PSK / 企业级 802.1X）
L2TP / PPTP 数据链路层（二层隧道） VPN 隧道，本身不加密，通常配 IPSec 使用

⚠️ 三个经典陷阱： 1. IPSec 在网络层，TLS 在传输层之上——别混。 2. SSH 是应用层（端口 22），虽然名字里带 "Shell"，但它是标准应用层协议。 3. L2TP/PPTP 是二层隧道协议，本身不提供加密（L2TP 常与 IPSec 配对：L2TP/IPSec）。

十、HTTPS 与 TLS 握手全过程（重点）

HTTPS = HTTP + TLS/SSL，默认端口 443（HTTP 是 80）。核心思想：握手阶段用非对称加密（安全地协商出对称密钥），之后的应用数据全部用对称加密（保证速度）。

10.1 TLS 握手时序图（TLS 1.2 简化版，必看）

   客户端 Client                                        服务器 Server
      │                                                      │
      │ ① ClientHello：                                       │
      │    支持的 TLS 版本 + 客户端随机数 + 密码套件列表  ───→ │
      │                                                      │
      │ ② ServerHello：                                       │
      │  ←── 选定的 TLS 版本 + 服务器随机数 + 选定密码套件      │
      │ ③ 服务器发送【数字证书】（含服务器公钥）+ 证书链 ───── │
      │ ④ ServerHelloDone（我发完了）                          │
      │                                                      │
      │    ⑤ 客户端验证证书：                                 │
      │       用 CA 公钥验签 + 有效期 + 吊销状态 + 域名匹配     │
      │    ⑥ 客户端生成预主密钥 PreMasterSecret，             │
      │       用【服务器公钥】加密后发送（ClientKeyExchange）   │
      │  ────────────────────────────────────────────────→     │
      │                                                      │
      │  双方各自计算：主密钥 = f(客户端随机数, 服务器随机数,   │
      │                        预主密钥)  → 派生会话密钥        │
      │                                                      │
      │ ⑦ 客户端发 Finished（用会话密钥加密，含握手摘要）─→    │
      │ ⑧ 服务器发 Finished                          ←──       │
      │                                                      │
      │ ══════ 握手结束，之后应用层 HTTP 数据全用对称密钥加密 ═│

10.2 必考结论

  1. 握手用非对称，通信用对称——这是性能与安全的平衡，几乎必考。
  2. 两个随机数 + 预主密钥一起生成会话密钥；随机数的作用是防重放（每次握手都不同，同样的预主密钥每次也导出不同的会话密钥）。
  3. 客户端验证服务器身份靠证书；服务器验证客户端身份（可选，如网银）靠要求客户端出示证书。
  4. TLS 在传输层之上、应用层之下；按 OSI 功能划分，加密功能对应表示层（见 day04-protocols.md §2.6）。
  5. 对称密钥（会话密钥）每次连接重新协商，用完即弃。

10.3 SSL 与 TLS 的关系（常考名称辨析）

  • SSL（Secure Socket Layer）：网景公司 1995 年提出，已完全废弃（SSL 3.0 2015 年被正式废弃，POODLE 攻击）。
  • TLS（Transport Layer Security）：SSL 3.0 的标准化继承者（TLS 1.0 ≈ SSL 3.1）。如今"SSL 证书""SSL/TLS"通常都指 TLS。
  • TLS 1.2：目前最广泛部署；TLS 1.3（2018 年）：握手压缩到 1-RTT（甚至 0-RTT）、废弃 RSA 密钥交换（强制使用支持完美前向安全 PFS 的 ECDHE）、移除 SHA-1/MD5 等弱算法。

⚠️ 易错点：考试若问"HTTPS 用什么协议保证安全"，答 TLS/SSL（现在统一说 TLS）；若问"SSL 是否仍在使用"，答已被 TLS 取代、不再安全。

十一、常见网络攻击与防御（配对记忆，高频）

考法：几乎全是"给出攻击名称/场景 → 选防御措施"，或反向。把下表的攻防配对背熟，这 3–4 分就稳了。

攻击 原理（一句话） 典型场景 防御措施
SQL 注入 把恶意 SQL 拼进用户输入，欺骗服务器执行 登录框输 ' OR 1=1 -- 绕过认证 参数化查询/预编译语句（最根本）、输入过滤与转义、最小权限原则、错误信息屏蔽、WAF
XSS（跨站脚本） 向网页注入恶意脚本，在受害者浏览器里执行，盗取 Cookie/会话 评论区插入 <script> 输出转义（HTML 实体编码，最根本）、CSP 内容安全策略、HttpOnly Cookie（脚本读不到 Cookie）、输入校验
CSRF（跨站请求伪造） 趁受害者已登录，诱导其点击伪造链接，借其身份发请求 钓鱼网站里"转账"按钮 Anti-CSRF Token、SameSite Cookie、验证 Referer/Origin、敏感操作二次验证
DDoS（分布式拒绝服务） 傀儡机（肉鸡/僵尸网络）发海量流量或请求，耗尽带宽或资源 流量清洗事件 流量清洗/CDN 分流、限流与验证码、黑洞路由、Anycast 分散流量、弹性扩容
中间人攻击（MITM） 攻击者冒充双方，拦截并转发/篡改通信 公共 WiFi 窃听、伪造 AP TLS/HTTPS（配合证书验证）、证书锁定、VPN、不在公共 WiFi 用明文服务
重放攻击 截获合法报文，原样重发以骗取服务 截获并重放登录报文/转账请求 时间戳、随机数/挑战-应答、一次性令牌（nonce）、序列号
网络钓鱼 伪造邮件/短信/网站，骗取账号密码等敏感信息 假银行邮件 安全意识教育、核对域名、MFA 多因素认证、浏览器/邮件网关拦截
暴力破解 穷举口令或密钥 弱口令被扫 强口令策略、登录失败锁定/限流、验证码、加盐慢哈希（bcrypt）
字典攻击 用常见密码字典逐一尝试 弱口令被扫 同上；禁止使用常见密码
社会工程学 利用人的心理弱点（冒充客服/领导）骗取信息 电话诈骗 安全培训、制度流程、交叉核实
DNS 劫持/污染 篡改 DNS 解析结果，诱导到假站点 假银行网站 DNSSEC、DoH/DoT（加密 DNS）、本地 hosts 校验
ARP 欺骗 伪造 ARP 应答，冒充网关 局域网窃听 静态 ARP 绑定、交换机动态 ARP 检测（DAI）、端口安全
APT（高级持续性威胁） 长期潜伏、定向渗透 针对性攻击 纵深防御、态势感知、零信任、终端检测响应（EDR）

11.1 XSS 与 CSRF 的区别（年年必考的辨析）

XSS 跨站脚本 CSRF 跨站请求伪造
攻击对象 网站本身（注入脚本到页面） 用户（借用户身份发请求）
核心动作 在受害者浏览器里执行攻击者的脚本 借受害者的登录态发送攻击者构造的请求
是否需要注入站点 需要（站点有注入漏洞） 不需要（站点本身可能没漏洞）
是否需要用户已登录 不一定 必须（否则没有可盗用的身份）
最根本防御 输出转义 Token / SameSite Cookie
关系 XSS 常是 CSRF 的"跳板"——XSS 偷到 Token 后可绕过 CSRF 防护

一句话区分：XSS 是"在你的浏览器里跑我的代码"，CSRF 是"用你的身份发我的请求"。

11.2 拒绝服务（DoS）的常见手段（补充）

手段 原理
SYN Flood 疯狂发 SYN 但不完成第三次握手，把服务器半连接队列耗尽（TCP 半连接攻击）
Smurf 用伪造的源 IP（受害者）向广播地址发 ICMP，放大流量
Teardrop 发送分片重叠的畸形 IP 分组，导致目标系统崩溃（系统漏洞型）
Land 源地址与目的地址相同，导致系统循环处理

十二、防火墙（包过滤 / 应用级网关 / 状态检测）

12.1 防火墙的三种主要技术（必背对比表）

类型 工作层次 原理 优点 缺点
包过滤防火墙 网络层 + 传输层 依据 IP 地址、端口号、协议号、传输方向逐条匹配规则，决定放行/丢弃 速度快、对应用透明、处理开销小 不检查应用层数据，无法防御应用层攻击（SQL 注入/XSS）；无法识别伪造源 IP 的某些攻击；规则维护易出错
应用级网关（应用代理） 应用层 内外网通信必须先连到代理，代理完全理解应用协议后中转 安全性最高、可检查应用内容、可审计日志 速度慢；每种协议需单独的代理程序；对客户端可能不透明（需配置代理）
电路级网关 会话层 只代理连接建立过程（如 SOCKS），不检查应用内容 比应用代理快，比包过滤多一层保护 不检查应用内容；需客户端支持
状态检测防火墙 网络层 ~ 应用层 维护连接状态表：首包按安全规则严格检查并记录状态，后续包按状态表直接放行 兼顾安全与性能（不用每个包都查规则）——当前主流 实现复杂、仍需配合应用层检查

⚠️ 易错点： 1. 包过滤防火墙看不到应用层数据——所以它挡不住 SQL 注入/XSS（这些是应用层攻击）。这是最常考的一条。 2. 状态检测的核心是"状态表"——它知道"这是一个已建立的 TCP 连接的第 N 个包"，而不是把每个包都当新连接处理。 3. 应用级网关能理解应用协议，所以能审计和过滤内容，代价是慢。

12.2 防火墙的部署与局限

部署方式： - DMZ（非军事区/隔离区）：放在"内网—DMZ—外网"三区域之间，DMZ 里放对外提供服务的服务器（Web、邮件、DNS）。外网只能进 DMZ，不能直接进内网。 - 默认拒绝（白名单）原则：除非规则明确允许，否则一律拒绝。这是防火墙的基本安全原则。

防火墙的 5 大局限（常考"防火墙不能做什么"）： 1. 防外不防内——对来自内网的攻击基本无能为力（据统计多数攻击来自内部）。 2. 不能防范绕过它的流量（拨号、私接 WiFi、U盘）。 3. 不能防止应用层攻击（包过滤型；需 WAF/应用层防火墙）。 4. 不能对加密流量做内容检查（除非由它终结 TLS，否则看不到内容）。 5. 单点故障——防火墙本身宕机则全网断连（需双机热备）。

十三、入侵检测 IDS 与入侵防御 IPS

13.1 IDS（Intrusion Detection System，入侵检测系统）

功能：实时监测网络/系统中的可疑行为，发现入侵并告警。

部署：旁路部署（镜像/分光方式接在网络关键节点），不在数据转发路径上。

两类检测技术（必考辨析）：

检测技术 原理 优点 缺点
误用检测（特征检测） 像"病毒库"——把已知攻击的特征模式建库，匹配即报警 准确率高（报了基本都是真攻击）、误报低 只能发现已知攻击，漏报新型攻击（0day）；需持续更新特征库
异常检测 先建立"正常行为基线"，偏离基线即报警 能发现未知攻击 误报率高（新业务、正常波动都可能报）

蜜罐（Honeypot）：故意暴露的"诱饵"系统，引诱攻击者进入，捕获其行为特征，用于研究和预警。

13.2 IPS（Intrusion Prevention System，入侵防御系统）

功能：不仅检测，还能直接阻断（丢弃恶意包、断开连接、阻断 IP）。

部署：串联部署（inline），位于数据转发路径上，因此要求低延迟、高可用（一旦故障会影响网络通畅）。

13.3 IDS vs IPS（必背对比）

对比维度 IDS 入侵检测 IPS 入侵防御
部署方式 旁路（镜像流量） 串联（在线）
响应方式 只告警/记录，不干预 主动阻断/丢弃恶意流量
处理时序 检测在传输之后（事后告警） 在转发过程中实时阻断
对网络的影响 不影响正常转发 在转发路径上，故障可能断网
适用场景 审计、取证、安全运营监控 边界防护、实时拦截

一句话：IDS 是"摄像头"（只看不拦），IPS 是"保安"（发现就拦）。

十四、VPN 与 IPSec 基础

14.1 VPN 是什么

VPN（Virtual Private Network，虚拟专用网络）：在公共网络（Internet）之上建立专用的、加密的通信隧道，效果如同拉了一根专用专线，但成本远低于专线。

VPN 的四项关键技术： 1. 隧道技术：把一种协议的包封装进另一种协议的包里传输。 2. 加密技术：保证隧道内数据机密性。 3. 身份认证：确认接入者身份（用户名口令、证书、预共享密钥）。 4. 密钥管理：协商与分发密钥（如 IKE）。

14.2 IPSec（网络层安全协议，VPN 主力）

IPSec 工作在网络层（IP 层），对上层数据透明保护。两个核心协议：

协议 协议号 提供的安全服务 要点
AH（Authentication Header，认证头） 51 数据完整性 + 身份认证 + 防重放 不加密！不提供机密性（数据仍是明文，只是不能改、不能伪造）
ESP（Encapsulating Security Payload，封装安全载荷） 50 加密（机密性）+ 完整性 + 认证 + 防重放 最常用；AH 能做的 ESP 都能做，ESP 还能加密

⚠️ 高频易错点：AH 不提供加密/机密性！"用 AH 保证数据保密性"是错的；要保密必须用 ESP。

14.3 IPSec 的两种工作模式（必考，会画图区分）

【传输模式 Transport】只保护 IP 上层载荷（端到端，主机到主机）

  ┌─────────┬───────────────────────┐
  │ IP 头   │  AH/ESP + TCP/UDP 数据 │   ← 原 IP 头保留，AH/ESP 插在 IP 头和载荷之间
  └─────────┴───────────────────────┘

【隧道模式 Tunnel】加密整个原 IP 包，套上新的 IP 头（站点到站点，VPN 网关到网关）

  ┌─────────────┬───────────────────────────────┐
  │ 新 IP 头     │  AH/ESP + 【原 IP 头 + 载荷】  │  ← 整个原包被保护，源/目的地址被隐藏
  └─────────────┴───────────────────────────────┘
模式 保护范围 典型场景 特点
传输模式 仅保护 IP 载荷（IP 头不保护） 主机到主机的端到端加密 开销小；原 IP 头暴露（可被流量分析）
隧道模式 保护整个原 IP 数据报（含原 IP 头） VPN 网关到网关（分支机构互联）、主机到网关 隐藏内部源/目的地址，安全性更高；开销更大；IPSec VPN 最常用隧道模式

其他 IPSec 组件： - SA（Security Association，安全关联）：一个单向的逻辑连接（双向通信需两个 SA），由 SPI（安全参数索引）+ 目的 IP + 安全协议（AH/ESP） 唯一标识。 - IKE（Internet Key Exchange）：自动协商 SA 和密钥的协议，基于 Diffie-Hellman 算法安全交换密钥。

14.4 常见 VPN 对比

VPN 类型 工作层次 特点
IPSec VPN 网络层（三层） 保护所有 IP 流量；适合站点到站点互联；客户端需安装软件
SSL/TLS VPN 应用层/传输层（七层） 用浏览器即可接入，无需安装客户端；可做细粒度（到应用/URL）权限控制；适合远程接入
MPLS VPN 数据链路/网络层之间（标签交换） 运营商提供，隔离而非加密（QoS 有保障）；常被称为"专线替代"
L2TP / PPTP 数据链路层（二层隧道） 封装 PPP 帧；本身不加密，通常与 IPSec 配对使用（L2TP/IPSec）

十五、无线局域网安全（WEP → WPA → WPA2 → WPA3，简表）

标准 加密算法 现状
WEP RC4（24 位 IV，缺陷致命） 已完全破解，几分钟即可破，绝不可用
WPA RC4 + TKIP（加长 IV、动态密钥） WEP 的过渡补丁，已不推荐
WPA2 AES + CCMP（802.11i 标准） 当前主流，企业版配合 802.1X + RADIUS 认证
WPA3 AES + SAE（替代 PSK 的对等认证） 新一代，抗离线暴力破解、强制完美前向安全（PFS）

关联：SM4 是我国 WAPI 无线安全标准使用的对称算法（见 §2.1）。

6 表示层          ├─ 合并 ─→│                 IMAP/DNS/Telnet/SSH/SNMP/DHCP
5 会话层          ┘         └────────────────  （加密/压缩/编码 = 表示层）
───────────────────────────────────────────────────────────────────
4 传输层          ─────────→   传输层          TCP/UDP（PDU: 报文段）
───────────────────────────────────────────────────────────────────
3 网络层          ─────────→   网际层          IP/ICMP/ARP/IGMP（PDU: 分组）
                                                    设备：路由器
───────────────────────────────────────────────────────────────────
2 数据链路层      ┐         ┌─ 网络接口层      Ethernet/PPP/Wi-Fi（PDU: 帧）
1 物理层          ┘ 合并 ─→│                     设备：交换机/网桥、集线器/中继器
───────────────────────────────────────────────────────────────────

Day 4 六条核心结论： 1. 口诀「物联网传会表应」（物/链/网/传/会/表/应，自下而上）。 2. ARP 属网际层（网络层）——把 IP 解析为 MAC；虽不经 IP 封装，但软考按网际层作答。（day04 §2.3、§6.3） 3. ICMP 属网络层；ping/traceroute 是应用层程序，"程序在哪层"≠"用哪个协议"。（day04 §2.3） 4. 端口号在 TCP/UDP 首部（传输层），IP 首部没有端口号。（day04 §2.4） 5. 封装自上而下逐层加头：报文→报文段→IP 数据报→帧→比特；解封装相反。（day04 §五） 6. 加密/压缩/编码转换 = 表示层；HTTPS 里的 TLS 加密功能对应表示层。（day04 §2.6）

必背端口号（day04 §七）：FTP 20/21、SSH 22、Telnet 23、SMTP 25、DNS 53、DHCP 67/68（UDP）、TFTP 69（UDP）、HTTP 80、POP3 110、IMAP 143、SNMP 161（UDP）、HTTPS 443、RDP 3389。

16.3 板块二：TCP 连接管理与子网划分（Day 5）

TCP 连接管理（详见 day05-tcp.md §二–§六）：

三次握手：  C ──SYN, seq=x──→ S          C: SYN-SENT
           C ←─SYN+ACK, seq=y, ack=x+1── S  S: SYN-RCVD
           C ──ACK, seq=x+1, ack=y+1→ S     C 先 ESTABLISHED

四次挥手：  A ──FIN──→ B                     A: FIN-WAIT-1 → FIN-WAIT-2
           B ──ACK──→ A                     B: CLOSE-WAIT（数据没发完，先别断）
           B ──FIN──→ A                     B: LAST-ACK
           A ──ACK──→ B，等 2MSL → CLOSED    A: TIME-WAIT（2MSL）
  • 为什么三次：防止"已失效的旧连接请求"迟到导致服务器白白分配资源。
  • TIME-WAIT 等 2MSL：① 保证最后的 ACK 到达；② 让本连接残留报文从网络消失。
  • TCP 首部固定 20B，UDP 固定 8B；UDP 无连接、不可靠、快，实时音视频优先选 UDP。

拥塞控制四算法（day05 §6）：

慢开始：cwnd 每 RTT 加倍（指数，1→2→4→8…，"慢"指起点小）
拥塞避免：cwnd 达 ssthresh 后每 RTT +1（线性）
快重传：连续 3 个重复 ACK → 立即重传，不等超时
快恢复：ssthresh = cwnd/2，cwnd = ssthresh（不回 1！）
超时（最严重）：ssthresh = cwnd/2，cwnd = 1（回 1！）

一句话区分："3 个重复 ACK = 偶发丢包，温和减半；超时 = 严重拥塞，打回 1"。

子网划分 5 步法（day05 §八，必考计算，目标 100%）：

① 看前缀 n → 掩码值与块大小（块大小 = 256 − 掩码值所在段）
② 网络地址 = IP AND 掩码（所在段 = ⌊IP ÷ 块大小⌋ × 块大小）
③ 广播地址 = 网络地址 + 块大小 − 1（主机位全 1）
④ 可用主机数 = 2^h − 2（h = 32 − n；−2 是网络地址和广播地址）
⑤ 子网数 = 2^b（b = 借用位数 = n − 原前缀）

关键对照表（day05 §7.3）：/30→2 主机、/29→6、/28→14、/27→30、/26→62、/25→126、/24→254。 CIDR/超网：合并 2^k 个连续网络，前缀减 k（4 个 /24 → /22）。VLSM：按各子网主机数分别定掩码，节约地址。跨网段时 ARP 求默认网关的 MAC（不是目的主机的）。

16.4 板块三：信息安全（Day 6）

加密体系"五层楼"（本日 §2–§8，从下到上背）：

┌─────────────────────────────────────────────────────────────┐
│ ⑤ PKI / CA 证书        ← 解决"这公钥真是那人的吗"（信任链）   │
├─────────────────────────────────────────────────────────────┤
│ ④ 数字签名（A 私钥签摘要）  ← 身份认证 + 抗否认 + 完整性       │
├─────────────────────────────────────────────────────────────┤
│ ③ 报文摘要 MD5/SHA/HMAC ← 完整性（MD5=128 / SHA-1=160 /       │
│                             SHA-256=256；HMAC 带密钥能防伪造）  │
├─────────────────────────────────────────────────────────────┤
│ ② 数字信封（B 公钥加密会话密钥 K）← 解决对称密钥的分发         │
├─────────────────────────────────────────────────────────────┤
│ ① 加密算法：对称 DES/3DES/AES（快、量大）                     │
│              非对称 RSA/ECC（慢、管钥匙+签名）                 │
└─────────────────────────────────────────────────────────────┘

安全协议层级（本日 §九）：IPSec = 网络层（AH 只认证不加密 / ESP 加密+认证；传输 vs 隧道模式）；TLS = 传输层之上（HTTPS = HTTP+TLS，443）；SSH = 应用层（22）；WPA2/WPA3 = 链路层。

HTTPS 握手一句话：握手用非对称（安全协商出对称会话密钥），通信用对称（保证速度）（本日 §十）。

攻防配对四条高频（本日 §十一）： - SQL 注入 → 参数化查询/预编译（+ 输入过滤、最小权限） - XSS → 输出转义（+ CSP、HttpOnly Cookie）——"在你浏览器跑我的代码" - CSRF → Token / SameSite Cookie——"用你身份发我的请求" - 重放攻击 → 时间戳 / 随机数挑战 / 一次性 Token

防护设备三件套（本日 §12–§14）： - 防火墙：包过滤（网络层，快但看不到应用层）/ 应用级网关（应用层，慢但安全）/ 状态检测（状态表，当前主流）；局限：防外不防内、不挡应用层攻击。 - IDS vs IPS：旁路部署只告警 = 摄像头；串联部署会阻断 = 保安；误用检测查已知（漏报新攻击）、异常检测查未知（误报高）。 - VPN：公网上建加密隧道；IPSec VPN 三层、SSL VPN 七层（免装客户端）、MPLS 隔离不加密。

十七、快速自测（遮住答案速答）

  1. 信息安全 CIA 三要素是？答：机密性、完整性、可用性。
  2. 只有谁能提供抗否认？答：数字签名（因为私钥只有发送方有）。
  3. DES 有效密钥长度？分组长度？答：56 位 / 64 位。
  4. 3DES 的密钥长度？答：112 位或 168 位。
  5. AES 分组长度？密钥长度？答：分组固定 128 位；密钥 128/192/256 位。
  6. AES-128/192/256 分别几轮？答：10 / 12 / 14 轮。
  7. 对称加密最大的缺点？答：密钥分发困难（n 人需 n(n−1)/2 个密钥）。
  8. n 个人用非对称加密需要几个密钥？答：2n 个（每人一对）。
  9. RSA 的数学基础？答：大整数因子分解困难。
  10. ECC 的优势？答：密钥短、同等安全（256 位 ECC ≈ 3072 位 RSA）。
  11. DSA 能用来加密吗？答：不能，只能签名。
  12. 数字信封里，"信封"是用什么加密的？答：接收方的公钥（加密的是对称会话密钥 K）。
  13. MD5 / SHA-1 / SHA-256 的输出长度？答：128 / 160 / 256 位。
  14. 报文摘要与加密的根本区别？答：摘要不可逆（单向）。
  15. HMAC 比普通摘要多了什么？答：带密钥，能防伪造、能认证。
  16. 数字签名能保证机密性吗？答：不能，只能保证身份认证、抗否认、完整性。
  17. CA 签发证书用谁的私钥？验证证书用谁的公钥？答：CA 的私钥 / CA 的公钥。
  18. 证书验证的 4 个步骤？答：验签名、查有效期、查吊销（CRL/OCSP）、域名匹配。
  19. HTTPS 握手阶段用什么加密？通信用什么加密？答：非对称 / 对称。
  20. HTTPS 默认端口？答：443。
  21. XSS 和 CSRF 最根本的防御分别是？答：输出转义 / Token（或 SameSite Cookie）。
  22. 防重放攻击的三种手段？答：时间戳、随机数/挑战-应答、一次性令牌。
  23. 包过滤防火墙工作在哪层？能挡 SQL 注入吗？答：网络层+传输层；挡不住（应用层攻击）。
  24. 状态检测防火墙的核心数据结构？答：连接状态表。
  25. IDS 与 IPS 的部署方式与响应区别？答：IDS 旁路只告警；IPS 串联会阻断。
  26. IPSec 的 AH 能加密吗？答：不能，只做认证/完整性；加密用 ESP。
  27. IPSec 隧道模式保护什么？答：整个原 IP 数据报（含原 IP 头）。
  28. IPSec 工作在哪层？答：网络层。
