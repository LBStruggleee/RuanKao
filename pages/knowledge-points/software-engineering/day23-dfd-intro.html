Day 23（10/13）软件工程⑤：DFD 大题入门

阶段定位：Phase 2 错题回归③ 的下午配套。软考中级·软件设计师 科目二（下午卷）试题一固定考数据流图（DFD），15 分——这是整份试卷里最稳的拿分点：题型固定、判分有套路、会画三层图就能拿 12 分以上。

本日定位：这是一份入门导览，不是答题模板。目标是：今天下午花 1 小时，从"看见 DFD 题就发懵"到"知道先看什么、先画什么、错在哪"。

⚠️ 与已有文件分工（不要重复学）： - 概念与定义（DFD 四要素、分层与平衡规则、图书馆借阅系统完整示例）→ Phase 1 的 day12-process.md §4，本文不重复，只在需要时指回去； - 答题模板与考场技巧（试题一四步法、外部实体识别法、存储定位法）→ Day 27 的 subject2/dfd-uml-notes.md，本文不重复，只告诉你什么时候去翻它； - 本文讲入门视角：三层图怎么从一张白纸长出来、读图顺序、平衡规则的图示化、常见错误的判别练习。

说明：本文所有 ASCII 图按「CJK 字符 = 2 个显示列、等宽字体」排版，与 day12-process.md 一致；若发现错位，请检查编辑器是否使用了等宽中文字体。

一、先记住一句话

DFD 只画"数据从哪来、到哪去、被谁加工"，不画控制逻辑。

这一句话区分了 DFD 和程序流程图，也是下午试题一里无数陷阱的源头： - DFD 里没有判断框、没有循环、没有时序——只有带箭头的数据流； - 每条数据流必须有名字，名字是名词短语（"订单""分析结果"），不是动词（"下单""分析"）； - 每个数据流箭头只有一端连加工（另一端连外部实体或数据存储），不能凭空起飞。

二、DFD 的三层结构（一个例子贯穿）

为了把三层图讲清楚，本文用一个网上购书系统作为例子（和 day12-process.md §4.4 的图书馆借阅系统不同，方便你两份对照练习）。

需求描述（模仿试题一【说明】的写法，3 项功能）：

  1. 订单处理：读者提交订单，系统核对图书库存与订单记录后生成发货单返回给读者。
  2. 图书采购：出版社提供新书目录，系统据此生成采购单发回出版社，并将入库新书登记到图书信息表。

识别出的要素：

外部实体 数据存储 加工
E1 读者 D1 图书信息表 1 订单处理
E2 出版社 D2 订单表 2 图书采购

2.1 顶层 DFD（关联图 / Context Diagram）

规则：整个系统看作一个加工（编号常为 0 或不编号），只画外部实体与系统之间的数据流，不画数据存储（存储是系统内部的，顶层看不见）。

└──────────┘   发货单      │                      │
                            └──────┬──────────┬────┘

顶层图的作用：圈定系统边界——谁在系统外面（实体）、系统跟谁交换什么数据。顶层图里出现的实体集合，在 0 层图里必须一个不多一个不少（实体守恒）。

加工编号规则（必背）：逐层用小数点串联——父加工 1 拆成 1.1、1.2、1.3；1.2 再拆就是 1.2.1、1.2.2……。看到编号就能追溯到父加工，阅卷老师也按编号给分。

再往下什么时候停？ 当每个加工都简单到能写出一两句"小说明"（加工逻辑）时，就不用再拆了。软考试题一一般只考到 0 层和 1 层，很少要求画 2 层。

三、读图顺序：E → D → P → 流

下午试题一总是先给图、再问填空。读图按下面四圈扫，顺序不能乱：

第 1 圈：圈外部实体 E（方框）

  • 找人、设备、外部系统：题目【说明】里动作的发出者和接收者；
  • 排除：系统自己（"网上购书系统"）、被处理的数据（"图书""订单"是数据流名字，不是实体）、系统内部生成的结果；
  • 检查：顶层图和 0 层图的实体集合必须完全一致。

第 2 圈：圈数据存储 D（双横线）

  • 扫【说明】里的动词：存储 / 保存 / 记录 / 维护 / 写入 / 读取 / 登记——被这些动词作用的名词就是存储；
  • 命名 = 被存储的名词 + "表 / 信息表 / 文件 / 记录"（后缀灵活，核心词必须来自【说明】原词）；
  • 注意合并：若【说明】写"对图书信息和 信息和库存信息进行维护"，可能是一个"图书信息表"，别拆成两个。

第 3 圈：圈加工 P（圆角矩形 / 圆形）

  • 【说明】的每一项功能就是一个加工，功能有 N 项，0 层一般就有 N 个加工；
  • 加工命名用动宾短语（"订单处理""图书采购"），不用名词（"订单"）也不用动词（"处理"）。

第 4 圈：顺数据流（带箭头的线）

  • 从实体出发，沿箭头走一遍：实体 → 加工 → 存储 → 加工 → 实体；
  • 每条流问三个问题：叫什么名字？从哪来？到哪去？——答案三要素缺一不可（这是试题一问题 3 的给分点）；
  • 读到存储时注意方向：读 = 存储 → 加工，写 = 加工 → 存储（day12-process.md 的高频陷阱）。

口诀："先圈实体再找库，功能对齐画加工，顺着箭头数流名，读写方向别搞反。"

四、画图顺序（和读图同一个顺序）

自己画图（试题一问题 4 的"加工分解"会要求画）时，也是 E → D → P → 流：

步骤 动作 产出
① 定实体 列出所有 E，画在图纸边缘 顶层图的全部方框
② 定存储 列出所有 D，画在图中部 双横线框 D1、D2…
③ 定加工 对照【说明】功能项，画在实体与存储之间 圆角矩形 1、2…
④ 连数据流 按需求逐句连箭头，每个箭头当场命名 全部数据流
⑤ 编号与命名 加工编号（1、1.1…）、检查名字是名词短语 可提交的图

为什么是这个顺序：实体和存储是名词，从【说明】里最容易捞出来，先确定它们就等于先定好了图的"骨架"；加工是动词，等骨架立起来再填，不会画到一半发现没地方放存储。

五、平衡规则图示化（核心考点）

day12-process.md §4.3 给了平衡规则的定义，这里把三条规则画成可以直接照着检查的图。

5.1 守恒规则（每个加工要守恒）

   ✅ 正确：有输入、有输出
   ┌──────────────┐
   │  加工 P       │
   └──────────────┘
   ▲              │
   │输入          │输出
   ────────────────

   ❌ 错误 1：黑洞——有输入无输出
        输入
         │
         ▼
   ┌──────────────┐
   │  加工 P       │  （数据进去了，没出来）
   └──────────────┘

   ❌ 错误 2：奇迹——有输出无输入
   ┌──────────────┐
   │  加工 P       │
   └──────────────┘
                  │输出
                  ▼
   （数据凭空产生）

   ❌ 错误 3：输入不足以产生输出
        输入A
         │
         ▼
   ┌──────────────┐
   │  加工 P       │──► 输出 = f(A, B)  （B 从哪来？没画）
   └──────────────┘

5.2 父子图平衡（上层 ↔ 下层）

父图（0 层）里加工 1 的进出：

   订单 ──► ┌──────────────┐ ──► 发货单
            │ 1 订单处理    │
            └──────────────┘
             ▲            │
          查询库存      写入订单 / 更新库存
          读取订单（进出 D1、D2 的流）

子图（1 层）里 1.1～1.3 合起来，进出必须与父图逐一对应：

   订单 ──► ┌─ 1.1 ─┐                ┌─ 1.3 ─┐ ──► 发货单
            └───────┘                └───────┘
                │  D2 订单表  D1 图书信息表  ▲
                └───► 1.2 ◄─────────────────┘

检查动作：把子图里所有与外部实体、数据存储相连的流列成两列（输入列 / 输出列），再和父图中被分解加工的流列成两列，逐条划掉。划不完或有剩余 = 不平衡。

注意：名称可以合并或分解（父图一条"读者请求"在子图可以是"借书请求 + 还书请求"），但数据的总量和方向不能变。

5.3 无悬空流

   ✅ 每条流至少一端连加工：
   E ──► P      P ──► E      D ──► P      P ──► D      P ──► P（加工之间）

   ❌ 实体 ↔ 实体直接相连：
   E1 ──────────────► E2    （中间没有加工，数据不经处理就到另一端？）

   ❌ 存储 ↔ 存储直接相连：
   D1 ──────────────► D2    （数据自己从一张表跳到另一张表？）

   ❌ 流的一端悬空：
   ? ──► P                     P ──► ?

5.4 一句话总结三条规则

每个加工要守恒（有进有出够用），父子图要守恒（进出不多不少），每条流要落地（一端必须连加工）。

六、常见错误类型 + 判别练习

6.1 六种典型错误（对号入座）

# 错误 一眼判别法 在试题一里的考法
1 黑洞 加工只有进、没有出 问题 3 补数据流时，某个加工下面"光秃秃"
2 奇迹 加工只有出、没有进 同上，反过来
3 输入不足以产生输出 输出里用到了某个数据，但没有任何流把它送进来 最难的一种，要逐项对输出做"来源追溯"
4 父子图不平衡 子图的进出流和父图对不上（多了或少了） 问题 3/4 常考："图 1-2 比图 1-1 少了哪条流？"
5 悬空流 / 实体直连 一条流两端都没有加工 问题 3 的错误选项常长这样
6 混入控制流 出现条件、循环、时序（"若成功则…""循环执行"） 改错题里把流程图当 DFD 画

官方答案原文（逐字记忆，问题 4 直接默写）：分解时需要注意的错误是—— 1、加工有输入但是没有输出；2、加工有输出但是没有输入；3、加工的输入不足以产生输出。 这三句几乎每份真题的分解题都按此给分（见 dfd-uml-notes.md 第 3 步）。

6.2 判别练习（先自己做，再翻 day27 笔记核对）

下列四个小题!缩微版的试题一场景。先自己判别错在哪、属于上表哪一类，再看括号里的提示去 dfd-uml-notes.md / dfd-uml-exercises.md 对应处核对。本文不直接给答案——判别能力是被"卡住一下"练出来的。

练习 1：某系统的【说明】写"业务员将检测申请单录入系统，系统生成检测任务单"。0 层图里画了 业务员 ──► 检测任务单。这条流有什么问题？

练习 2：子图（1 层）中加工 1.1～1.4 分别接收"读者请求"，父图（0 层）中加工 1 只有一条进流"借书请求"。父图与子图平衡吗？

练习 3：0 层图里某加工的输入是"历史监测信息"，输出来源需要它，但图上"历史监测信息"只在两个加工 P2 → P3 之间流转。这里最可能缺了什么？（提示：带"历史/批量/记录/已存"字样的输入只能来自数据存储）

练习 4：有人把"订单处理"加工画成：订单 ──► [库存够吗？] ──► 发货单，中间是菱形判断框。这违反了 DFD 的哪条根本规则？

核对位置：练习 1/3/4 → dfd-uml-notes.md「第 3 步 数据流平衡检查」；练习 2 → 本文 §5.2 与 day12-process.md §4.3。
