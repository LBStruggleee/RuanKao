答案与解析

第一部分：结果推导题

1. A 先按系分组，算各组人数与平均年龄，再用 HAVING 过滤、排序：

计算机系：1001(19)、1002(20)、1007(22) → 3 人，平均 = 61/3 = 20.33
数学系：  1003(18)、1004(21)           → 2 人，平均 = 39/2 = 19.5
信息系：  1005(23)、1006(19)           → 2 人，平均 = 42/2 = 21.0
HAVING AVG(Age) >= 20 → 淘汰数学系（19.5）
ORDER BY 平均年龄 DESC → 信息系(21.0) 在前，计算机系(20.33) 在后

结果：信息系/2/21.0；计算机系/3/20.33。B 选项排序方向反了；C 选项数学系平均 19.5 不满足 HAVING，不该出现；D 选项既漏了信息系、又留下了数学系。 （知识点：GROUP BY + HAVING + ORDER BY；对应 day07-sql.md §3.6）

2. A 先连接三表，再只留信息系学生：

信息系学生：1005 钱娜、1006 孙强
钱娜的选课：C1 数据库 95、C3 操作系统 78
孙强的选课：C2 数据结构 88、C3 操作系统 55
ORDER BY Grade DESC → 95、88、78、55

结果：钱娜/数据库/95；孙强/数据结构/88；钱娜/操作系统/78；孙强/操作系统/55。B 选项把 78 和 55 的顺序排反了（DESC 下 78 必须在 55 前）；C 选项完全没排序；D 选项前两行顺序就错了。 （知识点：三表内连接 + 排序；对应 day07-sql.md §2.4、§3.7）

3. C 内连接只保留有选课记录的学生，再筛选"成绩<60 或 成绩为 NULL"：

SC 全部 14 行中：
  Grade < 60 的：1006/C3/55（孙强，操作系统）→ 1 行
  Grade IS NULL 的：1002/C2/NULL（李华，数据结构）→ 1 行
  注意：NULL < 60 的结果是 UNKNOWN，所以"OR Grade IS NULL"这个条件不可省

结果：1002/李华/2；1006/孙强/3。A、B 各漏一行；D 是最大陷阱——1007 周敏确实没选课，但她在 SC 中一行都没有，内连接根本不会产生她的行，也就不会出现"1007/周敏/NULL"这一行。要查 1007 必须用左外连接（见 day07-sql.md 例 3）。 （知识点：NULL 的三值逻辑 + 内连接语义；对应 day07-sql.md §五陷阱 1、§3.7）

4. B 先算子查询（选了 C3 操作系统的人），再取补集：

子查询：Cno='3' 的 Sno → 1001、1003、1005、1006（4 人）
NOT IN → S 中不在该集合的学生：1002 李华、1004 赵磊、1007 周敏（3 人）

结果：李华、赵磊、周敏。A 恰好是补集（选了 C3 的人）；C 漏了周敏——周敏没选任何课，当然也没选 C3，属于"没选 C3"的人；D 明显错误。等价写法：NOT EXISTS (SELECT * FROM SC WHERE SC.Sno=S.Sno AND SC.Cno='3')。 （知识点：NOT IN 子查询；对应 day07-sql.md §3.8）

5. A C2（数据结构）共有 4 条选课记录，其中李华的成绩是 NULL：

COUNT(*)       → 数行 = 4（NULL 行也数）
COUNT(Grade)   → 数非空成绩 = 3（李华的 NULL 不数）
AVG(Grade)     → (85 + 70 + 88) / 3 = 243/3 = 81.0（分母是 3，不是 4）

结果：4 / 3 / 81.0。B 选项 COUNT(Grade) 把 NULL 算进去了；C 选项 COUNT() 少算了 NULL 行；D 是最容易错的——把 AVG 的分母当成 4：243/4 = 60.75。COUNT() 数行、COUNT(列) 数非空值、AVG 的分母只算非空值**，这三者必须分清。 （知识点：聚合函数对 NULL 的三种态度；对应 day07-sql.md §3.5、§五陷阱 2）

6. B 交集 = 同时出现在两个集合中的学号：

选了 C1 的：1001、1002、1003、1005（4 人）
选了 C2 的：1001、1002、1004、1006（4 人）
INTERSECT → 同时选了两门：1001、1002（2 人）

结果：1001、1002。注意 1002 李华的 C2 成绩虽是 NULL，但"选了这门课"这一事实成立（SC 中有该行，子查询的条件是 Cno='2'，与 Grade 无关），所以她算"选了 C2"。C 选项是 UNION 的结果（6 人）；D 选项是 EXCEPT（选了 C1 没选 C2）的结果——本题把集合运算的三个关键字放在同一组数据里考，务必区分。 （知识点：集合运算 INTERSECT；对应 day07-sql.md §3.9）

7. A 先选择（横向筛行）再投影（纵向选列）：

σ_{Age≥20}(S)：李华(20)、赵磊(21)、钱娜(23)、周敏(22) → 4 行
π_{Sname,Age}：保留姓名、年龄两列

结果：李华/20；赵磊/21；钱娜/23；周敏/22。B 是补集（年龄<20 的：张明 19、王芳 18、孙强 19）；C 混入了孙强 19（19 < 20，不该出现）；D 说明选择条件没生效。运算顺序：先 σ 后 π——若先投影掉了 Age 列，就没法再做 Age≥20 的选择了。 （知识点：选择 σ 与投影 π；对应 day07-sql.md §2.1、§2.2）

8. A 先连接、再按学分过滤、然后分组求和、最后筛组：

WHERE Credit = 4 → 只留 C1 数据库、C2 数据结构、C4 编译原理（C3 操作系统 3 学分被淘汰）
按学生分组求 SUM(Grade)：
  张明：C1 92 + C2 85 + C4 79 = 256
  李华：C1 75 + C2(NULL) = 75（SUM 忽略 NULL）
  王芳：C1 80 + C4 79 = 159
  赵磊：C2 70
  钱娜：C1 95
  孙强：C2 88
HAVING SUM(Grade) >= 250 → 只剩张明

结果：张明 / 256。D 是本题的主陷阱：344 是张明全部 4 门课的总分（92+85+88+79），但 WHERE Credit=4 已经把 C3 操作系统（88 分）排除在外，所以是 256。B 选项的李华只有 75 分，远不到 250。 （知识点：多表连接 + GROUP BY + HAVING + SUM 忽略 NULL；对应 day07-sql.md §3.5、§3.6、§3.7）

第二部分：关系代数与 SQL 概念

9. B SQL 的逻辑执行顺序是 FROM → WHERE → GROUP BY → HAVING → SELECT →（DISTINCT）→ ORDER BY：先确定数据来源（FROM），再过滤行（WHERE），然后分组（GROUP BY）、过滤组（HAVING），之后才选列（SELECT）、去重（DISTINCT），最后排序（ORDER BY）。A 把 SELECT 放最前、C 让 SELECT 抢在 WHERE 前、D 整体乱序——顺序错会导致"WHERE 里能不能用聚合/别名"这类判断全错。 （知识点：SQL 执行顺序；对应 day07-sql.md §3.4）

10. C WHERE 在 GROUP BY 之前执行，作用是过滤行，不能使用聚合函数（此时还没分组，无从聚合）；HAVING 在 GROUP BY 之后执行，作用是过滤组，可以使用聚合函数。A 错在"等价"——两者过滤对象不同（行 vs 组）；B 把两者的聚合函数权限说反了；D 错——HAVING 的标准用法正是写聚合函数，而列别名在标准 SQL 中并不能保证可用。 （知识点：WHERE vs HAVING；对应 day07-sql.md §3.6 对照表）

11. C DDL = CREATE / DROP / ALTER。SELECT、INSERT 属于 DML（数据操纵语言）；COMMIT 属于 DCL（数据控制语言，与 GRANT/REVOKE 一类）。"CREATE/DROP/ALTER 一定是 DDL"是最稳的判据。 （知识点：SQL 语言分类；对应 day07-sql.md §3.1）

12. B 关系模型三要素 = 关系数据结构 + 关系操作集合 + 关系完整性约束。A（关系/元组/属性）是关系数据结构里的术语；C（候选码/主码/外码）是码的分类；D（选择/投影/连接/除）是关系代数运算——三者都只是三要素中某一个要素的组成部分。 （知识点：关系模型三要素；对应 day07-sql.md §一）

13. C 元组（Tuple）= 一行。A 错（关系 = 一张表，不是一列）；B 错（属性 = 一列）；D 错（基数 = 行数，目 = 列数，两者正好相反，这是高频陷阱）。完整对照：关系=表、元组=行、属性=列、域=取值范围、目=列数、基数=行数。 （知识点：关系模型术语；对应 day07-sql.md §1.1）

14. B 自然连接自动在所有同名属性上做等值连接，并把重复的连接属性列合并成一列；等值连接是 θ 为 = 的连接，保留两个表的全部列（含两个同名的连接列）。A 错（自然连接的连接条件就是"同名属性相等"，并非不需要条件）；C 错（自然连接不限于主码，只要同名即可）；D 错（去重复列的是自然连接，不是等值连接）。 （知识点：等值连接 vs 自然连接；对应 day07-sql.md §2.4）

15. D 笛卡尔积 R × S 的元组数 = |R| × |S| = 5 × 8 = 40。C（13）是相加；A、B 分别是两个关系的行数。写 FROM R, S 忘了连接条件 = 笛卡尔积，是"查询返回多少行"类题目的标准考法。 （知识点：笛卡尔积；对应 day07-sql.md §2.3）

16. B 相关子查询的标志是：子查询引用了外层查询的列（这里是 SC.Sno = S.Sno），外层每处理一行就执行一次内层。A、C、D 的子查询都能独立执行一次（与外层某一行无关），属于不相关子查询：A 的子查询先算出"选了 C1 的学号集合"，C 的派生表先算出"年龄≥20 的学生"，D 的子查询只算一个全校平均年龄。 （知识点：相关子查询 vs 不相关子查询；对应 day07-sql.md §3.8）

17. C EXISTS 只判断子查询"是否有行返回"：有行 → TRUE，无行 → FALSE，完全不关心子查询查的是什么列（SELECT *、SELECT 1、SELECT 'x' 等价）。A 错（EXISTS 不返回那些行，那些行是子查询内部的中间结果）；B 描述的是标量子查询的语义；D 错——EXISTS 判断"存在性"，IN 判断"是否属于某集合"，虽然常能互相改写，但语义并不相同（尤其 NOT EXISTS 不受 NULL 影响，NOT IN 受 NULL 影响）。 （知识点：EXISTS 的语义；对应 day07-sql.md §3.8、§五陷阱 9、12）

18. B Grade = NULL 的比较结果是 UNKNOWN（三值逻辑），而 WHERE 只保留TRUE 的行，所以结果恒为空。判空必须用 IS NULL（选项 A、C、D 的写法都能查出数据：A 查 1002 的 C2 那一行、C 查两行、D 查其余 13 行）。 （知识点：NULL 的三值逻辑；对应 day07-sql.md §五陷阱 1）

19. C 左外连接保留左表（S）的全部 7 名学生：其中 6 名有选课记录，连接后产生 14 行；1007 周敏无匹配行，保留一行、SC 各列补 NULL → 共 14 + 1 = 15 行。A（7）误以为只保留左表行数；B（14）是内连接的结果；D（98）是笛卡尔积（7 × 14）的结果。 （知识点：左外连接的行数；对应 day07-sql.md §3.7）

20. A SQL 的结构对应关系代数的运算顺序：JOIN ↔ ⋈、WHERE ↔ σ、SELECT 列 ↔ π，且必须先连接、再选择、最后投影： - A 正确：S ⋈ SC → σ_{Cno='1' ∧ Grade≥80} → π_{Sno,Sname}，顺序完全对应。 - B 错在先投影后选择——π_{Sno,Sname} 之后关系里已经没有 Cno 和 Grade 列，后面的 σ 条件无从判断。 - C 错在选择只作用在 S 上——S 中根本没有 Cno、Grade 属性，σ 条件写错了地方。 - D 错在缺少投影——σ_{…}(S ⋈ SC) 返回 S 与 SC 的全部列，而 SQL 只选了 Sno、Sname 两列。 （知识点：SQL 与关系代数的相互转换；对应 day07-sql.md §2.6 对照表、§2.4 例 6）
