§零：前置概念速查（承接 Day 7）

范式判断完全建立在 Day 7 的「码家族」和「函数依赖」上。如果昨天这些还说不清，先回 day07-sql.md §1.1 背一遍再继续。

概念 一句话定义
候选码 能唯一标识元组、且任何真子集都不能标识的属性组（唯一性 + 最小性）
主码 从候选码中人为选定的一个
超码 能唯一标识元组的属性组（不要求最小）——候选码是最小的超码
主属性 包含在任一候选码中的属性（注意：只要在一个候选码里出现，就算主属性）
非主属性 不包含在任何候选码中的属性
全码 所有属性合起来才是候选码（此时没有非主属性）
外码 本关系的非主属性，引用了另一个关系的主码

⚠️ 易错点 1：主属性/非主属性的划分取决于候选码全集。如 R(A,B,C)，F={AB→C, AC→B}，候选码是 AB 和 AC，于是 A、B、C 全是主属性——B 在 AC 里、C 在 AB 里。 ⚠️ 易错点 2：候选码可以有多个；题目问"主属性有哪些"时，要把所有候选码的成员并起来。

§一、函数依赖（范式判断的地基）

1.1 定义

设 R(U) 是属性集 U 上的关系模式，X、Y ⊆ U。若对 R 的任意可能实例，只要两个元组在 X 上的取值相同，就必然在 Y 上的取值也相同，则称 Y 函数依赖于 X（或 X 函数决定 Y），记作 X → Y。

  • 语义上：X 是"因"，Y 是"果"。如 Sno → Sname（一个学号只对应一个姓名）。
  • 反过来不一定成立：Sname 一般 ↛ Sno（姓名可重名）。

1.2 平凡依赖与非平凡依赖

类型 定义 例子
非平凡函数依赖 Y ⊄ X（Y 不被 X 包含） (Sno, Cno) → Grade
平凡函数依赖 Y ⊆ X（Y 被 X 包含） (Sno, Cno) → Sno

平凡依赖恒成立（大全体自然包含小全体），所以范式规则只约束非平凡依赖。题目里若给出 X → Y 且 Y ⊆ X，直接当作"废话依赖"，不影响范式判断。

1.3 完全函数依赖与部分函数依赖（→ 2NF 的判据）

设 X → Y，且 Y ⊄ X（非平凡）：

类型 定义 记法
完全函数依赖 对 X 的任何真子集 X'，都有 X' ↛ Y X →(F) Y
部分函数依赖 存在 X 的某个真子集 X'，使 X' → Y X →(P) Y

例 1（完全依赖）：R(Sno, Cno, Grade)，F={(Sno,Cno)→Grade}。 (Sno,Cno) → Grade 是完全依赖：单独 Sno 决定不了 Grade（一个学生有多个成绩），单独 Cno 也决定不了 Grade（一门课有多个学生的成绩）。两个真子集都不行 → 完全依赖。

例 2（部分依赖）：R(Sno, Cno, Sname)，F={(Sno,Cno)→Sname, Sno→Sname}。 (Sno,Cno) → Sname 是部分依赖：存在真子集 {Sno}，使 Sno → Sname 成立。

⚠️ 易错点：单属性候选码不可能产生部分依赖（单属性码的唯一真子集是空集 ∅，∅ → Y 意味着"Y 是常数"，一般不考虑）。所以候选码只有一个属性的关系模式，只要满足 1NF 就自动满足 2NF——这是考场上的快解。

1.4 传递函数依赖与"直接依赖"（→ 3NF 的判据）

传递依赖定义：若 X → Y（非平凡，即 Y ⊄ X），且 Y ↛ X，而 Y → Z（Z ⊄ Y），则称 Z 传递依赖于 X，记 X →(T) Z。链条：X → Y → Z，且 Y 不决定 X。

例 3：R(Sno, Sdept, Sloc)（学生-系-宿舍楼），F={Sno→Sdept, Sdept→Sloc}。 Sno → Sdept → Sloc，且 Sdept ↛ Sno（一个系有多个学生），所以 Sloc 传递依赖于 Sno。

⚠️ 第一大易错点——传递依赖的"反例"（Y → X 时不是传递依赖）： 传递依赖必须满足 Y ↛ X。若 Y → X 也成立（即 X ↔ Y），则 Z 是直接依赖于 X，不是传递依赖。 例 4：R(Sno, Sname, Sdept)，F={Sno→Sname, Sname→Sno, Sname→Sdept}（姓名唯一，可反查学号）。 虽然 Sno → Sname → Sdept 的链条存在，但 Sname → Sno 成立，Y 决定 X，所以 Sdept 直接依赖于 Sno，不构成传递依赖。该关系模式可达 BCNF。

三类依赖判别速查表

依赖类型 判别条件 对应范式缺陷
部分依赖 X→(P) Y 存在候选码的真子集 X'，X'→Y 破坏 2NF
传递依赖 X→(T) Y X→Y→Z 且 Y↛X 破坏 3NF
左部不含码的非平凡依赖 X→Y，X 不含候选码 X 连超码都不是 破坏 BCNF

1.5 计算工具：Armstrong 公理与属性闭包

Armstrong 公理（3 条）：

公理 内容
A1 自反律 若 Y ⊆ X ⊆ U，则 X → Y（平凡依赖恒成立）
A2 增广律 若 X → Y，且 Z ⊆ U，则 XZ → YZ
A3 传递律 若 X → Y 且 Y → Z，则 X → Z

导出规则（3 条，做题更快）：

规则 内容
合并规则 若 X→Y 且 X→Z，则 X→YZ
分解规则 若 X→YZ，则 X→Y 且 X→Z
伪传递规则 若 X→Y 且 YW→Z，则 XW→Z

记忆：合并/分解是"一揽子"与"拆开"的互逆；伪传递 = 增广 + 传递。

属性闭包 X⁺——求候选码和验证依赖的核心工具：

算法：求属性集 X 在函数依赖集 F 上的闭包 X⁺
─────────────────────────────────────
X⁺ ← X
重复执行：
    对 F 中每一个函数依赖 W → V：
        若 W ⊆ X⁺，则 X⁺ ← X⁺ ∪ V
直到 X⁺ 不再增大（一次完整扫描无新增属性）为止

用途： - 验证依赖：判断 X→Y 是否被 F 逻辑蕴含 ⟺ Y ⊆ X⁺。 - 求候选码：若 X⁺ = U（全部属性），则 X 是超码；再验证最小性 → 候选码。

例 5：U={A,B,C,D,E}，F={AB→C, C→D, D→E}，求 {A,B}⁺。

X⁺ = {A,B}
扫描：AB→C 的左部 {A,B} ⊆ X⁺  → X⁺ = {A,B,C}
扫描：C→D  的左部 {C}   ⊆ X⁺  → X⁺ = {A,B,C,D}
扫描：D→E  的左部 {D}   ⊆ X⁺  → X⁺ = {A,B,C,D,E} = U  ✓

所以 {A,B} 是超码；去掉 A 后 {B}⁺={B}≠U，去掉 B 后 {A}⁺={A}≠U → AB 是候选码。

§二、候选码与主码的判定方法（考场核心技能）

2.1 属性分类法（最快、最不易错）

给定 F，把 U 中每个属性按"在 F 的左右部出现情况"分四类：

类别 判定 结论
L 类 只在左部出现 ✅ 必在候选码中
N 类 在 F 中从未出现 ✅ 必在候选码中（没人能决定它，只能靠自己）
R 类 只在右部出现 ❌ 一定不是候选码成员
LR 类 左右都出现 ⚠️ 待定，需闭包试凑

⚠️ 易错点：N 类属性"必在候选码中"是高频考点。如 U={A,B,C,D}，F={A→B, B→C}，D 从未出现 → D 必在候选码中，候选码是 AD（{A,D}⁺ = {A,B,C,D} = U）。

2.2 求解步骤（标准 4 步）

┌──────────────────────────────────────────────────────┐
│ 第 1 步：属性分类（L / N / R / LR，看 F 中出现位置）  │
└───────────────────────┬──────────────────────────────┘
                        ▼
┌──────────────────────────────────────────────────────┐
│ 第 2 步：取 X = L ∪ N，求闭包 X⁺                       │
└───────────────────────┬──────────────────────────────┘
                        ▼
                ┌───────────────┐
                │  X⁺ = U ？    │── 是 ─▶ X 即唯一候选码，结束
                └───────┬───────┘
                        ▼ 否
┌──────────────────────────────────────────────────────┐
│ 第 3 步：把 LR 类属性逐个加入 X，重算闭包              │
│   ① 先试单个属性：若 (X∪{A})⁺ = U 且 X⁺≠U，则         │
│      {X, A} 是候选码（"最小性"由第 2 步 X⁺≠U 保证）   │
│   ② 单个都不行，再试两个 LR 属性的组合                │
└───────────────────────┬──────────────────────────────┘
                        ▼
┌──────────────────────────────────────────────────────┐
│ 第 4 步：检查是否还有别的候选码                       │
│   对每个求出的候选码，试着把它的属性换成其它 LR 属性   │
│   若闭包仍 = U，则存在多个候选码（它们都是候选码）     │
└──────────────────────────────────────────────────────┘

多候选码检查技巧：若某属性 A 是必需（L 类或 N 类）且单独加上任意一个 LR 属性 B 就能使闭包 = U，那么 F 中所有"与 A 搭配可成码"的 LR 属性都会各自形成一个候选码。

2.3 候选码求解例题（3 道）

例 6（链式依赖，唯一候选码）：U={A,B,C,D}，F={A→B, B→C, C→D}。 - 分类：L={A}，R={D}，LR={B,C}。 - X={A}，X⁺ = {A}→B→C→D = {A,B,C,D} = U。 - 候选码 = A（唯一）。主属性 {A}，非主属性 {B,C,D}。

例 7（多候选码）：U={A,B,C}，F={AB→C, AC→B, BC→A}。 - 分类：三个属性都既在左部又在右部 → 都是 LR 类，没有 L/R/N 类属性。 - 单属性闭包：{A}⁺={A}、{B}⁺={B}、{C}⁺={C}，都不等于 U。 - 两属性闭包：{A,B}⁺ ⊇ AB→C = {A,B,C} = U ✅；{A,C}⁺ ⊇ AC→B = U ✅；{B,C}⁺ ⊇ BC→A = U ✅。 - 候选码 = AB、AC、BC（共 3 个）。三个属性都出现在某个候选码中 → A、B、C 全是主属性，无非主属性。

例 8（含 N 类属性）：U={A,B,C,D}，F={A→B, B→C}（属性 D 与任何依赖都无关）。 - 分类：L={A}（只在左部）；N={D}（F 中从未出现）；LR={B}（A→B 右、B→C 左）；R={C}（只在右部）。 - X = L∪N = {A,D}：X⁺ = {A,D} → A→B → {A,B,D} → B→C → {A,B,C,D} = U ✅。 - 验证最小性：{A}⁺ = {A,B,C}（缺 D，D 无法由任何依赖推出）≠ U；{D}⁺={D} ≠ U。 - 候选码 = AD（唯一）。主属性 {A,D}，非主属性 {B,C}。

这个例子说明一件重要的事："A 能决定 B、C"并不意味着"A 是候选码"——还差一个谁也推不出来的 N 类属性 D。N 类属性必须进候选码，否则它的闭包永远到不了 U。

§三、范式：定义、判断与分解

3.1 四级范式定义表（必背）

范式 定义（判据） 一句话理解
1NF 关系的每个属性都是原子的（不可再分），不允许"表中有表" 一列只存一个值，不能存集合/子表
2NF 满足 1NF，且每个非主属性都完全依赖于候选码（无部分依赖） 消除"非主属性只依赖主码的一部分"
3NF 满足 2NF，且每个非主属性都不传递依赖于候选码（无传递依赖） 消除"非主属性依赖另一个非主属性"
BCNF 满足 1NF，且每个非平凡函数依赖 X→Y 的左部 X 都包含候选码（X 都是超码） "决定者必须是码"，最严格

包含关系：1NF ⊇ 2NF ⊇ 3NF ⊇ BCNF（高级范式是低级范式的子集）。 软考范围内规范化的目标一般是 3NF（实际工程也常止于 3NF）；BCNF 用于消除"主属性对码的部分/传递依赖"。

3.2 3NF 的等价定义（做选择题更快）

R ∈ 3NF ⟺ 对 F⁺ 中每个非平凡函数依赖 X→Y，要么 X 是超码，要么 Y 的每个属性都是主属性。

这个等价定义说明：3NF 允许一种"不完美"的依赖存在——X 不是码，但 Y 只含主属性。这正是 3NF 与 BCNF 的唯一差距（见 §3.5 例 3）。

3.3 范式判断流程图（全文最重要的一张图）

三条考场快解（能省一半时间）： 1. 候选码是单属性 → 不可能有部分依赖 → 直接从第 4 步（传递依赖）开始查。 2. 所有属性都是主属性（没有非主属性）→ 第 3、4 步自动通过 → 直接判 3NF，只剩 BCNF 需要检查。 3. F 中每个依赖的左部都是候选码 → 直接判 BCNF（第 3、4、5 步全部通过）。

3.4 规范化分解（投影分解法）

记住两句话就够用：

违反的范式 分解动作
部分依赖 W→Y（W 是候选码 X 的真子集） 新建关系 (W, Y)；原关系删去 Y（保留 W 作外码指向新关系）
传递依赖 X→Y→Z 新建关系 (Y, Z)；原关系删去 Z（保留 Y 作外码指向新关系）

分解的质量要求（大题常问"该分解是否满足……"）： - 无损连接性：分解后自然连接的结果 = 原关系（不丢失、不多出元组）。 - 保持函数依赖性：F 中所有依赖都能在分解后的某个关系中被检查（不必跨关系）。 - 定理：分解到 3NF 总能同时做到无损连接 + 保持依赖；分解到 BCNF 能保证无损连接，但不一定保持依赖。

⚠️ 易错点：题目问"该分解是否保持函数依赖"时，逐条检查 F 中的依赖是否在某个子关系的属性集内。若有一条依赖的属性跨了两个子关系 → 不保持依赖（这是 BCNF 分解的常见代价）。

3.5 范式判断完整例题（4 道，考场模板）

例 9：R(Sno, Cno, Sname, Grade, Sdept) —— 最高 1NF

函数依赖集：F={(Sno,Cno)→Grade, Sno→Sname, Sno→Sdept}（姓名不唯一）。

第 1 步：求候选码 - 分类：L={Sno, Cno}（只在左部）；R={Grade, Sname, Sdept}（只在右部）；无 LR、N 类。 - X={Sno,Cno}，X⁺ = {Sno,Cno} → Grade、Sname、Sdept = U ✅。 - 候选码 = (Sno, Cno)。主属性 {Sno, Cno}；非主属性 {Sname, Sdept, Grade}。

第 2 步：关系是二维表，属性原子 → 满足 1NF。

第 3 步（部分依赖检查）：候选码是组合码，必须查！ - Sno → Sname：真子集 {Sno} 决定非主属性 Sname → Sname 部分依赖于候选码 ❌

结论：R ∈ 1NF（不满足 2NF）。

如何分解到 3NF： 1. 消除部分依赖：Sno→Sname、Sno→Sdept 的左部 {Sno} 是候选码真子集 → 拆出 S(Sno, Sname, Sdept)；原关系删去 Sname、Sdept，保留 Sno 作外码 → SC(Sno, Cno, Grade)。 2. 检查两个新关系： - S(Sno, Sname, Sdept)：F={Sno→Sname, Sno→Sdept}，候选码 Sno（单属性，无部分依赖）；Sname、Sdept 都直接依赖 Sno，无传递依赖（不存在 Sname→Sdept）→ BCNF。 - SC(Sno, Cno, Grade)：F={(Sno,Cno)→Grade}，候选码 (Sno,Cno)，Grade 完全依赖、无传递，左部含码 → BCNF。 3. 最终：S(Sno, Sname, Sdept) + SC(Sno, Cno, Grade)，均达 BCNF，且无损连接、保持依赖。 4. Sno 在 SC 中是外码（引用 S 的主码），这就是 E-R 转换中 1:N 联系的标准结果（见 §五）。

例 10：R(Sno, Sdept, Sloc, Mname) —— 最高 2NF

语义：学生属于一个系，系有一个宿舍楼，系有一位系主任。F={Sno→Sdept, Sdept→Sloc, Sdept→Mname}。

第 1 步：求候选码 - 分类：L={Sno}；R={Sloc, Mname}；LR={Sdept}。 - X={Sno}，X⁺ = {Sno}→Sdept→{Sno,Sdept}→Sloc、Mname = U ✅。 - 候选码 = Sno。主属性 {Sno}；非主属性 {Sdept, Sloc, Mname}。

第 2 步：原子属性 → 满足 1NF。

第 3 步（部分依赖）：候选码是单属性 → 不可能有部分依赖 → 满足 2NF 的这一半。

第 4 步（传递依赖）： - Sno → Sdept → Sloc：Sdept ↛ Sno（一个系有多个学生）→ Sloc 传递依赖于 Sno ❌ - Sno → Sdept → Mname：同理 → Mname 传递依赖于 Sno ❌

结论：R ∈ 2NF（不满足 3NF）。

💡 这正是"数据冗余"的根源：一个系有 500 个学生，"该系的宿舍楼和系主任"就重复存 500 遍；换系主任要改 500 行（更新异常）；新系还没招到学生就存不进系主任信息（插入异常）。

如何分解到 3NF： 1. 消除传递依赖 Sno→Sdept→Sloc、Sno→Sdept→Mname：把 (Sdept, Sloc, Mname) 拆成一个关系；原关系删去 Sloc、Mname → SD(Sno, Sdept)。 2. 检查： - SD(Sno, Sdept)：F={Sno→Sdept}，候选码 Sno → BCNF。 - DL(Sdept, Sloc, Mname)：F={Sdept→Sloc, Sdept→Mname}，候选码 Sdept（单属性，Sloc、Mname 直接依赖，无传递）→ BCNF。 3. 最终：SD(Sno, Sdept) + DL(Sdept, Sloc, Mname)，均达 BCNF，无损连接且保持依赖。Sdept 在 SD 中是外码。

例 11：R(A,B,C)，F={AB→C, C→B} —— 3NF 但不是 BCNF（最经典的分界例题）

第 1 步：求候选码 - 分类：L={A}（只在 AB→C 左部）；LR={B, C}（C 也在 C→B 的左部出现，故为 LR 类，不是 R 类）；R=∅。 - X={A}，X⁺={A}≠U。 - 试加入 LR 类 B：{A,B}⁺ = AB→C → {A,B,C} = U ✅ → AB 是候选码。 - 再检查是否存在其它候选码：把 B 换成 C 试试，{A,C}⁺ = C→B → {A,B,C} = U ✅ → AC 也是候选码。 - 候选码 = AB、AC。A、B、C 全是主属性（A 在两个码里，B 在 AC 里，C 在 AB 里），无非主属性。

第 2 步：原子 → 满足 1NF。

第 3 步（部分依赖）：没有非主属性 → 自动满足。

第 4 步（传递依赖）：没有非主属性 → 自动满足 → R ∈ 3NF。

第 5 步（BCNF 检查）：逐个检查非平凡依赖： - AB→C：左部 AB 是候选码（超码）✅ - C→B：左部 C 不是超码（C⁺={B,C}，不含 A），且右部 B 虽是主属性，但 BCNF 不允许左部不是码的依赖 ❌

结论：R ∈ 3NF，但 R ∉ BCNF。

💡 记住这个反例：它同时说明两件事——① 3NF 不蕴含 BCNF；② 3NF 的等价定义里"Y 是主属性"的豁免，正是 BCNF 取消的豁免。

如何分解到 BCNF： 1. 把违规依赖 C→B 拆出来：R1(C, B)（F1={C→B}，候选码 C → BCNF）。 2. 剩余属性：R2(A, C)（候选码 AC，无非平凡依赖 → BCNF）。 3. 检查无损连接：R1⋈R2 在 C 上连接，因 C→B，(R1⋈R2) 的投影 = R，无损 ✅。 4. 检查保持依赖：C→B 在 R1 中 ✅；AB→C 的属性 A、B、C 分属两个关系 → 不保持 ❌ → 这正是"BCNF 分解不一定保持依赖"的标准例证。

例 12：R(Sno, Cno, Grade) —— 直接 BCNF（快解示范）

F={(Sno,Cno)→Grade}。 - 候选码 (Sno,Cno)；主属性 {Sno,Cno}；非主属性 {Grade}。 - Grade 完全依赖于候选码（Sno 或 Cno 单独都不决定 Grade）→ 满足 2NF。 - 不存在 Sno→?→Grade 的传递链 → 满足 3NF。 - F 中唯一非平凡依赖的左部就是候选码 → 满足 BCNF。 结论：R ∈ BCNF。典型的"选课关系"——这也是为什么教务系统总把选课单独建表。

3.6 范式与异常的关系（概念题速答）

不满足 直接后果（冗余/异常）
1NF 属性非原子，无法用关系代数/SQL 正确处理（重复组）
2NF 数据冗余：非主属性随"部分码"重复存储；修改异常：改一处要改多行
3NF 数据冗余：非主属性链式重复；插入异常（新系无学生则系主任存不进去）、删除异常（删掉最后一个学生把系信息也删了）

规范化总目标：消除不必要的数据冗余，解决插入异常、删除异常和更新（修改）异常。 ⚠️ 反方向考点：规范化不是为了提高查询速度（过度规范化反而因多表连接降低查询性能），也不是为了减少表的数量。

§四、E-R 模型（实体-联系模型）

4.1 三要素与图形符号（必背）

要素 表示方法 说明
实体（Entity） 矩形 ▭ 客观存在并可相互区分的事物（学生、课程、图书）
属性（Attribute） 椭圆 ◌ 实体的特征（学号、姓名）。主键属性带下划线
联系（Relationship） 菱形 ◇ 实体间的关联（选课、借阅）。联系也可以有自己的属性
（连接） 无向边 — 连接实体与属性、实体与联系，边上标注联系基数（1 / N / M）

⚠️ 易错点：联系本身可以有属性。如"选课"联系有"成绩"、"借阅"联系有"借期/还期"。大题常考"哪些属性应挂在联系上而不是实体上"——判据：该属性只在"某个实体参与某次联系"时才有意义（成绩没有"选课"这个动作就不存在）。

4.2 三种联系类型（必背）

类型 定义 例子 转换时的基数标注
1:1（一对一） A 中每个实体最多与 B 中一个实体关联，反之亦然 班级 ↔ 班主任 两边都标 1
1:N（一对多） A 中一个实体可关联 B 中多个实体；B 中每个实体只关联 A 中一个 班级 → 学生 A 端标 1，B 端标 N
M:N（多对多） A 中一个实体可关联 B 中多个，反之亦然 学生 ↔ 课程 两边都标 N（或 M 和 N）

⚠️ 易错点：1:N 的方向要看清"谁是一、谁是多"。口诀："1 的一方是父亲，N 的一方是孩子"——外码永远加在 N 的一方（见 §5.3）。

§五、E-R 图转关系模式规则（大题拿分点）

5.1 实体与属性的转换

  • 每个实体 → 一个关系模式；实体的属性 → 关系的属性；实体的主键 → 关系的主键。
  • 实体的多值属性（如一个员工有多个电话）→ 必须独立成一个关系（员工电话(员工号, 电话号)，主键为两者组合），否则违反 1NF。

5.2 联系转换规则（必背）

联系类型 转换规则 新增外键 联系属性放哪
1:1 把任一方的主键作为外键加入另一方（建议加到"查询更频繁"的一端），并加 UNIQUE 约束 1 个 随外键并入
1:N 把 1 端的主键作为外键加入 N 端 1 个（在 N 端） 随外键并入 N 端
M:N 必须新建一个关系，包含两端实体的主键 + 联系的全部属性 2 个 放进新关系

⚠️ 第一大易错点：M:N 联系绝不能"把一端主键塞进另一端"——那样无法表达"多对多"（一行只能存一个对方实体）。必须独立建表。 ⚠️ 第二大易错点：1:N 的外键加在 N 端，方向反了是常见错误。口诀："多的一方记着少的一方"。 ⚠️ 第三大易错点：联系的属性不能丢。如转换"选课"时忘了"成绩"，大题会被扣步骤分。

5.3 转换后的自检清单

逐条打勾，大题步骤分就拿全了：

  1. ☐ 每个实体都变成了一个关系，主键正确。
  2. ☐ 每个 M:N 联系都独立成了一个关系，主键 = 两端主键的组合（若联系属性不能唯一，需加属性进主键）。
  3. ☐ 每个 1:N 联系都把 1 端主键作为外码放进了 N 端。
  4. ☐ 每个 1:1 联系都把一方主键作为外码放进了另一方（且有 UNIQUE）。
  5. ☐ 所有外键都指向被引用关系的主键，且被引用关系的主键确实存在。
  6. ☐ 联系的属性没有丢失（如成绩、借期、学期）。
  7. ☐ 没有把实体的非主属性错放进联系的独立关系。

§六、必记结论速查（20 条）

  1. 函数依赖 X→Y：X 相同 ⇒ Y 必相同。平凡依赖（Y⊆X）恒成立，范式不管它。
  2. 完全依赖：候选码的任何真子集都决定不了 Y；部分依赖：存在真子集能决定 Y。
  3. 传递依赖三要素：X→Y（非平凡）、Y↛X、Y→Z。Y→X 成立时不是传递依赖。
  4. 单属性候选码不可能产生部分依赖 → 这类关系满足 1NF 即满足 2NF。
  5. 没有非主属性的关系（全主属性）→ 直接满足 3NF，只需再查 BCNF。
  6. 候选码求法 = 属性分类（L/N/R/LR）+ 闭包。L 类、N 类必在候选码中；R 类一定不是。
  7. 闭包 X⁺ = U ⟺ X 是超码；超码 + 最小性 = 候选码。
  8. 1NF = 属性原子；2NF = 消除非主属性的部分依赖；3NF = 消除非主属性的传递依赖；BCNF = 每个非平凡依赖的左部都含候选码。
  9. 包含关系：1NF ⊇ 2NF ⊇ 3NF ⊇ BCNF。3NF 不蕴含 BCNF（反例：R(A,B,C)，F={AB→C, C→B}）。
  10. 3NF 等价判据：每个非平凡依赖 X→Y，要么 X 是超码，要么 Y 全是主属性；BCNF 取消了后半句豁免。
  11. 分解动作：部分依赖 W→Y ⇒ 拆出 (W,Y)；传递依赖 X→Y→Z ⇒ 拆出 (Y,Z)。
  12. 分解到 3NF：无损连接 + 保持依赖都能保证；分解到 BCNF：保证无损，但不一定保持依赖。
  13. 规范化的目的：消除不必要的数据冗余，解决插入异常、删除异常、更新异常——不是为了提高查询速度。
  14. E-R 三要素 = 实体（矩形）+ 属性（椭圆）+ 联系（菱形）；主键属性带下划线。
  15. 联系类型 1:1 / 1:N / M:N；联系本身可以有属性（成绩、借期、学期）。
  16. 1:1 转换：任一方主键作外键并入另一方（加 UNIQUE）。
  17. 1:N 转换：1 端主键作外键并入 N 端（"多的一方记着少的一方"）。
  18. M:N 转换：必须新建关系，主键 = 两端主键组合，联系属性并入新关系。
  19. 实体的多值属性（多个电话）必须独立成关系，否则违反 1NF。
  20. E-R 转换后自检：实体→关系、M:N 独立成表、外键方向正确、联系属性没丢。
