框架的三条主线（背死）： 1. 静态结构线：关系模型三要素 → 码家族 → 三类完整性 → 1NF（原子性）。 2. 动态操作线：关系代数（σ/π/⋈/×/÷）↔ SQL（WHERE/SELECT/JOIN/FROM/NOT EXISTS），一一对应。 3. 设计质量线：函数依赖 → 候选码 → 范式（1NF→2NF→3NF→BCNF）→ 规范化分解；E-R 模型 → 关系模式（1:1/1:N/M:N 三条转换规则）。

第 2、3 条线的交汇点就是科目二大题：先画 E-R（第 3 条线），再转成关系模式（第 3 条线），最后在上面写 SQL（第 2 条线）。三步一气呵成，每一步都有固定规则可循。

§四、数据库阶段必背结论清单（20 条）

关系模型与关系代数（Day 7 §一、§二） 1. 关系模型三要素 = 关系数据结构 + 关系操作集合 + 关系完整性约束。 2. 关系=表、元组=行、属性=列、码=键、目=列数、基数=行数。 3. 三类完整性 = 实体（主码非空且唯一）+ 参照（外码空或存在）+ 用户定义（CHECK/NOT NULL/UNIQUE）。 4. 关系代数五种基本运算 = σ 选择、π 投影、∪ 并、− 差、× 笛卡尔积；σ↔WHERE、π↔SELECT（π 天然去重，SQL 要 DISTINCT）、⋈↔JOIN、÷↔"全部"（NOT EXISTS 双重否定）。 5. 等值连接保留两个连接列，自然连接合并为一列；笛卡尔积行数 = 左表行数 × 右表行数。

SQL（Day 7 §三） 6. SQL 执行顺序 = FROM → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT。 7. WHERE 过滤行（分组前，禁聚合、禁用 SELECT 别名）；HAVING 过滤组（分组后，可用聚合）。 8. COUNT(*) 数行含 NULL；COUNT(列) 数非空值；SUM/AVG/MAX/MIN 全部忽略 NULL（AVG 分母 = COUNT(列)）。 9. 判空一律 IS NULL，= NULL 恒为 UNKNOWN（三值逻辑）。 10. 内连接只留两边匹配的行；左外保留左表全部、右表补 NULL；右外对称；全外全保留。 11. 左外连接 + WHERE 右表列 IS NULL = 找"在左表但不在右表"的行；外连接中 ON 是连接条件（保留行）、WHERE 是过滤条件（删除行），不可互换。 12. EXISTS 只看有无行返回（SELECT * 与 SELECT 1 等价）；NOT IN 遇 NULL 可能恒假，"不存在"优先 NOT EXISTS。 13. DDL = CREATE/DROP/ALTER；DML = SELECT/INSERT/UPDATE/DELETE；DCL = GRANT/REVOKE/COMMIT/ROLLBACK（软考按三分法）。

范式（Day 8 §一、§二、§三） 14. 完全/部分依赖看"真子集能否决定 Y"；传递依赖三要素 = X→Y 非平凡、Y↛X、Y→Z（Y→X 成立时不是传递依赖）。 15. 候选码求法 = 属性分类（L/N/R/LR）+ 闭包：L 类、N 类必在候选码中；R 类一定不是；闭包 X⁺=U ⟺ X 是超码，超码 + 最小性 = 候选码。 16. 1NF=原子；2NF=无非主属性部分依赖；3NF=无非主属性传递依赖；BCNF=每个非平凡依赖左部都含候选码；包含关系 1NF ⊇ 2NF ⊇ 3NF ⊇ BCNF。 17. 三条考场快解：单属性码无部分依赖；全主属性直接 3NF；F 中左部皆码直接 BCNF。3NF 不蕴含 BCNF（反例：R(A,B,C)，F={AB→C, C→B}，候选码 AB 与 AC，全主属性 → 3NF；C→B 左部不含码 → 非 BCNF）。 18. 分解动作：部分依赖 W→Y ⇒ 拆出 (W,Y)；传递依赖 X→Y→Z ⇒ 拆出 (Y,Z)；分解到 3NF 无损 + 保持依赖都能保证，BCNF 保证无损但不一定保持依赖。

E-R 与数据库设计（Day 8 §四、§五） 19. E-R 三要素 = 实体（矩形）+ 属性（椭圆）+ 联系（菱形），主键属性带下划线；联系本身可以有属性（成绩、借期、参加日期）。 20. 转换规则：1:1 任一方主键作外键并入另一方（加 UNIQUE）；1:N 1 端主键作外键并入 N 端（口诀"多的一方记着少的一方"）；M:N 必须新建关系，主键 = 两端主键组合，联系属性并入新关系；实体多值属性必须独立成关系。

规范化的目的（Day 8 §3.6）：消除不必要的数据冗余，解决插入异常、删除异常、更新异常——不是为了提高查询速度（常考反义选项）。

§六、四张"一眼错"陷阱表（考前最后过一遍）

陷阱表 1：NULL 与聚合（第一大考点）

场景 错误直觉 正确结果（以 SC 的 C2 为例：85 / NULL / 70 / 88）
COUNT(*) NULL 行不算 4（数行，NULL 算 1 行）
COUNT(Grade) 4 3（数非空值）
AVG(Grade) 243÷4 = 60.75 243÷3 = 81.0（分母 3 不是 4）
WHERE Grade = NULL 等价于 IS NULL UNKNOWN，一行查不出
CHECK(Grade>=0 AND Grade<=100) NULL 成绩被拒绝 放行（UNKNOWN 当作通过）

陷阱表 2：JOIN 家族行数（S 7 行 / SC 14 行，1007 无选课）

JOIN 结果行数 记忆点
内连接 14 只留两边都匹配的行，1007 直接消失
左外（S LEFT JOIN SC） 15 +1007（SC 列补 NULL）
右外（S RIGHT JOIN SC） 14 SC 的 14 行全部能匹配到 S
全外 15 +1007
笛卡尔积（FROM S, SC 无条件） 98 7 × 14，灾难

陷阱表 3：范式分界（3NF vs BCNF）

关键问题 结论
非主属性对码有部分依赖？ 有 → 最高 1NF（组合码才可能出现）
非主属性对码有传递依赖？ 有 → 最高 2NF（注意 Y↛X 的验证）
非平凡依赖左部都含码？ 否 → 最高 3NF（此时必存在"X 非码、Y 是主属性"的依赖）
全是主属性的关系？ 直接 3NF，只差 BCNF 检查
3NF 一定 BCNF？ 否：R(A,B,C)，F={AB→C, C→B}，候选码 AB、AC，3NF 但非 BCNF

陷阱表 4：E-R 转换方向

联系类型 最常见错误 正确做法
1:N 外键加在 1 端 / 新建关系 1 端主键作外键并入 N 端
M:N 把一端主键塞进另一端（无法表达多对多） 必须新建关系，主键 = 两端主键组合
联系的属性 丢掉成绩/参加日期/承担角色 随外键并入（M:N 并入新关系）
多值属性 塞进实体关系（违 1NF） 独立成关系，主键为组合

§八、阶段收尾：数据库与 OS / 网络的串联

第一阶段三天科目看似独立，实则是同一种"分层"思想的三种表现：

科目 "分层"的表现 数据库对应的层
OS 用户接口 → 文件系统 → 内存 → 硬件：把复杂的底层管理包成简单的抽象 关系模型把"怎么存"抽象成"一张二维表"，用户不必关心物理存储
网络 OSI 七层：每层只管一件事，层间靠协议接口 SQL 是"非过程化"语言——只说"要什么"，不说"怎么算"（关系代数是过程化的"怎么算"）
数据库 概念模型（E-R）→ 逻辑模型（关系模式）→ 物理存储：设计自顶向下逐层细化 E-R 图是"概念层"，关系模式是"逻辑层"，规范化是"逻辑层的质量优化"

一句话总结第一阶段：OS 教你资源如何被管理，网络教你机器如何互连，数据库教你数据如何被组织。后两阶段（软件工程、设计模式、专业英语）都建立在这三门之上——数据库大题尤其依赖 E-R + SQL 这条线，Phase 2 学 UML 时会再次用到"实体—联系"的建模思维。
