Day 7（9/27）数据库系统①：关系模型与 SQL

考试地位：SQL 是科目二（软件设计）大题的必考内容——近年的大题几乎每年都有一道"读 SQL / 写 SQL / 补全 SQL"的题（5 空 × 15 分 = 最高 15 分，占大题总分 15/75 ≈ 20%）；科目一的选择题中，关系代数与 SQL 语义每年稳定出现 2–3 道。数据库是弱项科目，但 SQL 是短期内最容易拿到手的分数：规则固定、套路清晰，今天练熟 = 大题稳拿。

今日目标：① 关系模型三要素 + 关系代数五种运算能口述；② SQL 完整 SELECT 语法与执行顺序能默写；③ 四种 JOIN 的结果差异能画出来；④ WHERE vs HAVING、NULL 与聚合两大陷阱不再错。

§一、关系模型三要素

关系模型由三要素组成，这是概念题的标准考点（"关系模型由____组成"）：

要素 内容 通俗解释
① 关系数据结构 关系（一张二维表）及相关的域、笛卡尔积等概念 数据长什么样
② 关系操作集合 选择、投影、连接、除、并、交、差等关系运算（关系代数） 能对数据做什么
③ 关系完整性约束 实体完整性、参照完整性、用户定义完整性 数据必须满足什么规则

1.1 术语对照表（必背）

关系模型术语 日常叫法 一句话
关系（Relation） 一张表（Table） 一张二维表就是一个关系
元组（Tuple） 一行（记录） 表里的一行
属性（Attribute） 一列（字段） 表里的一列
域（Domain） 列的取值范围 属性值的合法集合，如 Age ∈ {15, …, 45}
码 / 键（Key） 能唯一标识元组的属性组 见下方"码家族"
目（Degree） 表的列数 关系有 n 列就叫 n 目关系
基数（Cardinality） 表的行数 关系有 m 行就说基数为 m

⚠️ 易错点："目"数列数、"基数"数行数。考题常把两者反过来问，例如"一个 5 目 1000 个元组的关系"= 5 列、1000 行。

码（Key）家族

术语 定义
候选码 能唯一标识元组、且任何真子集都不能标识的属性组（最小性）
主码（Primary Key） 从候选码中人为选定一个
全码（All-key） 关系的所有属性合起来才是候选码（极端情况）
外码（Foreign Key） 本关系的非主属性，但它引用了另一个关系的主码
主属性 包含在任何一个候选码中的属性
非主属性 不包含在任何候选码中的属性

例：SC 表中 (Sno, Cno) 必须组合起来才能唯一标识一行 → (Sno, Cno) 是主码，Sno 和 Cno 都是主属性；Grade 是非主属性。

1.2 关系模型对关系的基本要求（= 1NF 的要求）

  • 每一列必须是原子的（不可再分），不允许"表中有表"——这正是第一范式 1NF 的内容。
  • 列的取值来自同一个域；每一列有唯一的列名；行的顺序、列的顺序无关紧要。
  • 任意两行不能完全相同（关系是集合，集合元素不重复）。

1.3 三类完整性约束

完整性 内容 对应约束
实体完整性 主码不能取空值，且必须唯一 PRIMARY KEY
参照完整性 外码要么全为空，要么必须等于被引用关系中某个已存在的主码值 FOREIGN KEY … REFERENCES …
用户定义完整性 用户根据业务定义的约束，如年龄 0–150、性别男女 CHECK / NOT NULL / UNIQUE

⚠️ 易错点：参照完整性允许外码为空（"还没分配"），只是不能填一个不存在的主码值。 ⚠️ CHECK 与 NULL：CHECK(Grade>=0 AND Grade<=100) 对 NULL 成绩是放行的——NULL 参与比较结果是 UNKNOWN，CHECK 把 UNKNOWN 当作通过。所以 1002 的 C2 成绩为 NULL 可以插入（本文数据已实际验证）。

§二、关系代数（过程化语言）

关系代数是过程化语言（写清"怎么算"），SQL 是非过程化语言（只说"要什么"）。这是选择题高频考点。

五种基本运算：选择 σ、投影 π、并 ∪、差 −、笛卡尔积 ×（附加运算：交 ∩、连接 ⋈、除 ÷ 都可由基本运算导出）。

2.1 选择（Selection，σ）——"选行"

形式化定义：σ_F(R) = { t | t ∈ R ∧ F(t) 为真 }

F 是条件表达式，可含比较运算（>、≥、=、≠、<、≤）和逻辑运算（∧ 与、∨ 或、¬ 非）。选择是横向切割，只动行，不动列。

例 1：σ_{Sdept='计算机系'}(S)

运算过程：在 S 中逐行检查 Sdept='计算机系' 是否为真
结果（3 行，4 列不变）：
Sno Sname Sdept Age
1001 张明 计算机系 19
1002 李华 计算机系 20
1007 周敏 计算机系 22

例 2：σ_{Age≥20}(S)

运算过程：在 S 中逐行检查 Age≥20 是否为真（列数仍为 4，一行都不删）
结果（4 行，4 列不变）：
Sno Sname Sdept Age
1002 李华 计算机系 20
1004 赵磊 数学系 21
1005 钱娜 信息系 23
1007 周敏 计算机系 22

若只想取姓名和年龄两列，那是先 σ 后 π 的组合：π_{Sname, Age}(σ_{Age≥20}(S))——此时中间的 σ 仍是 4 列，只有最后一步 π 才把列削减到 2 列（见 §2.2 例 3）。

SQL 对应：SELECT * FROM S WHERE Sdept='计算机系' —— σ ↔ WHERE。

2.2 投影（Projection，π）——"选列"

形式化定义：π_A(R) = { t[A] | t ∈ R }，其中 A 是 R 的属性子集。

投影是纵向切割，只动列。投影后可能去掉重复行（因为关系是集合）。

例 3：π_{Sname, Age}(S)

Sname Age
张明 19
李华 20
王芳 18
赵磊 21
钱娜 23
孙强 19
周敏 22

例 4（投影去重的典型）：π_{Sdept}(S)

Sdept
计算机系
数学系
信息系

3 行而非 7 行——计算机系出现了 3 次但只保留 1 次。SQL 对应：SELECT DISTINCT Sdept FROM S——π ↔ SELECT 的列 + DISTINCT。

2.3 笛卡尔积（Cartesian Product，×）

形式化定义：R(A) × S(B) 是 R 中每个元组与 S 中每个元组拼接成的所有元组，共 |R| × |S| 行。

例 5：S × SC，行数 = 7 × 14 = 98 行。

⚠️ 易错点：写 FROM S, SC 而忘了连接条件 → 就是笛卡尔积，结果行数 = 左表行数 × 右表行数，是性能与正确性的双重灾难。面试/考试常考的"查询返回了多少行"就是数这个。

2.4 连接（Join，⋈）——"带条件的笛卡尔积"

形式化定义（θ 连接）：

R ⋈{AθB} S = σ{AθB}(R × S)

即：先做笛卡尔积，再按条件 A θ B 筛选。θ 是比较运算符。

连接类型 定义 要点
θ 连接 R ⋈{AθB} S = σ{AθB}(R × S) θ 可以是 >、<、≥、≤、=、≠
等值连接 θ 为 = 的连接 保留两表的连接属性（重复列留着）
自然连接（Natural Join） 在所有同名属性上做等值连接，并去掉重复的连接属性列 结果列数更少
外连接 在内连接基础上，把未匹配的行也保留，缺的列补 NULL 分左外 / 右外 / 全外

⚠️ 等值连接 vs 自然连接（高频考点）：等值连接保留两个连接列，自然连接把它们合并成一列。例如 S ⋈ SC：等值连接保留 S.Sno 和 SC.Sno 两列；自然连接只留一列 Sno。

例 6（等值连接 + 选择 + 投影组合，最经典的考题形态）：

π_{Sno, Sname}(σ_{Cno='1' ∧ Grade≥80}(S ⋈ SC))

分步运算： 1. S ⋈ SC（按 Sno 等值连接）：14 行（SC 的 14 行都能匹配到 S）。 2. σ_{Cno='1' ∧ Grade≥80}：C1 且成绩≥80 的选课行——C1 的成绩为 92(1001)、75(1002)、80(1003)、95(1005)，≥80 的有 92、80、95 → 3 行。 3. π_{Sno,Sname}：

Sno Sname
1001 张明
1003 王芳
1005 钱娜

SQL 对应：SELECT S.Sno, Sname FROM S JOIN SC ON S.Sno=SC.Sno WHERE SC.Cno='1' AND SC.Grade>=80（已实际执行验证，结果与上面完全一致）。

2.5 除运算（Division，÷）——"包含全部"

这是最难、也最常考的运算，专用于表达"查询……全部……"这类需求。

形式化定义：设关系 R 的属性为 A∪B，关系 S 的属性为 B（B 是 R 的一部分属性）：

R ÷ S = π_A(R) − π_A( π_A(R) × S − R )

语义：R ÷ S 的结果是 A 上的一组取值 t，使得对 S 中的每一个元组 s，(t, s) 都在 R 中——即"t 与 S 的所有组合都存在于 R"。

例 7：π_{Sno, Cno}(SC) ÷ π_{Cno}(C) —— 查询选修了全部课程的学生。

分步运算： 1. C 表的全部课程号 = {1, 2, 3, 4}（π_{Cno}(C) 共 4 行）。 2. 各学生选课集合（π_{Sno,Cno}(SC) 的 14 行按 Sno 分组）：

Sno 选课集合 是否 ⊇ {1,2,3,4}
1001 {1, 2, 3, 4} ✅ 是
1002 {1, 2} ❌
1003 {1, 3, 4} ❌
1004 {2} ❌
1005 {1, 3} ❌
1006 {2, 3} ❌
1007 {} （SC 中无记录） ❌
  1. 结果：
Sno
1001

SQL 对应（除运算没有直接的 SQL 关键字，用 NOT EXISTS 双重否定实现）： sql SELECT Sno, Sname FROM S WHERE NOT EXISTS ( -- 不存在一门课…… SELECT * FROM C WHERE NOT EXISTS ( -- ……该学生没有选 SELECT * FROM SC WHERE SC.Sno = S.Sno AND SC.Cno = C.Cno ) ); 双重否定记法：不存在 X 使得 不存在 Y = 对每个 X 都存在 Y = "全部"。已实际执行验证，结果 = 张明（1001）。

2.6 关系代数 ↔ SQL 对照表（必背）

关系代数 SQL 说明
σ_F(R) WHERE F 选择 = 行过滤
π_A(R) SELECT A（必要时加 DISTINCT） 投影 = 列选择；π 天然去重，SQL 要手动 DISTINCT
R × S FROM R, S（无连接条件）/ CROSS JOIN 笛卡尔积
R ⋈_θ S R JOIN S ON θ θ 连接
自然连接 NATURAL JOIN / 同名列等值连接并去重
R ∪ S UNION（去重）/ UNION ALL（不去重） 并
R ∩ S INTERSECT 交
R − S EXCEPT（Oracle 写 MINUS） 差
R ÷ S NOT EXISTS 双重否定 "全部"型查询

记忆口诀：σ 选行、π 选列、⋈ 连表、÷ 全部、∪∩− 集合。

§三、SQL 完整语法

3.1 SQL 语言分类

分类 全称 语句
DDL（数据定义语言） Data Definition Language CREATE、DROP、ALTER（部分系统含 TRUNCATE）
DML（数据操纵语言） Data Manipulation Language INSERT、DELETE、UPDATE、SELECT
DCL（数据控制语言） Data Control Language GRANT、REVOKE、COMMIT、ROLLBACK
（DQL） 数据查询语言 部分教材把 SELECT 从 DML 中单独列出
（TCL） 事务控制语言 部分教材把 COMMIT/ROLLBACK 从 DCL 中单独列出

⚠️ 易错点（考过）：不同教材对 SELECT 和 COMMIT/ROLLBACK 的归属有分歧。软考按 DDL / DML / DCL 三分法作答：CREATE、DROP、ALTER 一定是 DDL（最稳的判据）；GRANT/REVOKE 一定是 DCL。

3.2 DDL：数据定义

建表（含完整三类完整性约束）

CREATE TABLE SC (
    Sno   CHAR(4)     NOT NULL,          -- 用户定义完整性：非空
    Cno   CHAR(2)     NOT NULL,
    Grade SMALLINT,                      -- 允许为空（没考试的学生）
    PRIMARY KEY (Sno, Cno),              -- 实体完整性：主码非空且唯一
    FOREIGN KEY (Sno) REFERENCES S(Sno), -- 参照完整性：外码
    FOREIGN KEY (Cno) REFERENCES C(Cno),
    CHECK (Grade >= 0 AND Grade <= 100)  -- 用户定义完整性：检查约束
);

已用本文数据实际验证：插入 (1001,1,92) 成功；插入 (1001,1,50) 因主码重复被拒绝；插入 (1001,5,120) 因 CHECK 违反被拒绝；插入 (1002,2,NULL) 成功（NULL 通过 CHECK）。

常用 DDL 一览

DROP TABLE SC;                          -- 删除表（结构+数据）
ALTER TABLE SC ADD COLUMN Teacher CHAR(8);  -- 增加列
CREATE VIEW v_cs AS SELECT * FROM S WHERE Sdept='计算机系';  -- 建视图（虚表）
CREATE INDEX idx_sno ON SC(Sno);        -- 建索引

视图（VIEW）：是一张虚表——数据库只存它的定义（一条 SELECT），不存数据。视图可以简化查询、提供逻辑数据独立性、实现权限控制。带 WITH CHECK OPTION 的视图会拒绝执行那些会使视图查不到该行的 INSERT/UPDATE。

3.3 DML：数据更新

-- 插入
INSERT INTO S VALUES ('1008', '吴迪', '计算机系', 20);
INSERT INTO S (Sno, Sname) VALUES ('1009', '郑爽');   -- 未列出的列取 NULL

-- 修改
UPDATE SC SET Grade = Grade + 5 WHERE Sno = '1006';   -- 孙强 C2: 88→93, C3: 55→60

-- 删除
DELETE FROM SC WHERE Grade IS NULL;                  -- 删除 1002 的 C2 记录

已实际验证：UPDATE 后 1006 的成绩变为 C2=93、C3=60；DELETE 后 1002 只剩 C1=75 一条记录，SC 表从 14 行变 13 行。 ⚠️ DELETE vs TRUNCATE vs DROP：DELETE 是 DML、可带 WHERE、可回滚；TRUNCATE 是 DDL、清空全表、不可回滚、速度快；DROP 连表结构一起删。 ⚠️ 删除一行用主码定位：DELETE FROM SC WHERE Sno='1006' AND Cno='3'——只用 Sno 会删掉该学生的所有选课行。

3.4 DQL：完整查询语法与执行顺序

完整语法模板

SELECT [DISTINCT] 列名/表达式/聚合函数 [AS 别名]     -- ⑤ 选列
FROM   表1 [JOIN 类型 JOIN 表2 ON 连接条件]          -- ① 确定数据来源
WHERE  行过滤条件                                    -- ② 过滤行
GROUP BY 分组列                                     -- ③ 分组
HAVING 组过滤条件                                    -- ④ 过滤组
ORDER BY 排序列 [ASC|DESC]                          -- ⑥ 排序
[LIMIT n];                                          -- ⑦ 限定行数

逻辑执行顺序（必须倒背如流）

FROM → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT

记忆口诀："先找表（FROM），再筛行（WHERE），再分组（GROUP BY），再筛组（HAVING），最后选列（SELECT）、去重（DISTINCT）、排序（ORDER BY）、限量（LIMIT）"。

执行顺序解释了三条硬规则（选择题常考）：

规则 原因
WHERE 中不能用聚合函数（WHERE AVG(Grade)>80 非法） WHERE 在 GROUP BY 之前执行，那时还没有分组，谈不上聚合
WHERE 中不能用 SELECT 中定义的别名 SELECT 在 WHERE 之后执行，别名还没诞生（MySQL 是例外，但软考按标准 SQL）
HAVING 中可以用聚合函数，WHERE 中不能 HAVING 在分组之后执行，专门用来过滤组

3.5 聚合函数（COUNT / SUM / AVG / MAX / MIN）

函数 作用 对 NULL 的处理
COUNT(*) 统计行数 NULL 也算 1 行（统计的是行，不是某列的值）
COUNT(列) 统计该列非空值的个数 忽略 NULL
COUNT(DISTINCT 列) 统计该列非空且去重后的个数 忽略 NULL
SUM(列) 求和 忽略 NULL
AVG(列) 平均值 = SUM/COUNT（都忽略 NULL） 忽略 NULL（分母不含 NULL 行）
MAX(列) / MIN(列) 最大 / 最小 忽略 NULL

⚠️ 第一大陷阱——NULL 与聚合：COUNT(*) 数行、COUNT(列) 数非空值、AVG 的分母只算非空行。三者对 NULL 的态度不同，务必区分。 ⚠️ 聚合函数只能出现在 SELECT 列表、HAVING 子句、ORDER BY 子句中，不能出现在 WHERE 中。 ⚠️ 聚合函数会自动跳过 NULL 行：SELECT AVG(Grade) FROM SC WHERE Cno='2' 的分母是 3 不是 4（见 §四例 5）。

3.6 分组：GROUP BY 与 HAVING

用途：按某列分组后，对每组施加聚合。

例：查询每门课的选课人数和平均成绩

SELECT Cno, COUNT(*) AS 选课人数, AVG(Grade) AS 平均成绩
FROM SC
GROUP BY Cno
HAVING COUNT(*) >= 3          -- 只要选课人数 ≥ 3 的课
ORDER BY 平均成绩 DESC;        -- 按平均成绩降序
Cno 选课人数 平均成绩
1 4 85.5
2 4 81.0
3 4 77.75

结果推导（已实际执行验证）：C1 成绩 92/75/80/95 → 人数 4、均值 (92+75+80+95)/4 = 85.5；C2 成绩 85/NULL/70/88 → 人数 4（COUNT() 数行，NULL 行也算）、均值 = (85+70+88)/3 = 81.0（AVG 忽略 NULL）；C3 成绩 88/90/78/55 → 人数 4、均值 311/4 = 77.75；C4 只有 1003 的 79 → 人数 1，被 HAVING COUNT(*)>=3 过滤*。

⚠️ WHERE vs HAVING 对照表（必考）

WHERE HAVING
作用 过滤行（分组前） 过滤组（分组后）
执行时机 GROUP BY 之前 GROUP BY 之后
能否用聚合函数 不能 能
能否引用 SELECT 别名 不能（标准 SQL） 部分系统可以
没有 GROUP BY 时 单独可用 单独可用（把整张表当一组）

连接条件 vs 过滤条件（左外连接里的经典陷阱）： - 内连接中，ON 连接条件 与 WHERE 过滤条件 效果相同。 - 外连接中完全不同：ON 里写的是连接条件，不匹配的行保留并补 NULL；WHERE 里写的是过滤条件，直接删除整行。 - 例：S LEFT JOIN SC ON S.Sno=SC.Sno WHERE Grade>=80 会把 1007（成绩为 NULL）过滤掉；若想保留 1007，过滤条件要写进 ON 或改用内连接再 UNION。左外连接一旦在 WHERE 中限制了右表列，往往就退化成内连接。

3.7 连接（JOIN）：四种 JOIN 的结果差异

用同一份数据（S 7 行、SC 14 行）对比，已逐行实际执行验证：

JOIN 语义 结果行数 相对内连接多了谁
S INNER JOIN SC 只保留两边都匹配的行 14 —
S LEFT JOIN SC 保留左表全部行，右表无匹配补 NULL 15 + 1007 周敏（SC 列为 NULL）
S RIGHT JOIN SC 保留右表全部行，左表无匹配补 NULL 14 无（SC 的 14 行全部都能匹配到 S → 与内连接相同）
S FULL OUTER JOIN SC 左右两表的行全部保留 15 + 1007 周敏

左外连接示例（SELECT S.Sno, Sname, SC.Cno, Grade FROM S LEFT JOIN SC ON S.Sno=SC.Sno，共 15 行，此处只看 1007）：

Sno Sname Cno Grade
1007 周敏 NULL NULL

自连接（Self Join）：一张表和自己连接，必须起别名。

-- 查询每门课及其直接先修课名（C 表自连接）
SELECT C1.Cno, C1.Cname, C2.Cname AS 先修课
FROM C C1 LEFT JOIN C C2 ON C1.Cpno = C2.Cno;
Cno Cname 先修课
1 数据库 数据结构
2 数据结构 NULL
3 操作系统 NULL
4 编译原理 数据结构

外连接的方向记忆：LEFT 保留左、RIGHT 保留右、FULL 全保留；谁被保留，谁没匹配上就给对方补 NULL。

3.8 子查询

按出现位置分类

位置 例子 说明
WHERE 子查询 WHERE Sno IN (…) 最常见，结果当条件用
FROM 子查询（派生表） FROM (SELECT …) T 结果当表用，必须起别名
HAVING 子查询 HAVING AVG(Grade) > (SELECT …) 过滤组
SELECT 子查询（标量子查询） SELECT Sname, (SELECT …) AS … 只能返回单行单列

按是否相关分类

类型 特点 例
不相关子查询 子查询独立执行一次，结果供外层使用 SELECT Sname FROM S WHERE Sno IN (SELECT Sno FROM SC WHERE Cno='1')
相关子查询 子查询引用了外层查询的列，外层每查一行就执行一次 SELECT … WHERE EXISTS (SELECT * FROM SC WHERE SC.Sno=S.Sno AND …)

EXISTS 与 IN

-- IN：判断某值是否在子查询结果集合中
SELECT Sname FROM S WHERE Sno IN (SELECT Sno FROM SC WHERE Cno='1');
-- 结果：张明、李华、王芳、钱娜（4 人选了 C1）

-- EXISTS：判断子查询是否"有行返回"，不关心具体返回什么
SELECT Sname FROM S WHERE EXISTS (SELECT * FROM SC WHERE SC.Sno=S.Sno AND SC.Cno='1');
-- 结果同上（相关子查询，外层每行都触发一次内层执行）

⚠️ EXISTS 的关键：SELECT * 还是 SELECT 1 还是 SELECT 'x' 都一样——EXISTS 只看有没有行返回（true/false），不在意列的内容。题目问"EXISTS (SELECT * …) 等价于什么"时不要被 * 迷惑。 ⚠️ NOT IN 的 NULL 陷阱：若子查询结果里含 NULL，x NOT IN (…) 可能永远为假（因为 x <> NULL 是 UNKNOWN）。NOT EXISTS 不受此影响——表达"不存在"时优先用 NOT EXISTS。

NOT EXISTS 双重否定表达"全部"（见 §2.5 除运算）：查询选修了全部课程的学生。

3.9 集合运算

运算 关键字 结果 要求
并 UNION 去重合并 两查询列数相同、对应列类型兼容
并（不去重） UNION ALL 保留重复行 同上
交 INTERSECT 交集 同上
差 EXCEPT（Oracle: MINUS） 在前者中但不在后者中 同上 
-- 选了 C1 或 C2 的学生（并）
SELECT Sno FROM SC WHERE Cno='1'
UNION
SELECT Sno FROM SC WHERE Cno='2';
-- 结果 6 行：1001、1002、1003、1004、1005、1006（1007 没选课）

-- 同时选了 C1 和 C2 的学生（交）
SELECT Sno FROM SC WHERE Cno='1'
INTERSECT
SELECT Sno FROM SC WHERE Cno='2';
-- 结果 2 行：1001、1002（注意：1002 的 C2 成绩虽为 NULL，但"选了课"这一事实成立）

-- 选了 C1 但没选 C2 的学生（差）
SELECT Sno FROM SC WHERE Cno='1'
EXCEPT
SELECT Sno FROM SC WHERE Cno='2';
-- 结果 2 行：1003、1005

⚠️ 易错点：UNION 默认去重（等价于并集），UNION ALL 不去重（结果行数可能更多）。问"返回多少行"时一定要看清楚是哪个。 ⚠️ 标准 SQL 不保证集合运算结果的顺序（UNION/INTERSECT/EXCEPT 的结果在标准 SQL 中是无序的）；需要顺序必须显式加 ORDER BY。某些实现（如 SQLite/MySQL）恰好按第一列升序输出，但这只是实现习惯、不能作为答题依据——考试按标准 SQL 语义作答。

§四、完整 SQL 例题（4 道，含表数据 / 查询 / 结果推导）

所有结果均已用 SQLite 实际执行验证。

例 1：分组统计（GROUP BY + HAVING + ORDER BY + NULL）

题目：查询选课人数 ≥ 3 的课程号、选课人数、平均成绩，按平均成绩降序。

SELECT Cno, COUNT(*) AS 选课人数, AVG(Grade) AS 平均成绩
FROM SC
GROUP BY Cno
HAVING COUNT(*) >= 3
ORDER BY 平均成绩 DESC;

推导过程：

Cno 各成绩 COUNT(*) SUM/AVG 分母 平均成绩 是否 ≥3 人
1 92, 75, 80, 95 4 342 / 4 85.5 ✅
2 85, NULL, 70, 88 4 243 / 3 81.0 ✅
3 88, 90, 78, 55 4 311 / 4 77.75 ✅
4 79 1 79 / 1 79.0 ❌ 被 HAVING 过滤

最终结果：

Cno 选课人数 平均成绩
1 4 85.5
2 4 81.0
3 4 77.75

本题三个考点一次练到：① COUNT(*) 数行（C2 的 NULL 行算 1 人）；② AVG 忽略 NULL（C2 分母是 3 不是 4，均值 81.0 而非 60.75）；③ HAVING 在分组后过滤组（C4 被淘汰）。

例 2：三表连接 + 条件过滤 + 排序

题目：查询计算机系学生中成绩 ≥ 80 的姓名、课程名、成绩，按成绩降序。

SELECT Sname, Cname, Grade
FROM S JOIN SC ON S.Sno = SC.Sno
     JOIN C ON SC.Cno = C.Cno
WHERE Sdept = '计算机系' AND Grade >= 80
ORDER BY Grade DESC;

推导过程： 1. 计算机系学生：1001 张明、1002 李华、1007 周敏。 2. JOIN SC：张明有 4 条选课（92/85/88/79）、李华有 2 条（75/NULL）、周敏 0 条（被内连接淘汰）。 3. 筛选 Grade≥80：张明 92(C1 数据库)、88(C3 操作系统)、85(C2 数据结构)；李华 75 和 NULL 均不满足。 4. 降序排列。

最终结果：

Sname Cname Grade
张明 数据库 92
张明 操作系统 88
张明 数据结构 85

考点：内连接自动丢弃"没选课"的周敏；NULL 成绩既不满足 >=80 也不满足任何比较。

例 3：左外连接找出"没有匹配"的行

题目：查询一门课都没选的学生。

SELECT S.Sno, Sname
FROM S LEFT JOIN SC ON S.Sno = SC.Sno
WHERE SC.Sno IS NULL;

推导过程：左外连接保留全部 7 名学生；1007 周敏在 SC 中无匹配行，其 SC.Sno、SC.Cno、SC.Grade 全部补 NULL；WHERE SC.Sno IS NULL 只留下她。

最终结果：

Sno Sname
1007 周敏

这是"左外连接 + IS NULL"的标准范式：找出"在 A 中但不在 B 中"的行。等价写法：SELECT … FROM S WHERE Sno NOT IN (SELECT Sno FROM SC)。 ⚠️ 判断"无匹配"必须用 IS NULL，不能写 = NULL（SC.Sno = NULL 的结果是 UNKNOWN，一行都查不出来）。

例 4：NOT EXISTS 双重否定（除运算的 SQL 实现）

题目：查询选修了全部课程的学生姓名。

SELECT Sno, Sname
FROM S
WHERE NOT EXISTS (
    SELECT * FROM C
    WHERE NOT EXISTS (
        SELECT * FROM SC
        WHERE SC.Sno = S.Sno AND SC.Cno = C.Cno
    )
);

推导过程： 1. 外层遍历每个学生 s：内层第一重 = "存在一门课 c，s 没选"。 2. NOT EXISTS(第一重) = "不存在这样一门课" = "每门课 s 都选了"。 3. 逐个学生对照：张明选了 {1,2,3,4} = 全部课程 ✅；其余学生的选课集合都缺课 ❌。

最终结果：

Sno Sname
1001 张明

对应关系代数：π_{Sno,Cno}(SC) ÷ π_{Cno}(C)。"全部"型题目在 SQL 里就是双重否定，这是科目二大题的高频写法。

例 5（补充）：聚合函数对 NULL 的三种态度

题目：统计 C2（数据结构）这门课的选课人数、有成绩的人数、平均分。

SELECT COUNT(*) AS 选课人数, COUNT(Grade) AS 有成绩人数, AVG(Grade) AS 平均分
FROM SC
WHERE Cno = '2';

推导过程：C2 共 4 条记录（1001→85、1002→NULL、1004→70、1006→88）。 - COUNT(*) = 4（数行，NULL 行也算） - COUNT(Grade) = 3（数非空成绩值，NULL 跳过） - AVG(Grade) = (85+70+88)/3 = 243/3 = 81.0（分母 3，不是 4）

最终结果：

选课人数 有成绩人数 平均分
4 3 81.0

这张表是第一大考点的浓缩：COUNT(*) ≠ COUNT(列) ≠ AVG(列) 的分母。

§五、常见陷阱表（考前必看）

# 陷阱 错误写法 正确写法 结果差异
1 判空 WHERE Grade = NULL WHERE Grade IS NULL = NULL 恒为 UNKNOWN，一行查不出
2 聚合与 NULL 认为 AVG 分母含 NULL 行 AVG 忽略 NULL；COUNT(*) 不忽略 C2 例：均值分母 3 而非 4
3 聚合放 WHERE WHERE AVG(Grade)>80 HAVING AVG(Grade)>80 语法错误，WHERE 在分组前执行
4 WHERE vs HAVING 用 HAVING 过滤未分组的单行条件 行过滤用 WHERE、组过滤才用 HAVING 语义不同；WHERE 更快（先过滤后分组）
5 连接条件 vs 过滤条件（外连接） 左外连接后 WHERE 右表列 IS NOT NULL 过滤右表条件应放进 ON（或改用内连接） 外连接 + WHERE 限制右表 → 退化成内连接
6 忘了连接条件 FROM S, SC（无 WHERE） FROM S JOIN SC ON … 笛卡尔积：7×14 = 98 行
7 UNION vs UNION ALL 求"并集"时用了 UNION ALL 求并集用 UNION（去重） UNION ALL 结果可能多行
8 投影忘去重 SELECT Sdept FROM S（7 行） SELECT DISTINCT Sdept FROM S（3 行） 关系代数 π 天然去重，SQL 要手动 DISTINCT
9 NOT IN 含 NULL WHERE Sno NOT IN (含 NULL 的子查询) 改用 NOT EXISTS NOT IN 可能恒为假（<> NULL 是 UNKNOWN）
10 DELETE 范围 DELETE FROM SC WHERE Sno='1006'（删 2 行） 删一行要主码定位：WHERE Sno='1006' AND Cno='3' 少一个条件 = 多删行
11 GROUP BY 后的 SELECT SELECT Sname, AVG(Grade) … GROUP BY Sno 非聚合列必须是分组列 标准 SQL 报错；部分系统"随机取值"
12 EXISTS 的 SELECT 列表 以为 EXISTS(SELECT *) 与 EXISTS(SELECT 1) 不同 完全等价，只看有无行返回 无结果差异，是迷惑选项
13 ORDER BY 默认方向 以为默认降序 默认 ASC（升序），NULL 的位置由系统决定（不要假设） "返回顺序"题要看清 ASC/DESC
14 DDL/DML 归属 把 SELECT 当 DDL / 把 COMMIT 当 DML CREATE/DROP/ALTER = DDL；SELECT/INSERT/UPDATE/DELETE = DML；GRANT/REVOKE/COMMIT/ROLLBACK = DCL 概念题直接得分点

§六、必记结论速查（20 条）

  1. 关系模型三要素 = 关系数据结构 + 关系操作集合 + 关系完整性约束。
  2. 术语：关系=表、元组=行、属性=列、码=键、目=列数、基数=行数。
  3. 三类完整性 = 实体（主码非空唯一）+ 参照（外码空或存在）+ 用户定义（CHECK 等）。
  4. 关系代数五种基本运算 = 选择 σ、投影 π、并 ∪、差 −、笛卡尔积 ×。
  5. σ 选行（↔ WHERE）；π 选列（↔ SELECT，天然去重）；⋈ 连表（↔ JOIN）；÷ 表"全部"（↔ NOT EXISTS 双重否定）。
  6. 等值连接保留两列，自然连接合并为一列。
  7. 笛卡尔积行数 = 左表行数 × 右表行数。
  8. SQL 执行顺序 = FROM → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT。
  9. WHERE 过滤行（分组前，不能用聚合）；HAVING 过滤组（分组后，能用聚合）。
  10. COUNT(*) 数行含 NULL；COUNT(列) 数非空值；SUM/AVG/MAX/MIN 全部忽略 NULL；AVG = SUM(列)/COUNT(列)。
  11. 判空一律 IS NULL，= NULL 恒为 UNKNOWN（三值逻辑：TRUE / FALSE / UNKNOWN）。
  12. 内连接只留两边都匹配的行；左外保留左表全部、右表补 NULL；右外对称；全外全保留。
  13. 左外连接 + WHERE 右表列 IS NULL = 找"在左表但不在右表"的行。
  14. 外连接中 ON 是连接条件（保留行），WHERE 是过滤条件（删除行）——不可互换。
  15. 集合运算 UNION（去重）/ UNION ALL（不去重）/ INTERSECT（交）/ EXCEPT（差），要求列数相同、类型兼容。
  16. EXISTS 只看有无行返回，不看列内容（SELECT * 与 SELECT 1 等价）。
  17. "全部"型查询 = NOT EXISTS 双重否定（除运算的 SQL 实现）；"至少一个" = IN / EXISTS。
  18. DDL = CREATE/DROP/ALTER；DML = SELECT/INSERT/UPDATE/DELETE；DCL = GRANT/REVOKE/COMMIT/ROLLBACK。
  19. DELETE 可回滚、可带 WHERE；TRUNCATE 清全表、不可回滚；DROP 连表结构一起删。
  20. 视图是虚表（只存定义不存数据）；WITH CHECK OPTION 保证更新后行仍能被视图查到。
