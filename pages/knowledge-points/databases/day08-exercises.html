Day 8（9/28）数据库② 练习题：范式判断与 E-R 图（共 20 题）

说明：本题是 Day 8 的章节题，也是数据库大题的考前核心训练。题目分布：范式判断选择题 15 道（1–15，含函数依赖判定、候选码求解、范式级别判断、规范化分解）、E-R 图大题 1 道（16）、E-R / 范式综合选择题 4 道（17–20）。 完整答案与解析在文件末尾。建议独立完成（约 60 分钟）再对答案。 做题纪律（本套题最重要的一条）：第 1–15 题严禁"看一眼就选"。必须在草稿纸上写出三步： ① 属性分类（L/N/R/LR）+ 闭包 → 候选码； ② 划分主属性 / 非主属性； ③ 按流程图逐级判断（部分依赖 → 传递依赖 → BCNF）。 这三步就是科目二大题的阅卷步骤分——过程对、结论自然对；跳步、结论必错。

20. 关系数据库规范化的主要目标是（ ）。

  • B. 减少关系模式的数量，简化数据库结构
  • C. 提高查询速度，减少连接运算
  • D. 保证数据库的安全性，防止非法访问

答案与解析

第一部分：范式判断选择题

1. 答案：B

候选码为 (Sno, Cno)（L 类属性 Sno、Cno 的闭包 = 全部属性）。Sno 是候选码的真子集，且 Sno→Sname 成立 → Sname 对候选码是部分函数依赖。

不选 A：完全依赖要求"任何真子集都决定不了"，而 {Sno} 能决定 Sname。 不选 C：不存在 Sno→Y→Sname（Y↛Sno）的中间链。 不选 D：平凡依赖要求 Sname ⊆ (Sno, Cno)，显然不成立。

2. 答案：C

Sno→Sdept（非平凡，Sdept ⊄ {Sno}），Sdept↛Sno（一个系有多个学生），Sdept→Mname（Mname ⊄ {Sdept}）→ 三个条件全部满足 → 传递函数依赖。

不选 B：候选码 Sno 是单属性，单属性码不可能产生部分依赖。 不选 A：完全依赖说的是"对候选码及其子集"的关系，这里问的是依赖的类型，链条 Sno→Sdept→Mname 表明是传递的。

3. 答案：B

传递依赖的定义要求 Y↛X。本题 F 中 Sname→Sno 成立（Y 能决定 X），所以 Sno→Sname→Sdept 不构成传递依赖，Sdept 直接依赖于 Sno。

这是传递依赖最经典的"反陷阱"：链条存在 ≠ 传递依赖，必须再验证 Y↛X。 不选 C：候选码 Sno 是单属性，不存在"候选码的一部分"。

4. 答案：A

属性分类：L={A}（只在 A→B 左部）；R={D}（只在 C→D 右部）；LR={B, C}（B 在 A→B 右、B→C 左；C 在 B→C 右、C→D 左）。 {A}⁺ = {A} → A→B → {A,B} → B→C → {A,B,C} → C→D → {A,B,C,D} = U。 → 候选码 = A（唯一）。主属性 {A}，非主属性 {B,C,D}。

不选 B、C：A 单独就能决定全部属性，AB、ABC 是超码但不是候选码（不满足最小性）。

5. 答案：B

属性分类：L={A, B}；R={E}；LR={C, D}。 {A,B}⁺ = {A,B} → AB→C → {A,B,C} → C→D → {A,B,C,D} → D→E = U。 → 候选码 = AB（唯一）。

验证最小性：{A}⁺={A}≠U，{B}⁺={B}≠U。 不选 C、D：它们是超码，不是候选码。

6. 答案：C

三个属性都既在左部又在右部 → 全是 LR 类，无 L/R/N 类属性。 单属性闭包：{A}⁺={A}、{B}⁺={B}、{C}⁺={C}，均 ≠ U。 两属性闭包：{A,B}⁺ → AB→C = U ✅；{A,C}⁺ → AC→B = U ✅；{B,C}⁺ → BC→A = U ✅。 → 候选码 = AB、AC、BC（共 3 个）。每个属性都出现在某个候选码中 → A、B、C 全是主属性，无非主属性。

不选 D：ABC 是超码（AB 已能决定 C），不满足最小性，不是候选码。

7. 答案：D

候选码 (Sno, Cno)；主属性 Sno、Cno；非主属性 Grade。 Grade 完全依赖于候选码（Sno 或 Cno 单独都决定不了 Grade）→ 满足 2NF；不存在 候选码→Y→Grade 的传递链（Grade 不出现在任何依赖的左部，无法充当中间属性 Y）→ 满足 3NF；F 中唯一非平凡依赖 (Sno,Cno)→Grade 的左部就是候选码 → 满足 BCNF。

8. 答案：C

由第 6 题已求出：候选码 AB、AC、BC；A、B、C 全是主属性，没有非主属性。 - 部分依赖检查：无非主属性 → 自动通过 → 满足 2NF。 - 传递依赖检查：无非主属性 → 自动通过 → 满足 3NF。 - BCNF 检查：F 中每个非平凡依赖的左部 AB、AC、BC 都是候选码 → 满足 BCNF。

→ 最高满足 BCNF。

9. 答案：A

候选码 (Sno, Cno)（Sno、Cno 都是 L 类）。主属性 Sno、Cno；非主属性 Sname、Grade。 Sno 是候选码的真子集，且 Sno→Sname → 非主属性 Sname 部分依赖于候选码 → 不满足 2NF。 → 最高满足 1NF。

修复方法：把 (Sno, Sname) 拆成一个新关系（若还有 Sdept 等其它 Sno 决定的属性，一起带走），原关系保留 Sno 作外码。

10. 答案：B

候选码 Sno（L 类，{Sno}⁺=U）。主属性 {Sno}；非主属性 Sdept、Sloc。 - 部分依赖：候选码是单属性 → 不可能有部分依赖 → 满足 2NF 的这一半。 - 传递依赖：Sno→Sdept→Sloc，Sdept↛Sno（一个系有多个学生）→ Sloc 传递依赖于 Sno → 不满足 3NF。

→ 最高满足 2NF。

修复方法：把 (Sdept, Sloc) 拆成一个新关系，原关系删去 Sloc、保留 Sdept 作外码。

11. 答案：B

候选码 (Sno, Cno)（Sno、Cno 都是 L 类）。主属性 Sno、Cno；非主属性 Tno、Tname。 - 部分依赖（候选码是组合码，必须逐个真子集检查）：候选码 (Sno,Cno) 的真子集只有 ∅、{Sno}、{Cno}。{Sno}⁺={Sno}（F 中唯一的依赖左部 (Sno,Cno) 不被 {Sno} 包含，闭包无法增长），{Cno}⁺={Cno}——两个真子集都决定不了 Tno、Tname → 无部分依赖 → 满足 2NF。 - 传递依赖：(Sno,Cno)→Tno→Tname，Tno↛(Sno,Cno)（一位教师教多个学生的选课记录）→ Tname 传递依赖于候选码 → 不满足 3NF。

→ 最高满足 2NF。

注意与第 9 题的区别：本题 Tname 是完全依赖于组合码 (Sno,Cno) 的（因为必须知道"哪个学生选的哪门课"才能确定 Tname），但它是传递依赖于候选码——完全依赖与传递依赖可以并存，2NF 只管"部分/完全"，3NF 才管"是否传递"。

12. 答案：B

属性分类：L={A}；LR={B, C}（C 也在 C→B 的左部出现，故为 LR 类，不是 R 类）；R=∅。 {A}⁺={A}≠U；{A,B}⁺ → AB→C = U ✅ → AB 是候选码。 再检查其它可能：{A,C}⁺ → C→B = {A,B,C} = U ✅ → AC 也是候选码。 → 候选码 = AB、AC。A、B、C 全是主属性（B 在 AC 中、C 在 AB 中），无非主属性。 - 无非主属性 → 满足 2NF、满足 3NF。 - BCNF 检查：C→B 的左部 C 不是超码（{C}⁺={B,C}，不含 A），且 BCNF 不接受"右部是主属性"的豁免 → 不满足 BCNF。

→ 最高满足 3NF，不满足 BCNF。（这是 3NF ⊂ BCNF 的标准反例。）

不选 A：C 在候选码 AC 中，所以 C 也是主属性——候选码不止一个。 不选 C：C→B 的左部不含候选码，破坏 BCNF。

13. 答案：B

属性分类：L={A, B}（只在 AB→CD 左部）；R={D}（在 AB→CD、C→D 右部）；LR={C}（AB→CD 右、C→D 左）。 {A,B}⁺ = {A,B} → AB→CD = {A,B,C,D} = U → 候选码 = AB（唯一）。 主属性 {A, B}；非主属性 {C, D}。 - 部分依赖检查（候选码是组合码，必查）：AB 的真子集 ∅、{A}、{B} 的闭包都只含自身，都不能决定 C 或 D → 无部分依赖 → 满足 2NF。 - 传递依赖检查：AB→C（非平凡，C⊄AB），C↛AB（{C}⁺={C,D}，不含 A、B），C→D（D⊄C）→ AB→C→D 构成非主属性 D 对候选码的传递依赖 → 不满足 3NF。

→ 最高满足 2NF。

分解到 3NF：把 (C, D) 拆成一个新关系 CD(C, D)（F={C→D}，候选码 C，达 BCNF）；原关系删去 D、保留 C 作外码，变为 R₁(A, B, C)（F={AB→C}，候选码 AB，达 BCNF）。

14. 答案：D

  • SD(Sno, Sdept)：F₁={Sno→Sdept}，候选码 Sno（单属性）。非主属性 Sdept 完全依赖（单属性码无部分依赖）、无传递依赖（不存在 Sdept→X→Sdept 的链条）→ 满足 3NF；唯一非平凡依赖的左部 Sno 是候选码 → BCNF。
  • DL(Sdept, Sloc)：F₂={Sdept→Sloc}，候选码 Sdept → 同理 → BCNF。

→ 两个关系模式都达到 BCNF，且该分解无损连接（在 Sdept 上连接可还原原关系）并保持依赖（Sno→Sdept、Sdept→Sloc 分别落在两个子关系中）。

不选 C：BCNF 的检查不因"非主属性直接依赖"而止步于 3NF——BCNF 看的是"左部是否含码"，本题两个依赖的左部都是各自候选码。

15. 答案：B

R 的候选码为 (Sno, Cno)（Sno、Cno 都是 L 类），非主属性 Tno、Tname，其中 Tname 传递依赖于候选码（见第 11 题解析）。 规范化到 3NF 需消除传递依赖 (Sno,Cno)→Tno→Tname：把 (Tno, Tname) 拆成一个新关系 T，原关系保留 Tno → 得到 SC(Sno, Cno, Tno) 和 T(Tno, Tname)。

  • SC(Sno, Cno, Tno)：F={(Sno,Cno)→Tno}，候选码 (Sno,Cno)，Tno 完全依赖、无传递 → 满足 3NF；左部含码 → 实际已达 BCNF。
  • T(Tno, Tname)：F={Tno→Tname}，候选码 Tno → BCNF。
  • 该分解无损连接：每个 (Sno,Cno) 只有唯一 Tno，Tno 又唯一决定 Tname，自然连接可还原全部信息。
  • 该分解保持依赖：(Sno,Cno)→Tno 在 SC 中可检查，Tno→Tname 在 T 中可检查。

不选 A：SCT 中仍存在 Tno→Tname 的传递依赖，没有达到 3NF，分解无效。 不选 C：第一关系丢了 Tno，(Sno,Cno)→Tno 这条依赖无处安放，且无法从 T 中恢复"某学生某门课的教师"。 不选 D：完全丢失了"学生选课与教师"的对应关系。

16. 参考答案

部门 部门号、部门名称、办公电话 部门号
员工 工号、姓名、性别、出生日期 工号

负责 部门 — 项目 1:N — 一个项目只由一个部门负责，一个部门可负责多个项目
参加 员工 — 项目 M:N 参加日期、承担角色 一个员工可参加多个项目，一个项目由多个员工参加

关键判据：联系属性"参加日期、承担角色"只在"某员工参加某项目"时才有意义，因此必须挂在联系上，不能放到员工或项目实体里。

（3）转换为关系模式

关系模式 属性 主键 外键
部门 （部门号，部门名称，办公电话） 部门号 —
员工 （工号，姓名，性别，出生日期，部门号） 工号 部门号（→ 部门）
项目 （项目号，项目名称，预算，负责部门号） 项目号 负责部门号（→ 部门）
参加 （工号，项目号，参加日期，承担角色） （工号，项目号） 工号（→ 员工）；项目号（→ 项目）

转换依据： - 实体 → 关系：部门、员工、项目各成一个关系，实体主键即关系主键。 - 1:N 联系"属于"：把 1 端（部门）的主键作为外码并入 N 端（员工）→ 员工.部门号。 - 1:N 联系"负责"：把 1 端（部门）的主键作为外码并入 N 端（项目）→ 项目.负责部门号。 - M:N 联系"参加"：必须独立成一个关系，其主键为两端实体主键的组合（工号，项目号），联系属性（参加日期、承担角色）并入该关系。

自检（对照 §5.3 清单）：四个实体关系齐全 ✅；唯一的 M:N 联系独立成表 ✅；两个 1:N 联系外键都加在 N 端 ✅；联系属性未丢失 ✅；外键均指向已存在的主码 ✅。

（4）"参加"关系模式的范式判断

"参加"关系模式为 参加（工号，项目号，参加日期，承担角色），其函数依赖集为 F={（工号，项目号）→ 参加日期，（工号，项目号）→ 承担角色}（一个员工参加一个项目只对应一条记录）。

  • 候选码：（工号，项目号）。工号、项目号都只在左部出现 → L 类，闭包 = 全部属性 → 候选码为（工号，项目号）。
  • 主属性：工号、项目号；非主属性：参加日期、承担角色。
  • 2NF：非主属性完全依赖于候选码（单独工号或单独项目号都决定不了参加日期/承担角色）→ 满足。
  • 3NF：不存在非主属性对候选码的传递依赖（没有"参加日期 → 承担角色"这类链）→ 满足。
  • 结论：参加 关系模式满足 3NF（进一步，其两个非平凡依赖的左部都是候选码，因此也满足 BCNF）。

这也说明：M:N 联系独立成关系后，其结构天然就是"组合主键 + 联系属性"，通常直接达到 3NF/BCNF——这是 E-R 转换与范式判断在大题中的自然交汇点。

第三部分：E-R / 范式综合选择题

17. 答案：A

E-R 模型三要素与图形符号：实体=矩形、属性=椭圆、联系=菱形；实体与属性、实体与联系之间用无向边连接；主键属性带下划线。

18. 答案：B

M:N 联系必须新建一个关系：属性 = 两端实体主码 + 联系自身的属性，主码 = 两端实体主码的组合。

不选 A：那是 1:N 的做法（把 1 端主码并入 N 端）。M:N 若这样做，一行只能存一个对方实体，无法表达"多对多"。 不选 C：主码必须是组合，不能任选其一，否则无法唯一标识一行。

19. 答案：B

一个员工只属于一个部门 → 部门:员工 = 1:N → 把 1 端（部门）的主码"部门号"作为外码加入 N 端（员工）。

口诀："多的一方记着少的一方"。不选 C：新建关系是 M:N 的做法。

20. 答案：A

规范化的本质是消除不必要的数据冗余，从而解决插入异常、删除异常、更新（修改）异常。

不选 C：规范化通常增加关系数量，查询时需要更多连接，不直接提高查询速度（为查询性能考虑时甚至会有意做反规范化）。 不选 D：安全性由用户认证、权限控制（GRANT/REVOKE）等机制保证，与范式无关。
