一、存储体系的层次结构

1.1 为什么需要存储器层次结构

理想的存储器应当容量像磁盘一样大、速度像寄存器一样快、成本像磁带一样低——但这三者互相矛盾。现实中的物理存储器件遵循一条铁律：

速度越快的存储器，容量越小、每位价格越贵。

因此现代计算机不依赖单一存储器，而是把多种存储器按速度从快到慢、容量从小到大、价格从贵到便宜排列成层次，让常用的内容尽量呆在靠近 CPU 的快速层，不常用的才放到慢速大容量层。这就是存储器层次结构（memory hierarchy）。

1.2 四级层次结构

   ┌──────────┬──────────┬───────────┬──────────┐
   │  寄存器   │  Cache   │   主存     │  辅存     │
   │ (CPU内)  │(CPU核内) │ (内存条)   │(磁盘/SSD) │
   ├──────────┼──────────┼───────────┼──────────┤
   │  速度     │ <1ns     │ 1~10ns    │ 10~100ns  │ ms 级    │  ← 越往下越慢
   │  容量     │ <1KB     │ 几十KB~MB  │ GB 级     │ TB 级    │  ← 越往下越大
   │  每位价格 │   最贵    │    贵     │   便宜    │  最便宜   │  ← 越往下越便宜
   │  由谁管理 │ 编译器   │  硬件     │ 操作系统  │ 操作系统  │
   └──────────┴──────────┴───────────┴──────────┘
        ↑                ↑                    ↑
     CPU 直接访问     CPU 直接访问        CPU 不能直接访问（需经主存转存）

层次结构的三条关键结论：

结论 说明
相邻层之间存在速度差 层次结构的意义就在于"用快层缓存慢层的常用内容"。相邻层速度差太小，层次就没价值
每层都是下一层的一个子集的缓存 Cache 的内容是主存内容的子集；主存（虚拟存储）的内容是辅存内容的子集
CPU 只能直接访问寄存器、Cache、主存 辅存（磁盘/SSD）不能被 CPU 直接寻址，其中的数据必须先调入主存才能被 CPU 访问

⚠️ 易错点（高频）：题目问"CPU 不能直接访问的存储器是"，答案是辅存（磁盘、SSD、磁带）。寄存器、Cache、主存都在 CPU 可直接寻址的范围内。注意：Cache 和主存都在 CPU 可直接访问之列，只是访问路径不同。

补充（一句话记忆）：Cache 用 SRAM（静态 RAM，触发器存信息，不需刷新、速度快、集成度低、成本高）；主存用 DRAM（动态 RAM，电容存信息，需定期刷新、集成度高、成本低）。「Cache 贵在快、主存贵在多」。

1.3 局部性原理（Cache 的理论依据）

层次结构之所以有效，是因为程序在执行时对存储器的访问不是均匀随机的，而是相对集中的——这就是局部性原理（principle of locality）。它分两种：

类型 定义 典型来源 例子
时间局部性 刚被访问过的信息，很可能很快又被访问 循环、堆栈、热点变量、频繁调用的函数 for(i=0;i<1000;i++){ s += a[i]; } 中的 s、i 在 1000 次循环中被反复访问
空间局部性 一旦访问了某个单元，不久后其邻近单元也很可能被访问 顺序执行的指令、顺序遍历的数组 访问 a[0] 后紧接着访问 a[1]、a[2]、…；取指后顺序取下一条指令

⚠️ 易错点：循环计数器体现的是时间局部性（同一个变量反复被访问）；数组顺序遍历体现的是空间局部性（相邻地址被访问）。这两者经常被放在同一题里混淆——判断依据是"是同一个地址反复出现（时间），还是相邻地址接连出现（空间）"。

正因为有局部性，我们可以在 CPU 与主存之间加一个小容量的 Cache：把最近/最常用的一小部分内容搬进 Cache，CPU 访存时先查 Cache——大多数请求都能在快速层被满足。

1.4 三个层次的两个接口（把 OS 与组成串起来）

   CPU ──► [Cache] ──► 主存 ──► 辅存
            ↑                ↑
      「Cache—主存」层    「主存—辅存」层（虚拟存储）
       硬件管理，对程序员   OS + 硬件管理（页表/TLB）
          完全透明          对应用程序员透明
  • Cache—主存层：解决速度问题（主存太慢）。由硬件自动管理，对各类程序员都透明。
  • 主存—辅存层（虚拟存储）：解决容量问题（主存太小）。由操作系统 + 硬件（MMU/TLB）管理，对应用程序员透明、对系统程序员可见。

⚠️ 易错点：不要说"虚拟存储对程序员完全透明"——它只对应用程序员透明；系统程序员（写 OS 的人）必须管理页表。而 Cache 是连系统程序员都不用管的（全硬件）。

二、Cache 的工作原理

2.1 Cache 的定位

Cache（高速缓冲存储器）位于 CPU 与主存之间，用 SRAM 实现，速度接近 CPU。其唯一目的：缓解「CPU 快、主存慢」的速度矛盾（突破冯·诺依曼瓶颈）。

工作流程（读操作）：

   CPU 发出主存地址
        ↓
   ① 地址送到 Cache 控制器 → 查"地址映射变换机构"（目录表）
        ↓
   ② 命中（Cache 中有该块）→ 直接从 Cache 取数据送 CPU  ──► 结束（快）
   ② 未命中（缺失）→ 访问主存取该块 ──┬──► 数据送 CPU
                                    └──► 同时装入 Cache（利用空间局部性）

关键：未命中时从主存取出的数据同时送给 CPU 和 Cache——这样下次再访问该块（或其邻近单元）就能命中。

2.2 Cache 的基本结构

一个 Cache 行（也叫槽/块/Line）由三部分组成：

   ┌────────────┬────────┬──────────────────────────────┐
   │  有效位 V   │  标记  │           数据区              │
   │ (1 bit)    │ (Tag)  │ (一个主存块的大小，如 64B)     │
   └────────────┴────────┴──────────────────────────────┘
  • 有效位 V：该行是否装着有效数据（开机时全部为 0）。
  • 标记 Tag：记录该行当前装的是主存的哪一块（主存字块标记）。
  • 数据区：存放主存块的内容。

判断命中的统一逻辑（所有映射方式都一样）：

   ① 用主存地址的"行号/组号"字段定位到 Cache 的某一行或某一组；
   ② 比较该行/组内各行的 Tag 与主存地址的 Tag 字段；
   ③ 若 Tag 相等 **且** 有效位 V = 1 → 命中；
      否则 → 未命中（缺失）。

2.3 命中、缺失与命中率

概念 定义
命中（hit） CPU 要访问的信息恰在 Cache 中
缺失（miss） CPU 要访问的信息不在 Cache 中，需访问主存
命中率 h h = 命中次数 / 总访问次数 = N_c / (N_c + N_m)
缺失率 1 − h

⚠️ 易错点：命中率公式的分母是总访问次数（命中 + 未命中），不是"未命中次数"。看到"访问 Cache 命中 1800 次、未命中 200 次"，分母是 2000，h = 0.9。

2.4 Cache 的四个性能指标（公式必须全部记牢）

设：命中率 h，Cache 存取时间 t_c，主存存取时间 t_m，速度比 r = t_m / t_c。

指标 公式 说明
命中率 h h = N_c / (N_c + N_m) 由访存统计得到
平均访问时间 t_a t_a = h · t_c + (1 − h) · t_m 命中走 Cache、缺失走主存的时间加权和
加速比 S S = t_m / t_a 相对"完全不用 Cache（每次都访主存）"的提速倍数
效率 e e = t_c / t_a × 100% = 1 / [h + (1 − h)·r] Cache 访问时间占平均访问时间的比例，恒 ≤ 100%

效率的两种写法是等价的（记住恒等式，考场可交叉验证）：

   t_a = h·t_c + (1−h)·t_m = t_c·[h + (1−h)·(t_m/t_c)] = t_c·[h + (1−h)·r]
   ⇒  e = t_c / t_a = 1 / [h + (1−h)·r]        ✓
   且  e = S / r     （加速比 ÷ 速度比 = 效率，用这个恒等式检查答案最方便）

⚠️ 易错点 1：加速比 S 可以大于 1，效率 e 一定 ≤ 100%。两者不是一回事：S = t_m/t_a > 1，e = t_c/t_a < 1。 ⚠️ 易错点 2：有的题目把"缺失开销"定义为"先查 Cache 未命中 + 再访主存"（即 t_c + t_m），则 t_a = h·t_c + (1−h)(t_c + t_m)。软考默认的公式是 t_a = h·t_c + (1−h)·t_m（命中只算 Cache 时间、缺失只算主存时间）。除非题目明确说"未命中时 Cache 与主存都要访问"，否则一律用默认公式。 ⚠️ 易错点 3（语言陷阱）：题目说"主存比 Cache 慢 4 倍"，意思是 t_m = 4 · t_c（即 r = 4），不是"慢了 4 倍"（t_m = 5·t_c）。软考一律按前者理解。

三、Cache 的三种映射方式（本日核心）

3.0 统一设定（本节所有例题沿用，便于对比）

主存容量 16 MB = 2²⁴ B，按字节编址 → 主存地址 24 位。 Cache 容量 64 KB = 2¹⁶ B。 块（行）大小 64 B = 2⁶ B → 块内偏移 6 位。 Cache 块（行）数 = 64 KB / 64 B = 1024 = 2¹⁰ 行。 主存块数 = 16 MB / 64 B = 2¹⁸ = 262144 块。

先记住一个不变的骨架：任何映射方式下，主存地址都由三部分拼成：

   ┌──────────────┬──────────────┬──────────────┐
   │  主存字块标记  │  字块内地址   │   块内偏移    │
   │     (Tag)    │ (行号/组号)   │  (offset)    │
   └──────────────┴──────────────┴──────────────┘
  • 块内偏移：永远 = log₂(块大小) = 6 位（定位块内某个字节）。
  • 字块内地址：定位 Cache 中的行或组——直接映射叫"行号"，组相联叫"组号"，全相联没有这一段。
  • 主存字块标记 Tag：剩下的位数全部给 Tag。

位数守恒律（用来检查所有题目）：Tag 位数 + 字块内地址位数 + 块内偏移位数 = 主存地址总位数；且 Tag 位数 + 组号位数 = 主存块号位数（= 主存地址位数 − 块内偏移位数）。

3.1 直接映射（Direct Mapping）

映射规则：主存块 j 只能放在 Cache 的 j mod C 行（C = Cache 行数）。即每个主存块在 Cache 中只有唯一一个固定位置。

地址结构（统一设定下）：

   ┌─────────────┬──────────────┬──────────────┐
   │  Tag  8 位   │  Cache 行号   │  块内偏移 6 位 │
   │             │    10 位      │              │
   └─────────────┴──────────────┴──────────────┘
   主存块号 18 位 = Tag 8 位 + 行号 10 位   （24 = 8 + 10 + 6 ✓）

推导过程：

   块内偏移 = log₂(64B) = 6 位
   Cache 行数 = 64KB / 64B = 1024 = 2¹⁰ → 行号 10 位
   Tag = 24 − 10 − 6 = 8 位
   验证：每个 Cache 行对应主存块数 = 2¹⁸ / 2¹⁰ = 2⁸ = 256 块 → Tag 需 8 位区分 ✓

地址变换过程（例）：主存地址 0x3A5F2C

   ① 求主存块号：0x3A5F2C ÷ 64 = 59772 (0xE97C)
   ② 求行号：59772 mod 1024 = 380 (0x17C)
   ③ 求 Tag：59772 ÷ 1024 = 58 (0x3A)
   ④ 求偏移：0x3A5F2C mod 64 = 44 (0x2C)
   ⑤ 查目录表第 380 行：若有效位 V=1 且 Tag=58 → 命中，取该行第 44 字节

二进制直切（更直观，考场推荐）：

   0x3A5F2C = 0011 1010 | 01 0111 1100 | 101100
              └─Tag=0x3A─┘└──行号=380───┘└偏移=44┘
                    8 位        10 位       6 位
优点 缺点
实现最简单、速度最快（只需 1 个比较器） 冲突率最高——映射到同一行的多个主存块互相争用，即使其他行空闲也被迫替换
目录表（标记阵列）容量小 命中率低，Cache 空间利用率差

适用：对速度要求极高、Cache 容量较大的场合。

3.2 全相联映射（Fully Associative Mapping）

映射规则：主存块可以放在 Cache 的任意一行。

地址结构（统一设定下）：

   ┌────────────────────────────┬──────────────┐
   │        Tag  18 位          │  块内偏移 6 位 │
   └────────────────────────────┴──────────────┘
   主存块号 18 位全部用作 Tag   （24 = 18 + 6 ✓，无"字块内地址"段）

推导：没有行号/组号字段 → 主存块号 18 位全部是 Tag；偏移仍为 6 位。

地址变换过程：主存地址 0x3A5F2C

   ① 主存块号 = Tag = 0x3A5F2C ÷ 64 = 59772 (0xE97C)
   ② 偏移 = 0x3A5F2C mod 64 = 44 (0x2C)
   ③ 把 Tag 59772 与 Cache 全部 1024 行的 Tag **并行比较**：
      任一行 Tag 相等且 V=1 → 命中，取该行第 44 字节
优点 缺点
冲突率最低（任意位置都可放） 比较器最多：需要 Cache 行数个比较器（此例 1024 个），硬件开销巨大
命中率高、空间利用率高 查表电路复杂、速度受限

适用：小容量 Cache（行数少，比较器开销可控）。这是"全相联只适合小容量"的根本原因。

3.3 组相联映射（Set Associative Mapping）

映射规则：把 Cache 分成若干组，每组包含相同数量的若干行（路 way）。主存块 j 只能放在组 j mod G（G = 组数）中，但组内可以放在任意一路。

地址结构（统一设定下，以 4 路组相联为例）：

   ┌──────────────┬────────────┬──────────────┐
   │  Tag  10 位   │  组号 8 位  │  块内偏移 6 位 │
   └──────────────┴────────────┴──────────────┘
   主存块号 18 位 = Tag 10 位 + 组号 8 位   （24 = 10 + 8 + 6 ✓）

推导过程：

   组数 = Cache 行数 / 路数 = 1024 / 4 = 256 = 2⁸ → 组号 8 位
   Tag = 主存块号位数 − 组号位数 = 18 − 8 = 10 位

地址变换过程：主存地址 0x3A5F2C

   ① 主存块号 = 59772 (0xE97C)
   ② 组号 = 59772 mod 256 = 124 (0x7C)
   ③ Tag（= 块号 ÷ 组数）= 59772 ÷ 256 = 233 (0xE9)
   ④ 块内偏移 = 44 (0x2C)
   ⑤ 在第 124 组的 4 路中并行比较 Tag：
      任一路 Tag = 233 且 V=1 → 命中，取该路第 44 字节

二进制直切：

   0x3A5F2C = 0011 1010 01 | 0111 1100 | 101100
              └─Tag=0xE9(233)┘└组号=124─┘└偏移=44┘
                   10 位          8 位       6 位
优点 缺点
冲突率与命中率介于直接与全相联之间（折中） 需要 路数个比较器（4 路 → 4 个）+ 组内选择器
硬件复杂度可控 —

适用：绝大多数现代 CPU 的 L1/L2 Cache（2/4/8/16 路最常见）。

3.4 三种映射方式对比（必背表）

对比项 直接映射 全相联映射 组相联映射
主存块可放位置 唯一固定一行 任意一行 固定组内的任意一路
地址结构 Tag + 行号 + 偏移 Tag + 偏移 Tag + 组号 + 偏移
Tag 位数（统一设定） 8 18 10（4 路）/ 9（2 路）/ 11（8 路）
字块内地址位数 log₂(行数) = 10 无 log₂(组数)
比较器个数 1 Cache 行数个（1024） 路数（4 路 → 4）
冲突率 最高 最低 中等
命中率 最低 最高 中等
硬件复杂度 最低 最高 中等
适用 大容量 Cache 小容量 Cache 现代主流 L1/L2

记忆口诀：「直接一对一（固定位置、一个比较器）、全相联一对多（任意位置、全行比较）、组相联分组一对多（组内任意、组数×路数个比较器）」。

3.5 统一视角：三者其实是"路数"的连续谱

这是理解三种映射方式最好的一张图——它们不是三个独立的东西，而是同一个模型的三个特例：

   路数 way = 1 ────────────► 组数 G = 行数 C ────► 就是「直接映射」
        │
   路数 way = 2 / 4 / 8 ───► 组数 G = C/way ────► 就是「组相联映射」
        │
   路数 way = C ───────────► 组数 G = 1 ────────► 就是「全相联映射」

统一映射公式：主存块 j → 组号 = j mod G，组内可放在任意一路。 - G = C（每组 1 行 = 1 路）→ 退化为直接映射。 - G = 1（全部行为一组 = C 路）→ 退化为全相联映射。

位数随路数变化的规律（统一设定，24 位地址）：

路数 组数 组号位数 Tag 位数 地址结构 合计
1（直接） 1024 10 8 8 + 10 + 6 24 ✓
2 512 9 9 9 + 9 + 6 24 ✓
4 256 8 10 10 + 8 + 6 24 ✓
8 128 7 11 11 + 7 + 6 24 ✓
1024（全相联） 1 0 18 18 + 0 + 6 24 ✓

规律（考场秒用）：路数每翻一倍，组数减半、组号少 1 位、Tag 多 1 位。总位数守恒 = 主存地址位数。

3.6 冲突演示例题（直接映射 vs 组相联）

题目：统一设定下，主存块 3 与主存块 1027 是否会在 Cache 中互相争用位置？

解答：

   直接映射：行号 = 块号 mod 1024
       块 3   → 3 mod 1024 = 3      → Cache 第 3 行
       块 1027 → 1027 mod 1024 = 3  → Cache 第 3 行   ← 同一行！冲突！
       （即使 Cache 其他 1023 行全空着，块 1027 也会把块 3 挤出去，反之亦然）
       两者的 Tag：块 3 的 Tag = 3÷1024 = 0；块 1027 的 Tag = 1（正是靠 Tag 区分彼此）

   4 路组相联：组号 = 块号 mod 256
       块 3   → 3 mod 256 = 3    → 第 3 组
       块 1027 → 1027 mod 256 = 3 → 第 3 组   ← 同组，但组内有 4 路！
       两者分别占用第 3 组的两路，可同时驻留 → 不冲突

   全相联：两块可放在任意行 → 不冲突

结论：交替访问相隔"恰好一个 Cache 行数"的两个主存块（如 0、1024、0、1024…）是直接映射最坏的访问模式——每次都冲突，命中率趋近 0。把直接映射改成 2 路组相联，这类冲突立刻消失。这就是组相联存在的意义。

四、Cache 命中率计算（3 道完整手算例题）

例题 1：由访存统计求全部四个指标（基础题）

题目：某 Cache—主存系统，Cache 存取周期 t_c = 10 ns，主存存取周期 t_m = 100 ns。执行一段程序共完成 2000 次访存，其中 Cache 未命中 100 次。求命中率 h、平均访问时间 t_a、加速比 S、效率 e。

解答：

   ① 命中次数 = 2000 − 100 = 1900
      h = 1900 / 2000 = 0.95            （95%）

   ② t_a = h·t_c + (1−h)·t_m
         = 0.95 × 10 + 0.05 × 100
         = 9.5 + 5 = 14.5 ns

   ③ S = t_m / t_a = 100 / 14.5 ≈ 6.90    （相对无 Cache 提速约 6.9 倍）

   ④ e = t_c / t_a = 10 / 14.5 ≈ 0.6897 = 68.97%
      交叉验证（用 e = 1/[h + (1−h)·r]，r = t_m/t_c = 10）：
        e = 1 / (0.95 + 0.05 × 10) = 1 / 1.45 = 0.6897 ✓
      再用恒等式 e = S/r = 6.897 / 10 = 0.6897 ✓

答案：h = 0.95；t_a = 14.5 ns；S ≈ 6.90；e ≈ 69.0%。

含义：即使命中率高达 95%，效率也只有 69%——因为缺失一次要付出 10 倍的时间代价。速度比 r 越大，同样的命中率下效率越低。

例题 2：给定命中率与两个时间求效率（加速比/效率辨析）

题目：已知 Cache 存取周期 t_c = 20 ns，主存存取周期 t_m = 80 ns，命中率 h = 0.9。求平均访问时间、加速比与效率。

解答：

   ① t_a = 0.9 × 20 + 0.1 × 80 = 18 + 8 = 26 ns

   ② S = t_m / t_a = 80 / 26 ≈ 3.08

   ③ e = t_c / t_a = 20 / 26 ≈ 0.7692 = 76.92%
      交叉验证：r = 80/20 = 4，e = 1/(0.9 + 0.1×4) = 1/1.3 = 0.7692 ✓
                e = S/r = 3.077/4 = 0.7692 ✓

答案：t_a = 26 ns；S ≈ 3.08；e ≈ 76.9%。

⚠️ 易错点：本题最常见的错误是把加速比和效率搞混——加速比是 t_m/t_a（>1），效率是 t_c/t_a（≤1）。记住 「加速比往大看（相对慢主存），效率往小看（相对快 Cache）」。

例题 3：已知平均访问时间指标反求命中率（逆推题型）

题目：某 Cache—主存系统，t_c = 10 ns、t_m = 100 ns。要求系统的平均访问时间不超过 20 ns，命中率至少要达到多少？

解答（把 t_a 公式反解 h）：

   t_a = h·t_c + (1−h)·t_m
      = h·10 + (1−h)·100
      = 100 − 90h                ← 关键化简：t_a 随 h 线性下降

   令 100 − 90h ≤ 20
      90h ≥ 80
      h ≥ 80/90 = 8/9 ≈ 0.8889 = 88.89%

   验算 h = 8/9：t_a = 100 − 90 × (8/9) = 100 − 80 = 20 ns ✓（恰好达标）

答案：命中率至少 88.9%。

万能反解公式（直接背）：h = (t_m − t_a) / (t_m − t_c)。例如本题 h = (100 − 20)/(100 − 10) = 80/90 ✓。已知 t_a、t_c、t_m 求 h 时，用这个式子最快。

4.1 拓展：两级 Cache（了解，偶考）

现代 CPU 有 L1/L2 甚至 L3。设 L1 命中率 h₁、访问时间 T₁；L2 在 L1 未命中的那些请求中的命中率 h₂、访问时间 T₂；主存时间 T_m：

   t_a = h₁·T₁ + (1 − h₁)·[ T₂ + (1 − h₂)·T_m ]

例：h₁ = 0.9、T₁ = 5 ns、h₂ = 0.8、T₂ = 20 ns、T_m = 100 ns：

   t_a = 0.9 × 5 + 0.1 × (20 + 0.2 × 100) = 4.5 + 0.1 × 40 = 4.5 + 4 = 8.5 ns

注意 h₂ 是在 L1 未命中者中的命中率（条件命中率），不是全系统命中率。若问"全系统最终在 L2 命中的比例"，答案是 (1−h₁)·h₂ = 0.1 × 0.8 = 0.08。

五、Cache 的替换策略与写策略

5.1 替换策略（Cache 满了/冲突时淘汰谁）

策略 全称 规则 特点
RAND 随机替换 随机选一行替换 实现最简单，命中率不稳定
FIFO 先进先出 淘汰最先进入 Cache 的块 实现简单（队列），未考虑局部性，可能 Belady 异常
LRU 最近最少使用 淘汰最长时间未被访问的块 最常用、命中率最高（符合时间局部性），硬件需记录"最近访问时间"

⚠️ 易错点（名称辨析）：LRU = 最近最少使用（Least Recently Used），淘汰的是"最久没用的"；LFU = 最不经常使用（Least Frequently Used），淘汰的是"访问次数最少的"。两者都常被译混。软考 Cache 替换策略的标准答案是 LRU。

5.2 写策略（Cache 命中写操作时，主存怎么办）

问题：CPU 写数据时若命中 Cache，是只写 Cache 还是同时写主存？这决定 Cache 与主存是否保持一致。

策略 写命中时的操作 优点 缺点
写直达（Write Through，全写法） 同时写 Cache 和主存 实现简单、Cache 与主存始终一致 写操作慢（每次都要访主存）、带宽消耗大
写回（Write Back，回写法） 只写 Cache，并把该行脏位（dirty bit）置 1；该行被替换时才写回主存 写操作快（多数写只动 Cache） 存在 Cache 与主存不一致的窗口，需额外脏位，多处理器一致性复杂

未命中时的写策略（配合上面的命中策略使用）：

策略 写未命中时的操作
写分配（Write Allocate） 先把主存块调入 Cache，再在 Cache 中写
非写分配（Not Write Allocate） 不调入 Cache，直接写主存

经典配对（必背）：

   写直达  +  非写分配      ← 适用于写操作不频繁 / 写后不太可能再访问同一数据的场景
   写回    +  写分配        ← 适用于写操作频繁的场景（利用时间局部性，多次写合并为一次主存写）

⚠️ 易错点："写回 + 非写分配"是低效组合，"写直达 + 写分配"是矛盾组合（既然每次写都同步到主存了，再调入 Cache 意义不大）。考场常考的是标准配对。

六、虚拟存储与 Cache 的关系

6.1 虚拟存储回顾（衔接 Day 2 OS 内存管理）

虚拟存储（页式）把辅存当主存的扩展：程序使用虚拟地址（逻辑地址），实际访问的是物理地址。转换靠页表，加速靠 TLB（快表）：

   虚拟地址 = 页号 + 页内偏移   ──查页表──►   物理地址 = 页框号 + 页内偏移
                          （页表存"页号→页框号"映射，放在主存里）
   TLB（快表，在 CPU 内）缓存页表中最常用的表项，避免每次转换都访一次主存。

6.2 TLB / 页表 / Cache 三者协同（典型访存路径）

一次完整的取数据过程（从虚拟地址到数据）：

   CPU 给出虚拟地址 VA
        │
        ▼
   ┌─ 查 TLB ─────────────────────────────────────┐
   │  命中 → 得到物理地址 PA                        │
   │  未命中 → 查页表（访存 1 次；多级页表可能多次） │
   │           页表缺失（缺页）→ 缺页中断：         │
   │             从磁盘把页调入主存、更新页表、重试  │
   └───────────────────────────────────────────────┘
        │  物理地址 PA
        ▼
   ┌─ 用 PA 查 Cache ──────────────────────────────┐
   │  命中 → 直接从 Cache 取数据（最快，全程 0~1 次主存访问）│
   │  未命中 → 访问主存取数据                        │
   │           → 同时装入 Cache                     │
   └───────────────────────────────────────────────┘
        │
        ▼
      数据返回 CPU

关键点： 1. TLB 存的是"虚拟页号 → 物理页框号"；Cache 存的是"物理地址 → 数据"。两者是串联的：先 TLB 得到物理地址，再用物理地址查 Cache。 2. TLB 查找是硬件级的、不算访存（这一点与 Day 2 的 OS 题一致：TLB 命中时地址转换 0 次访存）。 3. 理想情况（TLB 命中 + Cache 命中）：0 次访存就拿到数据——这就是层次结构的价值。 4. 最坏情况：缺页（磁盘 I/O）+ Cache 未命中，代价是毫秒级。

6.3 Cache 与虚拟存储对比

对比项 Cache—主存层 主存—辅存层（虚拟存储）
解决的问题 速度（主存太慢） 容量（主存太小）
管理者 硬件（全部自动） 操作系统 + 硬件（MMU/TLB）
透明性 对所有程序员透明 对应用程序员透明，系统程序员可见
信息单位 块（行，如 64B） 页（如 4KB）
地址变换机构 目录表（标记阵列） 页表 + TLB
缺失处理 从主存调入（硬件自动） 缺页中断（OS 从磁盘调入）
替换算法 LRU/FIFO/RAND 页面置换算法 OPT/FIFO/LRU/Clock（Day 2 学过）

记忆口诀：「Cache 硬件管、为速度；虚存系统管、为容量；Cache 块小、虚存页大；Cache 缺失硬件补、虚存缺页中断补」。

七、总线

7.1 什么是总线

总线（Bus）是计算机各部件之间传送信息的公共通道。它是一组导线，每一根传送一位信息。总线的三个特点： - 分时共享：同一时刻只能有一对部件使用总线发送数据（所以需要总线仲裁）。 - 简化结构：相比"每两个部件之间都拉一根专用线"（复杂度 O(n²)），总线把复杂度降到 O(n)。

7.2 总线的分类（按信号类型）

总线类型 传送内容 方向 说明
数据总线 DB 数据（含指令） 双向 宽度（位数）决定一次能传送的数据量，常与机器字长一致
地址总线 AB 地址（内存/I/O 端口地址） 单向（CPU 输出） 位数决定 CPU 可直接寻址的最大物理地址空间（n 位 → 2ⁿ 个单元）
控制总线 CB 控制信号（读/写、中断请求、总线请求、时钟等） 双向 CPU 发读/写命令给外设；外设发中断请求/总线请求给 CPU

⚠️ 易错点 1（高频）：MAR 一定接地址总线（单向），MDR 一定接数据总线（双向）——这是 Day 10 的知识点，在总线这章换个角度考。 ⚠️ 易错点 2：控制总线是双向的——不要因为它叫"控制"就以为只有 CPU 单向发出控制命令；外设的中断请求、总线请求、状态信号也走控制总线。 ⚠️ 易错点 3：地址总线的位数决定的是"最大物理寻址空间"（物理地址空间），不是"实际主存容量"，也不是虚拟地址空间。

7.3 总线宽度与带宽计算（必考计算）

核心公式：

   总线带宽 = 总线工作频率 × 总线宽度 / 8          （单位：MB/s）
   其中"总线宽度/8"= 每次并行传送的字节数

例题 1（基础）：某总线工作频率 100 MHz，数据总线宽度 32 位，求带宽。

   带宽 = 100 MHz × (32 / 8) B = 100 × 4 = 400 MB/s

例题 2（对照记忆）：PCI 总线工作频率 33 MHz、宽度 64 位；另一总线 66 MHz、32 位。二者带宽相同吗？

   PCI 64 位：33 × 8 = 264 MB/s
   66MHz 32 位：66 × 4 = 264 MB/s        ← 相同！

结论：带宽 = 频率 × 宽度，频率高一倍且宽度减一半，带宽不变。这是"频率与宽度互相补偿"的典型。

例题 3（复用陷阱，高频）：某总线时钟频率 10 MHz，地址总线和数据总线复用（分时使用同一组线传送地址和数据），一个总线周期占用 2 个时钟周期，每个总线周期并行传送 4 字节数据。求总线带宽。

   解法 1（先算总线周期时长）：
      总线周期 = 2 个时钟周期 = 2 / 10 MHz = 0.2 μs
      带宽 = 4 B / 0.2 μs = 20 MB/s

   解法 2（先算有效频率）：
      有效数据传送频率 = 10 MHz / 2 = 5 MHz
      带宽 = 5 MHz × 4 B = 20 MB/s        ✓ 两法一致

⚠️ 易错点：复用总线的带宽要先扣除"传地址占用的时间"——题目若说"一个总线周期 = 2 个时钟周期"，意味着只有一半时间在传数据，带宽比不复用时减半。

反求题：要求带宽 800 MB/s，总线工作频率 100 MHz，数据总线应多宽？

   宽度 = 800 × 8 / 100 = 64 位

7.4 同步总线与异步总线

对比项 同步总线 异步总线
时序依据 统一的时钟信号 无统一时钟，靠握手信号（请求 REQ / 应答 ACK）
传送过程 所有设备按同一时钟节拍工作，定长周期 每次传送双方互相应答，周期可变
优点 简单、速度快（无握手开销） 适应速度差异大的设备、总线可长
缺点 必须迁就最慢的设备；总线长度受限（时钟偏移） 控制复杂、握手有延迟
适用 速率相近的部件间（CPU—主存、L2—Cache） 速率差异大的 I/O 设备

握手方式：异步总线的握手分全互锁（请求与应答互相确认，最可靠）、半互锁、不互锁三种。

折中方案——半同步总线：在同步时钟基础上加 WAIT / READY 等待信号，让慢速设备"申请等待"。这是现代总线最常用的方式。

7.5 总线仲裁（了解，偶考）

总线同一时刻只允许一个设备发送数据，必须有仲裁机制决定谁使用：

仲裁方式 做法 特点
链式查询（菊花链） 总线请求信号沿链串行传递，离仲裁器最近的设备优先获得 硬件最简单；但优先级固定、查寻慢、对故障敏感
计数器定时查询 仲裁器用计数器轮询各设备 优先级可变（取决于计数器初值）
独立请求方式 每个设备有独立的请求线与仲裁器相连 速度最快、优先级灵活；硬件最复杂（连线最多）

主设备 / 从设备：主设备能发起并控制总线传送（如 CPU、DMA 控制器）；从设备只能响应（如主存、I/O 端口）。

8.3 组成原理三大计算题型（占分最多）

九、本日必记结论（20 条，冲刺时遮住右边默写）

  1. 存储层次：寄存器 → Cache → 主存 → 辅存；速度递减、容量递增、每位价格递减。
  2. CPU 只能直接访问寄存器、Cache、主存；辅存不能被 CPU 直接访问。
  3. Cache 用 SRAM，主存用 DRAM（DRAM 需刷新）。
  4. 时间局部性＝同一数据近期重复使用（循环计数器）；空间局部性＝邻近地址接连访问（数组遍历、顺序取指）。
  5. Cache—主存层解决速度问题、由硬件管理、对所有程序员透明；主存—辅存层（虚拟存储）解决容量问题、由 OS+硬件管理、对应用程序员透明。
  6. 命中率 h = N_c/(N_c+N_m)；分母是总访存次数。
  7. 平均访问时间 t_a = h·t_c + (1−h)·t_m（软考默认公式，除非题目说明缺失要加算 Cache 查找时间）。
  8. 加速比 S = t_m/t_a（>1）；效率 e = t_c/t_a ≤ 100%；e = S/r = 1/[h+(1−h)r]，其中 r = t_m/t_c。
  9. 反求命中率万能式：h = (t_m − t_a)/(t_m − t_c)。
  10. 直接映射：主存块 j → j mod C 行（C 为 Cache 行数），地址 = Tag + 行号 + 偏移，1 个比较器，冲突率最高。
  11. 全相联：主存块可放任意行，地址 = Tag + 偏移（无字块内地址），行数个比较器，只适用于小容量 Cache。
  12. 组相联：主存块 j → j mod G 组（G 为组数），组内任意路，地址 = Tag + 组号 + 偏移，路数个比较器，现代主流。
  13. 统一视角：直接映射 ＝ 1 路组相联；全相联 ＝ 最大路数（1 组）组相联；路数翻倍 → 组数减半、组号 −1 位、Tag +1 位。
  14. 位数守恒律：Tag + 组号/行号 + 偏移 = 主存地址位数；Tag + 组号 = 主存块号位数（= 地址位数 − 偏移位数）。
  15. 偏移位数 = log₂(块大小)；行号位数 = log₂(Cache 行数)；组号位数 = log₂(组数) = log₂(行数/路数)。
  16. 判断命中：Tag 相等 且 有效位 V = 1（缺一个都不算命中）。
  17. 替换策略：LRU（最近最少使用）最常用；注意 LRU ≠ LFU（后者按访问次数）。
  18. 写直达同时写 Cache 与主存（保持一致但慢）；写回只写 Cache 并置脏位、替换时才写回（快但有一段不一致）。
  19. 经典配对：写直达 + 非写分配；写回 + 写分配。
  20. 数据总线双向、地址总线单向、控制总线双向；总线带宽 = 工作频率 × 宽度/8（复用总线要扣除地址占用时间）；同步总线靠统一时钟、异步总线靠握手。

十、快速自测（遮住答案，5 分钟）

  1. 存储体系中速度最快的是？ → 寄存器
  2. CPU 不能直接访问的是？ → 辅存（磁盘）
  3. 循环变量 i 被反复访问体现什么局部性？ → 时间局部性
  4. 顺序数组 a[0],a[1],… 体现什么局部性？ → 空间局部性
  5. 命中 1900 次、未命中 100 次，h = ？ → 0.95
  6. h=0.95、t_c=10ns、t_m=100ns，t_a = ？ → 14.5 ns
  7. 上题的加速比 S 与效率 e 分别是？ → ≈ 6.90；≈ 69.0%
  8. 已知 t_a ≤ 20ns、t_c=10、t_m=100，最低 h = ？ → 80/90 ≈ 88.9%
  9. 直接映射下，Cache 行号 = 主存块号 ______ C？ → mod（取余）
  10. 全相联为什么只适用于小容量 Cache？ → 每个 Cache 行都要一个比较器，行数多则硬件开销爆炸
  11. 4 路组相联需要几个比较器？ → 4 个
  12. Cache 由 SRAM 还是 DRAM 构成？ → SRAM
  13. Cache 写策略中"置脏位、替换时才写主存"的是？ → 写回（Write Back）
  14. TLB 与 Cache 谁先被执行？ → 先 TLB（虚→实），再用物理地址查 Cache
  15. 地址总线 32 位，最大物理寻址空间是？ → 2³² = 4 GB
  16. 100MHz、32 位数据总线的带宽 = ？ → 400 MB/s
