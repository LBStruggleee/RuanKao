Day 11计算机组成原理② 练习题：存储体系 / Cache 映射 / 命中率 / 总线（20 选择 + 3 计算）

说明：本题是 Day 11 的章节题，也是计算机组成原理阶段（Day 10–11）的收尾套题。 题目分布：存储体系与局部性 4 题（1–4）、三种映射方式与地址结构 6 题（5–10）、命中率/写策略/透明性 6 题（11–16）、虚拟存储与 Cache 协同 1 题（17）、总线 2 题（18–19）、Day 10 回顾 1 题（20）。 另有 3 道独立 Cache 计算题（21–23），每题给出完整解答步骤。 完整答案与解析在文件末尾。建议独立闭卷完成（选择题约 30 分钟 + 计算题 20 分钟）再对答案。 做题纪律： - 第 5–7 题（映射地址结构）必须打草稿：先写"块内偏移 = log₂(块大小)"、再写"行号/组号 = log₂(行数/组数)"、最后用位数守恒律（Tag + 组号/行号 + 偏移 = 主存地址位数）检查。这类题的错因 90% 是漏掉"偏移位"或把"组数"当"行数"。 - 第 13、14 题与计算题 21、23 是计算题，必须写出 h、t_a、S、e 四个量的完整算式，不要只写结论。 - 目标是 16/20 以上（80%）；第 5、6、7、13、14、19 题是高频陷阱题，请重点关注。

附：Day 10 笔记「快速自测」速答（组成阶段回顾）

  1. CPU = 运算器 + 控制器；ALU/ACC/PSW 属运算器，PC/IR/MAR/MDR 属控制器。
  2. MAR 接地址总线（单向），MDR 接数据总线（双向）。
  3. 地址码 m 位 → 直接寻址 2ᵐ 单元；间接寻址范围由存储字长决定。
  4. 相对寻址 EA = (PC) + A，A 为补码；PC 是下一条指令地址。
  5. 流水线周期 Δt = 最长段；等长段 T = (k+n−1)·Δt、S = kn/(k+n−1)、E = n/(k+n−1)。
  6. 不等长段 T = Σt + (n−1)·Δt（第 1 条按各段实际时间和走完全程）。
  7. 超标量 TP_max = m/Δt；超流水线 TP_max = n/Δt。
  8. RISC：指令少且定长、只有 Load/Store 访存、硬布线控制、依赖流水线与优化编译。

第七部分：独立 Cache 计算题（21–23，每题给出完整解答）

这 3 道题是组成原理阶段计算题的主力题型，请务必打草稿、写出每一个中间量。 答案与完整步骤在文件末尾「计算题解答」部分。

21.（命中率与系统指标 · 基础型） 某 Cache—主存系统中，Cache 存取周期 t_c = 20 ns，主存存取周期 t_m = 200 ns。执行一段程序共完成 2500 次访存，其中 Cache 未命中 250 次。求： （1）命中率 h； （2）平均访问时间 t_a； （3）加速比 S； （4）效率 e。

22.（组相联地址变换 · 映射型） 沿用统一设定：主存 16 MB（按字节编址），Cache 64 KB，块大小 64 B，采用 2 路组相联映射。已知某次访存的主存地址为 0x1F5A3C。求： （1）主存地址的各字段结构与位数（Tag / 组号 / 块内偏移）； （2）该地址对应的 Tag、组号、块内偏移（用十进制与十六进制表示）； （3）若 Cache 第 360 组中已装入两个有效块，其 Tag 分别为 40 和 62，判断本次访问是否命中；若命中，数据在 Cache 的何处。

23.（约束条件反求 · 逆推型） 某 Cache—主存系统中，t_c = 10 ns，t_m = 90 ns。系统设计要求平均访问时间 t_a ≤ 18 ns。求： （1）最低命中率 h_min； （2）若实际运行时命中率只有 h = 0.85，此时的平均访问时间是多少？是否满足设计要求？ （3）若保持（1）求出的命中率不变，而把 Cache 升级为 t_c = 5 ns 的高速 SRAM（主存时间不变），此时的平均访问时间与加速比各是多少？

答案与解析

答案速查：1.C 2.B 3.B 4.D 5.B 6.D 7.B 8.A 9.D 10.B 11.B 12.C 13.B 14.B 15.B 16.A 17.B 18.C 19.C 20.C

1. C。 存储层次从上到下依次是寄存器 → Cache → 主存 → 辅存，越靠上速度越快、容量越小、每位价格越贵。寄存器在 CPU 内部，速度最快（<1 ns），也最贵。 - B（Cache）比寄存器慢；A（主存）更慢；D（辅存）最慢（ms 级）。 - 易错提醒：不要把"Cache"当成存储体系中最快的层次——寄存器才是。

2. B。 层次结构的核心规律：越靠上速度越快、容量越小、每位价格越贵；越靠下相反。 - A 错：容量和价格都说反了（越靠上容量越小、价格越贵）。 - C 错：相邻两层速度差异越大，层次结构才越有价值（把热数据放到快层才有意义）。 - D 错：辅存远慢于主存，且不能被 CPU 直接访问，不能替代主存。

3. B。 时间局部性＝"刚用过的很快又用"——循环计数变量 i 在每次循环中被反复访问，是同一个地址反复出现；空间局部性＝"用了 a[i]，不久 a[i+1] 也会被用"——数组元素存放在相邻地址，顺序遍历访问的是邻近单元。 - 判别口诀："同一地址反复出现 → 时间；相邻地址接连出现 → 空间"。 - C、D 错：把两者的类型互换或合并，都是典型混淆。

4. D。 CPU 只能直接访问寄存器、Cache、主存；辅存（磁盘、SSD、磁带）不能被 CPU 直接寻址，其中的数据必须先调入主存才能被 CPU 访问。 - A、B、C 都在 CPU 可直接寻址的范围内。 - 易错提醒：Cache 虽小且由硬件管理，但 CPU 可以直接访问它——"透明"（程序员看不见）不等于"CPU 访问不到"。

5. B。 直接映射地址 = Tag + 行号 + 块内偏移：

块内偏移 = log₂(64B) = 6 位
Cache 行数 = 64KB / 64B = 1024 = 2¹⁰ → 行号 10 位
Tag = 24 − 10 − 6 = 8 位
验证：主存块数 = 16MB/64B = 2¹⁸，每行对应 2¹⁸/2¹⁰ = 2⁸ = 256 块 → Tag 8 位可区分 ✓
  • A（6 位）：把"块内偏移"当成 Tag。
  • C（10 位）：把"行号位数"当成 Tag。
  • D（18 位）：这是全相联的 Tag 位数（见第 6 题）。

6. D。 全相联映射下主存块可放在任意行，地址中没有行号/组号字段：

Tag = 主存地址位数 − 块内偏移 = 24 − 6 = 18 位
（主存块号 2¹⁸ 全部用作 Tag）
  • C（14 位）是本题最大陷阱：误以为全相联仍保留"行号字段"，用 24 − 10 = 14。全相联没有字块内地址这一段。
  • B（8 位）是直接映射的 Tag 位数。

7. B。 组相联：组数 = Cache 行数 / 路数：

组数 = 1024 / 4 = 256 = 2⁸ → 组地址 8 位
Tag = 主存块号位数 − 组号位数 = 18 − 8 = 10 位
地址结构：Tag(10) + 组号(8) + 偏移(6) = 24 位 ✓（位数守恒律）
  • A（1024 组，10 位）：把 4 路组相联当成了直接映射（1 路）。
  • C（512 组，9 位）：这是 2 路组相联的答案。
  • D（64 组，6 位）：这是 16 路组相联的答案。
  • 规律：路数每翻一倍，组数减半、组号少 1 位、Tag 多 1 位。

8. A。 直接映射的映射公式：Cache 行号 = 主存块号 mod Cache 总行数（C = 1024）。例如主存块 3、1027、2051 都映射到第 3 行（1027 mod 1024 = 3）。 - B 错：除以块大小取余得到的是"块内偏移"，不是行号。 - C 错：映射关系是固定的取余运算，与比例常数无关。 - D 错：Cache 映射由硬件完成，与操作系统无关（这正是 Cache 对程序员透明的原因）。

9. D。 全相联映射需要把 Tag 与 Cache 全部行的标记并行比较，每个 Cache 行都要配一个比较器。因此行数越多，比较器开销越大——全相联只适用于小容量 Cache（行数少，比较器开销可控）。 - A、B、C 均为正确叙述。 - 对比记忆：直接映射 1 个比较器；n 路组相联 n 个比较器；全相联"行数个"比较器。

10. B。 n 路组相联在判断命中时，只需在该组内的 n 路中并行比较 → 需要 n 个比较器。2 路组相联 → 2 个比较器。 - A（1 个）是直接映射的比较器数。 - C（512 个）是误把"组数"当比较器数。 - D（1024 个）是全相联的比较器数（Cache 有 1024 行）。

11. B。 Cache 与主存之间的信息调动（装入、替换、回写）全部由硬件自动完成，对各类程序员（应用程序员、系统程序员）都透明。 - A 错（最大陷阱）：程序员无法用指令控制 Cache（不能指定哪些数据进 Cache），这正是 Cache 与"寄存器/主存"的区别。 - C 错：Cache 只存放主存中最活跃的一小部分（受容量限制），不是完整副本。 - D 错：Cache 容量远小于主存，不能替代主存，主存仍是程序与数据的完整载体。

12. C。 命中率 h = 命中次数 / 总访存次数 = 1800 / (1800 + 200) = 1800 / 2000 = 0.90。 - A（0.80）错把"未命中率 200/1000"之类弄混；B（0.85）、D（0.95）为数字凑错。 - 易错提醒：分母是总访存次数（2000），不是未命中次数。

13. B。

t_a = h·t_c + (1−h)·t_m = 0.9 × 20 + 0.1 × 80 = 18 + 8 = 26 ns
  • A（18 ns）：只算了命中路径 h·t_c = 0.9 × 20 = 18，漏掉了缺失代价 (1−h)·t_m。平均访问时间是命中与缺失的加权和，两项都不能丢。
  • C（28 ns）：把 t_m 误当成 100 ns（0.9×20 + 0.1×100 = 28）——题目给的是 80 ns。
  • D（50 ns）：把 t_a 算成两个时间的算术平均 (20 + 80)/2 = 50。平均访问时间是按概率加权，不是简单平均（除非 h 恰为 0.5）。
  • 做题纪律：先把已知量 h、t_c、t_m 单独列一行，再代入公式，可避免"看错数字"和"漏项"两类错误。

14. B。

e = t_c / t_a = 20 / 26 ≈ 0.7692 = 76.9%
交叉验证：r = t_m/t_c = 80/20 = 4，e = 1/[h + (1−h)r] = 1/(0.9 + 0.1×4) = 1/1.3 ≈ 0.7692 ✓
恒等式：e = S/r = 3.077/4 ≈ 0.7692 ✓
  • A（25%）：把效率算成了 t_c/t_m = 20/80 = 25%——效率的分母是平均访问时间 t_a，不是主存时间 t_m。
  • C（90%）：把命中率当成效率。
  • D（308%）：把加速比当成效率了。效率恒 ≤ 100%，任何超过 100% 的"效率"答案必错。

15. B。 LRU = Least Recently Used，最近最少使用，淘汰最长时间未被访问的块（符合时间局部性，命中率最高，是 Cache 最常用的替换算法）。 - A 是 RAND（随机）；C 是 FIFO（先进先出）；D 是 LFU（最不经常使用）。 - 易错提醒：LRU ≠ LFU——LRU 看"多久没访问"（时间），LFU 看"访问了多少次"（频度）。

16. A。 写直达（Write Through）：写命中时同时写 Cache 和主存，保持一致但慢；写回（Write Back）：写命中时只写 Cache并置脏位，该行被替换时才写回主存，快但存在不一致窗口。 - B、D 错：写回法不是每次写都同步到主存，因此不是每时每刻都与主存一致（只在被替换时才写回）。 - C 错：写直达通常与非写分配配合；写回才与写分配配合（写未命中时先把块调入 Cache，之后多次写合并为一次主存写回）。

17. B。 TLB（Translation Lookaside Buffer，快表）缓存的是页表中最常用的"虚拟页号 → 物理页框号"映射，避免每次地址转换都要访问一次主存中的页表，因此作用是加快虚拟地址到物理地址的转换。 - A 错：缓存主存数据块的是 Cache，不是 TLB。 - C 错：磁盘页面由主存（页框）在缺页时承载，不是 TLB 的职责。 - D 错：TLB 不影响 Cache 命中率，它影响的是地址转换速度。 - 协同链条：虚拟地址 →（查 TLB）→ 物理地址 →（查 Cache）→ 数据。TLB 在前、Cache 在后，两者串联。

18. C。 控制总线是双向的：CPU 向外设发出读/写、中断响应等控制信号；外设也向 CPU 发出中断请求、总线请求、状态信号等。因此"控制总线是单向的"是错误叙述。 - A、B、D 均为正确叙述。尤其注意 D：地址总线位数 = 最大物理寻址空间的位数（n 位 → 2ⁿ 个编址单元），这是固定结论。 - 关联记忆：MAR 接地址总线（单向）、MDR 接数据总线（双向）（Day 10 §1.4）。

19. C。

总线带宽 = 工作频率 × 总线宽度 / 8 = 100 MHz × (32 / 8) B = 100 × 4 = 400 MB/s
  • A（100 MB/s）：把 32 位当成 8 位（宽度/8 = 1 字节）。
  • B（200 MB/s）：宽度误当 16 位。
  • D（3200 MB/s）：忘记除以 8（100 × 32 = 3200，单位变成了"兆位/秒 Mbit/s"而非 MB/s）。
  • 单位陷阱：带宽公式的"宽度/8"是把"位"换算成"字节"——看到结果特别大时，先检查是否漏了 /8。

20. C。（Day 10 回顾 · 不等长段流水线）

Δt = max(10, 15, 20, 10) = 20 ns   （第 3 段是瓶颈段）
Σt = 10 + 15 + 20 + 10 = 55 ns
T  = Σt + (n − 1)·Δt = 55 + 99 × 20 = 55 + 1980 = 2035 ns
  • A（2000 ns）：把 T 误算成 n·Δt = 100 × 20 = 2000 ns——丢掉了第 1 条指令装满流水线的 Σt 那一段。
  • B（2030 ns）：进位错误（55 + 1980 = 2035，不是 2030）。
  • D（5500 ns）：这是非流水线时间 T₀ = n·Σt = 100 × 55 = 5500 ns，不是流水线时间。
  • ⚠️ 核心易错点：不等长段 T = Σt + (n−1)·Δt，不是 k·Δt + (n−1)·Δt。第 1 条指令按各段实际时间之和走完全程。

计算题解答（21–23，含完整步骤）

计算题 21（命中率与系统指标 · 基础型）

已知：t_c = 20 ns，t_m = 200 ns，总访存 2500 次，未命中 250 次。

（1）求命中率 h

命中次数 = 总访存次数 − 未命中次数 = 2500 − 250 = 2250
h = 命中次数 / 总访存次数 = 2250 / 2500 = 0.90        （即 90%）

（2）求平均访问时间 t_a

t_a = h·t_c + (1 − h)·t_m
    = 0.90 × 20 + 0.10 × 200
    = 18 + 20 = 38 ns

（3）求加速比 S

S = t_m / t_a = 200 / 38 ≈ 5.26        （相对"完全不用 Cache"提速约 5.26 倍）

（4）求效率 e

e = t_c / t_a = 20 / 38 ≈ 0.5263 = 52.63%
交叉验证（两种独立写法，结果必须一致）：
  ① 速度比 r = t_m / t_c = 200 / 20 = 10
     e = 1 / [h + (1 − h)·r] = 1 / (0.90 + 0.10 × 10) = 1 / 1.90 ≈ 0.5263 ✓
  ② 恒等式 e = S / r = 5.263 / 10 ≈ 0.5263 ✓

答：h = 0.90；t_a = 38 ns；S ≈ 5.26；e ≈ 52.6%。

思考：命中率高达 90%，效率却只有 52.6%——因为速度比 r = 10，每缺失一次要付出 10 倍代价。速度比 r 越大，同样的命中率下效率越低。

计算题 22（组相联地址变换 · 映射型）

已知：主存 16 MB（24 位地址），Cache 64 KB，块 64 B，2 路组相联，主存地址 = 0x1F5A3C。

（1）求地址各字段结构与位数

块内偏移 = log₂(块大小) = log₂(64B) = 6 位
Cache 行数 = 64KB / 64B = 1024 = 2¹⁰
组数 = Cache 行数 / 路数 = 1024 / 2 = 512 = 2⁹  → 组号（字块内地址）= 9 位
Tag = 主存块号位数 − 组号位数
    = (24 − 6) − 9 = 18 − 9 = 9 位

地址结构：

┌────────────┬────────────┬──────────────┐
│  Tag  9 位  │  组号  9 位 │  块内偏移 6 位 │
└────────────┴────────────┴──────────────┘
检查（位数守恒律）：9 + 9 + 6 = 24 ✓

（2）求该地址的 Tag、组号、偏移

① 先求主存块号 = 地址 ÷ 块大小 = 0x1F5A3C ÷ 64 = 2054716 ÷ 64 = 32104 (0x7D68)
② 组号 = 主存块号 mod 组数 = 32104 mod 512 = 360  (0x168)
③ Tag  = 主存块号 ÷ 组数       = 32104 ÷ 512  = 62   (0x3E)
④ 块内偏移 = 地址 mod 块大小 = 2054716 mod 64 = 60   (0x3C)

二进制直切法（考场更快，推荐）：0x1F5A3C = 0001 1111 0 | 1 0110 1000 | 111100

Tag  = 0001 1111 0   = 62   (0x3E)     （高 9 位）
组号 = 1 0110 1000   = 360  (0x168)    （中 9 位）
偏移 = 111100        = 60   (0x3C)     （低 6 位）

重建验证：(62 × 512 + 360) × 64 + 60 = 32104 × 64 + 60 = 2054656 + 60 = 2054716 = 0x1F5A3C ✓

（3）判断是否命中

本次访问定位到 Cache 第 360 组（由组号 360 决定）；
该组内两个有效块的 Tag 分别为 40 和 62；
本次访问的 Tag = 62 → 与其中一个相等，且有效位 V = 1 → 命中！
数据位置：Cache 第 360 组中 Tag = 62 的那一行，块内第 60 个字节（0x3C）。

答：（1）Tag 9 位 + 组号 9 位 + 偏移 6 位；（2）Tag = 62 (0x3E)，组号 = 360 (0x168)，偏移 = 60 (0x3C)；（3）命中，数据在第 360 组中 Tag=62 行的第 60 字节处。

若第（3）问改为"该组内两个有效块的 Tag 为 40 和 100"：则 Tag 62 未出现在组内 → 未命中（缺失），需访问主存取第 32104 块，并按替换策略装入第 360 组的某一路。

计算题 23（约束条件反求 · 逆推型）

已知：t_c = 10 ns，t_m = 90 ns，要求 t_a ≤ 18 ns。

（1）求最低命中率 h_min

把 t_a 公式展开并整理：
   t_a = h·t_c + (1 − h)·t_m
       = h·10 + (1 − h)·90
       = 90 − 80h                    ← 关键化简：t_a 随 h 线性下降
代入约束：
   90 − 80h ≤ 18
   80h ≥ 72
   h ≥ 72/80 = 0.90
验算 h = 0.90：t_a = 0.90 × 10 + 0.10 × 90 = 9 + 9 = 18 ns ✓（恰好达标）

答：最低命中率 h_min = 0.90（90%）。

万能反解公式：h = (t_m − t_a) / (t_m − t_c) = (90 − 18)/(90 − 10) = 72/80 = 0.90 ✓

（2）若 h = 0.85，求 t_a 并判断是否达标

t_a = 0.85 × 10 + 0.15 × 90 = 8.5 + 13.5 = 22 ns
22 ns > 18 ns → 不满足设计要求（超出 4 ns）

答：t_a = 22 ns，不满足要求。

（3）Cache 升级为 t_c = 5 ns，h 保持 0.90 不变

t_a = 0.90 × 5 + 0.10 × 90 = 4.5 + 9 = 13.5 ns
S  = t_m / t_a = 90 / 13.5 = 6.67
（效率 e = t_c / t_a = 5 / 13.5 ≈ 37.0%；检查 e = S/r = 6.667/18 ≈ 0.370 ✓，r = 90/5 = 18）

答：t_a = 13.5 ns；S ≈ 6.67。

注意（3）的规律：把 t_c 从 10 ns 降到 5 ns，t_a 从 18 ns 只降到 13.5 ns（没降一半）。原因是 t_a 的主要权重在缺失路径上（0.1 × 90 = 9 ns 占 13.5 ns 的 2/3）。当命中率已经很高时，进一步降低 t_c 的收益有限——此时应优先设法提高命中率。这个结论说明：提升命中率是改善 Cache 性能最有效的手段。
