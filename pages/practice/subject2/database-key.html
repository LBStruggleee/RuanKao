【问题1】（4 分）补充 4 个联系

推导答案：

联系名 实体1 实体2 联系类型
联系1 分公司 业务部 1:n
联系2 业务部 职员 1:n
联系3 职员 业务部（主管） 1:1
联系4 职员 分公司（经理） 1:1

丢分点解析（联系类型判定口诀如何应用）：

口诀："两端都唯一 → 1:1；一端唯一一端不唯一 → 1:n；两端都不唯一 → m:n"。 "唯一"指该端实体在该联系中是否只能出现一次（一个实体对象是否只参与一次联系）。

  1. 分公司—业务部 = 1:n：需求 (1)「每个分公司设立仅为本分公司服务的多个业务部」—— 分公司端唯一（一个分公司对多个业务部），业务部端不唯一 → 1:n。
  2. 业务部—职员 = 1:n：需求 (2)「每个业务部有多名职员，每个职员只能来源于一个业务部」 ——业务部端唯一，职员端不唯一 → 1:n。
  3. 业务部—职员（主管）= 1:1：需求 (2)「每个业务部各有一名主管负责」+ 需求 (3) 岗位含"主管"——每个业务部一名主管，每名主管只负责一个业务部 → 1:1。

  4. 分公司—职员（经理）= 1:1：需求 (1)「每个分公司各有一名经理，负责分公司的管理工作」+ 需求 (3) 岗位含"经理"——分公司端唯一，经理端也唯一（一名经理只管一个分公司）→ 1:1。

  5. 关键陷阱：经理、主管不是独立实体，它们是职员的岗位（需求 (3) 明确"岗位包括： 经理、主管、研发员、业务员等"）。把"经理""主管"画成新实体是本题最常见错误。

  6. "唯一"的判别动作：在草稿纸上把每个实体对象列出来，问自己"这个业务部有几个主管？ 这个主管管几个业务部？"——把需求里的量词（一名/多名/只属于）逐对核对。
  7. 1:1 的另一种处理：1:1 联系转换时既可以把 1 端主键放另一端，也可以让它两边都放； 本题"主管""经理"最终以属性形式出现在关系模式里（业务部.主管号、分公司.经理号），

    这与问题 2/3 的答案直接对应——联系类型判对了，关系模式填空自然对。

知识点：【科目二·试题二】E-R 图联系类型判定（1:1 / 1:n / m:n）

【问题2】（3 分）关系模式填空

答案（原文）： （a）：经理号，电话 （b）：地址，分公司编号，主管号 （c）：所属业务部编号

丢分点解析（如何从需求定位缺失属性）：

方法：把每个关系模式与需求属性清单逐条比对，缺什么填什么。

  • （a）分公司（分公司编号，名称，（a），联系地址）：需求 (1) 给全部分公司属性为 "分公司编号、名称、经理号、联系地址和电话"。模式中已有"分公司编号、名称、联系地址"， 缺 经理号、电话 → （a）= 经理号，电话。
  • 易错点：漏填"电话"——需求里"电话"在句末，比对着比着就丢了； 一个空里缺几个属性就填几个，用逗号隔开一次写全。
  • （b）业务部（业务部编号，名称，（b），电话）：需求 (2) 给全部属性为 "业务部编号、名称、地址、电话和分公司编号"，加上需求中"每个业务部各有一名主管" 对应的主管号。模式中已有"业务部编号、名称、电话"，缺 地址、分公司编号、主管号 → （b）= 地址，分公司编号，主管号。
  • 易错点：漏"主管号"——它没出现在需求 (2) 的属性清单原句里，而要从 "每个业务部各有一名主管"这句话推出（1:1 联系把主管的主键放进业务部端）。
  • （c）职员（职员号，姓名，岗位，（c），电话，家庭成员姓名，成员关系）： 需求 (3) 给全部属性为"职员号、姓名、所属业务部编号、岗位、电话、家庭成员姓名和成员关系"。 模式中已有"职员号、姓名、岗位、电话、家庭成员姓名、成员关系"，缺 所属业务部编号 → （c）= 所属业务部编号。
  • 易错点：把"所属业务部编号"误写成"部门号"——必须用需求原词（本题为"所属业务部编号"）。

知识点：【科目二·试题二】关系模式填空（属性比对法）

【问题3】（4 分）主键与外键

答案（原文）： 分公司主键：分公司编号 分公司外键：经理号 业务部主键：业务部编号 业务部外键：分公司编号，主管号

丢分点解析（主外键判定规则）：

  • 主键判定规则：看需求中"XX 号唯一标记/唯一标识/唯一确定……每一个元组"那句—— 被修饰的就是主键。
  • 需求 (1)「分公司编号唯一标记分公司关系模式中的每一个元组」→ 分公司主键 = 分公司编号。
  • 需求 (2)「业务部编号唯一标记业务部关系模式中的每一个元组」→ 业务部主键 = 业务部编号。
  • 外键判定规则：关系模式中出现的、引用别的关系主键的属性，就是外键。
  • 分公司关系里有"经理号"——它引用职员关系的职员号（经理是职员）→ 外键 = 经理号。
  • 业务部关系里有"分公司编号"（引用分公司关系）和"主管号"（引用职员关系） → 外键 = 分公司编号，主管号。
  • 易错点（高频）：
  • 漏外键：只写分公司编号、漏主管号（或反之）。规则是"关系模式里出现的所有 跨表编号都要算外键"，逐个属性问一遍"这个号是另一张表的主键吗？"；
  • 把主键当外键：业务部编号是业务部自己的主键，不是外键；
  • 把非键属性当外键：名称、地址、电话不是任何表的主键，不是外键。

知识点：【科目二·试题二】主键 / 外键判定

【问题4】（4 分）数据冗余与模式分解

答案（原文）： 职员关系模式存在数据冗余，修改异常，插入异常，删除异常等问题。 应将"职员"关系模式进行分解，分解之后的关系模式如下：

职员1（职员号，姓名，岗位，所属业务部编号，电话） 职员2（职员号，家庭成员姓名，成员关系）

丢分点解析（规范化考点）：

  • 问题定位法：看关系模式里有没有非主属性对主键的部分函数依赖—— 职员（职员号，姓名，岗位，所属业务部编号，电话，家庭成员姓名，成员关系）中， 主键是职员号；但"家庭成员姓名、成员关系"是每个家属一行的数据， 一个职员有多名家属 → 职员号 → （姓名、岗位、电话…）这些信息被重复存储多遍。
  • 四种异常（背诵点，逐字记忆）：
  • 数据冗余：职员的基本信息随每个家属重复存储；
  • 修改异常：改职员电话要同时改多行，漏改就数据不一致；
  • 插入异常：职员还没录入家属就插不进来（或家属信息无法单独登记）；
  • 删除异常：删掉最后一个家属就连职员信息一起删没了。
  • 解决套路（通用三步）：
  • 找出"部分依赖"的属性组（本题：家庭成员姓名、成员关系 依赖 职员号）；
  • 把它拆成独立关系，并带上主键（本题：职员2（职员号，家庭成员姓名，成员关系））；
  • 剩余属性保留在原关系中（本题：职员1（职员号，姓名，岗位，所属业务部编号，电话））。
  • 答分要点：问题与解决方法都要答（本题 4 分通常问题 2 分 + 分解 2 分）； 分解后的关系模式必须写全属性，且新关系要带上被拆出的主键（职员号）， 否则两表无法关联。
  • 判别信号：题干出现"每个 XX 有多个 YY/多名 YY"且 YY 与 XX 混在一张表 → 基本就是"数据冗余 + 四异常 + 分解"这套答案。

知识点：【科目二·试题二】关系模式规范化（数据冗余/插入/删除/修改异常 + 模式分解）

⚠️ 本题答案页未被提取，全部为推导答案，已逐题标注。推导依据：需求原句 + E-R 转换规则。

【问题1】（6 分）补充 3 个联系

答案【存疑：推导答案】：

联系名 实体1 实体2 联系类型
联系1 客户 车辆 1:n
联系2 部门 员工 1:n
联系3 员工 维修单 1:n

丢分点解析（联系类型判定口诀如何应用）：

  1. 客户—车辆 = 1:n：需求 (2)「一个客户至少有一辆车，一辆车只属于一个客户」—— 客户端唯一（一辆车只对应一个客户），车辆端不唯一（一个客户多辆车）→ 1:n。
  2. 注意"至少有一辆"只是存在性约束，不改变联系类型。
  3. 部门—员工 = 1:n：需求 (4)「每个部门只有一名主管，但每个部门有多名员工， 每名员工只属于一个部门」——部门端唯一，员工端不唯一 → 1:n。
  4. 员工—维修单 = 1:n：需求 (5)「一个维修工可以接多张维修单，但一张维修单只对应 一个维修工」——员工端唯一，维修单端不唯一 → 1:n。

  5. 注意：维修单关联的是维修工（员工的一种岗位），不是"业务员"；需求 (3) 说明 "业务员填写维修单"，但需求 (5) 明确"维修工接单"，接单关系连的是员工（维修工）。

  6. 关于"部门主管"的处理（本题易错点）：需求 (4)「每个部门只有一名主管」看似是 部门—员工的 1:1 联系，但题目只要求 3 个联系。已选的 3 个联系覆盖了需求 (2)(4)(5) 的核心量词句；"主管"以属性形式落在部门关系模式里（部门（部门号，名称，主管，电话）， 其中"主管"是引用员工号的外键属性）。联系个数严格按题目要求（3 个），不要多画。

  7. 通用核对动作：每条量词句（一个/一名/多张/只属于）在草稿上写成 "X 端：唯一 / Y 端：不唯一"的对照，再套口诀得出类型。

知识点：【科目二·试题二】E-R 图联系类型判定（1:n 的量词句识别）

【问题2】（4 分）关系模式填空

答案【存疑：推导答案，经网络参考答案核对】： （a）客户性质 （b）客户号 （c）部门号 （d）车牌号，员工号

丢分点解析（如何从需求定位缺失属性 + 1:n 转换规则）：

核心规则：1:n 联系 → 把 1 端的主键放进 n 端关系模式。

  • （a）客户（客户号，客户名，（a），折扣率，联系人，联系电话）： 需求 (1) 给全部客户属性为"客户号、客户名、客户性质、折扣率、联系人、联系电话"。 模式缺 客户性质 → （a）= 客户性质。
  • 易错点：把"客户性质有个人或单位"误当成联系——它只是属性的取值范围。
  • （b）车辆（车牌号，（b），车型，颜色，车辆类别）： 需求 (2) 给车辆自身属性为"车牌号、车型、颜色和车辆类别"，没有"客户号"。 但客户—车辆是 1:n → 按 1:n 转换规则，把 1 端（客户）的主键"客户号"放进 n 端（车辆） → （b）= 客户号。
  • 易错点（高频）：只填需求里写出的车辆属性，忘了 1:n 联系要补"1 端主键"。 判别信号：空所在的关系模式是某个 1:n 联系的 n 端，且需求属性清单里没有对方主键 → 填对方主键。
  • （c）员工（员工号，员工名，岗位，（c），电话，家庭住址）： 需求 (3) 给员工自身属性为"员工号、员工名、岗位、电话、家庭住址"。 部门—员工是 1:n → 把 1 端（部门）主键"部门号"放进 n 端（员工）→ （c）= 部门号。
  • （d）维修单（维修单号，（d），维修内容，工时）： 需求 (5) 给维修单自身属性为"维修单号、车牌号、维修内容、工时"， 但关系模式里已有"维修单号、维修内容、工时"，缺车牌号（需求属性清单里有、模式里没有的属性要补） → 车牌号必填；同时员工—维修单是 1:n → 把 1 端（员工）主键"员工号"放进 n 端（维修单） → （d）= 车牌号，员工号（两个属性，一次写全）。
  • 易错点（高频）：只填员工号漏了车牌号——判别信号有两个：① 空所在关系模式的 需求属性清单里出现的属性，模式里缺了，要补进空里；② 若该关系是某 1:n 联系的 n 端， 还要补 1 端主键。两类缺项都要填。
  • 参考核对：网络参考答案（CSDN《2021 年下半年软件设计师下午真题答案及解析（二）》） 亦为 （d）= 车牌号 + 员工号（原文："对比发现缺失车牌号属性……应将维修工的主键归并到 维修单信息中"）。

知识点：【科目二·试题二】关系模式填空 + 1:n 联系转换规则（1 端主键入 n 端）

【问题3】（2 分）主键与外键

答案【存疑：推导答案，经网络参考答案核对】： 车辆关系主键：车牌号，外键：客户号 维修单关系主键：维修单号，外键：车牌号，员工号

丢分点解析（主外键判定规则）：

  • 主键：看"XX 号唯一标识……每一个元组"那句。
  • 需求 (2) 未直接说车牌号唯一，但"车牌号"是车辆的自然唯一标识 （一辆车一个车牌），且车辆关系模式以车牌号开头 → 主键 = 车牌号。
  • 需求 (5)「维修单号唯一标识维修单关系中的每一个元组」→ 主键 = 维修单号。
  • 外键：关系模式中引用别的关系主键的属性。
  • 车辆关系里有"客户号"（引用客户关系主键）→ 外键 = 客户号。
  • 维修单关系里有"员工号"（引用员工关系主键，问题 2 刚填）和"车牌号" （引用车辆关系主键，问题 2 刚填）→ 外键 = 车牌号，员工号（两个都算，别漏）。
  • 易错点：
  • 车辆外键漏写（车辆关系模式里的客户号是问题 2 刚填进去的，到问题 3 要记得它也是外键）；
  • 把维修单的"维修内容/工时"当外键——它们不是任何表的主键。

知识点：【科目二·试题二】主键 / 外键判定（问题 2 填入的"1 端主键"天然就是外键）

【问题4】（3 分）联系类型变化与处理

答案【存疑：推导答案】： 员工与维修单之间的联系类型会由 1:n 变为 m:n（因为一张维修单需要多个维修工处理， 而一个维修工仍可接多张维修单，两端都不唯一了）。 解决办法：不能把员工号继续作为维修单关系的一个普通属性（会违反第一范式、 出现数据冗余），应新增一个独立的关系模式来描述这个 m:n 联系，例如：

维修（维修单号，员工号，维修内容，工时）

主键为（维修单号，员工号），外键为维修单号（引用维修单关系）、员工号（引用员工关系）。

丢分点解析（m:n 联系的处理套路）：

  • 第一步：判断变化。原需求"一张维修单只对应一个维修工"→ 1:n； 新情况"一张维修单需要多个维修工，一个维修工可接多张维修单"→ 两端都不唯一 → m:n。 答题必须先点明"哪个联系（员工—维修单）由 1:n 变为 m:n"，这一步占分。
  • 第二步：处理方法。m:n 联系不能通过"在某一端加对方主键"实现 （一个维修单多个维修工 → 维修单关系里员工号会有多值，破坏第一范式）。 必须转成独立关系模式，主键 = 两端主键的组合（维修单号，员工号）。
  • 得分点拆解： ① 指出变化的联系与变化后的类型（1:n → m:n）； ② 指出不能简单加属性（会数据冗余/违反 1NF）； ③ 给出独立关系模式并说明主键/外键。
  • 通用答题模板（所有 m:n 变化题通用）：

    「X 与 Y 的联系由 1:n 变为 m:n。应将联系转换为独立关系模式 联系名（X 主键，Y 主键，联系属性），主键为（X 主键，Y 主键）， 外键为 X 主键、Y 主键，原关系中重复的属性移入该关系。」

知识点：【科目二·试题二】m:n 联系的识别与关系模式转换（独立关系 + 组合主键）

高频丢分点 Top（做完后对照回填到 database-notes.md）

  1. 联系类型判错：不逐对核对量词，凭感觉写 1:n 或 m:n （试题 A 的 1:1 主管/经理、试题 C/D 的三元 m:n:p）。
  2. 1:n 转换漏补"1 端主键"：n 端关系模式的空只填需求里写过的属性， 忘了 1:n 联系要求把 1 端主键放进 n 端（试题 B 的 (b)(c)(d)）。
  3. 外键漏写：关系模式里每个跨表编号都是外键，要逐个属性问一遍"它是别的表的主键吗" （试题 A 业务部两个外键、试题 C 接种三个外键）。
  4. m:n 忘了转独立关系 / 主键少组合：m:n 必须独立成关系模式，主键 = 两端主键组合 （试题 B 问题4、试题 C/D 问题3）。
  5. 三元联系拆成三个二元：一条信息挂三个实体时必须一个菱形连三实体 （试题 C/D 问题1）。
  6. 把"经理/主管/采购/接种/检测/销售"画成实体：它们分别是职员（岗位）或联系， 且题目常明确"不增加新的实体"。
  7. 联系属性挂错位置：采购数量/采购日期/检测日期/检测结果应挂在联系上， 不是实体的自身属性。
  8. 扩展设计题不画图只写模式：(1) 图上要画实体矩形+联系菱形+连线及属性， (2) 再给关系模式并标注主外键。
  9. 规范化的四异常背不全：数据冗余、修改异常、插入异常、删除异常（逐字背诵）； 分解后的新关系必须带上主键（职员号）。
