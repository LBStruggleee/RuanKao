二、E-R 图答题模板（试题二，15 分）

第 1 步：需求 → 实体（找"信息包括"句式）

核心口诀：找"XX 信息包括：……"句式；"包括"后面的名词列表就是实体及其属性。

  • 什么是实体：需求中独立存在、需要单独存储信息的对象（客户、车辆、员工、部门、维修单、门店……）。
  • 识别法：
  • 逐条扫【需求分析结果】，每个"（n）XX 信息包括：A、B、C"对应一个实体；
  • 属性 = "包括"后面跟的名词短语；
  • 【逻辑结构设计】给出的关系模式名（如"客户（客户号，…）"）直接确认实体名。
  • 必须排除：
  • 岗位 / 类别（"岗位有业务员、维修工、主管"——是属性的取值范围，不是实体）；
  • "经理/主管"（它们是职员的岗位，不是独立实体——试题 A 的核心陷阱）；
  • 联系本身（"采购""接种""检测""销售"是联系，不是实体，题目常明确"不增加新的实体"）。

第 2 步：实体 → 联系（找量词句）+ 联系类型判定口诀

核心口诀：1:1 两端都唯一；1:n 一端唯一；m:n 都不唯一。

"唯一"= 该端实体对象在这个联系中只出现一次（一个对象只参与一次该联系）。 判定动作：把需求里的量词句抄成对照表，逐对打钩：

需求原句 X 端 Y 端 联系类型
「一个客户至少有一辆车，一辆车只属于一个客户」 客户：唯一 车辆：不唯一 1:n
「一个维修工可以接多张维修单，但一张维修单只对应一个维修工」 员工：唯一 维修单：不唯一 1:n
「每个部门只有一名主管」 部门：唯一 主管(职员)：唯一 1:1
「接种者可能需要进行多次疫苗接种，每次都可以在全市任意一家医院」 被接种者：不唯一 医院：不唯一 m:n

三类句式速查：

需求句式 联系类型
"一个 X 只有一个 Y，一个 Y 只有一个 X" / "每个 X 只有一名 Y，每名 Y 只负责一个 X" 1:1
"一个 X 有多个 Y，一个 Y 只属于一个 X" / "每个 X 只有一名 Y" 1:n
"一个 X 有多个 Y，一个 Y 属于多个 X" / "X 可以多次……每次都可以任意 Y" m:n

三元联系判定（2022 上 / 2023 上考点）

识别信号：一条信息同时挂三个实体—— - 2022 上：「记录接种者疫苗接种信息，包括接种医院信息，被接种者信息，疫苗供应商名称和接种日期」 - 2023 上：「记录零件采购信息，某个车型的某种零件可以从多家供应商采购，某种零件也可以被多个车型采用，某家供应商也可以供应多种零件」

判定法：逐对检查三端两两的量词，三对都"不唯一" → 三元多对多（*:*:* / m:n:p）。

画法：一个菱形连三个实体（不要拆成三个两两的二元联系——两两联系无法完整表达 "谁、在哪家、用了哪家供应商/采购了什么"这一组信息）。

E-R 图符号

符号 含义
矩形 实体（实体名写在框内）
椭圆 属性（用线连到所属实体；主键属性下加下划线）
菱形 联系（联系名写在菱形内；菱形用线连接参与联系的实体）
无向边上的数字/字母 联系类型（1、n、m 或 1:1、1:n、m:n；三元写 *:*:*）

第 3 步：联系/实体 → 属性（属性归属判定）

  • 实体自身属性：需求中"XX 信息包括"后、描述该实体自身特征的名词（客户号、客户名、折扣率…）；
  • 联系属性：只在"联系发生时"才有意义的名词——采购数量、采购日期、检测日期、检测结果、 销售数量、销售日期、接种日期、工时……这些挂在菱形（联系）上，不是任何实体的自身属性。
  • 易错点：把"工时"当员工属性（它是维修单/联系上的属性）、把"采购数量"当零件属性。

第 4 步：E-R → 关系模式转换规则（核心，直接决定问题 2/3/4 的分）

联系类型 转换规则 例（试题 B 汽车维修）
1:1 任选一端，把另一端主键放进去（+联系属性）；或两端互放 部门（…，主管）——把员工号以"主管"属性放进部门
1:n 把 1 端主键放进 n 端关系模式（+联系属性） 车辆（车牌号，客户号，…）；维修单（维修单号，员工号，…）
m:n 必须转成独立关系模式：R（1 端主键，n 端主键，联系属性），主键 = 两端主键的组合 检测（医院名称，被检测者身份证号，检测日期，检测结果）
三元 m:n:p 独立关系模式，主键 = 三端主键的组合（+能区分多次的属性） 采购（车型编号，供应商名称，零件编码，采购数量，采购日期）

判别信号（做题时直接条件反射）： - 空所在的关系模式是某 1:n 联系的 n 端，且需求属性清单里没有对方主键 → 填 1 端主键； - 需求出现"多次……每天最多一次/每次都可以任意"→ m:n，时间/日期属性要进主键； - 【逻辑结构设计】已直接给出一个只由"两个/三个实体主键 + 少量属性"组成的关系模式 （如"供货（供货商名称，（a），供货内容）"）→ 这个关系本身就是 m:n 独立关系， 空 (a) 填缺失的那端主键。

主键 / 外键判定规则

  • 主键：需求中"XX 号唯一标识 / 唯一标记 / 唯一确定……每一个元组"那句被修饰的属性； 实在找不到原句时，用"编号/号/身份证号/车牌号"这类天然唯一标识。
  • 外键：关系模式中引用别的（已存在的）关系主键的属性。 判定动作：把关系模式的每个属性问一遍"它是另一张表的主键吗？"——是就写外键。
  • m:n / 三元独立关系：主键 = 组合（两端或三端主键，外加能区分多次的属性如检测日期）； 外键 = 组成主键的每个属性（它们分别引用各实体关系的主键）。
  • 注意：问题 2 刚填进空里的"1 端主键"，到问题 3 标注外键时天然就是外键——不要填完就忘。

扩展设计题四步模板（问题 3/4，7 分大题）

题干特征："现新增如下需求……""还兼有 XX 业务……"→ 套这四步：

  1. 新增实体照需求抄属性：题干给定的属性逐字照抄成关系模式 （被检测者（身份证号，姓名，地址，电话）；门店（门店编号，地址，电话））；
  2. 新增联系照需求判类型：找量词句判 1:1 / 1:n / m:n （"多次检测 + 任意一家医院"→ m:n；"一个车型在多家门店销售，一家门店卖多种车型"→ m:n）；
  3. m:n 必转独立关系模式：两端实体主键 + 联系属性 （检测（医院名称，被检测者身份证号，检测日期，检测结果））；
  4. 标注主键与外键：主键 = 组合（+区分多次的属性），外键 = 两端主键。
  5. 必须画图：题目若要求"在图 2-1 中体现"——矩形画新实体、菱形画新联系、连线并标基数； 只写关系模式会丢步骤分。

规范化题模板（数据冗余 / 四异常 / 分解）

  • 题干特征："假设每个 XX 有多个 YY，那么该关系模式存在什么问题？应如何解决？"
  • 问题（背诵，逐字）：存在数据冗余、修改异常、插入异常、删除异常等问题。
  • 解决三步：
  • 找出随"多个 YY"重复存储的属性（家庭成员姓名、成员关系 / 多值属性）；
  • 把重复组拆成独立关系，并带上主键；
  • 剩余属性留在原关系。
  • 例：职员（职员号，姓名，岗位，所属业务部编号，电话，家庭成员姓名，成员关系） → 职员1（职员号，姓名，岗位，所属业务部编号，电话）
  • 职员2（职员号，家庭成员姓名，成员关系）。
  • 本质：非主属性对主键存在部分函数依赖（家属信息依赖"职员号 + 家属名"）， 分解即升级到 2NF/3NF。

三、SQL 大题常见考法（上午卷为主，下午备考）

虽 2020–2023 试题二未考纯 SQL 书写，但 SQL 是上午卷每年必考（2–3 分）， 且部分年份下午题会用 SQL 表达完整性约束。下列四类考法各给 1 个真题例句。

3.1 建表 CREATE TABLE（含主外键约束）

考法：给出关系模式，要求用 SQL 建表并声明主键、外键、非空等约束。 核心语法：PRIMARY KEY (...) / FOREIGN KEY (...) REFERENCES 表(列) / NOT NULL。

真题例句（用 2021 下试题二真实关系模式构造）：

CREATE TABLE 维修单 (
    维修单号 CHAR(10) PRIMARY KEY,          -- 主键（维修单号唯一标识每一个元组）
    员工号   CHAR(10),                       -- 问题2填入的 1 端主键
    维修内容 VARCHAR(100),
    工时     DECIMAL(5,1),
    FOREIGN KEY (员工号) REFERENCES 员工(员工号)  -- 外键引用员工关系主键
);

易错点： - 外键没写（最常见的丢分点——每个跨表编号都要声明 FOREIGN KEY ... REFERENCES）； - 约束位置错：列级约束跟在列定义后，表级约束（复合主键/多外键）放在最后一列之后； PRIMARY KEY (a, b) 是表级写法，不能写成 a PRIMARY KEY, b PRIMARY KEY； - 引用的表/列名要存在：REFERENCES 员工(员工号) 中员工号必须是员工表的主键。

3.2 查询 SELECT（连接 / 子查询 / 分组聚合）

考法 A：等价连接（关系代数 ↔ SQL 互转）

真题例句（2019 下半年上午，(54)(55)）： 题干：给定关系 R（A, B, C, D）和 S（B, C, E, F），与关系代数表达式 π1,5,7(σ2=5(R×S)) 等价的 SQL 语句如下：

SELECT R.A, S.B, S.E FROM R, S WHERE R.B = S.B;
  • 解析：R×S 的第 1、5、7 列依次为 R.A、S.B、S.E（投影）；σ2=5 即 R.B = S.B（选择）。
  • 易错点：JOIN 条件漏——多表查询 FROM R, S 必须配 WHERE R.B = S.B 连接条件， 漏了会得到笛卡尔积；列名歧义时要写 表名.列名（如 R.B）。

考法 B：分组聚合 + HAVING

真题例句（2017 上半年上午，(54)(55)(56)）： 题干：关系模式 SP_P（供应商号, 项目号, 零件号, 数量），"每个供应商可以为多个项目供应 多种零件"。查询至少供应了 3 个项目（包含 3 项）的供应商，输出其供应商号和供应零件数量 的总和，并按供应商号降序排列：

SELECT 供应商号, SUM(数量)
FROM   SP_P
GROUP BY 供应商号
HAVING COUNT(DISTINCT(项目号)) > 2
ORDER BY 供应商号 DESC;
  • 解析：聚合 SUM(数量) 必须配 GROUP BY；"至少 3 个项目"是分组后的筛选用 HAVING （不是 WHERE——WHERE 不能用聚合函数）；COUNT(DISTINCT ...) 去重计数； 降序 ORDER BY ... DESC。
  • 易错点：WHERE/HAVING 用混（聚合条件必须放 HAVING）；漏 DISTINCT 导致重复计数； 忘记 ORDER BY 的 DESC。

考法 C：子查询（常考 IN / NOT IN / EXISTS）：

SELECT 客户号, 客户名 FROM 客户
WHERE 客户号 IN (SELECT 客户号 FROM 车辆 WHERE 车辆类别 = '新能源');

3.3 权限 GRANT / REVOKE

考法：授予权限并允许转授 / 收回权限。

真题例句（2023 上半年上午，(55)(56)）： 题干：如果将 Students 表的插入权限赋予用户 User1，并允许其将该权限授予他人， 那么正确的 SQL 语句如下：

GRANT INSERT ON TABLE Students TO User1 WITH GRANT OPTION;
  • 语法：GRANT <权限> ON [TABLE] <对象> TO <用户> [WITH GRANT OPTION]
  • 解析：权限是"插入"→ INSERT；"赋予用户 User1"→ TO User1； "允许其将该权限授予他人"→ WITH GRANT OPTION（选项 C）。
  • 易错点：INSERT ON 要连用（GRANT INSERT TABLE ... 缺 ON 语法错误）； WITH GRANT OPTION（允许转授权）与 WITH CHECK OPTION（视图检查约束）混淆。
  • 收回权限：REVOKE <权限> ON <对象> FROM <用户>。

3.4 视图 CREATE VIEW

考法：为某类用户创建只读/限定列的视图。

真题例句（用试题二真实关系模式构造）：

CREATE VIEW 维修明细视图 AS
SELECT 维修单号, 车牌号, 维修内容, 工时, 员工名
FROM   维修单 JOIN 员工 ON 维修单.员工号 = 员工.员工号
WHERE  工时 > 2;
  • 语法：CREATE VIEW 视图名 AS SELECT ...（视图是虚表，不实际存储数据）； 带 WHERE 限定可见行；多表用 JOIN ... ON ...（等价于 FROM A, B WHERE A.k = B.k）。
  • 易错点：JOIN 的 ON 条件漏（同 3.2）；视图的 SELECT 中不能含子查询里的某些聚集限制等。

SQL 考法速查表

考法 关键字 核心易错点
建表 CREATE TABLE ... PRIMARY KEY / FOREIGN KEY ... REFERENCES 外键漏写、约束位置错、引用列必须存在且为主键
连接查询 FROM R, S WHERE R.k = S.k / JOIN ... ON JOIN/ON 条件漏、列名歧义
分组聚合 GROUP BY ... HAVING COUNT/SUM ... ORDER BY ... DESC WHERE/HAVING 混用、漏 DISTINCT、忘 DESC
子查询 IN / NOT IN / EXISTS 内外层连接列写错
权限 GRANT ... ON ... TO ... WITH GRANT OPTION / REVOKE ... FROM INSERT ON 连用、GRANT OPTION 与 CHECK OPTION 混淆
视图 CREATE VIEW 名 AS SELECT ... AS 不可省、JOIN 条件漏

  2. 转换规则：1:n 把 1 端主键放 n 端；m:n 必须转独立关系，主键 = 两端主键组合； 三元 m:n:p 主键 = 三端主键组合。
  3. 主键看"唯一标识"那句；外键 = 关系模式里所有跨表编号。
  4. 扩展设计四步：抄实体属性 → 判联系类型 → m:n 转独立关系 → 标主键外键（并画图）。
  5. 规范化四异常：数据冗余、修改异常、插入异常、删除异常。
