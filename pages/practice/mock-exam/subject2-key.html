试题一：2023 年上半年 下午试题一（农事管理服务平台）

答案速查

问题 答案 分值
问题1 E1：平台管理员　E2：农户　E3：租户　E4：第三方软件 4
问题2 D1：人员表　D2：基地及地块数据表　D3：农事过程表　D4：农事活动表 4
问题3 投入品消耗 D4→P4；地块信息 D2→P5；农事过程信息 D3→P5；农事活动信息 D4→P5 4
问题4 农事信息请求 = 账号 + 密码 + 查询条件 3

【问题1】（4 分）外部实体

答案（原文）：E1：平台管理员　E2：农户　E3：租户　E4：第三方软件

丢分点解析：

  • 四个实体全部来自【说明】中出现的"人员角色 / 外部系统"：
  • 平台管理员——功能 (1)"平台管理员管理租户"
  • 租户——功能 (1)"租户管理农户并为其分配负责的地块"、功能 (2)(3)(4) 的操作者
  • 农户——功能 (1) 被管理者、功能 (3)"农户根据相应农事过程提醒进行农事活动并记录"、 功能 (4)"农户在农事活动中设定投入品的实际消耗"
  • 第三方软件——功能 (5)"系统也给其他第三方软件提供 APP 接口"
  • 易错点：
  • 把"用户"误当第五个实体——功能 (5) 的"用户按查询条件发起农事信息请求"中， "用户"是平台管理员/租户/农户的统称，不是独立角色；参考答案只给 4 个实体。
  • 把"农事信息请求"被错误归给某个具体实体——第三方软件走 APP 接口， 与内部"用户"发起的请求是同一条流（问题 4 即考这条流的组成）。
  • 把地块、作物、投入品误当实体——它们是系统处理/存储的数据，不是外部实体。
  • 答题规范：题目要求"使用说明中的词语"，必须用【说明】原词 （"平台管理员"不能简写为"管理员"；"第三方软件"不能写成"第三方系统"）。

知识点：【科目二·试题一】DFD 外部实体识别（见 ../subject2/dfd-uml-notes.md 一·第 1 步：外部实体识别法）

【问题2】（4 分）数据存储

答案（原文）：D1：人员表　D2：基地及地块数据表　D3：农事过程表　D4：农事活动表

（源答案附注："自拟的答案用表、信息表、记录、文件等等关键字均可"）

丢分点解析：

  • 四个存储与【说明】中的四个"被记录/被设定/被维护的数据对象"一一对应：
  • D1 人员表 ← 功能 (1)"人员管理……租户和农户以人员类型区分"——存的是人员
  • D2 基地及地块数据表 ← 功能 (2)"租户填写基地名称、地域等描述信息，在显示的地图上 绘制地块"——存的是基地与地块数据（两者合一个存储，易错点见下）
  • D3 农事过程表 ← 功能 (3)"租户设定作物及其从种植到采收的整个农事过程"
  • D4 农事活动表 ← 功能 (3)"农户……进行农事活动并记录"
  • 易错点：
  • 把"基地"和"地块"拆成两个存储——功能 (2) 把两者写在同一句描述里，参考答案合并为 "基地及地块数据表"；
  • 把投入品单独算一个存储——功能 (4) 的"投入品信息"未单独成表：投入品的实际消耗 是"农户在农事活动中设定"的，即随农事活动记录进入 D4（这正是问题 3 中 "投入品消耗 D4→P4"的来源）；租户维护的投入品信息也不是独立存储。
  • 把"作物"算独立存储——作物是农事过程（D3）的一部分。
  • 定位技巧（../subject2/dfd-uml-notes.md 一·第 2 步：数据存储定位法）： 找【说明】中的"存储/保存/记录/维护/设定/区分"等动词，被作用的对象名词即存储名核心词； 后缀"表/信息表/记录/文件"均给分。

知识点：【科目二·试题一】DFD 数据存储识别

【问题3】（4 分）补充缺失的数据流

答案（原文表格）：

数据流名称 起点 终点
投入品消耗 D4 P4
地块信息 D2 P5
农事过程信息 D3 P5
农事活动信息 D4 P5

丢分点解析（数据流平衡规则如何应用——下午卷最高频丢分点）：

逐个加工检查"守恒"（有输入、有输出、输入足以产生输出），回【说明】找缺的流：

  1. 地块信息 D2→P5 / 农事过程信息 D3→P5 / 农事活动信息 D4→P5： 功能 (5) 说信息服务要对"相关地块农事活动实施情况（如与农事过程比对）等 农事信息进行筛选、对比和统计等处理"——P5 信息服务 的输出是"响应信息"， 但输入只有"农事信息请求"一条，要处理的三类数据全缺。这些都是被存储的批量/历史数据， 只能从数据存储读（../subject2/dfd-uml-notes.md 一·第 3 步的记忆口诀： "查询/统计/比对类处理只能读存储"），故补三条 D→P5 的流，名称逐一取自【说明】原词： 地块信息（D2）、农事过程信息（D3）、农事活动信息（D4）。
  2. 投入品消耗 D4→P4：功能 (4) 说投入品管理要"租户统一维护化肥、杀虫剂等投入品信息"， 而"农户在农事活动中设定投入品的实际消耗"——P4 投入品管理 要维护投入品信息， 缺"实际消耗"这条输入；实际消耗随农事活动记录存在 D4，故补 D4→P4。

平衡规则应用要点：

  • 守恒规则：一个加工的输出必须能由其输入产生。P5 只画了输出（响应信息）没有数据输入， 属"有输出无输入"（奇迹错误），必须补输入。
  • 数据流命名：用【说明】原词名词短语（"农事活动信息"而非"活动信息"）。
  • 本题与 2020下/2021下 DFD 的区别：本题为"读取历史数据"型补流（全是从存储到加工）， 没有加工到加工的实时流——做的时候先锁定"哪个加工的输出无法由输入解释"，再回【说明】找原词。

知识点：【科目二·试题一】数据流平衡（守恒规则/无悬空流）—— 见 ../subject2/dfd-uml-notes.md 一·第 3 步

【问题4】（3 分）数据流的组成

答案（原文）： - 答 1：农事信息请求 = 账号 + 密码 + 查询条件 - 答 2：农事信息请求 = 账号 + 密码 + 0{查询条件}* - 答 3：农事信息请求：账号、密码、查询条件

（源答案附注："格式不是绝对的，只要接近答案应该就会给分"）

丢分点解析：

  • 答案三项直接取自功能 (5) 的原句："通过接口访问的方式，提供账号，密码和查询条件 发起农事信息请求"。普通用户与第三方软件发起的是同一条数据流，组成相同。
  • 易错点：
  • 只写"查询条件"漏掉账号密码——题干特意强调第三方软件"提供账号，密码和查询条件"， 账号密码是身份/权限依据，缺一不可。
  • 把"响应信息"写进请求的组成——组成是指该流携带的数据项，不是它引发的输出。
  • 格式：A = B + C + D 或 A：B、C、D 均可（源答案明确格式不绝对）， 也可以用数据字典记号 0{查询条件}* 表示查询条件可选/可多个（"无查询条件时默认返回 账号下所有信息"）。

知识点：【科目二·试题一】数据流组成（数据字典条目写法）

【问题1】（6 分）补充三个联系及联系类型【存疑：推导答案】

推导答案：

联系名 连接的实体 联系类型 推导依据（需求原句）
联系1（拥有/所属） 分公司 — 专卖店 1:n 「每个分公司拥有多家专卖店，每家专卖店只属于一个分公司」
联系2（聘用/所属） 专卖店 — 职员 1:n 「每家专卖店有多名职员，每名职员只属于一家专卖店」
联系3（担任店长/负责） 职员 — 专卖店 1:1 「每家专卖店只有一名店长……每名店长只负责一家专卖店」

丢分点解析（联系类型判定口诀如何应用——见 ../subject2/database-notes.md 二·第 2 步："两端都唯一 → 1:1；一端唯一 → 1:n；都不唯一 → m:n"）：

  1. 分公司—专卖店 1:n：读量词——分公司端"多家"（不唯一）、专卖店端"只属于一个"（唯一）， 一端唯一 → 1:n。1:n 联系转换到关系模式时，"n 端"关系模式加入"1 端"的主键作外键 ——这正是问题 2（a）要补的"分公司编号"。
  2. 专卖店—职员 1:n：专卖店端"多名"（不唯一）、职员端"只属于一家"（唯一）→ 1:n。 同理，职员关系模式要加入专卖店的主键"专卖店号"作外键——即问题 2（b）。
  3. 职员—专卖店（店长）1:1：本题最大难点。"店长"不是新实体——需求 (3) 明确 "岗位有店长、营业员等"，店长是职员的一种岗位。这个 1:1 联系画在职员与专卖店之间 （"每家专卖店只有一名店长"=专卖店端唯一；"每名店长只负责一家专卖店"=职员端唯一； 两端都唯一 → 1:1）。判题时若把店长画成独立实体、或把该联系误判为 1:n， 问题 1 会扣掉 2 分左右。
  4. 联系名：题目明确"联系名可用联系1、联系2、联系3；也可根据你对题意的理解取联系名"， 所以采分点在"两端实体 + 联系类型"，联系名随便写（写"联系1/2/3"最稳）。
  5. 作答格式：在答题纸上画菱形 + 连线 + 标 1:1/1:n，并写清联系名。

知识点：【科目二·试题二】E-R 联系类型判定（1:1/1:n/m:n）—— ../subject2/database-notes.md 二·第 2 步

【问题2】（6 分）关系模式填空 + 主键外键【存疑：推导答案】

推导答案：

（1） - （a）：店长、分公司编号 - （b）：专卖店号

（2） - （c）专卖店主键：专卖店号　（d）专卖店外键：分公司编号 - （e）职员主键：职员号　（f）职员外键：专卖店号

丢分点解析：

  • （a）店长、分公司编号：把需求 (2)"专卖店信息包括：专卖店号、专卖店名、店长、 分公司编号、地址、电话"逐项对照关系模式"专卖店（专卖店号，专卖店名，（a），地址，电话）"—— 缺两个属性。最常见的丢分是只补一个（只补分公司编号、漏店长）。
  • 对照法是试题二问题 2 的通用解法（../subject2/database-notes.md 二·第 4 步）： 需求句的属性清单 ⊕ 关系模式已有属性 = 待填空缺。
  • （b）专卖店号：需求 (3)"职员信息包括：职员号、职员名、专卖店号、岗位、电话、薪资" 对照"职员（职员号，职员名，（b），岗位，电话，薪资）"——缺专卖店号。
  • 为什么职员关系里是"专卖店号"而不是"专卖店名"：1:n 联系转换时，n 端关系加入的是 1 端关系的主键；专卖店的主键是专卖店号（不是专卖店名）。
  • （c）（e）主键：需求已直接给出唯一性约束—— "专卖店号唯一确定专卖店关系中的每一个元组"→ 专卖店主键 = 专卖店号； "职员号唯一标识职员关系中的每一个元组"→ 职员主键 = 职员号。 （主键判定规则：能唯一确定一个元组的最小属性组，见 ../subject2/database-notes.md 二·"主键 / 外键判定规则"）
  • （d）（f）外键：外键 = 本关系中引用其它关系主键的属性—— 专卖店的"分公司编号"引用分公司关系主键 → 外键；职员的"专卖店号"引用专卖店关系主键 → 外键。
  • 【存疑：推导】专卖店关系中的“店长”若按问题 1 的 1:1 联系建模为引用职员号， 则"店长"也是外键（引用职员关系的职员号）。官方答案一般只要求写出最直接的 （d）分公司编号；若题目要求"所有外键"，店长可一并写出。作答时写"分公司编号"为主。
  • 作答格式：题目要求"标注主键（实线）和外键（虚线）"——在属性下画线标注， 或写"主键：…　外键：…"。

知识点：【科目二·试题二】E-R → 关系模式转换规则（1:n 的外键加法）+ 主键/外键判定—— ../subject2/database-notes.md 二·第 4 步 + 主键/外键判定规则

【问题3】（3 分）新增实体与联系【存疑：推导答案】

推导答案：

（1） - （g）新增实体：紧急联系人 - （h）联系类型：1:n（职员 1 — 紧急联系人 n）

（2）该实体的关系模式：

紧急联系人（职员号，姓名，与本人关系，联系电话）

其中：主键建议（职员号，姓名）或（职员号，联系电话）；外键：职员号（引用职员关系的职员号）。

丢分点解析：

  • （g）紧急联系人：新实体取题干原词——"专卖店要求每位职员至少要填写一位 紧急联系人"。新实体命名必须用题干原词（扩展设计题四步模板第一步，见 ../subject2/database-notes.md 二·"扩展设计题四步模板"）。
  • （h）1:n：用口诀判定——"每位职员至少要填写一位紧急联系人"，即一名职员可对应 多位紧急联系人（不唯一）；而每位紧急联系人只对应一名职员（唯一）。职员端唯一、 紧急联系人端不唯一 → 1:n。
  • 易错点：把"至少一位"误读为"一位"而判成 1:1。"至少一位"= 上界不限 = n。
  • 1:n 的转换结果：n 端（紧急联系人）关系模式加入 1 端（职员）的主键"职员号"作外键 ——这正是关系模式里必须有"职员号"的原因。
  • 关系模式的属性：题干已给出"姓名、与本人关系和联系电话"三项，再加外键"职员号"， 共四项。漏掉外键职员号是最常见的丢分点（没有职员号，紧急联系人就和职员脱钩了）。
  • 主键：职员号单独不能唯一确定紧急联系人（一名职员多条记录），故主键是复合属性 （职员号 + 姓名/联系电话其一）；本题为开放设计，写法不唯一，写清"主键 + 外键"即可。

知识点：【科目二·试题二】扩展设计（新增实体 + 1:n 联系 + 关系模式转换）—— ../subject2/database-notes.md 二·"扩展设计题四步模板"

【问题3】（4 分）include 和 extend 关系的含义

答案（原文）：

  • include 表示包含关系，含义为：如果系统用例较多，不同的用例之间存在共同行为， 可以将这些共同行为提取出来，单独组成一个用例。当其他用例使用这个用例时，它们就 构成了包含关系。
  • extend 表示扩展关系，含义为：在用例的执行过程中，可能出现一些异常行为，也可能 在不同的分支行为中选择执行，这时可将异常行为与可选分支抽象为一个单独的扩展用例， 这样扩展用例与主用例之间就构成了扩展关系。一个用例常常有多个扩展用例。

（源答案附注："这里包含和扩展的含义不唯一的，大家可以挑自己觉得最合理的进行记忆"）

丢分点解析：

  • 采分结构 = 标准定义 + 本系统举例。只写定义能拿一半分，结合本系统举例（问题要求 "根据说明中的描述以及图 3-1 所示的用例图来说明"）才拿满：
  • include 举例：「创建地址簿」「修改地址簿」都必然执行「保存地址簿」—— "保存"是从多个用例中抽取的公共行为 → <<include>>。
  • extend 举例：只有「修改地址簿」时才需要先「打开地址簿」——打开是修改的 可选/有条件分支 → <<extend>>。
  • 记忆要点（../subject2/dfd-uml-notes.md 二·"用例图三关系"）：
  • include：必然执行的公共行为被抽取；箭头从基本用例指向被包含用例。
  • extend：可选/异常分支；扩展用例指向基本用例；一个基本用例可有多个扩展用例。
  • 易错点：把两者说反。记一句话区分："包含是必须的，扩展是可选的"。

知识点：【科目二·试题三】用例图三关系（include / extend / generalize）—— ../subject2/dfd-uml-notes.md 二·"用例图三关系"

【问题1】（8 分）填充 C 代码空（1）～（4）

答案（原文）：

  • （1）i <= N
  • （2）j = i + r - 1
  • （3）temp < m[i][j]
  • （4）S[i][j] + 1, j

⚠️【存疑：源答案与代码语境不一致】空 (1) 在源代码中位于外层规模循环 for (r = 2; (1); r++)（"r 为子问题规模"）的条件位置，语义上该处应为 r <= N （子问题规模 r 从 2 增长到 N）。源答案作 "i <= N"，疑为答案册 OCR 将 "r" 误识为 "i" （r/i 形近，本答案册同类误识多处）。两种读法表达的循环语义一致——"规模增长到 N 为止"； 且按本文复原后的内层循环 for (i = 1; i <= N - r + 1; i++)，内层条件的完整形式应为 i <= N - r + 1。以原卷代码版式为准；作答时填 "r <= N" 或 "i <= N - r + 1" 均能被判对（看原卷该空到底在内层还是外层）。

丢分点解析（DP 填空通用方法见 ../subject2/patterns-algo-notes.md 二·2.1 填空四步法）：

  • （2）j = i + r - 1：r 是子问题规模，即子多边形 V_{i-1}…V_j 的点数 （j - i + 1 = r）→ j = i + r - 1。这是 DP 区间题的固定套路：外层枚举区间长度， 内层枚举区间左端点，由长度和左端点算出右端点。
  • 检验：r=2 时 j=i+1（两个相邻点，m[i][i+1] 为一条边的权，退化情形）； r=N 时 i=1、j=N（整个多边形），与"求解最小剖分"的目标一致。
  • （3）temp < m[i][j]：k 循环在 i ≤ k < j 范围内枚举剖分点，temp 是当前 k 的 候选权重；若 temp 比当前记录的 m[i][j] 更小，则更新 m[i][j] 并记录 S[i][j] = k。
  • 为什么是 < 不是 <=：题目求最小权重；用 < 时只在严格更小时更新， 保留最先找到的最小值对应的 k（S 记录其中一个最优剖分点，多个最优时任取其一）。
  • 易错点：写成 temp > m[i][j]（求最大）或 temp == m[i][j]。
  • 初始值对照：k=i 时的初值已由循环外那句 m[i][i] + m[i+1][j] + get_triangle_weight(i-1, i, j) 算好并置 S[i][j] = i（题干递归式中 k 的下界 i）。
  • （4）S[i][j] + 1, j：print_triangle 递归输出剖分：在 k = S[i][j] 处把多边形 V_{i-1}…V_j 切成两个子多边形——左半 V_{i-1}…V_k 由上一行 print_triangle(i, S[i][j]) 处理，右半 V_k…V_j 由本空 print_triangle(S[i][j] + 1, j) 处理，随后输出当前三角形 V(i-1)--V k--V j。
  • 推导技巧：递归函数的空通常是"参数的对称变换"。上一行是 (i, S[i][j])， 本行把第一参数从 i 换成 S[i][j]+1（跳过切点），第二参数保持 j。
  • 检验：if (i == j) return; 是递归出口——切到单点即返回，与 m[i][j] = 0 (i ≥ j) 的边界一致。
  • （1）见上方存疑说明：无论填在内外哪一层，语义都是"规模/下标增长到 N 为止"。

知识点：【科目二·试题四】动态规划——区间 DP（最优三角剖分），状态转移三件套 （状态定义 / 边界 / 递推式）见 ../subject2/patterns-algo-notes.md 二·2.2

【问题2】（7 分）设计策略与时空复杂度

答案（原文）：

  • （5）动态规划
  • （6）O(n³)（源记作 O（n3））
  • （7）O(n²)（源记作 O（n2））

丢分点解析：

  • （5）动态规划：题干已经把判定条件写全——"若在 Vk 处……得到一个最优的剖分方案， 则该最优剖分方案应该包含这两个子凸多边形的最优剖分方案"，即最优子结构； 加上重叠子问题（不同区间的最优值被反复引用）→ 动态规划。
  • 易错点：答成分治法或贪心。分治与 DP 的区别在于重叠子问题——本题主程序用 二维数组 m/S 自底向上记录所有子区间最优值（避免重复计算），这是 DP 的标志性写法。
  • （6）O(n³)：三重循环嵌套——r（规模，n 档）、i（左端点，≤n 档）、 k（剖分点，≤n 档）→ 最内层总执行次数为 O(n³)。
  • （7）O(n²)：两个 n×n 的二维数组 m[][] 和 S[][]（代码中 int m[N+1][N+1]、 int S[N+1][N+1]，各占 O(n²) 空间）→ 空间复杂度 O(n²)。
  • 易错点：把空间复杂度也写成 O(n³)——空间只看声明的数据结构规模，不看循环次数。

知识点：【科目二·试题四】算法策略判定 + 复杂度分析—— ../subject2/patterns-algo-notes.md 二·2.3（常考算法骨架清单·动态规划）+ 2.4
