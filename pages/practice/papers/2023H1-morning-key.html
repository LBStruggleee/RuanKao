二、逐题解析

计算机基础（第 1-6 题）

1. C｜【组成原理】系统总线 系统总线用于连接 CPU、主存及外设部件，是各部件间传输数据与控制信号的公共通道。B（运算器、控制器和寄存器）是 CPU 的组成部分，D（DMA/中断控制器）属外设管理部件，均不是总线"连接"的对象。

2. B｜【组成原理】存储体系 DMA 控制器与中断控制器直接与主存交换数据，发出的是主存物理地址。高速缓存对 CPU 透明（由硬件映射），虚拟地址由 CPU 经 MMU 产生，扇区地址属硬盘寻址，均与 DMA/中断控制器的数据传输无关。

⚠️ 题干"中断 CPU"原文如此，应为"中断控制器"（已在题目文件标注）。

3. C｜【组成原理】海明码 校验位 k 需满足 2^k − 1 ≥ n + k，n = 8：k=3 时 7 ≥ 11 不成立；k=4 时 15 ≥ 12 成立，故至少 4 位。

4. B｜【组成原理】中断 中断向量是中断服务程序的入口地址（中断向量表的内容）。A 是设备地址、C 是数据地址、D 是断点地址（现场保护的内容），均非中断向量。

5. D｜【组成原理】补码 补码零表示唯一（A 对）、减法可转加法（B 对）、符号位可参与运算（C 对）；但负数补码与真值的对应需"取反加 1"，并不简单直观，故 D 错误（本题选错误的叙述）。

6. C｜【组成原理】指令流水线 一条指令耗时 S = 2+2+1 = 5ns；流水段最长 2ns。n 条指令总时间 = S + 2×(n−1) = 5 + 2×999 = 2003ns。干扰项 2008ns（误用 5ns 为段长）易错。

网络与信息安全（第 7-11、66-70 题）

7. C｜【OSI 模型】 表示层负责数据格式转换、加解密与压缩。传输层管端到端可靠传输，会话层管会话建立与同步，应用层是用户接口。

8. D｜【HTTPS/PKI】 HTTPS 用非对称加密握手协商出会话密钥，再用对称加密加密后续 HTTP 消息（混合加密）。A/B 用公钥加密消息效率太低；C 方式正确但"公钥加密"描述错误。

9. C｜【HTTPS/PKI】 证书被吊销列入 CRL/OCSP 后，客户端验证证书合法性失败，无法再信任服务器。服务器仍可加解密与签名（A、B 错），客户端仍可发送信息（D 错）。

10. C｜【信息安全】入侵防御系统（IPS） IPS 自身即具备阻断能力，不需"联动 IDS 才阻断"——选项 C 描述的功能实际属于 IDS 的局限，故 C 不正确。A、B、D 均为 IPS 功能。

11. D｜【信息安全】Web 应用防火墙（WAF） WAF 防护 Web 应用层攻击：登录口令暴力破解（A）、恶意注册（B）、抢票机器人（C）均可防护。流氓软件驻留用户主机，需杀毒/反恶意软件处理，超出 WAF 防护范畴。

66. B｜【网络协议】WWW 万维网的控制协议是 HTTP。FTP 是文件传输，SSL 是加密协议（HTTPS = HTTP+SSL/TLS），DNS 是域名解析。

67. B｜【Linux】Web 服务器 Linux 上通常用 Apache 作 Web 服务器。IIS 是 Windows 的，NFS 是网络文件系统，MySQL 是数据库。

68. D｜【Linux】Apache 默认 Web 目录 按官方教程与原题（网络工程师 2018 年上半年第 31 题）答案为 /home/httpd。

⚠️ 答案PDF解析自相矛盾：先写"默认根目录为 /var/www/html 或 /var/www"，又写"站点主目录是 /home/httpd"。 考试按教程答案选 D。补充：现代 Apache 发行版（CentOS/RHEL 等）实际默认为 /var/www/html， /etc/httpd 是配置目录、/var/log/httpd 是日志目录（A、B 均非 Web 主目录）。

69. A｜【网络协议】SNMP SNMP 为应用层协议，其报文通过 UDP 传输（无连接、效率高）。TCP/IP/ICMP 均非其承载协议。

70. B｜【网络故障排查】 能上即时聊天（说明 IP、链路、网卡均正常）但打不开任何网页，是域名解析失效，即 DNS 配置错误。A/C/D 都会导致连聊天也断。

知识产权（第 12-14 题）

12. D｜【著作权】保护期 署名权（及修改权、保护作品完整权）的人身权保护期不受限制。发表权有期限（作者终生及死亡后 50 年），发行权、展览权属财产权也有期限。

13. C｜【软件保护】 国际上保护计算机软件知识产权的主要方式是实施版权法（以登记、授权、许可保护软件著作权）。合同法、物权法、刑法均非主要保护方式。

14. C｜【软件著作权】继承 软件著作权属自然人的，其死亡后在保护期内，继承人可继承除署名权外的其他各项权利——选项 C 称"继承所有权利"错误。A、B、D 均出自《计算机软件保护条例》。

软件工程（第 15-22、29-50 题）

15. C｜【数据流图】加工规格说明 加工规格说明须描述输入数据流到输出数据流的变换规则，应是高层次、抽象的规范，不给出实现细节（实现在程序设计中描述）。A、B、D 均正确。

16. C｜【软件设计原则】 好的设计原则包括模块化（A）、提高模块独立性（B）、提高抽象层次（D）。集中化不是好原则——集中设计易导致单点故障与性能瓶颈。

17. B｜【项目活动图】关键路径【存疑：图形复原】 关键路径 = 开始→C→E→H→J→K→结束，长度 = 6+6+4+5+2 = 23，故里程碑 E 在关键路径上（A、C、D 对应的 B、G、I 均不在最长路径上）。

复原边权：开始→A；A→B 5；A→C 6；B→D 3；B→E 3；C→E 6；C→F 3；D→G 3；D→H 5；E→H 4；E→I 1；F→I 4；G→K 4；H→J 5；I→J 2；J→K 2；K→结束。

18. D｜【项目活动图】关键路径长度 同上，关键路径长度 = 23。其余路径均小于 23（如经 B 的路径 5+3+5+5+2+… 明显更短）。

19. D｜【团队管理】沟通路径 n 人团队两两沟通路径数 = n(n−1)/2 = 8×7/2 = 28。64（误用 n²）、56（误用 n(n−1) 不除 2）、32 均错。

20. A｜【程序设计语言】短路计算 a or …：只要 a 为 true，整个表达式即确定为 true，右部不再计算——这正是短路。b/c/d 为 true 时表达式值仍需继续计算右部才能确定。

21. D｜【正规式】 (0|10)* 生成的串中，1 不能连续出现（每个 1 后必跟 0），0 可连续（00 合法），长度无奇偶约束（如 0、00、10 长度既有奇又有偶）。

22. B｜【参数传递】传值/传引用【存疑：图形复原】 hoo 第一参数传引用：x = x - 1 中 x 实为 a（引用），a 被改为 39；第二参数传值：hoo 内对 b 的修改不影响 foo 中 b，b 仍为 5。故输出 39, 5。

⚠️ 原卷"call by reerence"应为"reference"（已在题目文件标注）。

29. D｜【增量模型】 增量模型的优点是早交付可用产品（A）、早让用户熟悉（B）、高优先级功能多受测试（C）。但增量模型需预先规划功能并考虑扩展与兼容，设计并不更容易——D 不正确。

30. C｜【敏捷开发】 Scrum（并列争求法） 以约 30 天的迭代为"冲刺"，按需求优先级实现产品。XP 重工程实践，Crystal 重团队与交流，ASD 强调自适应调整。

31. C｜【模块耦合】 模块 A 用控制参数决定 B 执行哪部分语句，属控制耦合。数据耦合传数据值，标记耦合传数据结构，公共耦合共享全局数据区。

32. B｜【可移植性设计】 可移植性要求不使用特定环境的专用功能（B 与此相反，故 B 不属于该规则）。A、C、D（设备相关/无关分离、平台无关语言、不依赖平台类库）均为可移植性规则。

33. D｜【体系结构风格】管道—过滤器 管道—过滤器风格优点：构件高内聚低耦合（A）、支持复用（C）、支持并行执行（C 项）。它不适合交互处理应用（流式处理、无回溯），故 D 不正确。

34. B｜【白盒测试】路径覆盖【存疑：图形复原】 覆盖所有路径至少 4 个用例：① 判断1(N)→结束；② 判断1(Y)→判断2(N)→…；③ 判断1(Y)→判断2(Y)→判断3(N)→…；④ 判断1(Y)→判断2(Y)→判断3(Y)→回到判断1（循环路径）。

35. C｜【白盒测试】McCabe 复杂度【存疑：图形复原】 流程图有 3 个判定节点（判断1、2、3），McCabe 复杂度 V(G) = 判定节点数 + 1 = 3 + 1 = 4。

36. C｜【软件维护】 交付后为使用户界面更友好而改进图形输出，属改善性（完善性）维护。改正性修缺陷，适应性适应环境变化，预防性防患于未然。

37. A｜【面向对象】封装 学生的属性与操作均封装在学生对象中（数据+行为组合并隐藏实现细节）。

38. C｜【面向对象】消息 不同类的对象之间通过消息进行通信。继承是类间复用，多态是同一消息不同行为，重载是同名方法不同参数。

39. A｜【面向对象测试】层次 测试类中定义的每个方法属于算法层（最底层，针对算法/数据结构的单元测试）。类层、模板层非标准层次，系统层针对整个系统。

40. B｜【面向对象设计原则】 重用一个包中的某个类就要重用该包所有类，属共同重用原则（CRP）。共同封闭原则要求同包内变化方向一致，开放—封闭与接口分离是其它原则。

41. D｜【UML】序列图 序列图描述以时间顺序组织的对象之间的交互活动。A 是用例图，B 是对象图，C 是活动图。

42. C｜【UML 序列图】消息顺序【存疑：图形复原】 Loop[1..2] 内含消息 a、b，循环最少 1 次最多 2 次，先执行完循环内的 a、b，再执行最后的 c：即 a→b→a→b→c（循环 2 次后退出执行 c）。A/D 在 c 之后又执行循环内容（循环已结束），B 未执行循环。

43. B｜【UML】包图 包可拥有类、接口、构件、结点、协作、用例、图及嵌套包（A、C 对），包内同种元素不能重名（D 对）；但一个元素只能被一个包拥有（形成命名空间），故 B 不正确。

44. D｜【设计模式】原型模式【存疑：图形复原】 类图中 Resume 实现 Cloneable、声明 clone()，通过复制现有对象创建新对象（避免重复初始化代码、工作经历可不同）——这是原型（Prototype）模式。单例保证唯一实例，抽象工厂创建产品族，生成器分步构建复杂对象。

45. D｜【设计模式】分类 原型模式属创建型模式（与工厂、抽象工厂、生成器、单例同类）。

46. A｜【设计模式】策略模式 不同季节/节假日采用不同定价（多种可相互替换的算法），适合策略（Strategy）模式——把每种定价封装成独立策略对象。状态模式强调状态驱动行为改变，观察者强调依赖者被通知，命令模式把请求封装成对象。

47. D｜【设计模式】策略模式意图 策略模式意图：定义一系列算法，把它们封装起来并使它们可以相互替换。A 是命令模式，B 是观察者模式，C 是状态模式。

48. B｜【Python】type() Python 用 type() 获取对象类型（返回 <class 'int'> 等）。str() 转字符串，id() 返回对象唯一标识符，object() 是所有对象的基类。

49. D｜【Python】元组 (1, 2, 1, 2)（A）、1, 2, 1, 2（B，逗号即元组）、tuple()（C 空元组）均可；(1) 只是整数 1（括号当表达式用），单元素元组须写 (1,)，故 D 不能定义元组。

50. C｜【Python】语法 Python 没有 switch...case 语句（选择结构用 if...elif...else），故 C 不正确。A（for 迭代序列）、B（for/while 后可加 else）、D（支持嵌套循环）均正确。

操作系统（第 23-28 题）

数据库（第 51-56 题）

51. D｜【三级模式】 视图层（外模式）是最高抽象、逻辑层（模式）次之、物理层（内模式）最低——D 称"物理层比逻辑层更高"错误。

52. A｜【函数依赖】Armstrong 公理 自反律：若 Y ⊆ X ⊆ U，则 X→Y 为 F 蕴含（含 X→X）。B 是传递律，C 是分解律的变形，D 是合并律，均非自反律。

53. C｜【候选码】 F = {AB→C, CD→B}：D 不在任何函数依赖右部出现 → 必在候选码中；以 AB→C 出发，A、B 也不在右部 → ABD 是候选码；由 CD→B 出发，A、C、D 不在右部 → ACD 是候选码。共 2 个。

54. A｜【主属性】 ABD 与 ACD 的并集 = U = {A,B,C,D}，4 个属性均为主属性，非主属性 0 个。

55. B⚠️｜【SQL】授权 —— 分歧题 标准 SQL 授权语法：GRANT <权限> ON [TABLE] <对象> TO <用户> [WITH GRANT OPTION]。 题干模板为 GRANT （55） TABLE Students TO User1 （56），填 B「INSERT ON」 才能凑成 GRANT INSERT ON TABLE Students TO User1 …（语法完整）；若填 A「INSERT」则变成 GRANT INSERT TABLE Students …，缺少 ON，语法错误。

⚠️ 分歧说明：本地答案PDF标 (55)A，但其自身解题示例写的是 GRANT INSERT ON Students TO User1 WITH GRANT OPTION——INSERT 与 ON 连用，自相矛盾。 且本题是 2011 年下半年第 51、52 题逐字重复，该题官方答案为 B。 故本键册按 B，并在此显著标注；若以答案PDF为准记 A，请自行调整。

56. C｜【SQL】授权传递 允许 User1 将权限再授予他人，须加 WITH GRANT OPTION。FOR ALL、PUBLIC（授权给所有用户，非"允许转授"）、WITH CHECK OPTION（用于视图更新约束）均不合题意。

数据结构与算法（第 57-65 题）

57. C｜【栈】表达式求值 转后缀式：10 40 30 5 / - * 20 +。操作数栈最大深度：依次压入 10、40、30、5（4 个）才遇到第一个运算符 /，之后每算一次结果重新压入，深度不再增加。故容量至少为 4。

58. D｜【哈夫曼编码】 合法哈夫曼编码须满足 Kraft 等式 Σ 2^(−li) = 1（且哈夫曼树无度为 1 的结点、结点总数为奇数）： A：4×2⁻³ + 2⁻¹ = 0.5+0.5 = 1 ✓；B：2×2⁻⁴ + 2⁻³ + 2⁻² + 2⁻¹ = 1 ✓；C：3×2⁻² + 2×2⁻³ = 0.75+0.25 = 1 ✓； D：2×2⁻² + 3×2⁻³ = 0.5+0.375 = 0.875 ≠ 1 ✗（对应哈夫曼树会出现度为 1 的结点、结点数为偶数），故 D 不可能。

59. A｜【图的遍历】 邻接表存储下，BFS 每个顶点各入队/出队一次（O(n)），每条弧沿邻接表各访问一次（O(e)），总时间复杂度 O(n+e)。邻接矩阵存储才是 O(n²)。

60. C｜【折半查找】 折半查找每次将区间缩小一半，比较序列须与有序表的"折半路径"一致。C 序列 90→85→61→77→42：前三次已把 42 划在区间之外，第五次不可能再取到 42 作中点，故不可能。A、B、D 均可构造。

61. D｜【树/森林→二叉树】 森林转二叉树（左孩子右兄弟）：第一棵树 T1 为根，第二棵树 T2 挂在 T1 右侧，第三棵树 T3 挂在 T2 右侧——右子树包含第二、三棵树的全部结点 = n2 + n3。

62. D｜【排序】 要求 O(nlgn) 且稳定：归并排序（稳定、O(nlgn)）。直接插入 O(n²)，堆排序与快速排序不稳定。

63. B｜【排序】 要求 O(nlgn) 且空间 O(1)（原地）：堆排序（O(nlgn)、O(1)）。归并排序需 O(n) 辅助空间，快速排序最坏 O(n²)，直接插入 O(n²)。

64. C｜【算法策略】 Kruskal 每次选当前最短且不构成环的边，属贪心法。分治需分解-合并，动态规划用子问题最优值，回溯需搜索解空间。

65. A｜【最小生成树】【存疑：图形复原】 6 顶点需 5 条边。按权值升序选：AC(1) → DF(2) → BE(3) → CE(4) → CF(4)（此时 5 条边且无环），权值 = 1+2+3+4+4 = 14。

复原边权：AB 8；AC 1；AD 5；BC 5；CD 5；BE 3；CE 4；CF 4；DF 2；EF 9。

计算机英语（第 71-75 题）

主题：低代码（Low-code）/无代码（No-code）开发平台。

71. A｜【英语】可视化构建块 "通过可视化（visual）构建块（如拖放与下拉菜单界面）实现自动代码生成"——拖放/下拉界面即图形化操作。component-based（基于构件）、object-oriented（面向对象）、structural（结构化）均不指图形界面。

72. B｜【英语】指代关系 "这种自动化（automation）使用户专注于差异化部分而非编程的公分母"——this 指代上句的 automated code generation。

73. B｜【英语】无代码特点 "无代码采用完全不干预（hands-off）的方式，100% 依赖可视化工具"——与前文 low-code 的 handholding（手动干预）形成对比。generic（通用的）、labor-free（免费的/免劳动的）不合语境。

⚠️ 选项 A 原卷印为 "medern"，应为 "modern"（已在题目文件标注）。

74. B｜【英语】LCAP 特征 "IDE 具有 API、代码模板、可复用插件模块和图形连接器等内置（built-in）功能"——后文列举的均为平台自带功能。reusable（可复用的）只描述插件模块，不能统领 APIs/连接器；existed（存在的）非固定搭配。

⚠️ 选项 D 原卷印为 "well-konwn"，应为 "well-known"（已在题目文件标注）。

75. C｜【英语】最后一英里 "把精力重新投向开发（development）的最后一英里"——LCAP 自动化编码的通用部分，让专业开发者专注剩余的开发工作。delivery（交付）与"自动化编码"语境不完全对应。
