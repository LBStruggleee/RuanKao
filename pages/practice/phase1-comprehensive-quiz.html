Phase 1 综合测验：六科目混合 60 道选择题

测验范围：Phase 1 全部内容——操作系统（Day 1–3）10 题 + 计算机网络（Day 4–6）10 题 + 数据库（Day 7–8）10 题 + 计算机组成（Day 10–11）10 题 + 软件工程（Day 12–13）10 题 + 数据结构（Day 1 验证 / Day 14 补漏）10 题。 考试规则：计时 90 分钟，独立闭卷完成，每题 1 分，满分 60 分。 合格参照：科目一 75 题合格线为 45 分（60%），故本卷 36/60 为合格线；48/60 以上（80%）为 Phase 1 的冲刺目标（对应科目一 55+ 分的强度）。 做题纪律（分科切换节奏）： - OS / 组成 / 数据结构题：计算题必须打草稿（周转时间、地址转换、寻道、流水线、Cache、哈希 ASL），口算几乎必错； - 网络 / 软件工程题：概念题居多，凭记忆直接选，每题不超过 40 秒，把时间省给计算题； - 数据库题：SQL/范式题在草稿纸上逐步推导（候选码 → 主属性 → 范式），禁止"看一眼就选"。

完成后：对答案 → 按题号把对错填入「答题卡」→ 再把各科正确率填入文末「分科正确率统计表」与 knowledge-checklist.md 的「Phase 1 综合测验评分表」→ 任一科目正确率 < 60%（< 6/10）⇒ 该科知识点列入「二轮重点」（规则见 knowledge-checklist.md）。

1. B：阻塞态不能直接到执行态，必须先回就绪态排队，由调度程序选中后才能执行——这是五状态模型中最常考的非法转换判断。事件发生只是把进程"唤醒"到就绪，不等于"上 CPU"。

2. C：进程是资源分配的基本单位，线程是处理机调度的基本单位（固定考点）。同一进程内的线程共享地址空间、代码、数据、堆和打开的文件，但各自的栈与寄存器上下文是独享的。A、B、D 均正确。

3. B：SJF 按运行时间从短到长调度，顺序为 2 → 4 → 6 → 8。完成时间为 2、6、12、20；同时到达，周转时间 = 完成时间 − 0 = 2、6、12、20。平均周转 = (2+6+12+20) ÷ 4 = 10。必须画甘特图列时间轴，口算易排错顺序。

4. D：银行家算法在每次资源分配前检查系统是否处于安全状态，属于死锁避免（预防要破坏必要条件；检测是事后发现；鸵鸟策略是忽略）。

5. B：2 − 1（P）= 1；1 + 1（V）= 2；2 − 1（P）= 1；1 − 1（P）= 0；0 + 1（V）= 1。

6. C：页大小 4KB = 4096。页号 P = 5000 ÷ 4096 = 1（商），页内偏移 W = 5000 mod 4096 = 904。物理地址 = 块号 × 页大小 + W = 3 × 4096 + 904 = 12288 + 904 = 13192。（页式是"乘页大小"，段式才是"加段基址"——这是最常混的一对公式。）

7. C：TLB 命中时只需 1 次访存（取数据本身）——快表查找是硬件级操作，不计入访存次数。只有 TLB 未命中时，二级页表才需要 3 次（外层页表 + 内层页表 + 取数据）。

8. D：Belady 异常——分配的物理块数增加反而缺页次数增加——只出现在 FIFO。OPT、LRU、Clock 都不会出现，这是 FIFO 的标志性缺陷。

9. A：SSTF 每次选择离当前磁头最近的请求（必须逐段列出移动距离）： 53 → 65（12）→ 67（2）→ 37（30）→ 14（23）→ 98（84）→ 122（24）→ 124（2）→ 183（59）。 总距离 = 12+2+30+23+84+24+2+59 = 236。 注意 SSTF 会"折返跑"：67 之后最近的是 37（30）而不是 98（31），凭直觉往一个方向跑会算成 248 或 299。

10. B：一级索引的索引项数 = 块大小 ÷ 块号字节数 = 4KB ÷ 4B = 1024 项；每项指向一个 4KB 数据块 → 最大 = 1024 × 4KB = 4 MB。（对照记忆：一级 4MB / 二级 4GB / 三级 4TB。）

41. B：螺旋模型 = Boehm 1988 = 风险驱动，四象限/四活动顺序为制定计划 → 风险分析 → 实施工程 → 客户评估（客户评估是每圈收尾，不是起点）。瀑布 = 文档驱动；V 模型 = 开发测试对应；增量 = 分批交付可运行增量。

42. C：V 模型四对对应：需求 ↔ 验收、概要设计 ↔ 系统测试、详细设计 ↔ 集成测试、编码 ↔ 单元测试。最常见错误是把概设/详设与系统/集成配对颠倒。

43. A：敏捷四价值观的左项各不相同，不能串接：个体互动 > 流程工具；可工作软件 > 详尽文档；客户合作 > 合同谈判；响应变化 > 遵循计划。"可工作软件"的右项是详尽文档。

44. D：判别两步法——系统本身没错，是用户想要更多/更好 → 完善性维护（占比最大，约半数以上）。加新报表、导出 PDF 都是加新功能。适应性维护是"环境变了导致系统不适应"。

45. B：一句话"增量交产品，原型定需求"。增量模型每个增量都是可运行产品的一部分（累积成最终系统）；原型用于澄清/验证需求（抛弃型用完即弃）。两者都不是按规模划分的，故 A 错；C、D 与两模型的定义矛盾。

46. C：判别关键——传进去的值是"被处理的数据"（数据/标记耦合）还是"指挥对方怎么做的信号"（控制耦合）。控制标志决定 B 走哪段逻辑 → 控制耦合。若传的是整个记录 → 标记耦合；传简单参数 → 数据耦合。

47. A：有数据链（前元素输出是后元素输入）→ 顺序内聚；只按固定顺序执行而无数据链 → 过程内聚；通信内聚的判据是"使用同一输入或产生同一输出"。

48. D：强度顺序（由弱到强）：语句覆盖 < 判定覆盖 < 条件覆盖 < 判定-条件覆盖 < 条件组合覆盖 < 路径覆盖。注意判定在条件之前，且条件组合覆盖与路径覆盖互不包含（不能认为条件组合最强）。

49. B：V(G) = E − N + 2 = 12 − 9 + 2 = 5（别忘了 +2，漏了得 3）。交叉验算：判定节点数 = V(G) − 1 = 4。V(G) = 独立路径数 = 基本路径测试所需的最少测试用例数，故基本路径测试需要 5 个用例。

50. C：关键路径 = 从源点到汇点的最长路径，其长度 = 项目最短工期（不是最短路径！）。⚠️ 关键路径可能不止一条，缩短工期必须缩短所有关键路径共有的关键活动，故 B、D 错；A 把"最长"记成了"最短"。

51. A：先序首元 A 是根；中序中 A 左边 [D B E] 是左子树、右边 [C F] 是右子树。左子树先序 B D E：根 B，中序 D B E 中 B 左边 [D]、右边 [E] → B 的左孩子 D、右孩子 E。右子树先序 C F：根 C，中序 C F 中 C 左边空、右边 [F] → C 的右孩子 F。

        A
       / \
      B   C
     / \   \
    D   E   F

后序（左右根）= D E B F C A。

52. D：层序遍历用队列：出队即访问，其左右孩子依次入队。先/中/后序的非递归实现用栈。

53. C：重建二叉树必须包含中序（中序提供左右子树分界）。先序 + 后序不能唯一确定二叉树：例如 A(B,∅) 与 A(∅,B) 两棵不同的树，先序都是 AB、后序都是 BA。只有在"每个非叶子都有两个孩子"（真二叉树）时才唯一。

54. B：Dijkstra 不能处理负权边——其贪心正确性依赖"已加入集合 S 的顶点 dist 不会再被减小"，负权边可能违反该假设。处理负权要用 Bellman-Ford（O(VE)）。A、C、D 均正确。

55. A：Floyd 是全源（所有顶点对）最短路径算法，动态规划三重循环 O(V³)，可处理负权边但不能有负权回路。⚠️ 它的 k 循环必须在最外层，写成 for i for j for k 是错的。

56. D：Prim 从某顶点出发每次选"跨越已选/未选集合"的最小边，数组实现 O(V²)，适合稠密图；Kruskal 按边权排序依次选不成环的边（并查集判环），O(E log E)，适合稀疏图。两者都要求图连通，都保证求出最小生成树（故 A、B、C 错）。

57. C：拓扑排序（Kahn 算法）：每步选入度为 0 且尚未输出的顶点，删除其所有出边后继续。若输出顶点数少于顶点总数，说明图中有环。⚠️ AOV 网中顶点表示活动、边表示先后次序；AOE 网中边表示活动，两者别混。

58. B："最早看最长（max），最迟看最短（min）"：ve 从源点沿拓扑顺推、取所有前驱的 ve+w 的最大值；vl 从汇点（vl = ve）沿逆拓扑序推、取所有后继的 vl−w 的最小值。关键活动满足 l − e = 0。

59. A：不稳定排序 = 快、选、希、堆（口诀"快选希堆"）。冒泡、归并、基数都是稳定排序。本题 B、C、D 三项全部稳定。

60. D：12 mod 7 = 5 → 占位置 5；19 mod 7 = 5 冲突 → 下一空位 6；26 mod 7 = 5 冲突 → 5（占）→ 6（占）→ 0（空），占位置 0。查找 26 需比较 3 次（位置 5、6、0 各比较一次）。此时装填因子 α = 3/7 ≈ 0.43，改用链地址法则 12、19、26 同挂一条链，查找 26 仍需 3 次。
