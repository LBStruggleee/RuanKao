二、哈希：算出地址直接住进去

不想比较，想用关键字直接算出存储地址：H(key) = key mod p（除留余数法，p 取不大于表长的最大质数，让散布均匀）。两个 key 算出同一地址 = 冲突，处理办法三种：

方法做法要点
线性探测占了就往后挪一格（di = 1,2,3…）简单，但会堆积（连片占满，越堵越堵）
二次探测跳 1², −1², 2², −2²…跳跃式，缓解堆积
链地址同义词挂成一条链表本质就是 Lesson 0005 的链表；删除方便
装填因子 α = 元素数 ÷ 表长（越大越挤，冲突越多，ASL 越大）　　ASL(成功) = Σ每个元素的比较次数 ÷ 元素数

样例手算（背熟流程）

H(k) = k mod 7，表长 7，依次插入 16, 24, 9, 3（线性探测）：

16 → 16 mod 7 = 2（空 → 入格2，比较1次）；24 → 3（空 → 格3，1次）；9 → 2（被 16 占）→ 探 3（被 24 占）→ 探 4（入，3次）；3 → 3（占）→ 探 4（占）→ 探 5（入，3次）。

ASL(成功) = (1 + 1 + 3 + 3) ÷ 4 = 2；装填因子 α = 4/7 ≈ 0.57。

三、B 树与 B+ 树：放不进内存的「多路查找树」

数据量大到存在磁盘上时，二叉树每层都要读一次盘、树太深代价太高——于是把一个节点放宽成多路，树一下子变矮，读盘次数就少。m 阶 B 树三条硬规矩（概念题必背）：

  • 每节点最多 m 棵子树（最多 m−1 个关键字）；
  • 根节点至少 2 棵子树；非根非叶至少 ⌈m/2⌉ 棵子树（即 ⌈m/2⌉−1 个关键字）——3 阶 B 树 = 每节点 2~3 棵子树，就是「2-3 树」；
  • 所有叶子在同一层——绝对平衡，不存在 BST 那种退化。
对比点B 树B+ 树
子树数与关键字数n 棵子树 → n−1 个关键字n 棵子树 → n 个关键字
数据存哪所有节点都存关键字（和数据）非叶节点只当索引，记录全在叶子
叶子之间互不相连叶子链成有序链表 → 支持范围/顺序查询
典型应用文件系统索引数据库索引（InnoDB）

考法两句：「数据库索引用 B+ 树是因为叶子链表便于范围查询」→ 对；「m 阶 B 树所有叶子在同一层」→ 对（这是定义，不是巧合）。

五、自查（全对过课）

✅ 本课一页收获
  1. 折半 = 有序 + 顺序存储；最多比较 ⌊log₂n⌋ + 1 次（n=15→4，n=100→7，n=1023→10）。
  2. H(k)=k mod p，p = 不大于表长的最大质数；线性探测会堆积、二次探测跳跃、链地址挂链表。
  3. α = 元素数/表长，越大越挤；ASL(成功) = 比较次数总和 ÷ 元素数（样例表 = 2）。
  4. 判定树 = 折半过程的树形化，深度就是比较次数上限。
  5. B 树三条规矩：最多 m 棵子树、非根非叶至少 ⌈m/2⌉ 棵、叶子全同层；B+ 树三差异：n 子树 n 关键字、非叶只索引、叶子链成有序链表（数据库索引用它）。
