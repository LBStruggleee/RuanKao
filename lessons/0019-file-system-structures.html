文件系统：三种「租房方式」与索引的 4MB / 4GB / 4TB

对应原资料《操作系统③：文件系统与索引》· 模块：操作系统 · 文件管理 ｜ 预计 20 分钟
配套原资料：day03-disk.md §4–§7（只读，本课所有数字与其完全一致）

🎯 为什么是它 文件物理结构对比是上午卷每年必见的概念题；「索引块能管多大文件」和「读第 i 块要几次磁盘 I/O」是两个送分计算点——公式只有两条，但各有一个高频陷阱（索引块也算一次 I/O、块因子向下取整）。本课目标：把这两条公式变成本能。

一、最小必要知识

1. 逻辑结构（用户视角）与记录成组

逻辑结构与磁盘怎么存无关：流式文件 = 一串字节（Linux 普通文件）；记录式文件 = 若干逻辑记录（数据库文件）。把若干记录打包进一个物理块叫成组：

块因子 g = 物理块大小 ÷ 记录长度 （向下取整！）；碎片 = 块大小 − g × 记录长度

例：块 512 B、记录 80 B → g = 512÷80 = 6.4 → 6 条/块，用 480 B，碎片 32 B。放 7 条要 560 B > 512 B，放不下——g 必须向下取整。

2. 三种物理结构（磁盘视角，必背对比）

对比项连续分配链接分配索引分配
存放连续盘块分散 + 每块末尾「下一块指针」分散 + 一张索引表
FCB 存首块号 + 长度首块号指向索引块的指针
随机存取✅ 快（首块 + i）❌ 必须顺链遍历✅ 快（查索引表）
动态增长❌ 不便，外部碎片✅ 方便✅ 方便
典型CD-ROMFAText2/3/4、NTFS

记忆：连续 = 整租一套房（好找、搬家难）；链接 = 房东给你下一家的地址（好扩、要挨家找）；索引 = 房东有本通讯录（好找好扩、通讯录本身占地方）。

⚠ 三个高频陷阱 ① 连续分配产生外部碎片；② 链接分配不能随机存取（选择题最爱）；③ 索引分配既随机又好增长，代价是索引表占空间。

3. 索引计算：两条公式走天下

① 索引块项数 = 索引块大小 ÷ 块号字节数　② n 级索引容量 = 项数^n × 盘块大小
级数可管理块数最大文件（4 KB 块、4 B 块号，项数 1024 = 2¹⁰）
一级10241024 × 4 KB = 4 MB
二级1024²4 GB
三级1024³4 TB

规律：每多一级，容量 ×1024。4MB → 4GB → 4TB，一级跳一千倍。

混合索引（ext2 风格）读块 I/O 次数：10 直接 + 1 一级 + 1 二级 + 1 三级 ——

区域覆盖块号读数据需磁盘 I/O
直接（10 个）0 ~ 91 次
一级间接10 ~ 10332 次
二级间接1034 ~ 10496093 次
三级间接1049610 ~4 次

例（原资料 §6.4，必会）：访问逻辑地址 5 MB → 块号 1280 → 超过 1033，落在二级间接 → 读「一级索引块 + 二级索引块 + 数据块」= 3 次磁盘 I/O。索引块也要算一次磁盘读——这是本考点最高频的坑。

4. FAT、FCB/inode 与硬软链接（概念送分题）

  • FAT = 显式链接：把所有「下一块指针」集中成一张表（常驻内存）。表项 = 下一盘块号；0 = 空闲，−1 = 文件末块。FAT 是链接式，不是索引式，仍不支持真随机存取。
  • FCB：文件名 + 属性 + 物理地址在一起；inode：不含文件名（文件名在目录项里），同一 inode 可有多个文件名（硬链接）。
  • 硬链接 = 同一 inode 挂多个门牌：删原文件仍可访问、不能跨文件系统；软链接 = 存路径的纸条：删原文件即失效、可跨文件系统。

三、检索练习（先回忆，再作答）

✅ 本课一页收获
  1. 块因子 向下取整（512/80 → 6 条 + 32 B 碎片）；连续分配的块号 = 首块号 + i。
  2. 项数 = 块 ÷ 块号字节（4 KB/4 B → 1024）；容量 4MB / 4GB / 4TB 每级 ×1024。
  3. 混合索引 I/O：直接 1、一级 2、二级 3、三级 4 —— 索引块也算一次。FAT 表项存下一块号（0 空闲 / −1 末块）；inode 不含文件名；硬链接删原文件仍可用。
