一、两层楼对照：OSI 七层 vs TCP/IP 四层

先说为什么要分层。打个比方：你寄一个包裹，快递公司内部是分工的——打包的只管打包、分拣的只管分拣、开车的只管开车。每个环节只做自己那一件事，出问题也知道该找谁。网络传数据也一样：把「发数据」这件大事拆成几个环节，每个环节（层）只负责一件事，这就是分层模型。

这套「楼层图」有两个版本：OSI 画了 7 层（教科书版，分得细），TCP/IP 实际用 4 层（务实版，把细楼层合并了）。考试就爱考「某个协议住哪个版本的哪一层」。对应关系很简单：OSI 的上三层（应用、表示、会话）合起来 = TCP/IP 的应用层；OSI 的下两层（数据链路、物理）合起来 = TCP/IP 的网络接口层。看表：

OSI 七层TCP/IP 四层干什么（一句话）代表协议/设备
7 应用4 应用给用户软件用的接口HTTP/FTP/SMTP/DNS/Telnet/SNMP
6 表示格式转换、加密压缩（JPEG/加密在此概念层）
5 会话建立/管理/终止会话（RPC/SQL 会话概念）
4 传输3 传输端到端可靠/不可靠传输TCP / UDP（端口在这层）

⚠ 名字先对齐 表里 OSI 的「网络层」和 TCP/IP 的「网际层」是同一个楼层，只是两个版本叫法不同。后文两个名字会混用，不再区分——别以为是两层。

再看数据怎么「下楼」。打个比方：你写一封信（内容），装进信封写上门牌号，再套一层写上城市邮编，最后装进邮袋由货车运走——每过一道环节，就多包一层壳。网络里这叫封装：你的数据先加上 TCP 头（这时叫段），再加上 IP 头（叫包），再加上 MAC 头（叫帧），最后变成电信号（比特）发出去。收信人反向拆壳，一层层去掉头部，叫解封装。顺序：应用 → 传输(段) → 网际(包) → 链路(帧) → 物理(比特)。

二、归属总表（必背，按楼层背）

看表前先补一个词：端口号。一台电脑上同时跑着很多程序（浏览器、微信、游戏），数据到了电脑，该交给哪个程序？靠端口号——它就是同一台电脑上不同程序的「门牌号」（0–65535 号）。比如 80 号房间住着网站服务，25 号住着邮件服务。

层协议（全称顺一遍）记忆锚点
应用必背 5 个：HTTP 万维网 / FTP 20+21 文件 / SMTP 25 发邮件 / POP3 110 收邮件 / DNS 53 域名→IP
了解即可：Telnet 23 远程登录 / SNMP 161 网管 / DHCP 自动分配 IP / TFTP 简单文件		「上网收发找名字，远程网管自动配」

⚠ 三个高频陷阱 ① ARP 在网际层（不是应用层）——ARP 是干什么的？它把 IP 地址翻译成 MAC 地址（网卡号），这个翻译活儿是替 IP 打下手的，所以归网际层；② ICMP 在网络（网际）层——ping 这个命令是应用，但它底下跑的 ICMP 是报告差错的，归网际层；③ 端口号装在传输层 TCP/UDP 首部（不在 IP 头部——IP 头部只写 IP 地址）。

三、设备在几层（一个判断口诀）

先补两个地址概念：MAC 地址是网卡出厂时烙在芯片上的「身份证号」，全球唯一、终身不变；IP 地址则像「临时住址」，搬到哪儿变到哪儿。设备认哪个地址，就归哪层。生活场景帮你认设备：家里的路由器（连宽带、给手机分 IP 的那个盒子）认 IP，是网络层设备；楼道里的交换机（小区/公司把一堆网线插一起的那个铁盒子）只认 MAC，是数据链路层设备。

判断口诀——看设备「读到了哪一层地址」：只转发电信号 = 物理（中继器/Hub）；认 MAC = 数据链路（交换机/网桥）；认 IP = 网络（路由器）；还要管应用内容 = 网关/应用层防火墙。

四、自查（全对过课）

✅ 本课一页收获
  1. OSI 七层 ↔ TCP/IP 四层对照；发送封装、接收解封装。
  2. 应用层协议背端口号：FTP 21/SMTP 25/DNS 53/HTTP 80/HTTPS 443/Telnet 23/POP3 110/SNMP 161。
  3. 三个陷阱：ARP 网际层、ICMP 网络层、端口在传输层头部。
  4. 设备按「读到哪层地址」归层：Hub 物理、交换机链路、路由器网络。
