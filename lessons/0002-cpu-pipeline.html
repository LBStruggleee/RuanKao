一、CPU 里谁管什么（寄存器职责）

先给个框架：把 CPU 想成一间小工厂，里面分两个车间——控制器是「指挥的」（决定下一步干什么、去哪取指令），运算器是「干活的」（真正做加减乘除、比大小）。寄存器就是工厂里一个个贴了名字的小格子，每个格子只干一件事：

  • PC 程序计数器 = 书签：夹在程序这本「书」里，永远指着下一页（下一条指令在哪），读完一页自动翻到下一页（自动 +1）；遇到跳转指令就像「翻到第 50 页」，书签被改写。
  • IR 指令寄存器 = 正在读的那一行字：当前正在执行的指令本体就放在这里。配对记：PC 管地址、IR 管指令本体。
  • ACC 累加器 = 草稿纸：算术运算的中间结果先搁在这，比如加法的一个加数和得数都经过它。
  • PSW 状态字 = 考核板：记下这次运算的状态——进位了没？溢出了没？结果是零吗？（就是几个标志位）

次要点一笔带过：指令译码器负责「看懂」操作码（属于控制器）；MAR/MDR 是访问内存的「门牌」与「包裹」（送地址、收数据）。

部件职责考点一句话
PC 程序计数器存下一条指令的地址『自动 +1』指向下一条，转移指令改写它
IR 指令寄存器存当前正在执行的指令PC 管地址、IR 管指令本体
指令译码器解析操作码控制器的一部分
MAR / MDR存储器地址/数据寄存器访问内存的『门牌』与『包裹』
ALU + ACC + PSW算术逻辑运算、累加器、状态字（进位/溢出/零标志）运算器侧

指令执行三步：取指 → 译码（分析） → 执行。控制器 = PC/IR/译码器/时序；运算器 = ALU/ACC/PSW。

二、8 种寻址方式（有效地址公式表）

「寻址」掰开说：指令里写不下那么长的真实地址，只写一个「线索」——CPU 顺藤摸瓜找到操作数的过程叫寻址，「藤」的种类就是寻址方式。线索给得越直接越快（立即/直接寻址），越绕越慢（间接/变址）但换来灵活性。考点就是背下面这张「有效地址 EA」公式表。先看懂两个记号：① 带括号 = 间接一层——把括号里的值当作「地址」，再去内存取一次才拿到真正的数。比如 A=2000，内存 2000 号格子里放着 3000，3000 号格子里放着 55：EA=A 就是直接去 2000 号拿；EA=(A) 是先去 2000 号取出 3000，再去 3000 号拿 55——多跑一趟。② 访存 = 去内存取一次数，每访存一次就慢一点，所以表里「访存次数」就是速度排行的依据。

方式有效地址 EA特点/速度典型用途
立即寻址操作数就在指令里最快（不访存）常数赋值
直接寻址EA = A访存 1 次—
间接寻址EA = (A)访存 2 次以上，最慢—
寄存器寻址EA = Ri（操作数在寄存器）最快访问之一—
寄存器间接EA = (Ri)访存 1 次指针
基址寻址EA = 基址寄存器 + 偏移系统管理基址，程序不可改程序重定位/浮动（类比：程序搬家时只换基址寄存器这一个「门牌号基准」，代码一个字都不用改，整个程序就搬进新地址了）
变址寻址EA = 变址寄存器 + 形式地址用户可改变址数组循环遍历
相对寻址EA = PC + 偏移与位置无关转移指令
⚠ 高频辨析 基址 vs 变址：都是「寄存器 + 偏移」，区别在谁能改——基址寄存器由操作系统管理（程序浮动），变址寄存器由用户修改（数组下标）。

三、指令流水线（必考计算）

先打比方：流水线就像洗衣房——洗、烘、熨、叠四道工序。第一批衣服要走完全部工序才能拿出来，但第一批之后，每当洗完一批，烘也空出来了，所以每隔「最慢那道工序」的时间就能出一批。CPU 流水线同理：一条指令分成 k 段（k 道工序），n 条指令排着队过。

符号对号入座（记公式前先把字母认全）：

  • k = 流水线段数（工序数）
  • n = 指令条数（要洗多少批衣服）
  • Δt = 每一段花的时间（等长流水线里每道工序一样长）
  • Σti = 一条指令走完全部段的时间之和（ti 是第 i 段的时间，Σ 是「全部加起来」）
  • max(ti) = 最慢那一段的时间（瓶颈工序）

为什么 T = (k + n − 1)Δt：第 1 条指令要走完 k 段，花 kΔt；从它走出第 1 段开始，后面每 Δt 就有一条新指令进入流水线——所以第 1 条「铺管道」花了 kΔt，剩下 n−1 条每条只隔 Δt 出来：T = kΔt + (n−1)Δt = (k+n−1)Δt。

另外两个量怎么来的：加速比 S = 不用流水线的串行时间 ÷ 流水线时间（不流水线时每条指令都要完整走一遍 k 段，即 nkΔt），所以 S = nkΔt ÷ (k+n−1)Δt = nk/(k+n−1)；n→∞ 时 nk/(k+n−1)→k，意思是「流水线最多能快到段数那么倍」——段数就是天花板。吞吐率 TP = n / T（单位时间出多少条）。

等长 Δt，k 段 n 条：T = (k + n − 1)Δt　　加速比 S = nk / (k + n − 1)（极限 → k）
不等长各段 ti：T = Σti（首条） + (n − 1) × max(ti)　　吞吐率 TP = n / T

例（原资料 §4 原题）：4 段流水线，各段 10/15/20/10 ns，共 100 条指令：

先一步步看流水线怎么走（四段：取指 10ns → 译码 15ns → 执行 20ns → 写回 10ns）：

  • 第 1 条：10→25→45→55，即 55ns 走完全部 4 段（Σti = 10+15+20+10 = 55）。
  • 第 2 条：在第 20ns 进入第一段（等第一段空出来），之后 40→55→60→70 出来；第 3 条 35→…→85 出来……
  • 规律：从第 2 条起，每 20ns 出一条——20 就是最慢那段 max(ti)（瓶颈是执行段）。

所以：100 条 = 首条 55ns + 后面 99 条每条隔 20ns：
T = (10+15+20+10) + (100−1)×20 = 55 + 99×20 = 55 + 1980 = 2035 ns。

S 怎么算：分子是不流水线的串行总时间——不流水线时每条指令都要完整走 4 段共 55ns，100 条就是 100×55 = 5500ns；分母是流水线时间 2035ns：
S = 5500 ÷ 2035 ≈ 2.70。

TP 的单位换算别跳步：TP = 100 条 ÷ 2035ns = 0.0491 条/ns；1 秒 = 10⁹ ns，所以 0.0491×10⁹ = 4.91×10⁷ 条/秒（即 2035ns ≈ 2.035µs，每微秒出约 49.1 条）。

等长例：5 段 × Δt=1ns × 10 条 → T = (5+10−1)×1 = 14ns，S = nk/(k+n−1) = 50/14 ≈ 3.57。

CISC vs RISC：先解释两个词——微程序控制 = 把每条指令再拆成若干小步骤，交给一个内置的「小解释器」一步一步执行（灵活、好加新指令，但慢）；硬布线/组合逻辑 = 直接用电路连线把控制信号「焊死」出来（快，但指令定死了就不好改）。于是区别就好懂了：RISC = 指令定长、种类少、寻址方式少、寄存器多、以硬布线/组合逻辑为主——指令又简单又定长，正好一段一段排队过流水线，适合流水线；CISC = 指令变长、种类多、微程序控制——每条指令步数不一样，流水线没法整齐排队。

✅ 本课一页收获
  1. PC 存下一条指令地址、IR 存当前指令；控制器 vs 运算器各管一摊。
  2. 寻址：立即最快；间接最慢；基址=系统管理（浮动）、变址=用户改（数组）、相对=PC+偏移。

  4. RISC：定长、少种类、多寄存器、硬布线、宜流水线。
