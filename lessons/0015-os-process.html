一、进程：程序的一次“活的”执行

先回答最基础的疑问——进程和程序到底差在哪？打个比方：程序 = 菜谱（躺在磁盘上的死文件，谁都能拿去照着做）；进程 = 照着菜谱炒菜的整个过程（活物：正在占用锅碗、手上沾着油、炒到第几步都有记录）。同一本菜谱可以让三个人同时各炒各的——这就是一个程序对应多个进程。

另外记住一个词：阻塞 = 进程自己停下来等某件事发生（比如等用户敲键盘、等打印机打完）。等的事没发生，它就不动——后面状态图里会反复出现这个词。

  • PCB（进程控制块）是进程存在的唯一标志——相当于给炒菜过程建的一份「登记档案」：炒到哪一步了、用着哪些锅。创建进程 = 建 PCB，撤销 = 删 PCB。
  • 资源分配单位 = 进程，CPU 调度单位 = 线程。打个比方：进程是同一间厨房，线程是厨房里的多个厨师。菜谱和食材（代码/数据/堆/文件）是全厨房共享的；但每个厨师的手和刀必须各归各——栈和寄存器就是「正在算的现场」（算到哪一步、中间结果是多少），两个厨师共用一双手必然打架，所以线程独享栈与寄存器。（没见过「堆」「寄存器」没关系：堆=程序运行时临时放东西的大仓库，寄存器=CPU 手边放当前正在算的几个数的小抽屉，下节课细讲。）
  • 引入线程的目的：让同进程内多线程并发/并行（多个厨师同时开工），切换开销更小（在同一个厨房里换厨师，比搬去另一间厨房快得多）。

五状态模型（必背转换图）

一张图记五个状态怎么走：进程出生是「创建」，干完活是「终止」，中间在「就绪」（排队等 CPU）、「运行」（正在被 CPU 执行）、「阻塞」（停下来等某件事）之间转。

每条边单列成表（这就是全部合法转换，图里没有的线都是非法的）：

从 → 到什么时候发生
创建 → 就绪PCB 建好，进程排进就绪队列
就绪 → 运行被调度程序选中，拿到 CPU
运行 → 就绪时间片用完 / 被更高优先级抢占（还能跑，只是被换下来排队）
运行 → 阻塞等待 I/O / P 操作失败（要等一件事发生）
阻塞 → 就绪等的事发生了（I/O 完成 / V 唤醒）——注意只回到就绪排队，不能直接上 CPU
运行 → 终止进程干完活或被撤销
⚠ 两个高频判断 ① 阻塞 → 不能直接到运行，必须「阻塞 →（事件发生）→ 就绪 →（被调度）→ 运行」；② P 操作失败 → 阻塞，时间片用完 → 就绪（不是阻塞）。

二、进程调度算法（选择题四件套）

算法特点缺点
FCFS 先来先服务公平简单护航效应（一个超长作业排在前面，后面一堆小作业全被它拖住，像小轿车被大货车护航堵死）
SJF 短作业优先平均等待/周转时间最短长作业饥饿（一直排不上队——短作业源源不断地来，长作业永远轮不到）
RR 时间片轮转分时响应好时间片过大→退化为 FCFS；过小→切换开销大
多级反馈队列兼顾响应与吞吐实现复杂（仍防饥饿）
优先级紧急优先低优先级饥饿（可老化 aging 缓解：等得越久优先级慢慢涨，总有一天轮到它）

SJF 平均周转时间计算（动笔）：周转 = 完成 − 到达；带权周转 = 周转 ÷ 运行。例：作业 A(0 到达,跑3)、B(1,跑5)、C(2,跑2)。SJF 每次从「已到达、还没跑」的作业里挑最短的：

轮到谁到达开始完成周转 = 完成 − 到达
A（0 时刻只有它，先跑；跑 3）0033 − 0 = 3
C（3 时刻 A、B、C 都到了，C 最短 2，先跑）2355 − 2 = 3
B（只剩它，跑 5）151010 − 1 = 9

B 虽然最早（1 时刻）就到了，但每次都被更短的 C 插队——它一直等到 5 才开跑，10 才完成，这就是 SJF 对长作业的「饥饿」。平均周转 = (3 + 3 + 9) ÷ 3 = 5。

三、PV 操作与信号量（下午大题核心）

信号量 S 是一个带计数的门闸：P(S)：S−1，结果 < 0 则阻塞自己（门闸放不下人了，你排队等着）；V(S)：S+1，若有等待者则唤醒一个（放一个人进去）。P 是荷兰语 Passeren（通过），V 是 Vrijgeven（释放）——记住「P 减 V 加」。

看表前先认识两个词：临界资源 = 一次只能一个人用的东西（比如打印机，两个人同时用纸就乱了）；临界区 = 使用临界资源的那段代码（比如「发送到打印机」那几行）。

场景信号量设置要点
互斥（一个临界资源）mutex = 1P(mutex)…临界区…V(mutex)，成对出现（进门先 P、出门必 V）
生产者-消费者（缓冲区 n）mutex=1, empty=n, full=0
（empty = 数还剩几个空格子，初始 n 个全空；full = 数已有几个产品，初始 0 个；mutex 守缓冲区这扇门）		资源量 P 在互斥量 P 之前（顺序颠倒可能死锁）
读者-写者读读可并、写写互斥、读写互斥计数器 + 互斥保护计数器（第一个读者锁写、最后一个解锁）
哲学家进餐5 支筷子 = 5 个互斥量死锁经典：全员各拿一支等另一支 → 死锁；解法最多 4 人同时拿 / 奇数号先左后右、偶数号先右后左（破坏循环等待）

3.1 前驱图 → PV 代码（下午试题一的固定填空）

给一张前驱图（A→B、A→C、B→D、C→D 这种），要求补齐边上的 P/V——机械翻译四规则，不用理解也能填对：

  1. 每条边设一个信号量，初值 0（如 S1 对应 A→B，S2 对应 A→C…）；
  2. 边的起点：干完自己的活再 V 对应信号量——A 干完 → V(S1)、V(S2)；
  3. 边的终点：开干之前先 P 所有指向它的信号量——D 开干前 → P(S3)、P(S4)；
  4. 顺序不能反：先 P 后干活、干完才 V；一个节点被几条边指进来，就先 P 几个。

例：A→B，A→C，B→D，C→D（A 先行，B、C 并行，都完成后 D 才开始）：

信号量：S1(A→B) = S2(A→C) = S3(B→D) = S4(C→D) = 0

进程 A：            进程 B：          进程 C：          进程 D：
  A 的操作;           P(S1);            P(S2);            P(S3);
  V(S1);  V(S2);      B 的操作;         C 的操作;         P(S4);
                      V(S3);            V(S4);            D 的操作;

考法就是挖掉其中某个 P/V：数节点几条入边（几个 P）、几条出边（几个 V），对号入座即可。

四、动手：亲手把死锁“做”出来

💡 观察任务 先用正确顺序交替点生产和消费者，盯住 empty/full 此消彼长；缓冲区塞满后切到错误顺序模式再来一轮——亲眼看死锁怎么发生。「先 P 互斥量」的生产者握着锁睡去，消费者进不了临界区救它，两人永远等下去。

五、死锁：四个必要条件与银行家

死锁 = 几个进程互相等对方的资源，谁都动不了。比如两人吃饭：你拿一支筷子等我手里那支，我拿一支等你手里那支——谁也吃不成。

互斥 + 占有且等待 + 不可剥夺 + 循环等待（缺一不可，破坏其一即可预防）
  • 互斥：资源一次只能一个人用（筷子你用了我就不能用）；
  • 占有且等待：手里拿着筷子不放，还伸手要另一支；
  • 不可剥夺：不能从别人手里硬抢筷子，只能等他自己松手；
  • 循环等待：你等我、我等他、他等你，围成一个圈——只要有一个人先松手（先放下筷子），圈就破了。
策略做法例子
预防（静态）破坏四个条件之一一次性申请全部资源（坐下一开始就拿齐两支筷子）/ 资源有序分配
避免（动态）银行家算法：分配前判断安全状态安全序列存在才分配
检测资源分配图找环允许发生再处理
解除撤销进程 / 剥夺资源代价大，最后手段

银行家算法在干嘛？先给两个词一句话定义：安全序列 = 按某种顺序把资源分下去，每个进程都最终能拿到全部所需资源、跑完再还回来；安全状态 = 存在这样一条安全序列的状态。就像银行放贷：每次放款前先算一遍「假定这样贷出去，每个客户最终都能凑够本钱、完工还钱吗？」——只要存在一种顺序能全还上（安全），就敢放；算出来有人会永远凑不够（不安全），这笔就不贷。

迷你例子：系统还剩 3 台打印机。进程甲已占 1 台、还最多再要 2 台；进程乙已占 1 台、还最多再要 3 台。现在甲申请 2 台——批不批？

批给甲：剩 1 台。甲凑齐 3 台 → 跑完还回 3 台 → 剩 4 台 → 乙要 3 台也够 → 乙也能跑完。存在安全序列「甲→乙」，安全，批！

反过来，若只剩 2 台时乙先申请 3 台：批了剩 0 台，乙永远凑不齐（甲也在等），谁也跑不完——不安全，不批，让乙先等着。这就是「分配前判断安全状态」。

银行家 = 死锁「避免」——这四个概念怎么配对，选择题年年考。

六、自查（全对过课）

✅ 本课一页收获
  1. PCB = 唯一标志；资源分配 = 进程，调度 = 线程；线程独享栈与寄存器。
  2. 阻塞 → 不能直接运行；P 失败 → 阻塞；时间片到 → 就绪；SJF 平均等待最短但饥饿。
  3. 生产者-消费者：mutex=1, empty=n, full=0；资源量 P 在互斥量 P 之前；P 减 V 加。
  4. 死锁四条件缺一不可；银行家 = 死锁避免（预防=破坏条件、检测=找环、解除=撤销）。
