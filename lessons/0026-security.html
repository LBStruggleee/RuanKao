一、对称加密 vs 非对称加密

对称加密非对称加密
密钥加密解密同一把钥匙公钥加密、私钥解密（成对）
代表DES（56 位有效密钥/64 分组）、3DES（168）、AES（分组固定 128，密钥 128/192/256 → 轮数 10/12/14）、IDEA、RC4RSA（基于大整数分解）、ECC（椭圆曲线离散对数）、DSA
优/劣快，适合大量数据；密钥分发难（n 人两两需 n(n−1)/2 把）密钥分发简单（公钥公开）；慢，适合小数据/密钥交换

先把表格里的行话掰开。「密钥分发难」是什么意思？对称加密两个人必须拿到同一把钥匙——就像你和朋友共用一个密码本，可密码本怎么寄过去？路上会被偷，被偷了对方就能解开你们所有的信。人一多更糟：钥匙必须两两配对。手算一遍 n=3：甲-乙、甲-丙、乙-丙，每两个人共享一把，共 3×(3−1)/2 = 3 把；n=100 就是 100×99/2 = 4950 把——分发和保管都是灾难。

非对称加密怎么破这个局？一句话：密码本随便寄、锁钥匙留家里。公钥（挂在外面的锁）发给谁都行，被偷也无所谓；私钥（开锁的钥匙）永远不出门。所以分发简单，代价是算法慢。

再看代表算法里那句行话。RSA「基于大整数分解」：把两个大素数乘起来一瞬间就算完（容易），但拿到乘积想拆回去算到天荒地老也算不完（难）——世界上的计算机算不完，这就是安全性的来源。ECC「椭圆曲线离散对数」同理，也是数学上的单向难题，记名字即可。IDEA、RC4 也是对称算法，知道名字是「对称阵营」即可。

「分组」「有效密钥」「轮数」是什么？分组＝每次加密的一块数据多长（DES 每次嚼 64 位一块）；轮数＝把这块数据反复搅几遍——搅的遍数越多越难还原，所以密钥越长、搅的遍数越多、越安全。AES 密钥 128/192/256 位，对应轮数 10/12/14 遍：密钥长 64 位，就多搅 2 遍——10/12/14 从死数字变成有逻辑的对应。DES 名义密钥 64 位，其中 8 位是校验位（用来查错的），真正干活的有效密钥只剩 56 位——这就是「56/64」两个数字的来历。

二、五层楼：从摘要到加密

先给每层一个生活类比，再看术语：

  1. 数字摘要——像行李过秤出的重量单：行李多少公斤，秤只吐一个数字，从数字还原不出行李。对报文做 Hash 得固定长度指纹——MD5 128 位、SHA-1 160 位、SHA-256 256 位；保证完整性（防篡改）：报文改一个字，指纹就完全变样，但指纹本身藏不住也还原不出原文。
  2. 数字签名——像盖了章的合同：章只有你有，盖上去就赖不掉。发方用自己的私钥对摘要「盖章」，收方用发方的公钥验章：公钥人人可得，谁都能拿它验出「这章真是不是他盖的、内容改没改」。为什么不保密？——验得出真假，但藏不住内容（公钥谁都拿得到，等于公告栏里的章样）。所以签名保证完整性 + 不可否认性（发方抵赖不了），不保密！
  3. 数字证书（CA）——像派出所给公章做的备案：你说「这章是我的」没用，得有权威机构盖官方章担保。骗子场景：黑客宣称「我发的公钥是银行的」，你一加密，钱就进了他的锁。CA（网上公证处）用自己的私钥签发证书，担保「这把公钥真的属于银行」。和上一层对比：签名盖在报文摘要上，证书盖在公钥上。
    收方拿到证书后怎么验真伪？和验普通签名一个路子：用CA 的公钥去验证书上的章。那 CA 的公钥从哪来？浏览器和操作系统出厂时就内置了一批知名 CA 的公钥（信任链的起点，不用联网取、也没人能半路换掉）。骗子为什么伪造不了？骗子可以自己印一张假证书，但「CA 的章」要用 CA 的私钥才盖得出来——私钥在 CA 手里从不出门，骗子手里只有公钥，盖不出这个章；他用自己的私钥盖个假章，浏览器一拿内置的 CA 公钥去验，立刻穿帮。这就好比骗子能模仿奖状的花纹，却造不出教育局那枚备案公章。
  4. 数字信封——像用保险箱寄钥匙：货（数据）用普通锁锁好（对称加密，快），开货的钥匙放进只有对方能打开的保险箱（对方公钥加密）。数据用对称密钥加密（快），对称密钥再用对方公钥加密（安全分发）——两者结合，HTTPS 的思路。
  5. 加密体系——五层楼的落地：HTTPS = 在 HTTP 下面垫了 SSL/TLS 这层保险。SSL/TLS 就是干「数字信封」这件事的协议：先用证书验明对方身份（第 3 层），再协商对称密钥加密数据（第 4 层）。「443」是它的默认端口号（普通 HTTP 是 80）。

把「摘要→签名」两步走一遍（发方甲、收方乙）：

  1. 甲写好合同，先过秤出重量单（算摘要）；
  2. 甲在重量单上盖自己的章（私钥加密摘要）；
  3. 甲把「合同 + 盖章的重量单」一起发出去；
  4. 坏人半路把合同金额从 1 万改成 10 万；
  5. 乙收到后：自己给合同再过一次秤（重算摘要），再用甲的公钥验章——验出来的单子还是「1 万」，和手上这份「10 万」对不上，一验就穿帮。
⚠ 最高频陷阱 数字签名：发方私钥签、发方公钥验（验的是身份）；数据加密：收方公钥加、收方私钥解（保的是机密）。两把钥匙别接反。

三、攻击与防护配对

先看一个最经典的攻击怎么发生。SQL 注入：网站登录时后台会拼一句「用户名 = 你填的，密码 = 你填的」去数据库核对。坏人在输入框里填 ' or '1'='1——注意开头那个单引号是关键：后台拼句子时，你的输入本来会被塞进一对引号中间，变成「密码 = '你填的」；现在你填的内容自己带了一个引号，就提前把引号截断了——前半句变成「密码 = 空」（两个引号贴在一起，中间什么都没有，即空字符串），后半句的 or '1'='1 则混成了 SQL 指令的一部分。于是整句条件变成「密码 = 空 或者 1=1」，而 1 永远等于 1，条件永远成立，密码就绕过去了。防御「参数化查询」就是不让你填的内容混进指令本身：你填什么，都只当数据，不当命令。

再看两个脚本类攻击的场景：XSS（坏人把一段脚本藏进留言板，别人一看这条留言，脚本就在他的浏览器里偷 cookie——防御「输出转义」是让脚本只显示成文字、不执行，「CSP」是浏览器的一道白名单，规定页面只准加载哪些来源的脚本）；CSRF（你登录着购物网站没退出，坏人在别的网页里偷偷用你已登录的身份向购物网站发一个下单请求——防御「Token 校验」是要求请求里带一个坏人拿不到的暗号，「Referer」是请求头里标明「从哪个页面发来的」，网站一看来源不对就拒绝）。

攻击手法防御
SQL 注入输入框拼接 SQL 语句（如 ' or '1'='1 绕过密码）参数化查询/过滤输入
XSS 跨站脚本把脚本藏进页面（如留言板），访客浏览器替他执行输出转义/CSP（脚本白名单）
CSRF 跨站请求伪造盗用你已登录的会话（登录状态）冒充你发请求Token 校验/验证 Referer（请求来源）
DDoS控制大量傀儡机（被黑的肉鸡）一起洪泛（几万台机器同时疯狂发请求，把服务器门口堵死、资源耗尽），耗尽资源流量清洗（专业设备把恶意流量洗掉再放行）/CDN 分流
重放攻击截获合法报文，过段时间原样重发时间戳/一次性令牌/序列号

四、恶意代码分类（选择题常客）

五类恶意代码各给一个场景：病毒＝附着在正常程序上的寄生虫，你双击运行那个程序它才活过来；蠕虫＝不用寄生、自己就在网络里爬的虫，只要网里有一台机器有漏洞，它自己钻进去再扩散；木马＝伪装成免费软件/外挂的窃贼，你以为是工具，装上后它开后门把你的信息往外送；逻辑炸弹＝平时安静潜伏、等条件的定时破坏装置，比如埋在公司系统里「我被开除那天生效」；后门＝绕过正常登录检查的秘密通道。

类型特征一句话考点钩子
计算机病毒寄生在宿主程序中，用户运行宿主时激活需要宿主、可自我复制
蠕虫（Worm）独立程序，主动利用漏洞在网络自我传播不需要宿主（与病毒的本质区别）
木马（Trojan）伪装成有用软件，开后门盗信息，不自我复制伪装 + 远程控制
逻辑炸弹满足特定条件（日期/事件）时才触发破坏潜伏触发条件
后门（陷门）绕过正常认证进入系统的秘密通道绕过访问控制

五类怎么区分？三个问题收口：①看宿主——病毒要、蠕虫不要；②看复制——病毒、蠕虫会自我复制，木马不会；③看目的——木马偷信息，逻辑炸弹搞破坏。逻辑炸弹和病毒、木马的差别：它既不复制也不伪装，只等条件触发。

⚠ 高频判断 「蠕虫需要宿主程序」——错（蠕虫独立传播，病毒才需要宿主）；「木马能自我复制」——错（木马不复制，蠕虫才复制）。

五、防火墙与 IDS/IPS

先补一句类比再进表格。这里的「网络层」指只看信封地址（IP/端口），「应用层」指拆开信看内容。三类防火墙：包过滤 = 门卫只看胸牌（IP/端口对不对就放行，快但粗）；应用级网关 = 安检员开包逐件查（内容一条条检查，细但慢）；状态检测 = 记住「这个连接是不是我们自己发起的」，只放行正常来回，折中、主流。

IDS 和 IPS 的区别用两个东西记：IDS = 监控摄像头——挂在旁边看，看到贼只报警，拦不住（旁路监听）；IPS = 闸机——必须拦在通道上（串联部署），过的人都要被它检查一遍，发现贼直接丢包阻断。为什么 IPS 必须串在链路上？因为不挡在通道中间，包就不经过它，它根本没机会拦——摄像头再聪明也拦不住人，闸机才行。

设备原理位置/特点
包过滤防火墙网络层查 IP/端口规则（门卫看胸牌）快、粒度粗
应用级网关（代理）应用层逐条检查内容（安检员开包）细、慢
状态检测跟踪连接状态动态放行折中，主流
IDS 入侵检测旁路监听、发现报警（摄像头，只喊不打）不能阻断
IPS 入侵防御串联部署、直接阻断（闸机，又喊又打）必须拦在链路上才能丢包

VPN：在公共网络上挖一条只有你们俩能读的加密隧道——别人看得见有车过，看不见拉的什么货。IPSec 是实现 VPN 的协议族，两个部件一张小表：

概念大白话
ESP既锁箱子又贴封条：加密 + 认证（藏住内容，还验得出没被改、没被冒充）
AH只贴封条不锁箱：只认证不加密（验得出真假，内容裸奔）
传输模式只护载荷：一个 IP 包 = 信封（原 IP 头，写地址）+ 信纸（里面的数据）。「载荷」就是信纸——拆掉信封后真正要送的那部分内容。传输模式只给信纸套护套，信封地址原样不动，两台主机直接点到点护送
隧道模式护整包（连信封带信纸整个套一层新信封）

六、自查（全对过课）

✅ 本课一页收获
  1. 对称快（DES 56/3DES 168/AES 128 分组，轮数 10/12/14）、非对称分发易（RSA/ECC）。
  2. 摘要 MD5 128/SHA-1 160；签名 = 发方私钥（不可否认），加密 = 收方公钥（机密）；数字信封 = 对称加密数据 + 公钥加密密钥。
  3. 重放 → 时间戳/一次性令牌；XSS 转义、CSRF Token。
  4. IDS 旁路报警、IPS 串联阻断；防火墙三类：包过滤/应用网关/状态检测。
