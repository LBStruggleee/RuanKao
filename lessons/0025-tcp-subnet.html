一、TCP vs UDP（一句话分家）

TCPUDP
连接面向连接（三次握手建立）无连接，发完就算
可靠性可靠（确认重传、排序、流量/拥塞控制）不可靠（可能丢、乱序）
速度/开销慢、头部 20 字节起快、头部 8 字节
场景网页 HTTP、邮件、文件传输DNS 查询、视频直播、语音
🎬 像素小剧场 先看约 17 秒动画：SYN / SYN+ACK / ACK 三次握手把连接建立起来，传几包数据后 FIN / ACK / FIN / ACK 四次挥手断开——主机下方的状态芯片实时切换，状态名看着动画背。

二、三次握手 / 四次挥手（状态名必背）

状态是什么：TCP 连接从建立到断开，双方各自像一个有「进度条」的人——每个阶段都有一个状态名。考试就考「谁在什么时候进入哪个状态」，所以下面按步骤走一遍，状态名旁边都配了人话。

三次握手（建立连接），逐步看：

  1. 第 1 步：客户端发出 SYN（连接请求，相当于「我想跟你通话」）。
    → 发完客户端进入 SYN_SENT（= 我发出连接请求了，在等对方回应）；服务端收到后进入 SYN_RCVD（= 收到请求了，我也回一个表示同意）。
  2. 第 2 步：服务端回 SYN+ACK（= 同意，且我也想确认你能收到我说话）。
  3. 第 3 步：客户端回 ACK（= 收到！）。
    → 服务端收到后，双方都进入 ESTABLISHED（= 通话正式接通，可以传数据了）。

四次挥手（断开连接），逐步看（假设客户端先挂电话，主动方 = 客户端）：

  1. 第 1 步：主动方发出 FIN（= 我说完了）。→ 发完进入 FIN_WAIT_1（= 我关了我这边，在等对方确认）。
  2. 第 2 步：被动方回 ACK。→ 被动方进入 CLOSE_WAIT（= 对方说完了，我这边可能还有话没说完）。
  3. 第 3 步：被动方数据发完后也发 FIN。→ 被动方进入 LAST_ACK（= 我也说完了，等最后一次确认）。
  4. 第 4 步：主动方回 ACK。→ 主动方进入 TIME_WAIT（= 等一会儿再彻底挂断，见下面 2MSL），最终 CLOSED。
  • 为什么三次：双方都确认「我能发你能收」；两次会导致失效的连接请求突然到达造成资源浪费。
  • 为什么四次：关闭是两个方向各关一次（半关闭）。
  • TIME_WAIT 等什么？等 2MSL：MSL = 报文在网络里存活的最长时间（Maximum Segment Lifetime，比如设为 30 秒）。2MSL = 一来一回都等完——主动方最后那个 ACK 万一在路上丢了，对方重发的 FIN 还能赶到，本方来得及重发 ACK；同时等满 2MSL，旧连接的残留报文也彻底在网络里消亡，不会串到新连接里。

先分清两件事：流量控制管「对方」（别淹没接收方），拥塞控制管「网络」（别压垮路由器）。

  • 流量控制 = 滑动窗口：接收方每次回 ACK 时都附带一个窗口值（= 我缓冲区还剩多少地方），发送方发出去但没确认的数据量不许超过它。

拥塞控制先记两个名词：

  • cwnd（拥塞窗口）= 发送方当前敢往网络里发多少（全靠猜网络堵不堵，猜得保守就发得少）；
  • ssthresh（门限值）= 慢开始和拥塞避免的切换线：cwnd 低于它就指数猛涨（慢开始），涨到它就改成一次加 1 慢慢试探（拥塞避免）。

出问题时两种处理，对比着记：

① 超时（收不到任何 ACK）② 收到 3 个重复 ACK
网络状况严重拥塞（包全丢了）轻度拥塞（只丢了一包，后面的还在到）
处理ssthresh = 当前 cwnd 的一半；cwnd 重回 1，重新慢开始快重传：不等超时立刻重发丢失的包；快恢复：ssthresh 减半，cwnd 从新 ssthresh 起线性加 1
数字小例cwnd=16 超时 → ssthresh=8，cwnd=1 从头慢开始cwnd=16 收到 3 个重复 ACK → ssthresh=8，cwnd 从 8 起线性加 1（不归 1，因为网络还没全瘫）

三、子网划分 5 步法（必考计算）

「网段」掰开说：一个网段 = 一组「前半截门牌号相同」的 IP 集合，同网段内的设备可以直接互喊（不经过路由器）。掩码就是那条「前半截/后半截」的分界线——掩码 1 的位数定门牌号占多长；判断两个 IP 是否同网段：按掩码一遮，网络位完全一样就是同网段。

先补地基：有类地址与默认掩码（子网划分就是把有类地址再切细）。IP 32 位 = 网络位 + 主机位，首几位定类：

类首段范围默认掩码网络位/主机位用途
A1 ~ 126255.0.0.0（/8）8 / 24超大网络
B128 ~ 191255.255.0.0（/16）16 / 16大网络
C192 ~ 223255.255.255.0（/24）24 / 8小网络（常见考点）
  • 判类口诀：看首段数字——1~126 是 A、128~191 是 B、192~223 是 C。为什么只看这三段？单播 = 一对一的普通地址（一台电脑发给另一台），A/B/C 三类就是干这个的；而 224~239 是 D 类（组播）= 一对多（一台机器同时发给一组人，如视频会议），240 以上是 E 类 = 保留做实验用，都不发给普通设备；0 开头则表示「本网络」也有特殊用途——所以判类只看 A/B/C 三段，127 单独留给环回测试；
  • 私有地址段（必背）：A 类 10.0.0.0/8、B 类 172.16.0.0 ~ 172.31.255.255（/12）、C 类 192.168.0.0/16——不进公网路由；
  • 特殊地址：127.x.x.x 环回测试；主机位全 0 = 网络地址、全 1 = 广播地址（这就是可用主机 −2 的原因）；
  • 掩码里连续 1 = 网络位、连续 0 = 主机位——子网掩码本身不是 IP，它只标「哪段是门牌号、哪段是房间号」。

5 步法的原理先说一句：掩码末字节（掩码最后一个不为 0 的那个字节）把 0~255 这 256 个数整块一分为几——一个字节最多装 0~255 共 256 个数，掩码值占了开头一段，剩下的就是每块的大小，所以 块大小 = 256 − 掩码末字节值。「按块取整段起点」就是：从 0 开始，每跳一块大小数一次，看 IP 落在哪一块的开头。另外，第⑤步的 2^(32−n) − 2 和按块算是同一件事的两种算法：n 是网络位个数，主机位个数 = 32 − n，主机位有几位就有 2 的几次方个地址，再去掉网络地址和广播地址两个。

①掩码 /n → ②块大小 = 256 − 掩码末字节值 → ③网络地址 = IP 按块取整段起点
④广播地址 = 下一网络地址 − 1 → ⑤可用主机数 = 2^(32−n) − 2（主机位 = 32−n 个）

例 1：192.168.1.130 /26（掩码 255.255.255.192）：

块大小 = 256−192 = 64 → 段起点：0, 64, 128, 192 → 130 落在 128–191 段 → 网络地址 192.168.1.128，广播 192.168.1.191，可用主机 2⁶−2 = 62。

例 2：172.16.55.200 /20（掩码 255.255.240.0）：第三字节块 = 256−240 = 16 → 段 48–63 → 网络 172.16.48.0，广播 172.16.63.255，主机 2¹²−2 = 4094。

⚠ 三个陷阱 ① 可用主机数要 −2（网络地址 + 广播地址不可用）；② CIDR 聚合：先说人话——把 4 个连续的小网段合并成 1 个大网段对外宣告，就叫聚合（路由表里 4 行变 1 行）。为什么前缀要往左退 2 位？4 = 2²，每个 /24 占 24 位网络位，4 个连续的 /24 拼起来多的正好是 2 个主机位，所以网络位 24 − 2 = 22，即 /24 → /22（可想象 4 个小方块拼成 1 个大方块，边长扩大 2 倍）；③ 同一子网判断 = 网络地址相同（按最长掩码算）。

✅ 本课一页收获
  1. TCP 面向连接可靠（HTTP/邮件）、UDP 无连接快（DNS/直播）；握手 SYN_SENT→SYN_RCVD→ESTABLISHED。
