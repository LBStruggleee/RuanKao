TCP 与子网划分：三次握手 + 必考计算

课程总目录 ｜ 预计 40 分钟 ｜ 上一课：0024 分层模型
考点定位：三次握手/四次挥手状态、TCP vs UDP、子网划分 5 步法（必考计算，day05 有 8 道计算题）

🎯 这课的赢面 子网划分是网络板块计算量最大的必考点：5 步法（掩码→块大小→网络地址→广播地址→主机数）刷熟后 90 秒一题。TCP 三次握手/四次挥手的状态名则是送分概念题。

一、TCP vs UDP（一句话分家）

TCPUDP
连接面向连接（三次握手建立）无连接，发完就算
可靠性可靠（确认重传、排序、流量/拥塞控制）不可靠（可能丢、乱序）
速度/开销慢、头部 20 字节起快、头部 8 字节
场景网页 HTTP、邮件、文件传输DNS 查询、视频直播、语音
🎬 像素小剧场 先看约 17 秒动画：SYN / SYN+ACK / ACK 三次握手把连接建立起来，传几包数据后 FIN / ACK / FIN / ACK 四次挥手断开——主机下方的状态芯片实时切换，状态名看着动画背。

二、三次握手 / 四次挥手（状态名必背）

三次握手（建立）：                       四次挥手（释放）：
客户端 SYN ──→ 服务端    [SYN_SENT]      主动方 FIN ──→          [FIN_WAIT_1]
     ←── SYN+ACK         [SYN_RCVD]           ←── ACK            [CLOSE_WAIT→LAST_ACK]
客户端 ACK ──→           [ESTABLISHED]        ←── FIN
                                              ACK ──→            [TIME_WAIT→CLOSED]
  双方进入 ESTABLISHED                  等待 2MSL 后 CLOSED（确保最后 ACK 达到）
  • 为什么三次：双方都确认「我能发你能收」；两次会导致失效的连接请求突然到达造成资源浪费。
  • 为什么四次：关闭是两个方向各关一次（半关闭）。
  • TIME_WAIT 等 2MSL：保证最后的 ACK 能重发、旧报文消亡。

流量控制 = 滑动窗口（接收方通告窗口）；拥塞控制四招：慢开始（指数增）→ 拥塞避免（线性加 1）→ 超时则 ssthresh=当前一半、cwnd 重回 1；快重传（3 个重复 ACK）+ 快恢复。

三、子网划分 5 步法（必考计算）

①掩码 /n → ②块大小 = 256 − 掩码末字节值 → ③网络地址 = IP 按块取整段起点
④广播地址 = 下一网络地址 − 1 → ⑤可用主机数 = 2^(32−n) − 2

例 1：192.168.1.130 /26（掩码 255.255.255.192）：

块大小 = 256−192 = 64 → 段起点：0, 64, 128, 192 → 130 落在 128–191 段 → 网络地址 192.168.1.128，广播 192.168.1.191，可用主机 2⁶−2 = 62。

例 2：172.16.55.200 /20（掩码 255.255.240.0）：第三字节块 = 256−240 = 16 → 段 48–63 → 网络 172.16.48.0，广播 172.16.63.255，主机 2¹²−2 = 4094。

⚠ 三个陷阱 ① 可用主机数要 −2（网络地址 + 广播地址不可用）；② CIDR 聚合：4 个连续 /24 聚合成一个 /22（往左退 2 位）；③ 同一子网判断 = 网络地址相同（按最长掩码算）。

✅ 本课一页收获
  1. TCP 面向连接可靠（HTTP/邮件）、UDP 无连接快（DNS/直播）；握手 SYN_SENT→SYN_RCVD→ESTABLISHED。
  2. TIME_WAIT 等 2MSL；拥塞控制：慢开始指数、拥塞避免线性、超时减半 ssthresh、快重传 3 重复 ACK。
  3. 子网 5 步法：掩码 → 块 256−末字节 → 网络 → 广播 → 主机 2^(32−n)−2。
  4. /26 → 62 主机；/20 → 4094；4×/24 → /22。
