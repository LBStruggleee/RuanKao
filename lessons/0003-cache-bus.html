Cache 与总线：命中率计算 + 三种映射

课程总目录 ｜ 预计 40 分钟 ｜ 上一课：0002 CPU 与流水线
考点定位：命中率/平均访问时间/加速比（必考计算）、三种映射的地址拆分、总线带宽（day11-cache.md）

🎯 这课的赢面 一组公式通吃 Cache 计算题：ta = h×tc + (1−h)×tm；S = tm/ta；e = tc/ta。再加三种映射的「地址怎么切」（Tag | 行号/组号 | 块内偏移），和总线带宽 = 频率×宽度÷8。

一、存储层次与局部性

寄存器 → Cache → 主存 → 辅存：越往上越快越贵越小。Cache 有效的前提是局部性原理：刚用过的很快再用（时间局部性）、相邻的马上要用（空间局部性）。

二、命中率计算（一组公式通吃）

平均访问时间 ta = h×tc + (1−h)×tm　　加速比 S = tm / ta　　访问效率 e = tc / ta

例：Cache 速度 tc=20ns，主存 tm=100ns，命中率 h=90%：
ta = 0.9×20 + 0.1×100 = 28 ns；S = 100/28 ≈ 3.57；e = 20/28 ≈ 71.4%。

反解：要 ta ≤ 30ns，则 h ≥ (tm−ta)/(tm−tc) = (100−30)/(100−20) = 87.5%（万能反解式）。

三、三种映射：主存块能住 Cache 哪里？

映射规则主存地址切分优缺点
直接映射主存块 i → Cache 行 (i mod 行数)Tag | 行号 | 块内快、冲突多
全相联想住哪行住哪行Tag | 块内（无行号字段）最灵活、比较器多（贵）
组相联组间直接、组内全相联Tag | 组号 | 块内折中（主流，2/4 路组相联）
⚠ 高频陷阱 ① 全相联地址里没有行号字段（Tag 全长）；② 组相联『路数翻倍 ⇒ 组数减半 ⇒ Tag 加 1 位』；③ 计算各字段位数：块内 = log₂(块大小)，行号 = log₂(行数)，其余全是 Tag。

四、替换与写入

  • 替换算法：LRU / FIFO / RAND（LRU ≠ LFU）——与页面置换思想一致（Lesson 0016）。
  • 写策略：写直达（同时写 Cache 与主存，简单慢）/ 写回（只写 Cache、替换时才写主存，需脏位）。
  • 与虚拟存储的分工：TLB 管「虚拟→物理」转换，Cache 管「物理→数据」——两级各司其职。

五、总线

总线方向内容
数据总线 DB双向数据
地址总线 AB单向（CPU→外）地址；宽度 n 位 → 寻址 2ⁿ 空间
控制总线 CB双向（整体）时序与控制信号
总线带宽 = 总线工作频率 × 总线宽度（字节）　例：100MHz × 32bit/8 = 400 MB/s

七、自查（全对过课）

✅ 本课一页收获
  1. ta = h×tc+(1−h)×tm；S = tm/ta；e = tc/ta；反解 h = (tm−ta)/(tm−tc)。
  2. 映射三态：直接 Tag|行号|块内；全相联无行号；组相联 Tag|组号|块内，路数×2 ⇒ 组数÷2 ⇒ Tag+1。
  3. LRU/FIFO/RAND 替换；写直达 vs 写回（脏位）；TLB 虚→实、Cache 实→数据。
  4. 地址总线单向、数据总线双向；带宽 = 频率 × 宽度/8。
