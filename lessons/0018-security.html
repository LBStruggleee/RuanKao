信息安全：加密、签名与防护体系

课程总目录 ｜ 预计 35 分钟 ｜ 上一课：0017 TCP 与子网划分
考点定位：对称/非对称算法参数（必背数字）、数字签名用谁的密钥、防火墙与 IDS/IPS（day06-security.md，15 道题的板块）

🎯 这课的赢面 一张「五层楼」把整个板块串起来：数字摘要 → 数字签名 → 数字证书 → 数字信封 → 加密。必背数字一把抓（DES 56、3DES 168、AES 轮数 10/12/14、MD5 128、SHA-1 160），再加「数字签名 = 发方私钥」这一句，本板块选择题基本清空。

一、对称加密 vs 非对称加密

对称加密非对称加密
密钥加密解密同一把钥匙公钥加密、私钥解密（成对）
代表DES（56 位有效密钥/64 分组）、3DES（168）、AES（分组固定 128，密钥 128/192/256 → 轮数 10/12/14）、IDEA、RC4RSA（基于大整数分解）、ECC（椭圆曲线离散对数）、DSA
优/劣快，适合大量数据；密钥分发难（n 人两两需 n(n−1)/2 把）密钥分发简单（公钥公开）；慢，适合小数据/密钥交换

二、五层楼：从摘要到加密

  1. 数字摘要：对报文做 Hash 得固定长度指纹——MD5 128 位、SHA-1 160 位、SHA-256 256 位；保证完整性（防篡改）。
  2. 数字签名：发方用自己的私钥对摘要加密；收方用发方的公钥验证。保证完整性 + 不可否认性（发方抵赖不了）。不保密！
  3. 数字证书（CA）：CA 用自己的私钥签发「公钥属于某人」的证书，解决「公钥是真是假」。
  4. 数字信封：数据用对称密钥加密（快），对称密钥再用对方公钥加密（安全分发）——两者结合，HTTPS 的思路。
  5. 加密体系：HTTPS = HTTP over SSL/TLS（443 端口）。
⚠ 最高频陷阱 数字签名：发方私钥签、发方公钥验（验的是身份）；数据加密：收方公钥加、收方私钥解（保的是机密）。两把钥匙别接反。

三、攻击与防护配对

攻击手法防御
SQL 注入输入框拼接 SQL 语句参数化查询/过滤输入
XSS 跨站脚本向页面注入脚本输出转义/CSP
CSRF 跨站请求伪造盗用已登录会话发伪造请求Token 校验/验证 Referer
DDoS傀儡机洪泛耗尽资源流量清洗/CDN 分流
重放攻击截获合法报文再重发时间戳/一次性令牌/序列号

四、防火墙与 IDS/IPS

设备原理位置/特点
包过滤防火墙网络层查 IP/端口规则快、粒度粗
应用级网关（代理）应用层逐条检查内容细、慢
状态检测跟踪连接状态动态放行折中，主流
IDS 入侵检测旁路监听、发现报警只喊不打
IPS 入侵防御串联部署、直接阻断又喊又打
VPN / IPSecAH = 只认证；ESP = 认证+加密；传输模式护载荷、隧道模式护整包公共网络上建加密通道

五、自查（全对过课）

✅ 本课一页收获
  1. 对称快（DES 56/3DES 168/AES 128 分组，轮数 10/12/14）、非对称分发易（RSA/ECC）。
  2. 摘要 MD5 128/SHA-1 160；签名 = 发方私钥（不可否认），加密 = 收方公钥（机密）；数字信封 = 对称加密数据 + 公钥加密密钥。
  3. 重放 → 时间戳/一次性令牌；XSS 转义、CSRF Token。
  4. IDS 旁路报警、IPS 串联阻断；防火墙三类：包过滤/应用网关/状态检测。
