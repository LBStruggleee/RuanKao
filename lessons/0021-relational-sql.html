关系代数与 SQL：把查询翻译成运算

课程总目录 ｜ 预计 40 分钟 ｜ 上一课：0026 信息安全
考点定位：五种关系代数运算、SQL 执行顺序、聚合与 NULL、DCL 授权（day07-sql.md，20 题里 8 道查询结果题）

🎯 这课的赢面 两把钥匙：①关系代数五个符号各管一件事（σ 选行、π 投影列、⋈ 连接、× 笛卡尔积、÷ 除）；②SQL 的执行顺序 FROM→WHERE→GROUP BY→HAVING→SELECT→ORDER BY——一多半的查询结果题靠它推。

一、关系模型三要素与三类完整性

  • 三要素：数据结构（二维表）、操作集合（关系代数/SQL）、完整性约束。
  • 实体完整性：主键非空且唯一；参照完整性：外键要么为空、要么必须存在于被参照表；用户定义完整性：如年龄 0–150。

二、五种关系代数运算（符号 → 白话）

符号名称白话例
σ（sigma）选择挑行σ年龄>20(学生)
π（pi）投影挑列（自动去重）π姓名,年龄(学生)
⋈连接按条件横向拼表；自然连接 = 等值连接 + 去掉重复列学生 ⋈ 选课
×笛卡尔积两表所有行两两组合（列相加、行相乘）R × S
÷除「全部都…」查询：选出与 S 中每一个值都关联的 R 元组π学生(选课) ÷ π课程(课程)
⚠ 除运算 = 大题常客 「查询选修了全部课程的学生」→ 学生 ÷ 课程。SQL 里对应双重否定：不存在一门课程是他没选的（NOT EXISTS 套 NOT EXISTS）。

三、SQL 执行顺序（结果题的钥匙）

FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY
  • WHERE：行级过滤，不能用聚合函数；HAVING：组级过滤，配合 GROUP BY 用聚合。
  • NULL 陷阱：NULL 与任何值比较结果都是 UNKNOWN；COUNT(*) 数行（含 NULL），COUNT(列) 不数该列的 NULL；SUM/AVG 忽略 NULL。
  • JOIN 行数：内连接只留匹配行；左外连接左表全保留（右表补 NULL）。
  • 集合：UNION 去重、UNION ALL 不去重；INTERSECT 交、EXCEPT 差。

四、SQL 分类与授权（DCL）

类别语句例
DDL 数据定义CREATE / ALTER / DROPCREATE TABLE / VIEW / INDEX
DML 数据操纵SELECT / INSERT / UPDATE / DELETE增删改查数据本体
DCL 数据控制GRANT / REVOKEGRANT INSERT ON 学生 TO 用户1 WITH GRANT OPTION

GRANT 语句骨架：GRANT 权限 ON 对象 TO 用户 [WITH GRANT OPTION]（允许他再转授）；收回用 REVOKE。注意语法位置：表名前有 ON。

五、自查（先在纸上推结果再点）

✅ 本课一页收获
  1. σ 选行、π 选列、⋈ 连接、× 笛卡尔积（列加行乘）、÷ = 「全都…」查询。
  2. SQL 执行顺序 FROM→WHERE→GROUP BY→HAVING→SELECT→ORDER BY；WHERE 不用聚合。
  3. NULL：COUNT(*) 含 NULL、COUNT(列) 不含；NULL 比较得 UNKNOWN。
  4. GRANT 权限 ON 对象 TO 用户 [WITH GRANT OPTION]——DCL；CREATE/ALTER/DROP 是 DDL。
