🎯 这课的赢面 一句定位词分清测试类型（单元/集成/系统/验收、黑盒看功能白盒看结构），六级覆盖按强度排序，McCabe 三个公式互相换算：V = E − N + 2 = 判定节点数 + 1 = 区域数（图里围出的封闭房间 + 图外那 1 大开间）。

🧭 体系定位：面 2 软件工程 · 构造测试线——测试分级/白盒覆盖/McCabe/耦合内聚/维护。上游：0027 生命周期中的测试阶段（回地图）

一、测试分类（一句定位词）

阶段谁来做定位词
单元测试开发者单个模块；常用白盒；需要驱动/桩模块
集成测试开发者/测试模块拼起来；接口；自顶向下需桩模块、自底向上需驱动模块
回归测试开发者/测试改完代码后重跑既有用例，确认没把原来好的改坏
系统测试独立测试整个系统（性能/安全/恢复…）
验收测试用户主导Alpha 在开发方场地、Beta 在用户实际环境

表里两次出现的「驱动 / 桩」是什么？打个比方：桩模块 = 假装下属——领导（上层模块）还没等到下属完工，就找个替身机器人替下属应答，好让领导先测起来（所以自顶向下要用桩）；驱动模块 = 假装领导——下属（下层模块）先写好了，没人调用它，就造个临时"领导"去调用它（所以自底向上要用驱动）。一句话记：缺谁补谁——自顶向下缺下属补桩，自底向上缺领导补驱动。

回归测试：修好一个 bug、加了新功能之后，把以前写好的用例全部重跑一遍——就像修完水管要重新开一遍全屋的水龙头，确认没把别处改漏。改代码必回归，是考试常给的场景题。

黑盒（功能）三法：等价类（有效+无效类各取代表）、边界值（在等价类边界多测一发——最易出错的点）、因果图（把「多个条件怎么组合」画成一张图，再映射到对应动作——条件多、组合关系纠缠时才用，比如"会员且满 100 打 9 折、会员且满 200 打 8 折、非会员满 200 减 30"：2 个条件（是否会员、金额档）× 多种组合各对应不同动作，单独看每个条件都说不清该打几折，必须组合起来看，这才轮到因果图；如果只有一条"满 100 减 20"的简单规则，一个边界值就测完了，画图反而绕远）。白盒（结构）：逻辑覆盖，见下。

二、白盒覆盖六级（由弱到强）

语句 弱于→ 判定 弱于→ 条件/判定-条件 弱于→ 条件组合 弱于→ 路径

「弱于→」意思是：右边的要求包含了左边的要求，做到右边必然做到左边（好比「跑完全程」比「跑到 1 公里处」要求更高）。注意中间写作「条件/判定-条件」是因为条件覆盖和判定覆盖互不包含——条件覆盖并不保证判定覆盖（见下表），所以它们之间不画「弱于→」，而是合体成一个更强的「判定-条件覆盖」后再进链条。

覆盖要求记忆
语句覆盖每条语句至少执行一次最弱
判定覆盖（分支）每个判定的真/假分支各走一次比语句强
条件覆盖每个原子条件真假各一次（原子条件 = 不能再拆的单个比较，如 a>0、b>0；判定 if(a>0 && b>0) 则由两个原子条件拼成）不保证判定覆盖（条件都对但判定结果可能同向）
判定-条件覆盖判定 + 条件都满足两者合体
条件组合覆盖每个判定内条件取值组合全覆盖条件一多组合数翻倍（3 个条件就有 2³=8 种组合），用例数爆炸
路径覆盖所有可能路径最强、通常不可行

三、McCabe 圈复杂度 V(G)（必考计算）

V(G) = E − N + 2（边−节点+2） = 判定节点数 + 1 = 区域数（封闭房间 + 图外 1 间）
  • 控制流图化简：顺序语句合并成一个节点；if/while/for 每个判定算 1 个判定节点。case 分支怎么套用这条规则？一步一步换：有 k 个 case 分支时，先问有没有 default（兜底分支）。如果有 default：把 k−1 个分支各想成一次"if（值等于 X 吗）"，最后一次 else 落到 default——好比 5 扇门标着"是第 1 间吗？是第 2 间吗？…都不是就走默认门"，问 4 次（k−1=4 个判定节点），第 5 扇不用问。每个"问一次"就是一个判定、算 1 个判定节点，所以 k−1 个判定节点正好对应"每个判定算 1"这条规则，V = (k−1) + 1 = k。没有 default 呢？k 个分支就照实算 k 个判定节点——没有默认门兜底，每个分支都得单独问一次、单独引一次流程，好比 5 扇门每扇都要单独推；此时 V = k + 1。口诀：数"把流程单独引出去的分支"，有 default 少算 1（最后一个被兜底了），没 default 照实算。
  • V(G) = 线性独立路径数；经验值 V ≤ 10 为宜。「独立路径」就是从入口走到出口的一条走法，且至少含一段别的路径没走过的路——好比逛商场：不进任何店直走出口是一条，进 A 店是一条，先 A 后 B 又是一条；每条路线都带点新花样，才算"独立"。所以 V=3 就意味着：最少写 3 个用例，每个用例走一条独立路径——好比 3 条不同的逛法得逛 3 趟，每趟照着一条路线走。
  • 完整例题（两个串联 if，先画图再数）： 
            ┌─────────┐
        │  入口    │ ①
        └────┬────┘
             ▼
        ┌─ if A ─┐ ②        ← 判定节点 1（真/假两条出边）
        └─┬────┬─┘
       假 ↓    ↓ 真
        ┌──────┐
        │ 语句1 │ ③
        └──────┘
             ▼
        ┌─ if B ─┐ ④        ← 判定节点 2（真/假两条出边）
        └─┬────┬─┘
       假 ↓    ↓ 真
        ┌──────┐   ┌──────┐
        │ 语句2 │ ⑤ │ 语句3 │ ⑥
        └──┬───┘   └──┬───┘
           ▼          ▼
        ┌─────────┐
        │  出口    │ ⑦
        └─────────┘
    第一步：数节点 N。这张图我们不合并节点、照原图数（每条边都看得见，算完还能用另外两个公式验证），入口①、if A②、语句1③、if B④、语句2⑤、语句3⑥、出口⑦，N = 7。
    第二步：数边 E。一条条数（每条边都是图里画的一个箭头）：
    • 入口① → if A②（第 1 条）
    • if A② 假 → 直接到 if B④（第 2 条，图里那条"假直连"绕行箭头）
    • if A② 真 → 语句1③（第 3 条）
    • 语句1③ → if B④（第 4 条）
    • if B④ 假 → 语句2⑤（第 5 条）
    • if B④ 真 → 语句3⑥（第 6 条）
    • 语句2⑤ → 出口⑦（第 7 条）
    • 语句3⑥ → 出口⑦（第 8 条）
    共 E = 8（两个判定节点各带 2 条出边，合计 4 条，加上入口→if A、语句1→if B、语句2/3→出口共 4 条，4+4=8）。
    第三步：代入公式：V = E − N + 2 = 8 − 7 + 2 = 3。
    第四步：验证：判定节点数 + 1 = 2 + 1 = 3 ✓，两算一致。这 3 条独立路径正好对应上面商场的 3 条逛法：① A 假 B 假（两个 if 都不进真分支，直通出口——就是"不进任何店直走出口"那条）；② A 真 B 假（只进第一个 if，走语句1）；③ A 真 B 真（两个都进，走语句1+语句3）——每条都比前面的多走一段没走过的路，各写一个用例就覆盖了。注意：独立路径的选法不唯一，比如把②换成"A 假 B 真（走语句3）"也同样成立——只要 3 条路合起来是 3 条互不重复的走法即可，考试写哪一组都对，关键是别把"全不进"那条漏掉。 换个角度：如果把图化简（顺序节点合并），语句1③ 并入 if A→if B 之间的流，就得到 5 节点图，算出来 V 同样是 3——两种画法都行，但同一道题里口径要一致：要么全按原图数（N=7、E=8），要么全按化简图数（N=5、E=6：入口→ifA、ifA假→ifB、ifA真→ifB、ifB假→出口、ifB真→语句3、语句3→出口），不要混着数。为什么合并不改变 V？打个比方：一条只有单个出入口、中间不停靠的走廊，把走廊里的房间合并成"一条长廊"还是分成两间，入口和出口的接法没变，进出走法就一样多——顺序节点（一条线上的语句）不产生分岔，合并前后每条路径的走法完全相同，V 自然不变。注意例题图里 语句2⑤、语句3⑥ 不合并：它们分别挂在 if B 的假、真两条出边上，合并了这两条出边就指向同一个节点，分支的形状就没了；而化简图中被合并的都是"一条线上的顺序节点"，没有分岔，所以能并。
    验证三：数区域。把图当成一张平面地图：图里被边围出来的"封闭房间"有 2 间（if A 的真假两条路之间 1 间、if B 的真假两条路和语句2/语句3 之间 1 间），别忘了图外那一整个大开间也算 1 间——第一遍最容易漏掉它、只数出 2。所以区域数 = 2 + 1（外部）= 3 ✓。口诀：封闭房间数 + 外部那 1 间 = V，或者干脆记成"数房间、含外面那间"。

四、模块独立性：耦合七级 vs 内聚七级（必背排序）

「模块独立」 = 低耦合 + 高内聚，考法是给场景判级别或排顺序。耦合看模块之间怎么相连（越弱越好）；内聚看模块内部元素抱得多紧（越强越好）。

耦合（低 → 高，越左越好）判别关键词内聚（低 → 高，越右越好）判别关键词
非直接耦合两模块没有直接连线：信息要靠上级模块中转（A 传给上级、上级再传给 B），彼此不直接调用偶然内聚「顺手塞一起」——无逻辑关系的代码凑一个模块
数据耦合只传简单数据值（参数）逻辑内聚「同类任务选一个执行」（如把所有打印塞一起，用开关选择）
标记耦合传数据结构名（整个记录）时间内聚「同一时间段执行」（如初始化模块）
控制耦合传开关量/标志控制对方逻辑过程内聚「按固定流程先后执行」
外部耦合受外部环境/工具约束通信内聚「对同一数据集操作」（读同一个文件的不同统计）
公共耦合共享全局数据区顺序内聚「前一个的输出 = 后一个的输入」
内容耦合直接改对方代码/内部数据（最坏）功能内聚「一个模块一件事办到底」（最好）

易考易混的几级，配个生活例子：

  • 非直接耦合 vs 数据耦合（表里最像的两级）：非直接耦合的两个模块互相够不着——A 把东西交给领导，领导再转交 B，A 和 B 之间没有直接来往，靠上级中转；数据耦合是 A 直接调用 B、只递一个数字。差别在"有没有直接连线、要不要中转"，不在传的东西本身。
  • 数据耦合：同事只跟你借一个数字——"把单价 5 块传给我"。只传一个值，关系最清爽。
  • 标记耦合：不借用一个数字，而是把整张表格丢给对方——"这份客户档案（姓名+电话+地址全带着）你拿去用"。明明只用其中一栏，却把整个结构都给了。
  • 控制耦合：不是给数据，而是给指挥旗——"你去做 A 还是去做 B，听我标志位的"。对方干什么活由你遥控，纠缠就深了。
  • 公共耦合：几个部门不打招呼，直接翻同一个公用白板（全局数据区）读写——一个人擦了改了，别人全受牵连。
  • 内容耦合：干脆伸进对方口袋改东西——直接改对方内部数据或代码，最坏的一级。

记忆钩子：耦合「非数标控外公内」——非=非直接、数=数据、标=标记、控=控制、外=外部、公=公共、内=内容；内聚「偶逻时过通顺功」——偶=偶然、逻=逻辑、时=时间、过=过程、通=通信、顺=顺序、功=功能。考试给场景判级别：传参数=数据、传记录=标记、传标志=控制、共享全局=公共、改对方内部=内容；初始化一堆活=时间、流水处理=顺序、单一件事=功能。

维护四类型（概念题，考占比与场景）：完善性（加功能改善性能，占比约 50% 最高）、适应性（适应环境/平台变化）、纠正性（修 bug）、预防性（为将来改动打基础，占比最小）。口诀「完适纠预」，顺序按占比背。

✅ 本课一页收获
  1. 测试定位：单元白盒、验收用户主导（Alpha/Beta）；集成自顶向下用桩、自底向上用驱动。
