一、13 图分类（静态看结构、动态看行为）

静态图（结构）动态图（行为）
类图、对象图、构件图、部署图、包图、组合结构图、制品图用例图、顺序图、通信图、状态图、活动图、定时图、交互概览图
📦 先别慌：这 14 个名字怎么记 判断标准一句话：静态图 = 「画的是系统长什么样」（像建筑效果图，不随时间变），动态图 = 「画的是系统怎么运转」（像监控录像，有时间先后）。
每个名字配一句人话提示（括号里就是它管的事）：
  • 静态：类图（类与类的关系，考频最高）、对象图（某一时刻的具体对象快照）、构件图（软件拆成哪几个零件模块）、部署图（软件装在哪些机器上）、包图（文件夹式的归类）、组合结构图（类内部的零件结构）、制品图（生成的文件/安装包）。
  • 动态：用例图（用户能用系统干什么）、顺序图（办事流程的时间先后）、通信图（谁给谁发消息，不带时间轴）、状态图（一个对象的状态变化）、活动图（跨部门的流程图）、定时图（消息的时间点）、交互概览图（多段交互拼成一张总图）。
📌 应试策略：先只记加粗的 4 个（类图、用例图、顺序图、状态图）——它们直接进考题；其余 10 个混脸熟，见到能归到「静态/动态」哪一堆就够用了。
  • 用例图：参与者 + 用例 + 关系（下午大题第一问常考补用例名）。
  • 顺序图：把一次业务流程画成「谁给谁发消息、按时间从上往下」。打个比方：像微信聊天记录竖着排——每一列是一个参与者，谁发的话就横着画一条箭头过去，越往下时间越晚。三个新词先用大白话记住：
    • 生命线：对象下面垂的那条虚线——「这个人全程在线」。
    • 激活条：生命线上那根细长矩形——「这段时间他在忙这件事」。
    • 同步消息（实心三角箭头 ▶）= 打电话：发出后必须等对方回话才能继续办下一件事；异步消息（开放箭头 →）= 发微信：发完就走，不用等回信；返回消息（虚线）= 对方把结果递回来。
    一个最小的两对象例子（「你」在 ATM 取钱）： 
    你                ATM
│                  │
│──①取款(500元)──▶ │   ← 同步消息：实心三角▶，你等着 ATM 处理
│                  │
│◀- -②吐钱+回执- - │   ← 返回消息：虚线，ATM 把结果递回来
│                  │
│──③发短信通知───▶ │   ← 异步消息：开放箭头→，发完不等回执
│                  │
    ①③ 从「你」指向 ATM 是请求消息，② 虚线返回；同步（①，等吐钱）画实心三角，异步（③，通知后不管）画开放箭头。
  • 状态图：单个对象的状态变迁。先把三个词拆开：状态 = 对象此刻「处于什么情况」（待付款）；事件 = 让它换状态的那一下「触发」（用户点了付款）；动作 = 变状态时顺手干的活（扣款、发通知）。拿一张网购订单举例：
    [待付款] ── 事件：买家付款成功 ／ 动作：扣款、发通知 ──▶ [已付款]
[已付款] ── 事件：仓库揽收 ／ 动作：打印运单 ──▶ [已发货]
    读法：箭头上写「事件 ／ 动作」，事件触发转换，动作是转换时做的事，两个圆角框是前后两个状态。
    活动图：跨对象的工作流，像一张流程图但重点是「事情怎么流转」；泳道 = 每个部门（角色）一条竖道，看每一步落在谁的道里就知道「这步谁负责」；分叉/汇合 = 一件事拆成几件同时做、做完再合到一起。

二、类间六关系「依关聚组泛实」（强度从弱到强）

关系含义判别口诀UML 记号
依赖临时用一下，用完就走（生活例子：打车——那 20 分钟你临时用了司机的车，下车就再无关系；写代码时对应「参数、局部变量」，即只在方法里临时用一下的变量）『用完就走』虚线箭头
关联长期知道对方（生活例子：自己有辆固定车——车登记在你名下，长期绑定；写代码时对应「成员变量」，即长期挂在对象身上、随时能用的变量）『长期认识』实线（可有箭头/多重性 1..*）
聚合 Aggregation整体-部分，部分能独立存在『部门走了员工还在』空心菱形 ◇（贴在整体一端）
组合 Composition整体-部分，同生共死『公司没了部门也没了』实心菱形 ◆（贴在整体一端）
泛化 Generalization继承，is-a『老虎是动物』空心三角实线（指向父类）
实现 Realization实现接口，can-do『实现接口的承诺』空心三角虚线（指向接口）
⚠ 聚合 vs 组合（最易混） 问一句「部分能离开整体独立存在吗」：能 → 聚合（空心菱形 ◇）；不能（同生共死）→ 组合（实心菱形 ◆）。
菱形长什么样、贴在哪头？直接看图——菱形贴在连线靠「整体」的那一端（像挂件挂在整体身上）： 
组合（同生共死）    发动机 ◆━━━━ 汽车
                    （实心◆贴在整体「汽车」端：汽车没了，发动机跟着报废）

聚合（可分可合）    员工   ◇━━━━ 部门
                    （空心◇贴在整体「部门」端：部门解散，员工跳槽还在）
考试看图判别：先找到菱形在哪一端、那一端是谁——那一端就是整体；再看菱形是空心还是实心定聚合/组合。

三、用例图的 include / extend（方向相反！）

先认识两个词：基用例 = 系统的主要功能（比如「登录」——用户真正要做的那件事）；从它身上拆出去的步骤/插曲都不是基用例（「验证密码」只是登录路上的一个必经步骤）。

include 包含extend 扩展
语义基用例必然执行被包含用例——把每次都要走的「公共子流程」抽出来（登录每次都要验证密码）扩展用例可选地插入基用例——只在特殊情况发生的「异常/可选流程」（登录密码连错 3 次，才触发「账号锁定」）
箭头基用例 ──«include»──▶ 被包含用例扩展用例 ──«extend»──▶ 基用例

拿「登录」把两个方向各画一遍：

include（必经之路，从基出发）：
  [登录] ──«include»──▶ [验证密码]     ← 每次登录都必然执行 → 箭头从「基用例(登录)」指向被包含的步骤

extend（可选插曲，指回基）：
  [账号锁定] ──«extend»──▶ [登录]      ← 只有密码连错才触发（可选）→ 箭头从「扩展用例」指回「基用例」

记忆：include 从基指向被包含（必经之路）；extend 从扩展指回基（可选插曲）——两者方向相反，这是用例图最高频的一分。方向记法一句话：「必然」的从主功能出发，「可选」的指回主功能。

四、自查（全对过课）

✅ 本课一页收获
  1. 13 图分静态（类/对象/构件/部署/包…）与动态（用例/顺序/状态/活动…）。
  2. 六关系「依关聚组泛实」：强度递增；聚合空心菱形（可独立）、组合实心菱形（同生共死），菱形在整体端。
  3. 泛化实线空心三角（is-a）、实现虚线空心三角（接口）。
  4. include 基→被包含（必执行）；extend 扩展→基（可选）——方向相反。
