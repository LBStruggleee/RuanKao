一、编译与解释：一条流水线 vs 逐句翻译

编译型（C、C++）：整个源程序一次翻译成目标程序，之后脱离编译器独立运行，执行速度快，但跨平台差。解释型（Python、JavaScript 的典型实现）：边翻译边执行、不生成完整目标程序，跨平台好，执行慢。Java 特殊：先编译成字节码，再由 JVM 解释/即时编译执行。

编译的六个阶段（一条流水线，符号表全程服务、错误处理随时介入）：

阶段干什么能查出什么错（必考）
① 词法分析字符流 → 单词序列（标识符、关键字、常数、运算符）非法字符、单词拼写错误
② 语法分析单词序列 → 语法树（按文法规则组句子）if 缺 then、括号不匹配、分号缺失（结构错误）
③ 语义分析检查含义：类型检查、声明先于使用类型不匹配、使用未声明的变量
④ 中间代码生成产生与机器无关的中间表示（四元式/三元式）—
⑤ 代码优化等价变换提效率（合并常量、删公共子表达式）—
⑥ 目标代码生成中间代码 → 汇编/机器码，分配寄存器—
⚠ 必考套路 题目给一段错误代码问「在哪一个阶段被发现」：非法字符/写错关键字 → 词法；括号不配、语句结构不完整 → 语法；类型不符、函数未定义就调用 → 语义。一句话：词法看字，语法看形，语义看义。

二、正规式与有限自动机：给单词画模板

词法分析靠正规式（正则表达式）描述单词的模板。三种运算：| 或、连接（隐含）、* 重复 0 次或多次。优先级：* 最高，连接次之，| 最低。

要求正规式套路记忆
以 ab 开头ab(a|b|c)*（字母表 {a,b,c}）开头写死，后面任意串
以 ab 结尾(a|b|c)*ab任意串 + 结尾写死
含 ab(a|b|c)*ab(a|b|c)*前后任意，中间写死
偶数个 ab* (ab*ab*)*a 成对出现，b 随意填缝

有限自动机是正规式的机器形态，两者等价（正规式 ⇄ 自动机可互相转换）：

对比DFA 确定有限自动机NFA 非确定有限自动机
一个状态 + 一个输入唯一的后继状态可有多个后继状态
空边 ε不允许允许
初态唯一可以有多个
关系NFA 可确定化 → DFA；DFA 可最小化（合并等价状态）。识别能力等价

三、传值 vs 传引用：拷贝还是地址

函数调用时参数怎么传，决定了函数内改动会不会影响外面的实参：

方式传什么函数内修改形参典型语言
传值调用实参的拷贝不影响实参C 的标量参数、Java 的基本类型
引用调用（传地址）实参的地址直接影响实参C 的数组/指针参数、Java 的对象引用

经典考题：void f(int x){ x = 100; } 调用 f(a) 后 a 不变（传值，改的是拷贝）；改成 void f(int *x){ *x = 100; } 调用 f(&a) 后 a = 100（传地址）。

Java 判定口诀：基本类型（int/double…）传值拷贝；对象传的是「引用的拷贝」——函数内改对象字段会影响原对象，但让引用指向新对象不影响原变量。

四、动手：后缀表达式求值挑战（编译配套·先动笔再填）

后缀式 = 逆波兰式（同义别名，题目两个叫法都会用）：运算符写在两个操作数之后，求值用一个栈——操作数入栈、遇运算符弹出两个数计算再把结果入栈。中缀转后缀也是编译原理「中间代码」的常见形式（另有四元式、三元式）。

五、自查（全对过课）

✅ 本课一页收获
  1. 编译六阶段：词法 → 语法 → 语义 → 中间代码 → 优化 → 目标代码；符号表全程、错误处理伴随。词法看字、语法看形、语义看义。
  2. 正规式套路：开头/结尾/包含 = 写死对应位置，其余 (a|b|c)*；NFA 可有ε边多后继，可确定化为 DFA，能力等价。
  3. 传值 = 拷贝不影响实参；传引用 = 地址直接影响实参；Java 基本类型传值、对象传引用。
  4. 编译型快、解释型跨平台；Java 先编译成字节码再由 JVM 执行。
