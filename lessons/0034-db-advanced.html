数据库进阶：视图、并发控制、模式分解与触发器

课程总目录 ｜ 预计 30 分钟 ｜ 上一课：0033 面向对象基础
考点定位：并发三类问题与锁（每年 1~2 题）、视图定义与作用、模式分解无损判断——补上 0019 0020 之外的进阶散点

🎯 这课的赢面 两张表 + 一句判据：并发三类问题（丢失更新 / 不可重复读 / 读脏数据）按「谁动了谁的数据」对号；S 锁相容 X 锁不相容；视图是虚表——简化查询 + 提供安全隔离。

一、视图：一张「存查询」的虚表

视图（VIEW）是从一个或多个基本表（或其他视图）导出的虚表：数据库只存视图的定义（SELECT 语句），不存视图的数据——查询视图时实时从基本表算出来。

CREATE VIEW 视图名 AS SELECT …（WITH CHECK OPTION 可限制通过视图的更新必须满足条件）
作用说明
简化查询把复杂的多表连接/嵌套封装成一个视图，之后当表用
安全隔离（逻辑独立性）对用户只开放视图（如隐藏工资列），Grant 权限授到视图粒度；基本表结构变化时改视图定义即可，应用不改——外模式/模式映像保证逻辑独立性
数据独立性视图随基本表数据实时更新（虚表）；个别系统支持物化视图（实存数据、需刷新）
⚠ 高频判断 「视图中的数据在数据库中单独存储」——错（虚表只存定义）。但「通过视图可以更新基本表数据」——对（有限制：通常只允许更新单表、无聚合的视图）。

二、并发控制：三类问题与两种锁

多事务并发执行如果不加控制，会出三类数据不一致问题——识别它们的关键是谁读、谁写、先后顺序：

问题场景（T1 与 T2）关键词
丢失更新T1、T2 都读后写同一数据：T2 的写覆盖了 T1 的写「更新丢失」「两写互相覆盖」
不可重复读T1 两次读同一数据之间，T2 修改（或删除）了它 → T1 两次读到的值不一样「重复读值不同」
读脏数据T2 读到了 T1 已撤销（回滚）的中间值「回滚后读到旧值」

解法：封锁。两种基本锁——S 锁（共享锁/读锁）：读数据前加；X 锁（排他锁/写锁）：写数据前加。相容矩阵：

已持有 \ 请求S 锁X 锁
S 锁✓ 兼容（都可读）✗ 冲突
X 锁✗ 冲突✗ 冲突

两段锁协议（2PL）：事务分两个阶段——先只加锁/升级（扩展段），后只解锁（收缩段），两阶段之间不交叉。遵守 2PL 可保证可串行化（并发结果等价于某个串行执行），但不能避免死锁（判断题）。

三、模式分解：拆表拆得对不对

范式化（0020）把大表拆成小表的过程就是模式分解。拆完必须检查两点：

标准含义常见考法
无损连接拆开的两表自然连接后能完全还原原表，不多不少判断给定分解是否无损（Chase 列表法/公式法：公共属性至少包含一侧的码）
保持函数依赖原表的函数依赖在分解后仍能在各表上验证「分解后能否仍判断 X→Y」

快速判据：R 分解为 R1、R2，若 R1 ∩ R2 → R1 或 R1 ∩ R2 → R2（公共属性能函数决定其中一张表的全部属性），则分解无损。例：R(学号,姓名,系别) 拆成 R1(学号,姓名) 与 R2(学号,系别)：交集 {学号} → 学号 是 R1 的码 → 无损 ✓。3NF 一定可以达到既无损又保持依赖的分解；BCNF 能保证无损，不一定保持依赖（判断题）。

四、触发器与存储过程：数据厍里的自动机关

  • 触发器（Trigger）：绑定在表上的 ECA 规则——Event 事件（INSERT/UPDATE/DELETE）→ Condition 条件 → Action 动作自动执行。用途：复杂完整性约束（如「删除系别时级联删除学生」）、审计日志。定义在表上、由事件自动触发，不能像函数一样手动调用。
  • 存储过程：预编译存放在数据库中的 SQL 程序集，可带参数、被显式调用；优点：预编译效率高、减少网络流量、便于复用。
  • 主键 vs 外键：主键 = 实体完整性（非空唯一）；外键 = 参照完整性（取值必须参照表的主键存在或为空）——两类完整性的定义句年年考。

五、自查（全对过课）

✅ 本课一页收获
  1. 视图 = 虚表只存定义：简化查询 + 安全隔离 + 逻辑独立性；可有限更新。
  2. 并发三问题：丢失更新（两写覆盖）、不可重复读（两次读不同）、读脏数据（读到回滚值）。
  3. S/S 兼容，凡带 X 都冲突；两段锁保证可串行化但不防死锁。
  4. 分解判据：R1∩R2 能决定 R1 或 R2 → 无损；3NF 可兼顾无损 + 保持依赖。
  5. 触发器 ECA 自动执行；主键实体完整性、外键参照完整性。
