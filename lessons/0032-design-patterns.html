一、三大类怎么分

类别管什么成员（23 种）
创建型（5）对象怎么造单例、工厂方法、抽象工厂、建造者、原型
结构型（7）对象怎么拼适配器、桥接、组合、装饰、外观、享元、代理
行为型（11）对象怎么协作职责链、命令、解释器、迭代器、中介者、备忘录、观察者、状态、策略、模板方法、访问者

二、高频模式速查（题眼 → 模式）

先看两个大白话问题再进表：懒汉 vs 饿汉（单例的两种创建时机）——懒汉像共享打印机，谁第一次用谁开机（多个人同时第一次用，可能各开一台，所以考试里它要「加锁防并发、线程安全」）；饿汉像机房一开门就开好的那台机器，天生只此一份，天然线程安全。线程安全就是「多个人同时来用，也不会出乱子」。

题眼（场景关键词）模式意图一句话
全局唯一 / 一个类只有一个实例 / 提供全局访问点单例懒汉（第一次用到才创建）/ 饿汉（程序一加载就创建好）
子类决定实例化哪个类 / 延迟到子类工厂方法定义创建接口，让子类决定造谁
创建一族相关产品（产品族 = 一套配齐的产品，如 Win 键盘 + Win 鼠标算一族）抽象工厂一个工厂造一整套
分步组装复杂对象 / 相同构建过程不同表示（表示 = 最终造出来的不同成品形态）建造者同样的造流程（铺底→加料→封盖）分步固定，成品随指导不同而不同（大杯奶茶 / 大杯咖啡）
复制克隆已有对象原型用克隆替代 new
接口不兼容要转换适配器把旧接口包成目标接口
两个东西各自都在变、要拆开各变各的（形状×颜色、遥控器×电视）桥接抽象与实现分离（两个变化维度解耦），各自独立变化
树形部分-整体（文件/文件夹）组合单个与容器统一对待
动态给对象加职责 / 不改类加功能装饰一层层包，包一层加一层功能（Java IO 流）
统一复杂子系统的简单入口外观（门面）一个类包装一堆调用
共享细粒度对象 / 大量重复对象省内存（细粒度 = 拆到最小的那个小对象）享元像棋盘 361 个交叉点，棋子只造两个对象（黑一个、白一个），所有位置共享——不每个位置都 new 一个，省内存
控制访问 / 远程 / 保护代理挡在你前面，控制对目标的访问（不加功能）
请求沿链条逐级传递 / 谁处理看级别职责链审批流
把请求封装成对象 / 可撤销（参数化 = 不同请求装进同一种命令对象里，随便传、随便存、可排队）命令像点菜单：每张单是一个命令对象，可排队、可撤销、可留记录（日志）
一对多通知 / 发布-订阅观察者主题变 → 订阅者全部收到通知
保存与恢复对象状态（撤销/存档）备忘录不破坏封装地存快照（快照 = 某一时刻状态的完整拷贝，像游戏存档；不破坏封装 = 原对象自己决定存什么，外面的人只能存取整份快照、不能拆开偷看改里面的字段）
行为随状态改变（状态机）状态状态变 → 行为变
算法可整体替换（策略 interchangeable）策略同一接口不同算法
固定骨架、子类填细节模板方法父类定流程，子类填步骤
按顺序一个个访问集合元素（不暴露内部结构）迭代器顺序访问集合，不用关心里面怎么存的
很多对象互相引用、乱成一团网中介者把多对象互改改成星型：都只跟中间人打交道
数据结构稳定、操作多变（对不同元素做不同的事）访问者结构不动，访问的人随便加
一种语言定义了文法要解释执行解释器给文法规则各配一个类来解释

💡 行为型 11 种至此 11 种全齐。其中迭代器、中介者、访问者、解释器在软考里属于低频考点，上午题考到基本就是上面的题眼——认不出再回这张表翻。

💡 一句话区分装饰 vs 代理：都是「包一层」，但装饰是为你加功能（包上 BufferedReader 是为了让你多一个读行的能力），代理是挡在你前面管权限/远程（你本来就有这功能，代理只是替你把关或转发）。看意图：增强→装饰，控制访问→代理。

高频模式的画面感（先记场景，再对题眼）

  • 单例：打印机驱动程序全公司只用装一份，谁用都连到同一个——全局只此一份。谁第一次用谁开（懒汉），或一开机就装好（饿汉）。
  • 工厂方法：你只跟「奶茶店下单口」打交道，点奶茶、咖啡是各分店（子类）自己决定的——「造谁」交给子类。
  • 观察者：你订阅了公众号，号主一更新，所有粉丝自动收到推送——被观察者（号主）一变，订阅者（粉丝）全部收到通知。
  • 装饰：买奶茶「原味」→加珍珠→再加奶盖，一杯套一杯，每层多一个功能而不用新开一个品类——动态加职责。
  • 建造者：奶茶店流程固定「铺底→加料→封盖」，指导换个人（换参数），成品就从大杯奶茶变成大杯咖啡——过程一样，表示（成品）不同。
  • 命令：遥控器每个按键里存一个命令对象，按下就执行，还能一键撤销上一个操作——请求装成对象后可排队、可撤销。
  • 策略：去公司可以骑车、地铁、打车，路上时间随你整体换成哪种方案而变——同一目的，算法整体可替换。
  • 备忘录：打游戏前存个档，输了读档回滚——原对象生成快照、保管员只存不看，之后恢复。

三、大题答题三步（试题五/六）

  1. 读说明找题眼（「唯一实例」→单例；「保存/恢复」→备忘录；「通知」→观察者）；
  2. 对类图填角色：类图里的英文角色名就是「身份」，认准这几个——观察者两角色：Subject = 被观察者（发布通知的一方）/ Observer = 观察者（订阅收通知的一方）；备忘录三角色：Originator = 原对象（自己生成快照）/ Memento = 备忘录（快照本身）/ Caretaker = 保管员（只存快照、不看内容）；创建型常配「抽象工厂/具体工厂、抽象产品/具体产品」——先填抽象再填具体；
  3. 按签名填代码：「签名」就是方法的完整特征：方法名 + 括号里的参数类型 + 返回类型这套组合。空缺处照着同类方法的签名抄骨架（同类方法怎么写参数、返回什么，空缺处就照着填），别自创变量名。

四、自查（全对过课）

✅ 本课一页收获
  1. 三大类：创建 5（单例/工厂方法/抽象工厂/建造者/原型）、结构 7（适配器/桥接/组合/装饰/外观/享元/代理）、行为 11。
  2. 题眼直查：唯一实例→单例；产品族→抽象工厂；树形→组合；动态加职责→装饰；发布订阅→观察者；保存恢复→备忘录；算法替换→策略；骨架细节→模板方法。
  3. 单例：懒汉=第一次用到才创建（多人同时第一次用可能造出两个，要加锁防并发）；饿汉=程序一加载就创建好（只此一份，天然线程安全）。
  4. 大题三步：找题眼 → 填角色 → 按签名补码。
