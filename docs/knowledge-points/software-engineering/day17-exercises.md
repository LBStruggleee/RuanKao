## 完整答案与解析

### 第一部分：操作系统

**1. B**｜`[页式地址转换 / 二轮重点：页式地址转换（物理 = 块号×页大小+偏移）、多级页表访存 + TLB]`

- 页大小 4KB = 2¹² → 逻辑地址**低 12 位为页内偏移**，高位为页号；
- 3A6CH = `0011 1010 0110 1100`，低 12 位 = `1010 0110 1100` = **A6CH**（偏移），高 4 位 = `0011` = **3**（页号）；
- 查页面变换表：页号 3 → 物理块号 **7**；
- 物理地址 = 块号 7 × 1000H + 偏移 A6CH = **7000H + A6CH = 7A6CH**。

> 干扰项：A（6A6CH）= 块号 6 的错误答案；C（3A6CH）= 误以为地址不变；D（7A60H）= 拼接偏移时末位算错。**段式与页式不要混**：页式是"块号×页大小（拼接）"，段式才是"段基址 + 偏移（相加）"。

**2. B**｜`[多级页表访存次数与 TLB / 二轮重点：页式地址转换 + 多级页表访存 + TLB]`

- 页大小 4KB → 页内偏移 12 位；逻辑地址 32 位 → 一个进程最多 2³²/2¹² = **2²⁰ 页**；
- 一页（4KB = 2¹²B）可容纳的页表项数 = 2¹² / 2²（每项 4B）= **2¹⁰ = 1024 项**；
- 故**页目录（一级页表）**需要 2²⁰ / 2¹⁰ = **2¹⁰ = 1024 项**，占 1024 × 4B = **4096B = 4KB（恰好一页）**；
- **TLB 未命中**（页表在主存）时：读页目录项（1 次）→ 读二级页表项（1 次）→ 读数据（1 次）= **3 次访存**；
- **TLB 命中**时：页表项已在 TLB 中，**只需 1 次访存**（直接读数据），D 错。

> 记死：**TLB 命中 = 1 次访存；二级页表未命中 = 3 次访存；一级（单级）页表未命中 = 2 次访存。**

**3. A**｜`[磁盘调度 SSTF 寻道计算 / 二轮重点：磁盘 SSTF 寻道计算]`

SSTF 每次选**距当前磁头最近**的请求（注意它会**折返跑**，必须逐段列距离）：

```
当前 53 → 选 65（距离 12）  → 移动 12
    65 → 选 67（距离 2）    → 移动 2
    67 → 选 37（距离 30）   → 移动 30
    37 → 选 14（距离 23）   → 移动 23
    14 → 选 98（距离 84）   → 移动 84
    98 → 选 122（距离 24）  → 移动 24
   122 → 选 124（距离 2）   → 移动 2
   124 → 选 183（距离 59）  → 移动 59
合计 = 12+2+30+23+84+24+2+59 = 236
```

> 干扰项 D（169）是 SCAN/LOOK 类算法的结果，C（208）是 C-LOOK 的结果——**同一请求序列下不同算法结果不同，必须逐算法重算，不能混记**。

**4. B**｜`[索引文件可管理大小 / 二轮重点：磁盘调度 SSTF + 索引文件可管理大小]`

- 4KB / 4B = **1024 = 2¹⁰ 个地址项/索引块**（注意：**不是 256**，那是 1KB 块的情形）；
- **一级间接索引**：1024 × 4KB = **4MB**；
- **二级间接索引**：1024 × 1024 × 4KB = **4GB**；
- **三级间接索引**：1024 × 1024 × 1024 × 4KB = **4TB**。

> 必背对照（按块大小 4KB / 地址项 4B 记一套即可）：**一级 4MB / 二级 4GB / 三级 4TB**。若块大小改为 1KB（地址项 256），则一级 4MB / 二级 1GB / 三级 256GB——题干的"1024 项"是本题的关键数字。

**5. C**｜`[PV 操作信号量值计算 / 二轮重点：PV 操作信号量值 / 死锁四条件 / 银行家算法 = 死锁避免]`

- 信号量初值 = 可用资源数 = **3**，这也是信号量可能取到的**最大值**；
- 6 个进程各申请 1 台：先到者获得资源，3 台分完后，余下 3 个进程全部阻塞等待；
- 信号量值 = 可用资源数 − 等待进程数 = 3 − 6 = **−3**，此为**最小值**；
- 故 S 的取值范围为 **−3 〜 3**，最小值 −3。

> 规律：初值为 m、n 个进程各申请 1 个资源时，S 的取值范围为 **−(n−m) 〜 m**（n ≥ m 时必有 n−m 个进程在等待）。

**6. B**｜`[调度算法（SJF 周转时间计算）/ 二轮重点：调度算法 SJF 周转时间计算]`

SJF 非抢占式：有新作业到达时，在**已到达但尚未执行**的作业中选运行时间最短者。

```
t=0：仅 P1 已到达          → 执行 P1，完成于 t=8
t=8：就绪 P2(1,4) P3(2,2) P4(3,1) → 选最短 P4(1)，完成于 8+1=9
t=9：就绪 P2(4) P3(2)     → 选最短 P3(2)，完成于 9+2=11
t=11：就绪 P2(4)           → 执行 P2，完成于 11+4=15
```

周转时间 = 完成时刻 − 提交时刻：

| 作业 | 提交 | 运行 | 完成 | 周转时间 |
|------|------|------|------|---------|
| P1 | 0 | 8 | 8 | 8 |
| P2 | 1 | 4 | 15 | 14 |
| P3 | 2 | 2 | 11 | 9 |
| P4 | 3 | 1 | 9 | 6 |

平均周转时间 = (8+14+9+6)/4 = 37/4 = **9.25**。

> 干扰项 D（11.0）是把 SJF 误当 **FCFS** 的结果：FCFS 顺序 P1→P2→P3→P4，完成于 8、12、14、15，周转时间 8、11、12、12，平均 = 43/4 = 10.75。**把 SJF 与 FCFS 两种调度顺序各完整跑一遍，是避免混淆的唯一办法**：SJF 的关键在"**t=8 时才选最短**"，不是一开始就按时间最短排序。

### 第二部分：计算机网络

**7. A**｜`[子网划分 5 步法 / 二轮重点：子网划分 5 步法（网络/广播/可用主机 2^h−2）+ CIDR 聚合]`

5 步法：
1. **定主机位**：每个子网至少 25 台主机 → 主机位 h 需满足 2^h − 2 ≥ 25 → h = 5（2⁵−2 = 30 ≥ 25；2⁴−2 = 14 < 25）；
2. **定网络位**：C 类 /24 原有 24 位网络号，借走 32−24−5 = **3 位作子网号** → 新前缀 **/27**；
3. **写掩码**：/27 → 255.255.255.**224**（224 = 1110 0000，借了 3 位）；
4. **块大小** = 256 − 224 = 32 → 各子网网络地址为 .0、.32、.64、……
5. **子网数** = 2³ = **8 个**，每个子网可用主机数 = 30。

> 干扰项 B（/28，16 个子网）：每个子网只有 2⁴−2 = 14 台主机，**不满足"至少 25 台"**；C（/26）每个子网 62 台但只有 4 个子网，若题目只要求"至少 25 台且子网尽量多"，/27 才是正确解。

**8. C**｜`[CIDR 路由聚合 / 二轮重点：子网划分 + CIDR 聚合（2^k 个网络 → 前缀减 k）]`

- 聚合 **2^k 个**网络 → 前缀长度**减 k**；本题 4 = 2² 个网络 → /24 − 2 = **/22**；
- 聚合后的地址取这些网络的**共同前缀**：192.168.0.0 ~ 192.168.3.0 的第三个字节为 0(0000 0000)、1(0000 0001)、2(0000 0010)、3(0000 0011)，共同前 6 位为 `000000` → 第三字节为 **0**；
- 故聚合结果为 **192.168.0.0/22**，包含 2¹⁰ − 2 = 1022 个可用主机地址。

> 规律：**N 个连续且共下一跳的网络若能聚合，N 必须是 2 的幂**，且起始地址必须落在块边界上（本题 192.168.0.0 恰是 /22 的块起点）。若起始地址不是块边界（如 192.168.1.0 ~ 192.168.4.0），则**不能**一次聚合。

**9. B**｜`[协议层级归属 / 二轮重点：协议层级归属（ARP/ICMP = 网络层）+ 必背端口号]`

- **ARP（地址解析协议）**与 **ICMP（网际控制报文协议）**都工作在 **TCP/IP 的网络层（网际层/IP 层）**；
- 高频陷阱：ARP 报文**不封装在 IP 数据报中**（它由以太网帧直接承载），因此极易被误判为数据链路层；但 ARP 的职责是**将 IP 地址解析为 MAC 地址**，服务于 IP 协议，软考按**网络层**归属；
- 同层的还有 **RARP、IGMP、OSPF、RIP（用 UDP 承载但属网络层路由协议）**；ICMP 的典型应用 **ping、traceroute** 都跑在网络层之上。

**10. D**｜`[加密算法参数与数字签名 / 二轮重点：加密算法参数（DES 56/64、3DES 168、AES 分组 128）+ 数字签名不提供机密性]`

- A 正确：DES 分组 64 位、有效密钥 56 位（64 位中去掉 8 位校验位）；3DES 用两个或三个独立密钥，有效密钥 **168** 位；
- B 正确：AES **分组长度固定 128 位**，密钥 128/192/256 位对应轮数 **10/12/14** 轮；
- C 正确：MD5 摘要 **128** 位、SHA-1 **160** 位、SHA-256 **256** 位；
- **D 错误**：数字签名用**发送方私钥**签名，提供的是**身份认证、报文完整性、抗否认（不可抵赖）**，**不提供机密性**——任何拿到公钥的人都能验证并看到明文。需要保密时应"先加密、后签名"或使用数字信封（用对称密钥加密内容、再用对方公钥加密该对称密钥）。

**11. A**｜`[拥塞控制 / 二轮重点：拥塞控制 cwnd（超时回 1 vs 重复 ACK 减半）]`

- 两种丢包判据的处理方式**恰好相反**，必须先判判据再选公式：
  - **超时**（重传计时器超时）→ 判定"网络严重拥塞"→ **慢开始**：ssthresh = cwnd/2 = 24/2 = **12**，**cwnd = 1**；
  - **3 个重复 ACK**（快重传）→ 判定"只是个别报文丢失"→ **快恢复**：ssthresh = cwnd/2 = **12**，**cwnd = ssthresh = 12**（不回 1）。

> 记忆：**"超时回 1，重复 ACK 减半"**——这里的"减半"指 cwnd **设为减半后的值**（= 新 ssthresh），而不是从 1 开始慢慢爬。两个数字必须成对记：(12, 1) 与 (12, 12)。

### 第三部分：数据库

**12. B**｜`[聚合与 NULL / 二轮重点：聚合与 NULL（COUNT(*) / COUNT(列) / AVG 分母）]`

- `COUNT(*)` 统计**所有行**（含 NULL）= **4**；
- `COUNT(成绩)` 统计**成绩非 NULL** 的行 = **3**；
- `AVG(成绩)` = (90+80+70) / **3** = 240/3 = **80**（**分母不含 NULL 行**）。

> 干扰项 C（4，3，60）的 60 = 240/4，是把 NULL 行算进分母的结果——这是本考点的**标准陷阱**。四个数字必须脱口而出：**COUNT(*) 数行、COUNT(列) 数非空、SUM 忽略 NULL、AVG 分母只算非空**。

**13. C**｜`[JOIN 类型与行数 / 二轮重点：JOIN 类型与行数（左外 = 匹配 + 左表无匹配）]`

- **自然连接（内连接）**：只保留两表**匹配**的行 = **3**；
- **左外连接**：保留 R 的**全部 5 行** = 3 匹配 + 2 行右侧补 NULL = **5**；
- **右外连接**：保留 S 的**全部 4 行** = 3 匹配 + 1 行左侧补 NULL = **4**；
- **完全外连接**：3 匹配 + 2 仅左 + 1 仅右 = **6**。

> 口诀：**内连接不产生无匹配行；外连接的行数 = 匹配行 + 保留表的无匹配行**。判断"某个一行都没匹配的实体在结果中是否出现"——**内连接：不出现；左外连接：出现（右列全 NULL）**。

**14. C**｜`[候选码求解 / 二轮重点：候选码求解（L/N/R/LR 分类 + 闭包，多候选码要求全）]`

属性分类（只出现在左的为 L 类，只出现在右的为 R 类，两边都出现的为 LR 类）：
- **R 类**：D（只在右）→ **不在任何候选码中**；
- **L 类**：无；**LR 类**：A、B、C。

逐个求单属性闭包：
- A⁺ = A →(A→B) B →(B→C) C →(A→D) D = **{A,B,C,D} = U** ✓
- B⁺ = B → C → A → D = **U** ✓
- C⁺ = C → A → B → D = **U** ✓
- D⁺ = {D} ≠ U ✗

故候选键为 **{A}、{B}、{C}，共 3 个**。

> 本题的**最大错误源是"只求出一个候选码就停"**——看到 A 是候选码就选 A。凡是属性集能互相推出的（环形依赖链），往往有**多个**候选码；单属性逐一求闭包是最稳的做法。N 类（只在右）属性一定不在候选码中，这是"求全"的第一步筛除。

**15. C**｜`[范式判断 / 二轮重点：范式判断 5 步流程 / 3NF 与 BCNF 分界]`

5 步流程：
1. **求候选码**：A⁺=A ≠ U，B⁺=B ≠ U，C⁺={B,C} ≠ U；**AB**⁺ = {A,B,C} = U ✓，**AC**⁺ = {A,B,C} = U ✓（去掉 A 或 C 均不再 = U）→ 候选码 **AB、AC**，共两个；
2. **原子性**：所有属性不可再分 → 满足 **1NF**；
3. **部分依赖**：F 中无单属性码能决定其它属性（两个候选码都是复合码）→ **无部分函数依赖** → 满足 **2NF**；
4. **传递依赖**：不存在 X→Y、Y→Z（Y 不决定 X）的链 → 满足 **3NF**；另一种判法：**所有属性都是主属性**（A、B、C 都出现在某个候选码中），直接满足 3NF；
5. **BCNF**：检查每个依赖的左部是否含码——**C→B 的左部 C 不是候选码**（C⁺ = {B,C} ≠ U）→ 违反 BCNF。

故 R 最高满足 **3NF，但不满足 BCNF**。

> 这是 3NF/BCNF 分界的经典模型，务必记住判据：**BCNF 要求每个函数依赖的左部都必须包含候选码**；"全主属性"可保证 3NF 但**不能**保证 BCNF。

**16. D**｜`[E-R 转关系模式 / 二轮重点：E-R 转关系模式（M:N 独立建表 / 1:N 外键在 N 端 / 联系属性不丢）]`

- **1:1**：可独立建表，也可并入任一端（并入时把另一端主键作外键 + 联系自身属性一起带入）；
- **1:N**：通常并入 **N 端**（把 1 端主键作外键放在 N 端关系里）——外键加错端是常见扣分点；
- **M:N**：**必须**独立建表，属性 = 两端实体主键（作外键）+ 联系自身属性，**主键必须是两端主键的组合**；
- D 错：M:N 联系若只在两端各加外键，无法表达"哪个 A 与哪个 B 发生联系"，且联系自身的属性（如选课的"成绩""选课时间"）无处安放。

### 第四部分：计算机组成

**17. B**｜`[不等长段流水线 / 二轮重点：不等长段流水线（T = Σt+(n−1)Δt / E = S/k）+ 已知 S 反求 n]`

- 流水线周期 Δt = **最长功能段** = 150ns；
- 第 1 条指令按各段**实际时间之和**走完全程：Σt = 50+100+150+100+50 = **450ns**；
- 总时间 **T = Σt + (n−1)·Δt = 450 + (20−1)×150 = 450 + 2850 = 3300ns**；
- 效率 **E = n·Σt / (k·T)** = 20×450 / (5×3300) = 9000/16500 = **0.5454 ≈ 54.5%**。

> 干扰项 C（83.3%）是**误用等长段公式** E = n/(k+n−1) = 20/24 = 83.3% 的结果——**该公式只适用于各段时间相等的情况**。不等长段必须用定义式 E = n·Σt/(k·T)。另：加速比 S = n·Σt/T = 9000/3300 ≈ 2.73（本题未问），**任何效率 > 100% 的答案必错**。

**18. B**｜`[Cache 三种映射地址结构 / 二轮重点：Cache 三种映射地址结构（全相联无"字块内地址"字段）]`

位数守恒律（主存地址位数 = Tag + 组号/行号 + 块内偏移）：
- 主存 16MB = 2²⁴ B → 主存地址 **24 位**；
- 块大小 64B = 2⁶ → **块内偏移 6 位**；
- Cache 行数 = 64KB/64B = **1024 行**；**4 路组相联** → 组数 = 1024/4 = **256 = 2⁸** → **组号 8 位**；
- **Tag = 24 − 6 − 8 = 10 位**。

对照（同一配置下三种映射，位数守恒自查）：

| 映射方式 | 块内偏移 | 行号/组号 | Tag | 说明 |
|---------|---------|----------|-----|------|
| 直接映射 | 6 | 10（行号） | **8** | Tag = 24−6−10 |
| 全相联映射 | 6 | **0（无行号字段）** | **18** | 地址 = Tag + 偏移 |
| 4 路组相联 | 6 | 8（组号） | **10** | Tag = 24−6−8 |

> 高频陷阱：**全相联映射没有"行号/字块号"字段**，全部高位都是 Tag——看到选项里全相联的 Tag 比直接映射多 10 位（行号位数），就要意识到这是"无行号字段"造成的。

**19. A**｜`[Cache 命中率 / 二轮重点：Cache 命中率（t_a = h·t_c+(1−h)·t_m）/ S = t_m/t_a 与 e = t_c/t_a / 反求 h]`

- 平均访问时间 **t_a = h·t_c + (1−h)·t_m** = 0.9×20 + 0.1×80 = 18 + 8 = **26ns**；
- 加速比 **S = t_m / t_a** = 80/26 ≈ **3.08**；
- 效率 **e = t_c / t_a** = 20/26 ≈ **76.9%**（等价公式 e = 1/(h + (1−h)·r)，其中 r = t_m/t_c = 4：e = 1/(0.9+0.1×4) = 1/1.3 ≈ 76.9%，两式互为交叉验证）。

> 干扰项 D（e = 90%）误把命中率当效率；B（S = 4.0）误用 S = t_m/t_c。**记住两条硬边界：加速比可以 >1，效率永远 ≤100%**。反求命中率的万能公式：**h = (t_m − t_a)/(t_m − t_c)**（如本题要求 t_a ≤ 38ns → h ≥ (80−38)/(80−20) = 42/60 = 70%）。

**20. A**｜`[总线带宽 / 二轮重点：总线带宽 = 频率 × 宽度/8]`

- 总线带宽 = 总线工作频率 × 数据总线宽度（位）；
- 100MHz × 32 位 = 100 × 10⁶ × 32 = 3200 × 10⁶ **位/秒（兆位/秒）**；
- 换算为字节：3200 兆位/秒 ÷ 8 = **400 MB/s**。

> 干扰项 B（3200 MB/s）是**忘记除以 8** 的结果——这是本题型的头号陷阱：题目若问"MB/s"必须 ÷8，若问"兆位/秒"则不除。公式记死：**带宽（MB/s）= 频率（MHz）× 宽度（位）/8**。

### 第五部分：软件工程

**21. C**｜`[V 模型四对对应 / 二轮重点：V 模型四对对应（需求↔验收 / 概设↔系统 / 详设↔集成 / 编码↔单元）]`

V 模型的四对对应（必背）：

```
需求分析 ↔ 验收测试      （易错点：不是"系统测试"）
概要设计 ↔ 系统测试      （本题答案）
详细设计 ↔ 集成测试      （易错点：不是"单元测试"）
编  码   ↔ 单元测试
```

> 记忆链：**越靠左的开发文档对应越靠右的测试阶段**——需求是最早的文档，对应最晚的验收测试；详细设计比概要设计更细，对应更底层的集成测试。最常见错误是把"概要/详细设计"与"系统/集成测试"的配对颠倒。

**22. A**｜`[软件维护四类型判别 / 二轮重点：维护四类型判别（完善性 vs 适应性）]`

- **适应性维护**：为使软件**适应外部环境/技术环境的变化**而修改（利率政策调整、操作系统升级、硬件换代、法规变更）；
- **完善性维护**：为**满足用户的新需求、改进性能或增强功能**而修改（新增"理财产品推荐"、加新报表、加快查询）——这类维护在四类中**占比最高（约 50% 甚至更多）**；
- 正确性维护 = 改错误；预防性维护 = 为提高可维护性而主动修改。

> 判别两步法：**①"用户想要更多/更好" → 完善性；②"环境变了" → 适应性**。题干里"政策调整"是环境信号，"应客户要求新增功能"是需求信号。

**23. A**｜`[螺旋模型 / 二轮重点：螺旋模型 = Boehm 1988 = 风险驱动 + 四象限顺序]`

螺旋模型（Boehm，1988）将瀑布模型与演化模型结合，**以风险驱动**，每个螺旋周期（四象限）按固定顺序：

```
制定计划 → 风险分析 → 实施工程 → 客户评估
```

- **制定计划**：确定目标、备选方案与约束；
- **风险分析**：评估备选方案、识别风险、用原型等手段消除风险；
- **实施工程**：瀑布式的开发与验证；
- **客户评估**：评估成果、规划下一周期（**客户评估是每圈的收尾，不是起点**——D 选项把它放最前，错）。

> 易错点：**客户评估在最后**；且螺旋模型的特点是**风险驱动**，不是"快速提供初始版本"（那是原型/增量模型）。

### 第六部分：数据结构

**24. D**｜`[排序稳定性与建堆 / 二轮重点：排序稳定性（不稳定 = 快选希堆）+ 建堆 O(n)]`

- A 正确：**不稳定排序 = 快速、简单选择、希尔、堆**（口诀：**"快选希堆"**）；
- B 正确：建堆从第 ⌊n/2⌋ 个非叶子结点起向前调整，时间复杂度为 **O(n)**（**不是** O(nlgn)）；
- C 正确：归并排序稳定，时间复杂度 O(nlgn)，空间复杂度 O(n)；
- **D 错误**：快速排序**不稳定**（交换基准时可能改变相等元素的相对次序）。

**25. D**｜`[AOE 网与关键路径 / 二轮重点：图算法（关键路径 ve 取 max、vl 取 min）]`

- A 正确：关键路径是**最长路径**，其长度 = **最短工期**；
- B 正确：关键活动的总时差 = 0（最早开始 = 最迟开始），缩短关键活动才能缩短工期；
- C 正确：AOE 网必有关键路径，关键路径上的活动都是关键活动；
- **D 错误**：非关键活动有总时差 > 0，缩短它**只是在时差范围内**，**不能缩短整个工期**——只有缩短**关键活动**（且当缩短后该活动仍在某条关键路径上）才能缩短工期。

> ve/vl 记死：**ve（最早）从源点向后取 max，vl（最迟）从汇点向前取 min**；活动总时差 = vl(终点) − ve(起点) − 活动时长。AOV 网与 AOE 网别混：**AOV 顶点 = 活动**（用拓扑排序），**AOE 边 = 活动**（用关键路径）。
