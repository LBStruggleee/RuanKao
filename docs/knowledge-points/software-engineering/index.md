# 软件工程 - 知识点精讲

## 一、软件生命周期

### 1.1 软件生命周期阶段
```
问题定义 → 可行性研究 → 需求分析 → 概要设计 → 详细设计 → 编码 → 测试 → 运行维护
```

### 1.2 开发模型

| 模型 | 特点 | 适用场景 |
|------|------|---------|
| 瀑布模型 | 线性顺序 | 需求明确 |
| 增量模型 | 分批交付 | 需求可分优先级 |
| 螺旋模型 | 迭代+风险分析 | 大型高风险项目 |
| 敏捷开发 | 小步快跑 | 需求变化频繁 |
| 喷泉模型 | 迭代无间隙 | 面向对象开发 |

### 1.3 敏捷开发
- **核心价值观**：个体和互动 > 流程和工具；可工作的软件 > 详尽的文档；客户合作 > 合同谈判；响应变化 > 遵循计划
- **Scrum框架**：
  - Sprint（迭代周期，通常2-4周）
  - Product Backlog（产品待办列表）
  - Sprint Backlog（迭代待办列表）
  - Daily Scrum（每日站会）
  - Sprint Review（迭代评审）
  - Sprint Retrospective（迭代回顾）

## 二、需求分析

### 2.1 需求分析方法
- **结构化分析方法（SA）**：数据流图 + 数据字典
- **面向对象分析方法（OOA）**：用例图 + 类图

### 2.2 数据流图（DFD）
- 外部实体（方形）
- 处理过程（圆角矩形）
- 数据流（箭头）
- 数据存储（开口矩形）
- 父图与子图（平衡）

### 2.3 用例图
- 参与者（Actor）
- 用例（Use Case）
- 关系：关联、包含（<<include>>）、扩展（<<extend>>）、泛化

## 三、软件设计

### 3.1 设计原则
- **高内聚低耦合**：核心目标
- **模块化**：模块独立性
- **抽象**：提取共性
- **信息隐蔽**：封装

### 3.2 耦合类型（从强到弱）
1. 内容耦合：一个模块直接访问另一个模块内部
2. 公共耦合：共享全局数据
3. 控制耦合：一个模块控制另一个模块的逻辑
4. 标记耦合：通过参数传递数据结构
5. 数据耦合：仅通过参数传递数据（最理想）

### 3.3 内聚类型（从弱到强）
1. 偶然内聚：模块内各部分无关联
2. 逻辑内聚：完成相似功能
3. 时间内聚：同时执行
4. 过程内聚：按顺序执行
5. 通信内聚：使用相同数据
6. 顺序内聚：前模块输出是后模块输入
7. 功能内聚：完成单一功能（最强）

## 四、UML建模

### 4.1 UML图类型
| 图类型 | 用途 | 关键元素 |
|--------|------|---------|
| 用例图 | 功能需求 | 参与者、用例 |
| 类图 | 静态结构 | 类、属性、方法、关系 |
| 顺序图 | 交互顺序 | 对象、生命线、消息 |
| 状态图 | 对象状态 | 状态、转换、事件 |
| 活动图 | 业务流程 | 活动、分支、同步 |
| 组件图 | 组件依赖 | 组件、接口 |
| 部署图 | 物理部署 | 节点、组件 |

### 4.2 类图关系
| 关系 | 表示 | 含义 |
|------|------|------|
| 关联 | 实线 | 使用关系 |
| 聚合 | 空心菱形+实线 | 整体-部分（弱拥有） |
| 组合 | 实心菱形+实线 | 整体-部分（强拥有） |
| 依赖 | 虚线+箭头 | 使用另一个类 |
| 泛化 | 空心三角+实线 | 继承 |
| 实现 | 空心三角+虚线 | 实现接口 |

## 五、测试

### 5.1 测试分类

#### 黑盒测试（功能测试）
- 等价类划分
- 边界值分析
- 因果图
- 错误推测法

#### 白盒测试（结构测试）
- 语句覆盖
- 判断覆盖
- 条件覆盖
- 判定/条件覆盖
- 条件组合覆盖
- 路径覆盖

### 5.2 测试覆盖强度（从弱到强）
语句覆盖 < 判断覆盖 < 条件覆盖 < 判定/条件覆盖 < 条件组合覆盖 < 路径覆盖

### 5.3 测试阶段
1. **单元测试**：模块级（白盒为主）
2. **集成测试**：模块组装（黑盒+白盒）
3. **系统测试**：整个系统（黑盒为主）
4. **验收测试**：用户验收

### 5.4 测试方法
- **静态测试**：代码审查、走查（不运行程序）
- **动态测试**：实际运行程序
