## 答案与解析

### 第一部分：信息安全

**1. C** 对称加密的加密与解密**使用同一个密钥**，优点是**速度快**、适合加密大量数据，缺点是**密钥必须安全地分发给对方**（n 个人两两通信需 n(n−1)/2 个密钥）。A、B 把两者的密钥特征**说反了**；D 也反了——**非对称加密计算复杂、速度远慢于对称加密**，所以它只用于加密小数据（如会话密钥）和数字签名。
（知识点：对称 vs 非对称；对应 `day06-security.md` §四）

**2. B** **AES 的分组长度固定为 128 位**，与密钥长度无关；**密钥长度可以是 128/192/256 位**（对应 AES-128/192/256，轮数分别为 10/12/14）。这是**最高频的易错点**：题目故意把"分组长度"和"密钥长度"混在一起。A 选项"分组长度可变"是错的；D 选项 AES 是**对称**算法，不是非对称。
（知识点：AES 参数；对应 `day06-security.md` §2.1）

**3. C** **DES 的输入密钥是 64 位，但其中 8 位是奇偶校验位，实际参与加密的有效密钥是 56 位**；明文**分组长度为 64 位**。这是最容易把"56 和 64"记混的一对数字：**有效密钥 56 位，分组 64 位**。
（知识点：DES 参数；对应 `day06-security.md` §2.1）

**4. C** 3DES 用 **3 个 56 位密钥**（K1、K2、K3）做"加密-解密-加密"（EDE），**总密钥长度 = 3 × 56 = 168 位**。D 选项 192 位 = 3 × 64，错在**把含校验位的 64 位输入当成有效密钥**；B 选项 112 位是 **2 密钥 3DES**（K1=K3）的长度——题目明确说"3 个互不相同的密钥"，故不选 B。
（知识点：3DES 参数；对应 `day06-security.md` §2.1）

**5. D** **用接收方公钥加密、接收方私钥解密**，保证"只有接收方能看懂"，实现的是**机密性**。A（数字签名）和 C（抗否认）都是**用发送方私钥加密/签名**实现的；B（完整性）要靠**报文摘要/HMAC/数字签名**，单纯加密并不自动提供完整性。**"公钥加密 = 机密性；私钥签名 = 认证/抗否认"是必须分清的两条路线。**
（知识点：非对称加密的两种用法；对应 `day06-security.md` §3.1、§7.3）

**6. B** 数字信封的流程是：发送方随机生成对称会话密钥 K，**用 K 加密明文**，再用**接收方的公钥加密 K**，把"加密后的 K"（即信封）随密文一起发送。接收方用**自己的私钥拆开信封**得到 K，再用 K 解密。A 错（用发送方私钥加密 K，接收方无法解开）；C 描述的是"用 K 加密明文"这一步，不是信封本身；D 错——数字信封只保证**机密性**，**抗否认要靠数字签名**（§7）。
（知识点：数字信封；对应 `day06-security.md` §5）

**7. D** **MD5 的输出摘要长度固定为 128 位**。C 的 160 位是 **SHA-1**；B 的 256 位是 **SHA-256**。必背的三个长度：**MD5 = 128、SHA-1 = 160、SHA-256 = 256**。MD5 虽已被破解（可构造碰撞）、不能用于安全签名，但仍广泛用于**文件完整性校验**。
（知识点：摘要算法输出长度；对应 `day06-security.md` §6.2）

**8. B** 报文摘要的**核心性质是单向性（不可逆）**——**由摘要无法还原出原文**，这正是摘要与加密的根本区别（加密是可逆的）。B 说"可以还原"，显然错误。A、C、D 都正确：定长输出、雪崩效应、MD5/SHA-1 同属摘要算法。
（知识点：报文摘要的性质；对应 `day06-security.md` §6.1）

**9. D** 数字签名是**发送方用自己的私钥对报文摘要加密**生成签名，接收方用**发送方的公钥**验证。因为私钥只有发送方有，所以能保证**身份认证**（验得过 = 确实是他签的）、**抗否认**（他赖不掉）和**完整性**（报文被改，验证必失败）。A、C 选项的共同错误是**"数字签名保证机密性"**——签名是"盖章"，报文仍是明文，**机密性必须靠加密**；B 错在用"公钥签名"。
（知识点：数字签名原理；对应 `day06-security.md` §7）

**10. A** 数字证书的作用是把"**身份与其公钥**"绑定在一起，由 **CA 用自己的私钥对这组信息签名**后签发。验证时用 **CA 的公钥**验证签名——**信任 CA，就信任 CA 签发的证书**。B 选项错得最离谱：证书里放的是**公钥**，私钥绝不能出现在证书里；C 错在签名主体（申请人若能自己签名，证书就没有公信力）；D 错——证书有**有效期**，且可通过 **CRL/OCSP** 提前吊销。
（知识点：PKI/CA 与证书；对应 `day06-security.md` §8）

**11. B** HTTPS 的核心设计就是**性能与安全的平衡**：**握手阶段用非对称加密**（客户端用服务器公钥加密预主密钥，安全地协商出对称会话密钥），**之后所有应用数据都用对称密钥加密**（对称加密快，适合大量数据）。A 错（非对称太慢，不可能全程用）；C 错（是**客户端用服务器公钥**加密，不是"服务器用客户端公钥"）；D 错（会话密钥**每次连接重新协商、用完即弃**）。
（知识点：HTTPS/TLS 握手；对应 `day06-security.md` §十）

**12. C** **XSS 是"在受害者浏览器里执行攻击者注入的脚本"**（偷 Cookie/会话），**根本防御是输出转义（HTML 实体编码）**；**CSRF 是"借受害者的登录身份发送攻击者构造的请求"**，**根本防御是 Token / SameSite Cookie / 验证 Referer**。A 把两者的防御手段配错了；B 描述的是 XSS 而非 CSRF；D 错——**CSRF 必须建立在受害者已登录目标网站**的前提上，否则没有可盗用的身份。**一句话区分：XSS 在你浏览器里跑我的代码，CSRF 用你的身份发我的请求。**
（知识点：XSS 与 CSRF 的区分；对应 `day06-security.md` §11.1）

**13. C** **参数化查询（预编译语句）**把用户输入严格当作**数据参数**而非 SQL 代码的一部分，从原理上杜绝了 SQL 拼接注入，是**最根本**的防御。A 错——**只在客户端校验远远不够**（攻击者可绕过客户端直接构造请求）；B（隐藏错误信息）只是**降低信息泄露**、便于攻击者盲注，属于辅助手段；D 与 SQL 注入无关。
（知识点：SQL 注入防御；对应 `day06-security.md` §11）

**14. C** 重放攻击的特征是"**报文本身合法、只是被重复发送**"，所以单纯加密、摘要、加长密钥都拦不住——必须让报文**具有"一次性"特征**：**时间戳**（过期作废）、**随机数挑战/应答**（每次不同）、**一次性令牌 nonce**（用过即失效）。A 选项报文摘要只能防"篡改"，不能防"原样重放"；B、D 与重放无关。
（知识点：重放攻击与防御；对应 `day06-security.md` §11）

**15. D** **IDS 是"摄像头"**：**旁路部署**（镜像流量，不在转发路径上），发现入侵后**只记录、告警，不阻断**；**IPS 是"保安"**：**串联部署**（在数据转发路径上），能够**实时丢弃恶意包、阻断连接**，因此对延迟和可用性要求更高。A、B 把两者的部署方式与响应方式**分别说反了**；C 显然错误。
（知识点：IDS vs IPS；对应 `day06-security.md` §13）

### 第二部分：网络综合

**16. B** **IPSec 工作在网络层（IP 层）**，对所有 IP 报文提供保护，与上层应用无关，是 VPN 的主力；**SSL/TLS 工作在传输层之上、应用层之下**（在 OSI 中对应会话层/表示层的位置），为应用层数据提供加密，**HTTPS = HTTP + TLS**。这两个层级是**安全协议归属题**的最高频考点，务必记牢。
（知识点：安全协议的层级归属；对应 `day06-security.md` §九）

**17. A** **HTTPS = 443**、**SSH = 22**、**SNMP = 161**（SNMP 默认用 UDP）。B 的 23 是 **Telnet**（不安全的远程登录，SSH 的前身）、162 是 SNMP 的 **Trap** 端口（代理主动发陷阱报文给管理站）；C 的 80 是 **HTTP**；D 的 110 是 **POP3**（收邮件）。
（知识点：常见端口号；对应 `day04-protocols.md` §七）

**18. B** 主机 A 用掩码算出 8.8.8.8 **不在本网段**，于是把数据包交给**默认网关 192.168.10.1**。以太网帧按 MAC 封装，因此 ARP 解析的是**默认网关（路由器在本网段接口）的 MAC 地址**，而**不是**目的服务器的 MAC。A 是最典型的错误——目的服务器在**另一个链路**上，本网段的 ARP 广播根本到不了它；此后每一跳路由器都会重新解析下一跳的 MAC，但目的 MAC 在本网段永远是网关的。IP 头中的目的 IP 始终是 8.8.8.8 不变。
（知识点：默认网关与 ARP 的关系；对应 `day05-tcp.md` §9.4）

**19. A** 用 5 步法：
```
① /22 → 掩码 255.255.252.0，第三段块大小 = 256 − 252 = 4，h = 32 − 22 = 10
② 第三段：100 ÷ 4 = 25 余 0 → 25 × 4 = 100 → 网络地址 = 172.16.100.0
③ 广播地址：第三段 = 100 + 4 − 1 = 103；第四段（掩码为 0）全 1 → 255
   ∴ 广播地址 = 172.16.103.255
```
二进制验证：100 = 01100100，第三段掩码 252 = 11111100，AND = 01100100 = 100 ✓
**易错点**：B 选项（172.16.96.0）是块大小取成 16（误当 /20）的结果；C 选项（广播 172.16.100.255）是"把最后一段改 255、忘了第三段主机位也要置 1"的典型错误；D 选项两个都算错了（块大小按 4 但起始对齐错）。**广播地址必须是全部主机位置 1，即网络地址 + 块大小 − 1。**
（知识点：网络地址与广播地址计算；对应 `day05-tcp.md` §八 模板第 2、3 步）

**20. B**
```
4 个 /24 连续网络要聚合 → 2^k = 4 → k = 2 → 前缀 = 24 − 2 = 22
检查块对齐：第三段 0、1、2、3 = 00000(000/001/010/011)，前 6 位都相同（000000）
∴ 聚合后 = 172.16.0.0/22（掩码 255.255.252.0）
```
验证：/22 第三段块大小 = 4 → 覆盖 172.16.0.0 ~ 172.16.3.255，正好 4 个 /24 ✓
A 选项 /23 只能合并 2 个网络；C、D 前缀太短（合并 8 个/16 个）。**规律：合并 2^k 个连续网络，前缀减 k。**
（知识点：CIDR / 路由聚合；对应 `day05-tcp.md` §9.2）

**21. A** 先理清增长过程，再处理丢包：
```
慢开始（指数）：cwnd = 1 → 2 → 4 → 8（达到 ssthresh=8，转拥塞避免）
拥塞避免（线性）：cwnd = 9 → 10 → 11 → 12
在 cwnd = 12 时收到 3 个重复 ACK → 快重传 + 快恢复：
   ssthresh = cwnd / 2 = 12 / 2 = 6
   cwnd = ssthresh = 6（减半，但不回到 1）
此后从 6 开始按拥塞避免线性增长
```
**易错点**：B 选项（cwnd = 1）是**超时**的处理——**"超时回 1，重复 ACK 减半"**。超时说明网络严重拥塞，要狠狠降；3 个重复 ACK 说明只是偶发丢一包，网络基本通畅，温和降即可。C 选项 ssthresh 没变、D 选项 cwnd 没降，都不符合快恢复的规则。
（知识点：快重传与快恢复 vs 超时；对应 `day05-tcp.md` §6.2、§6.3）

**22. B** **AH（认证头）只提供数据完整性、身份认证和防重放，不提供加密（不保证机密性）**；**ESP（封装安全载荷）提供加密，以及完整性、认证与防重放**。简单记：**"AH 只认证不加密，ESP 又加密又认证"**，所以需要机密性时必须用 ESP。D 错——**ESP 既可用于隧道模式也可用于传输模式**（AH 同样如此）。
（知识点：IPSec 的 AH 与 ESP；对应 `day06-security.md` §14.2）

**23. A** 在 TCP/IP 体系结构中，**ARP 与 ICMP 都属于网际层（网络层）**。B 错——**ARP 报文直接封装在以太网帧中**（不经 IP 封装），这正是有人误以为它属于链路层的原因，但**软考按网际层作答**；C 错——把 **IP 解析为 MAC** 的是 **ARP**，ICMP 的作用是**差错报告与网络控制**（ping 用的是 ICMP）；D 错（两者都不在链路层）。
（知识点：ARP 与 ICMP 的层级归属；对应 `day04-protocols.md` §2.3、§6.3）

**24. C** TLS 握手时，客户端生成**预主密钥**后，用**服务器的公钥**加密发送（ClientKeyExchange 消息）；服务器用**自己的私钥**解密得到预主密钥。随后双方用"客户端随机数 + 服务器随机数 + 预主密钥"派生出对称会话密钥。A 选项（客户端私钥）用于**数字签名**场景；B 选项（客户端自己的公钥）毫无意义——服务器没有客户端私钥，无法解密；D 选项（会话密钥）在握手阶段**尚未生成**。
（知识点：TLS 握手密钥协商；对应 `day06-security.md` §十）

**25. A** 完整的 HTTPS 访问流程：**先 DNS 解析域名得到 IP**（①）→ **再建立 TCP 连接**（②，三次握手，因为 TLS 跑在 TCP 之上）→ **然后在 TCP 连接上完成 TLS 握手**（③，协商出对称会话密钥）→ **之后才能发送 HTTP 请求**（④，经协议栈逐层封装：报文→报文段→IP 数据报→帧→比特）→ **服务器用会话密钥解密并返回加密响应**（⑤）。B 错（TCP 握手前必须先知道 IP，DNS 必须在前）；C 错（TLS 握手必须在 TCP 连接建立之后）；D 错（HTTP 请求必须经 TLS 加密，所以必须在 TLS 握手之后）。**这道题把 Day 4（分层/封装）、Day 5（TCP 握手）、Day 6（TLS）串成了一条完整链路。**
（知识点：HTTPS 全流程综合；对应 `day04-protocols.md` §五、`day05-tcp.md` §二、`day06-security.md` §十）
