# Day 4（9/24）计算机网络①：分层模型与协议归属

> 本笔记是 Day 4 的核心输入材料，对应软考「计算机网络」中的**网络体系结构**部分。
> **高频命题点**：OSI 七层 vs TCP/IP 四层对照（**必背**）、各层协议的层级归属判断（**出现频率最高的题型**）、封装/解封装过程、常见端口号。
> **本笔记不涉及 IP 地址与子网划分**——那是 Day 5（TCP/IP 与子网划分）的内容；TCP 三次握手/拥塞控制也在 Day 5。本笔记只解决一个问题：**谁在哪一层，数据怎么一层层传过去**。

---

## 一、为什么要分层

先理解"分层"到底在解决什么问题，否则七层模型只能死记硬背。

**问题**：网络通信极其复杂——网线上的电信号怎么变成网页？中间要经过不同厂家设备、不同物理介质、跨多个网络。如果写成一个"大程序"处理所有事情，任何一处改动都要重写整个系统。

**分层的解法**：把复杂功能拆成若干层，**每层只管一件事**，向上提供接口，向下使用下层服务。

- **各层之间是接口关系**：上层调用下层，下层为上层服务；上层不关心下层怎么实现。
- **同层之间是"虚通信"**：发送方第 N 层和接收方第 N 层好像直接对话（实际数据要一层层向下、上物理链路、再一层层向上），这叫**对等层通信**，它们遵守的规则就是**协议**。
- **好处**：各层独立设计、灵活替换（以太网换成 Wi-Fi 不影响 HTTP）、易于实现和维护。

> **⚠️ 易错点**：分层后，**每一层都有自己的头部（首部）**。数据从上往下走，每过一层就被加一个头，这叫**封装**。接收方逐层去掉头部，叫**解封装**。第六节有完整图解。

## 二、OSI 七层模型（逐层精讲）

OSI（Open Systems Interconnection，开放式系统互联）参考模型由 ISO 提出，共 **7 层**。**记忆顺序从下到上编号 1→7**：物理 1、链路 2、网络 3、传输 4、会话 5、表示 6、应用 7。

```
┌───────────────────────────────┐  ← 第 7 层（最高层，离用户最近）
│  7. 应用层 Application         │    HTTP / FTP / SMTP / DNS …
├───────────────────────────────┤
│  6. 表示层 Presentation        │    编码 / 加密 / 压缩
├───────────────────────────────┤
│  5. 会话层 Session             │    会话的建立、维持、终止
├───────────────────────────────┤
│  4. 传输层 Transport           │    TCP / UDP   ← 端到端（进程到进程）
├───────────────────────────────┤
│  3. 网络层 Network             │    IP / ICMP / ARP  ← 主机到主机（点对点）
├───────────────────────────────┤
│  2. 数据链路层 Data Link       │    Ethernet / PPP   ← 相邻节点（帧）
├───────────────────────────────┤
│  1. 物理层 Physical            │    比特流（电信号/光信号）  ← 最底层
└───────────────────────────────┘
        数据从应用层一层层向下 → 物理链路传输 → 对端一层层向上
```

### 2.1 第 1 层：物理层（Physical）

| 项目 | 内容 |
|------|------|
| **职责** | 在物理介质上**透明地传输比特流**。规定接口的机械、电气、功能、规程特性（如引脚定义、电压范围）。 |
| **数据单元** | **比特（Bit）** |
| **典型协议/标准** | RS-232、RJ-45 接口标准、100BASE-T、光纤标准（如 1000BASE-SX） |
| **典型设备** | 中继器（Repeater）、集线器（Hub） |
| **一句话** | 只管"0 和 1 怎么变成电信号发出去"，不关心这些比特的含义。 |

### 2.2 第 2 层：数据链路层（Data Link）

| 项目 | 内容 |
|------|------|
| **职责** | 把比特组装成**帧**，在**相邻两个节点**（主机↔交换机、路由器↔路由器）之间可靠传输；用 **MAC 地址**寻址；差错检测（FCS/CRC）；介质访问控制（谁能在共享链路上发数据）。 |
| **数据单元** | **帧（Frame）** |
| **典型协议** | 以太网（IEEE 802.3）、Wi-Fi（IEEE 802.11）、PPP（点对点协议）、HDLC、CSMA/CD |
| **典型设备** | 网桥（Bridge）、（二层）交换机（Switch） |
| **寻址** | **MAC 地址（硬件地址，6 字节，如 08:00:27:71:9c:a2）** |

> **⚠️ 易错点**：链路层只在**相邻节点**间一跳一跳传（点到点/hop-by-hop），而网络层负责**端到端**跨多个网络把包送到目的地。交换机看 MAC 地址转发，不认识 IP。

### 2.3 第 3 层：网络层（Network）

| 项目 | 内容 |
|------|------|
| **职责** | **路由选择**（为分组选一条到目的网络的路径）和**转发**；用 **IP 地址**实现**跨越多个网络的端到端**通信；拥塞控制；网络互联。 |
| **数据单元** | **分组 / 包 / IP 数据报（Packet / Datagram）** |
| **典型协议** | **IP**（IPv4/IPv6）、**ICMP**、**IGMP**、**ARP**、路由协议 RIP / OSPF / BGP、NAT |
| **典型设备** | 路由器（Router）、三层交换机 |

> **⚠️ 高频易错（几乎每年必考其一）**：
> - **ARP（地址解析协议）属于网络层**，不是数据链路层！它为 IP 服务，把 **IP 地址解析为 MAC 地址**（"已知 IP，求 MAC"）。ARP 报文**不封装在 IP 数据报里**（它直接封装在以太网帧里），这正是有人误把它归到链路层的原因；但按 TCP/IP 体系结构，ARP 与 IP 同属网际层。**软考按"网络层/网际层"作答。**
> - **ICMP 属于网络层**，不是应用层！ping、traceroute 是**应用层的程序**，但它们**使用网络层的 ICMP 协议**——"程序在应用层，协议在网络层"要分清。

### 2.4 第 4 层：传输层（Transport）

| 项目 | 内容 |
|------|------|
| **职责** | 向上提供**端到端（进程到进程）**的通信服务；用**端口号**区分同一主机上的不同应用；流量控制、差错控制、拥塞控制（TCP）；分段与重组。 |
| **数据单元** | **报文段（Segment，TCP）/ 用户数据报（Datagram，UDP）** |
| **典型协议** | **TCP**（面向连接、可靠）、**UDP**（无连接、不可靠）、SCTP |
| **关键概念** | **端口号（0–65535）**，放在 TCP/UDP 首部 |

> **⚠️ 易错点**：**端口号是传输层的概念**，只在 TCP/UDP 首部里；IP 首部里**没有端口号**（只有 IP 地址）。"HTTP 用 80 端口"严格说是"HTTP 默认使用传输层 TCP 的 80 端口"。
>
> **TCP vs UDP 一句话**：TCP 像打电话（先拨号建立连接、确认对方听清了、可靠但慢），UDP 像寄明信片（不建连接、不管对方收没收到、快但不保证可靠，适合视频/语音/广播）。详细机制（三次握手、滑动窗口、拥塞控制）见 Day 5。

### 2.5 第 5 层：会话层（Session）

| 项目 | 内容 |
|------|------|
| **职责** | 建立、管理、终止**会话**（两个应用之间的"对话"）；提供**同步点**（长传输出错时可以从同步点重传，而不是从头来）。 |
| **数据单元** | 报文（数据组织单位，无独立标准协议） |
| **典型协议** | OSI 概念层，TCP/IP 中**没有对应层**，其功能并入应用层 |

> **考试注意**：会话层没有"明星协议"，常考的是"OSI 的会话层负责什么"这类职责题——答"会话的建立、维持与终止/同步"。

### 2.6 第 6 层：表示层（Presentation）

| 项目 | 内容 |
|------|------|
| **职责** | **数据表示形式的转换**：编码转换（ASCII↔Unicode 等）、**数据加密与解密**、**数据压缩与解压**。解决"两端表示数据的方式不同"的问题。 |
| **数据单元** | 报文 |
| **典型协议/标准** | OSI 概念层；JPEG、GIF 等图像编码、ASCII、加密标准（如 TLS/SSL 常被归为表示层功能） |

> **⚠️ 易错点**：题目问"**加密、压缩、编码转换**属于 OSI 哪一层"——答**表示层**。这是表示层的标志性功能，几乎必考。

### 2.7 第 7 层：应用层（Application）

| 项目 | 内容 |
|------|------|
| **职责** | 直接为**用户的应用进程**提供网络服务；定义应用层报文的格式与交互规则。 |
| **数据单元** | **报文（Message）** |
| **典型协议** | **HTTP/HTTPS、FTP、SMTP、POP3、IMAP、DNS、Telnet、SSH、TFTP、SNMP、DHCP** |

> **⚠️ 易错点**：应用层是**离用户最近**的层，但**不是"用户"本身**——它服务的是进程（如浏览器进程）。DNS 同时是应用层协议（它有自己的报文格式、用 TCP/UDP 53 端口通信）。

## 三、TCP/IP 四层模型

OSI 是"理论上"的参考模型，**TCP/IP 才是互联网实际使用的协议体系**。它把 7 层压缩为 **4 层**：

```
┌───────────────────────────────────────┐
│  应用层 Application                    │  HTTP HTTPS FTP SMTP POP3 IMAP
│                                       │  DNS Telnet SSH TFTP SNMP DHCP
├───────────────────────────────────────┤   （合并了 OSI 的应用+表示+会话三层）
│  传输层 Transport                      │  TCP / UDP
├───────────────────────────────────────┤
│  网际层 Internet（网络层）              │  IP ICMP IGMP ARP NAT
│                                       │  RIP OSPF BGP
├───────────────────────────────────────┤
│  网络接口层 Network Interface          │  Ethernet Wi-Fi PPP ARP 的工作载体
│  （= OSI 的数据链路层 + 物理层）         │  （有些教材称"链路层/网络访问层"）
└───────────────────────────────────────┘
```

**TCP/IP 各层要点**：

| 层 | 职责 | 关键协议 | 寻址方式 |
|------|------|---------|---------|
| **应用层** | 应用报文格式与交互；包含 OSI 的表示、会话功能 | HTTP、DNS、SMTP 等 | 域名/URL |
| **传输层** | 进程到进程通信，端口区分应用 | TCP、UDP | **端口号** |
| **网际层** | 主机到主机跨网络通信、路由转发 | IP、ICMP、ARP | **IP 地址** |
| **网络接口层** | 相邻节点帧传输、比特流发送 | Ethernet、Wi-Fi、PPP | **MAC 地址** |

> **⚠️ 易错点（寻址链）**：IP 地址（网络层）→ MAC 地址（链路层）→ 端口号（传输层）。跨网络找主机用 **IP**，同一链路上找网卡用 **MAC**，找到主机后区分进程用**端口**。ARP 就是把 IP 翻译成 MAC 的"翻译官"。

## 四、OSI 七层 vs TCP/IP 四层对照表（必背）

这是**考试原表**，必须能默写：

| OSI 七层 | TCP/IP 四层 | 对应说明 | 该层典型协议 |
|---------|------------|---------|-------------|
| 应用层（7） | 应用层 | TCP/IP 把三层合一 | HTTP、FTP、SMTP、DNS、Telnet |
| 表示层（6） | ↑ 并入应用层 | 编码/加密/压缩 | —（概念层） |
| 会话层（5） | ↑ 并入应用层 | 会话管理 | —（概念层） |
| 传输层（4） | 传输层 | 一一对应 | TCP、UDP |
| 网络层（3） | 网际层 | 一一对应 | IP、ICMP、ARP |
| 数据链路层（2） | 网络接口层 | 两层合一 | Ethernet、PPP |
| 物理层（1） | ↑ 并入网络接口层 | 比特流传输 | RS-232 等 |

**另一种常考对照视角（含数据单元与设备）**：

| OSI 层 | 数据单元（PDU） | 典型设备 | 典型协议 |
|--------|---------------|---------|---------|
| 应用层 | 报文（Message） | —（应用程序） | HTTP、FTP、SMTP、DNS |
| 表示层 | 报文 | — | 加密、压缩、编码 |
| 会话层 | 报文 | — | 会话管理 |
| 传输层 | 报文段/数据报（Segment/Datagram） | （传输层网关） | TCP、UDP |
| 网络层 | 分组/包（Packet/IP 数据报） | **路由器** | IP、ICMP、ARP |
| 数据链路层 | **帧（Frame）** | **网桥、交换机** | Ethernet、PPP |
| 物理层 | **比特（Bit）** | **中继器、集线器** | 电气标准 |

> **⚠️ 易错点**：很多教材还用**五层混合模型**（应用/传输/网络/数据链路/物理）——它只是"教学用"的折中（把 TCP/IP 四层的网络接口层重新拆成两层）。题目若问"五层模型"，按此作答即可；**但题目明确问 TCP/IP 时，答案就是四层**。

## 五、封装与解封装全过程（必考，ASCII 图解）

**封装（发送方，自上而下）**：数据每经过一层，就被加上该层的**头部**（链路层还加**尾部**）。像套娃一样，一层层套上去。

**解封装（接收方，自下而上）**：逐层读取并去掉头部，把数据交给上层。

以"浏览器访问网页"（HTTP over TCP over IP over Ethernet）为例：

```
【发送方：封装过程】

 应用层：  浏览器生成 HTTP 请求报文
                ┌──────────────────────────────────┐
                │          HTTP 报文（数据）          │          ← 应用层 PDU：报文
                └──────────────────────────────────┘
                                  ↓ 加 TCP 首部
 传输层：        ┌──────┬───────────────────────────┐
                │ TCP  │     HTTP 报文（数据）        │          ← 传输层 PDU：TCP 报文段
                │ 首部 │  (源端口 1234 / 目的端口 80)  │             （UDP 则叫用户数据报）
                └──────┴───────────────────────────┘
                                  ↓ 加 IP 首部
 网络层：  ┌────┬──────┬───────────────────────────┐
          │ IP │ TCP  │     HTTP 报文（数据）        │          ← 网络层 PDU：IP 数据报/分组
          │首部│ 首部 │ (源 IP 192.168.1.5 → 目的 IP) │
          └────┴──────┴───────────────────────────┘
                                  ↓ 加帧头和帧尾
 链路层：┌──────┬────┬──────┬─────────────┬──────┐
        │帧头（源│ IP │ TCP  │ HTTP 报文    │ 帧尾 │      ← 链路层 PDU：帧
        │MAC→目的│首部│ 首部 │             │ FCS │         （FCS = 帧检验序列，CRC 差错检测）
        │MAC）  │    │     │             │      │
        └──────┴────┴──────┴─────────────┴──────┘
                                  ↓ 转成信号
 物理层：     0101011010011110... （比特流）          ← 物理层 PDU：比特
                                  ↓
                      ══════ 网线 / 光纤 / 无线 ══════


【接收方：解封装过程】（顺序完全相反，逐层去头）

 物理层：  收到比特流 0101011010... → 交给链路层
 链路层：  按 MAC 地址判断是给自己的帧 → 检查 FCS 无错 → 去掉帧头/帧尾 → 取出 IP 数据报 → 交给网络层
 网络层：  检查目的 IP 是本机 → 去掉 IP 首部 → 取出 TCP 报文段 → 交给传输层
 传输层：  按目的端口号 80 找到 Web 服务进程 → 去掉 TCP 首部 → 取出 HTTP 报文 → 交给应用层
 应用层：  Web 服务进程解析 HTTP 请求，返回网页
```

**关键结论（背死）**：

1. **封装 = 发送方逐层"加头"**；链路层**既加头又加尾**（FCS 校验码）。
2. **解封装 = 接收方逐层"去头"**，顺序与封装相反。
3. 每一层的**头部只给自己的对等层看**：发送方 TCP 加的序号、端口，只有接收方 TCP 会读取和处理；IP 首部只有两端的 IP 层处理——这就是**对等层虚通信**。
4. **链路层有尾部（FCS）**，其他层只有头部。这是唯一加尾部的层。
5. 路由器转发分组时：物理层→链路层→**网络层**（读 IP、查路由表、重新选下一跳）→链路层（重新封装成新帧）→物理层。**路由器只工作到网络层，不读 TCP/HTTP 头**；而交换机只工作到链路层（读 MAC）。

> **⚠️ 易错点**：数据在**发送侧**从应用层向物理层流动（逐层封装），在**接收侧**从物理层向应用层流动（逐层解封装）。数据"流动方向"在两侧相反，但**对等层之间是水平虚通信**。

## 六、各层协议归属总表（层级判断题专用）

### 6.1 应用层协议（用户看得见的服务）

| 协议 | 全称 | 作用 | 端口 | 传输层协议 |
|------|------|------|------|-----------|
| **HTTP** | 超文本传输协议 | 网页传输 | 80 | TCP |
| **HTTPS** | 安全的 HTTP | HTTP + **TLS/SSL 加密** | 443 | TCP |
| **FTP** | 文件传输协议 | 文件上传/下载 | **控制 21 / 数据 20** | TCP |
| **SMTP** | 简单邮件传输协议 | **发送**邮件 | 25 | TCP |
| **POP3** | 邮局协议第 3 版 | **接收**邮件（下载后服务器删除） | 110 | TCP |
| **IMAP** | 互联网邮件访问协议 | **接收**邮件（服务器端同步管理） | 143 | TCP |
| **DNS** | 域名系统 | 域名 → IP 解析 | **53** | **TCP + UDP** |
| **Telnet** | 远程登录协议 | 明文远程登录 | 23 | TCP |
| **SSH** | 安全外壳协议 | 加密远程登录 | 22 | TCP |
| **TFTP** | 简单文件传输协议 | 小文件传输（无连接） | 69 | **UDP** |
| **SNMP** | 简单网络管理协议 | 网络设备管理 | **161**（trap 162） | **UDP** |
| **DHCP** | 动态主机配置协议 | 自动分配 IP | **67（服务器）/ 68（客户端）** | **UDP** |

### 6.2 传输层协议（只有"两个半"）

| 协议 | 特点 | 典型应用 |
|------|------|---------|
| **TCP** | 面向连接、可靠、字节流、全双工 | HTTP、FTP、SMTP、Telnet、SSH |
| **UDP** | 无连接、不可靠、报文、开销小、快 | DNS（查询）、TFTP、SNMP、DHCP、视频/语音 |
| SCTP | 面向连接、支持多宿主（了解即可） | 电话信令等 |

### 6.3 网际层（网络层）协议

| 协议 | 全称 | 作用 |
|------|------|------|
| **IP** | 网际协议 | 定义 IP 数据报格式、寻址与路由（IPv4/IPv6） |
| **ICMP** | 互联网控制报文协议 | 差错报告与网络控制；**ping / traceroute** 用它 |
| **IGMP** | 互联网组管理协议 | 组播组成员管理 |
| **ARP** | 地址解析协议 | **IP 地址 → MAC 地址**（请求广播、应答单播） |
| **NAT** | 网络地址转换 | 内网 IP ↔ 公网 IP 转换，缓解地址不足 |
| **RIP / OSPF / BGP** | 路由协议 | 路由表的建立与更新（RIP 距离向量、OSPF 链路状态、BGP 自治域间） |

### 6.4 网络接口层（链路层 + 物理层）

| 协议/标准 | 作用 |
|----------|------|
| **Ethernet（IEEE 802.3）** | 局域网最主流链路层协议（MAC 帧、CSMA/CD） |
| **Wi-Fi（IEEE 802.11）** | 无线局域网（CSMA/CA） |
| **PPP** | 点对点链路（拨号、专线，可支持认证） |
| **HDLC** | 面向比特的链路层协议 |
| **ARP 的工作载体** | ARP 报文直接封装在以太网帧中传输 |

> **⚠️ 终极易错点汇总（层级判断题的四个陷阱）**：
> 1. **ARP → 网络层/网际层**（为 IP 服务，IP→MAC；虽封装在以太网帧中，但不属于链路层）。
> 2. **ICMP → 网络层**（不是应用层；ping 是应用层程序，但协议是 ICMP）。
> 3. **DNS 用 TCP 也用 UDP**（一般查询走 UDP 53；区域传送/大响应走 TCP 53）。
> 4. **加密/压缩/编码转换 → OSI 表示层**；HTTPS 的 TLS/SSL 常被归为实现表示层功能。

## 七、常见端口号表（必背）

端口号范围 **0–65535**（16 位，放在 TCP/UDP 首部）：

| 类别 | 范围 | 说明 |
|------|------|------|
| **熟知端口（well-known）** | **0–1023** | 分配给服务器端的标准服务（HTTP 80 等） |
| **注册端口** | 1024–49151 | 注册给特定应用（如 MySQL 3306） |
| **动态/临时端口** | 49152–65535 | 客户端临时使用，由系统随机分配 |

**必背端口表**（软考高频）：

| 端口 | 协议 | 端口 | 协议 |
|------|------|------|------|
| **20** | FTP 数据 | **80** | **HTTP** |
| **21** | FTP 控制 | **443** | **HTTPS** |
| **22** | SSH | **110** | POP3 |
| **23** | Telnet | **143** | IMAP |
| **25** | SMTP | **161/162** | SNMP（161 查询 / 162 trap 告警） |
| **53** | DNS（TCP+UDP） | **3389** | RDP（远程桌面） |
| **67/68** | DHCP（67 服务器 / 68 客户端） | **3306** | MySQL |
| **69** | TFTP | **8080** | HTTP 备用 |

**分组记忆法**：
- **20 串端口**：FTP(20/21)、SSH(22)、Telnet(23)、SMTP(25)——"文件、安全登录、明文登录、邮件"。
- **50–60**：DNS(53)、DHCP(67/68)、TFTP(69)。
- **80**：HTTP(80)；**4 开头**：HTTPS(443)。
- **110–160**：POP3(110)、IMAP(143)、SNMP(161)。
- **记住发送 vs 接收邮件**：SMTP **25 发**，POP3 **110 收**（IMAP 143 也是收）。
- **FTP 两条连接**：21 控制（传命令）、20 数据（传文件）。

## 八、记忆口诀

### 8.1 OSI 七层顺序（从下到上 1→7）

> **「物 链 网 传 会 表 应」**
> 谐音：**物联网传会表应**（"物联网传（递）会（议）表（格）应（答）"）

展开：**物**理层 → **链**路层 → **网**络层 → **传**输层 → **会**话层 → **表**示层 → **应**用层

英文版（从上到下）：**A**ll **P**eople **S**eem **T**o **N**eed **D**ata **P**rocessing
（**A**pplication, **P**resentation, **S**ession, **T**ransport, **N**etwork, **D**ata-link, **P**hysical）

### 8.2 各层协议归属（一句话版）

> **应用层全是"服务"**：网页（HTTP/S）、文件（FTP/TFTP）、邮件（SMTP/POP3/IMAP）、域名（DNS）、登录（Telnet/SSH）、管理（SNMP）、配 IP（DHCP）。
> **传输层只记两个**：TCP 可靠、UDP 快。
> **网际层记四个**：IP 寻路、ICMP 报错、**ARP 找 MAC**、路由协议（RIP/OSPF/BGP）。
> **接口层全是"硬件相关"**：以太网、Wi-Fi、PPP。

### 8.3 寻址三件套

> **IP 找主机（网络层）、MAC 找网卡（链路层）、端口找进程（传输层）**；
> 跨网用 IP，同链路用 MAC，进机用端口，**IP 变 MAC 找 ARP**。

### 8.4 封装方向

> **发送方：从上往下层层"穿衣服"（加头）；接收方：从下往上层层"脱衣服"（去头）；链路层还多穿一双"袜子"（帧尾 FCS）。**

## 九、快速自测（遮住答案速答）

1. OSI 七层从下到上依次是？ → **物理、数据链路、网络、传输、会话、表示、应用**。
2. ARP 属于哪层？ → **网络层（网际层）**，把 **IP 解析为 MAC**。
3. ICMP 属于哪层？ → **网络层**；ping 用 ICMP。
4. 端口号放在哪个协议的首部？ → **TCP/UDP 首部（传输层）**，IP 首部没有端口。
5. 数据链路层的数据单元是？ → **帧**；网络层是 **分组/IP 数据报**；传输层是 **报文段/数据报**；物理层是 **比特**。
6. 交换机工作在哪层？路由器呢？ → 交换机**数据链路层**（看 MAC）；路由器**网络层**（看 IP）。
7. 加密、压缩、编码转换是 OSI 哪层功能？ → **表示层**。
8. 封装时唯一加尾部的层是？ → **数据链路层（FCS）**。
9. DNS 使用传输层的什么协议？ → **TCP 和 UDP 都用（53 端口）**。
10. SMTP 与 POP3 的端口分别是？ → **25（发）/ 110（收）**；IMAP 是 **143**。
11. TCP/IP 四层是哪四层？ → **应用层、传输层、网际层、网络接口层**。
12. DHCP 端口？ → **服务器 67、客户端 68，都用 UDP**。
