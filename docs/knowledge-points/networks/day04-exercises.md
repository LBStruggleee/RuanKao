8. **数据链路层**（FCS 是唯一加尾部的那一层）。
9. **TCP 和 UDP 都用（端口 53）**。
10. SMTP **25（发）**、POP3 **110（收）**、IMAP **143**。
11. **应用层、传输层、网际层、网络接口层**。
12. 服务器 **67**、客户端 **68**，传输层用 **UDP**。

## 答案与解析

### 第一部分：层级判断 / 协议归属

**1. A** OSI 从下到上七层依次为：**物理层(1)、数据链路层(2)、网络层(3)、传输层(4)、会话层(5)、表示层(6)、应用层(7)**。口诀：**「物联网传会表应」**。B 选项"互联网层"是 TCP/IP 的叫法（网际层），不是 OSI 的层名。（知识点：OSI 七层顺序；对应 `day04-protocols.md` §二）

**2. D** HTTP 是为浏览器与 Web 服务器之间传输网页的应用层协议，属**应用层**。A 传输层是 TCP/UDP；C 表示层负责加密/压缩/编码转换；B 会话层负责会话管理。（知识点：应用层协议归属；对应 `day04-protocols.md` §2.7）

**3. C** **ARP 属于 TCP/IP 的网际层**（与 IP 同层），作用是把 **IP 地址解析为 MAC 地址**。ARP 报文直接封装在以太网帧中传输（不用 IP 封装），所以有人误以为它属于网络接口层/链路层——**这是最典型的易错点，软考按网际层（网络层）作答**。（知识点：ARP 层级归属；对应 `day04-protocols.md` §2.3、§6.3）

**4. C** ICMP 与 IP 同属**网络层**，用于差错报告与网络控制。**易错点**：ping、traceroute 是**应用层的程序**，但它们调用的是**网络层的 ICMP 协议**——"程序在哪一层"和"用哪个协议"是两回事。（知识点：ICMP 层级归属；对应 `day04-protocols.md` §2.3）

**5. C** 传输层的代表协议是 **TCP 和 UDP**。A HTTP 是应用层；B ARP 是网络层（网际层）；D IP 是网络层。（知识点：传输层协议；对应 `day04-protocols.md` §2.4）

**6. C** 网络层协议有 **IP、ICMP、IGMP、ARP** 及路由协议（RIP/OSPF/BGP）。A Telnet 应用层（23 端口）；B UDP 传输层；D SMTP 应用层（25 端口，发邮件）。（知识点：网络层协议集合；对应 `day04-protocols.md` §6.3）

**7. C** **二层交换机**和网桥工作在**数据链路层**（根据 **MAC 地址**转发）。中继器、集线器工作在**物理层**（只放大/转发比特信号，不识别地址）；路由器工作在**网络层**（根据 **IP 地址**转发）。（知识点：网络设备与层级；对应 `day04-protocols.md` §四「对照表」）

**8. D** 各层数据单元（PDU）：应用层 = 报文（Message），传输层 = 报文段/数据报（Segment/Datagram），网络层 = 分组/IP 数据报（Packet），**数据链路层 = 帧（Frame）**，物理层 = 比特（Bit）。（知识点：PDU 与层级；对应 `day04-protocols.md` §四「对照表」）

**9. B** **表示层**负责数据表示形式的转换：**加密与解密、压缩与解压、编码转换**。这是表示层的标志性功能，几乎必考。注意区分：会话层负责"会话的建立/维持/终止与同步"，应用层负责"为用户进程提供网络服务"。（知识点：表示层职责；对应 `day04-protocols.md` §2.6）

**10. C** **IP、ICMP、ARP** 同属 TCP/IP **网际层**。A（HTTP/FTP/SMTP）是应用层；B（TCP/UDP）是传输层；D（Ethernet/PPP/Wi-Fi）是网络接口层。**注意 D 里的 Wi-Fi 是 802.11，属于网络接口层，不是"无线网络层"**。（知识点：TCP/IP 网际层协议集合；对应 `day04-protocols.md` §6.3）

**11. B** 端口号位于 **TCP/UDP 首部**（传输层），用于**区分同一主机上的不同应用进程**（进程到进程的复用与分用）。**IP 首部只有 IP 地址，没有端口号**，A 错；端口号范围是 **0–65535**（0–1023 只是熟知端口），C 错；端口号的分配与使用由传输层负责，D 错。（知识点：端口号概念；对应 `day04-protocols.md` §2.4、§七）

**12. C** DHCP 是**应用层**协议，为客户端自动分配 IP 地址等配置信息；传输层使用 **UDP**，**服务器端口 67、客户端端口 68**。DHCP 不是传输层或网络层协议。（知识点：DHCP 层级与端口；对应 `day04-protocols.md` §6.1、§七）

### 第二部分：常见端口号

**13. B** FTP 使用**两条 TCP 连接**：**控制连接（传命令）端口 21**，**数据连接（传文件）端口 20**（主动模式）。题目问的是"控制连接"，故选 21。（知识点：FTP 端口；对应 `day04-protocols.md` §6.1、§七）

**14. B** **接收**邮件用 POP3（端口 **110**）或 IMAP（143）；**发送**邮件用 SMTP（25）。A 把"发"和"收"弄反了，这是最常见的一组易错搭配。（知识点：邮件协议端口；对应 `day04-protocols.md` §6.1）

**15. B** **HTTPS = HTTP + TLS/SSL**，默认端口 **443**；HTTP 默认 80。8080 常作为 HTTP 的备用端口，161 是 SNMP。（知识点：HTTPS 端口；对应 `day04-protocols.md` §6.1、§七）

**16. C** DNS **既用 TCP 又用 UDP，端口都是 53**：一般域名查询走 UDP（快、开销小）；区域传送（主从 DNS 同步）和超过 512 字节的大响应走 TCP。这是 DNS 的特殊之处，考试常考。（知识点：DNS 端口与传输协议；对应 `day04-protocols.md` §6.1）

### 第三部分：封装与解封装

**17. B** 封装是**自上而下逐层加头**：应用层生成 **HTTP 报文** → 传输层加 TCP 首部成 **TCP 报文段** → 网络层加 IP 首部成 **IP 数据报** → 链路层加帧头和帧尾成 **帧** → 物理层转成**比特流**。A 把 TCP 和 IP 的顺序颠倒了；C 把 IP 与 TCP 的顺序、帧与比特的顺序都弄错了；D 是**解封装**（接收方）的顺序，不是封装。（知识点：封装过程；对应 `day04-protocols.md` §五）

**18. C** 路由器工作在**网络层**：收到帧后解封装到网络层，**读取 IP 首部中的目的地址、查路由表决定下一跳**，然后重新封装成**新的链路层帧**（源/目的 MAC 都换成新一段链路上的）再发出。路由器**不读 TCP/UDP 和应用层首部**（除非做 NAT 等特殊处理）。因此它处理的是"网络层及以下"。（知识点：路由器转发与封装；对应 `day04-protocols.md` §五「关键结论 5」）

### 第四部分：传输层特性与综合

**19. B** TCP 与 UDP 都在传输层、都提供**进程到进程**（端到端）通信：**TCP 面向连接、可靠**（确认、重传、流量与拥塞控制），**UDP 无连接、不可靠但开销小、速度快**。C 恰好说反了（"保证不丢失不重复有序"是 TCP）；D 也反了——**实时音视频恰恰优先选 UDP**（允许少量丢包、要求低延迟）。TCP 的握手机制与拥塞控制见 Day 5。（知识点：TCP vs UDP；对应 `day04-protocols.md` §6.2）

**20. B** HTTPS 中 **TLS/SSL 提供加密**，其功能最贴近 OSI 的**表示层**（加密、压缩、编码转换正是表示层的职责）。TLS 实际工作在传输层之上、应用层之下（"会话层/表示层"的位置），但按 OSI 功能划分，加密属于**表示层**。**易错点**：不要因为 HTTPS 是"应用"就选应用层。（知识点：表示层功能识别 + HTTPS 组成；对应 `day04-protocols.md` §2.6、§6.1）
