## 一、磁盘的物理结构（先认识"地址"）

### 1.1 结构图

```
                  ┌─────────────────────────────┐
                  │         盘片（platter）       │
                  │   ┌─────────────────────┐   │
                  │   │  磁道(track)：同心圆  │   │
                  │   │  ┌───────────────┐  │   │
                  │   │  │ 扇区(sector)  │  │   │  ← 磁盘读写的最小单位
                  │   │  │ = 一个物理块   │  │   │    （通常 512B / 4KB）
                  │   │  └───────────────┘  │   │
                  │   └─────────────────────┘   │
                  └─────────────────────────────┘
   一根主轴串起多张盘片，每个盘面（正反两面）各有一个磁头：

   盘面0  ──┐
   盘面1  ──┤  所有盘面上"半径相同"的磁道组成一个【柱面 cylinder】
   盘面2  ──┤     （磁头统一作径向移动，同一柱面内的磁头可同时定位）
   盘面3  ──┘
```

### 1.2 关键概念（必背表）

| 概念 | 含义 | 编号方向 |
|------|------|---------|
| **盘片 / 盘面** | 磁盘的物理载体，每面涂有磁性介质 | 盘面号 = 磁头号 |
| **磁道（track）** | 盘面上的同心圆环 | 从外向内编号 0,1,2,… |
| **扇区（sector）** | 磁道被切成的弧段，是磁盘**读写的最小单位** | 一个磁道常分为 63 个扇区 |
| **柱面（cylinder）** | 所有盘面上**半径相同**的磁道集合 | 从外向内编号 0,1,2,… |

### 1.3 磁盘物理地址（三元组）

一个数据块在磁盘上的物理地址 = **（柱面号，磁头号（盘面号），扇区号）**。

```
   访问一个数据块：
     ① 磁头径向移动 → 定位【柱面】   ← 花的时间叫【寻道时间】（机械，最慢）
     ② 选中对应【磁头/盘面】          ← 电子切换，极快
     ③ 盘片旋转 → 定位【扇区】        ← 花的时间叫【旋转延迟】
     ④ 边转边读出数据                ← 花的时间叫【传输时间】
```

> **⚠️ 易错点 1**：柱面号从**外向内**递增（最外圈是柱面 0）；但"向内移动"到底是朝 0 还是朝最大柱面，不同教材说法不一。**做题时以题目给定的方向为准**，本笔记一律用「向柱面号减小方向移动 = 朝 0 移动」的说法。
>
> **⚠️ 易错点 2**：磁盘的**物理块大小 = 扇区大小**（一个扇区就是一个物理块/盘块）。文件系统中的"盘块"通常就是扇区或几个连续扇区的簇。

## 二、磁盘存取时间（三段式，必考）

### 2.1 公式

> **平均存取时间 Ta = 平均寻道时间 Ts + 平均旋转延迟 Tr + 传输时间 Tt**

| 组成 | 决定因素 | 能否优化 |
|------|---------|---------|
| **寻道时间 Ts** | 磁头移动到目标柱面的机械移动时间 | ✅ **磁盘调度算法优化的就是它** |
| **旋转延迟 Tr** | 盘片转速；平均看做转**半圈** | 靠提高转速 |
| **传输时间 Tt** | 转速与要读的数据量 | 靠提高转速/密度 |

> **⚠️ 核心结论**：**磁盘调度算法（FCFS/SSTF/SCAN…）只影响寻道时间**，与旋转延迟、传输时间无关。题目让你"比较几种调度算法"，实际是比**总寻道距离**。

### 2.2 两个常用换算（背死）

- **转一圈的时间** = `60 秒 ÷ 转速（转/分）`
- **平均旋转延迟** = **半圈**的时间 = `30 ÷ 转速（转/分）` 秒

| 转速 | 转一圈 | 平均旋转延迟 |
|------|--------|-------------|
| 3600 r/min | 16.67 ms | 8.33 ms |
| 5400 r/min | 11.11 ms | 5.56 ms |
| 7200 r/min | **8.33 ms** | **4.17 ms** |
| 10000 r/min | 6.00 ms | 3.00 ms |

### 2.3 存取时间手算例题

> **例题**：某磁盘转速为 7200 转/分，平均寻道时间为 8 ms，每个磁道有 500 个扇区。求读取一个扇区的平均存取时间。

**解：**

1. 转一圈的时间 = 60 ÷ 7200 = 0.008333 s = **8.33 ms**。
2. 平均旋转延迟 = 半圈 = 8.33 ÷ 2 = **4.17 ms**。
3. 传输一个扇区的时间 = 8.33 ms ÷ 500 = 0.0167 ms = **16.7 μs**。
4. 平均存取时间 Ta = 8 + 4.17 + 0.0167 ≈ **12.19 ms**。

> **验证**：寻道（机械）8 ms ≈ 66%，旋转 4.17 ms ≈ 34%，传输几乎可忽略。**所以减少寻道距离 = 提高磁盘性能的钥匙**——这正是磁盘调度算法存在的意义。
>
> **⚠️ 易错点**：题目若问"读取一个扇区"的传输时间，用"转一圈时间 ÷ 每道扇区数"；若问"读取一个磁道"，传输时间 = 转一圈的时间。两者千万别混。

## 三、磁盘调度算法（必考计算题！）

### 3.1 六种算法对比（必背表）

| 算法 | 全称 | 策略 | 优点 | 缺点 |
|------|------|------|------|------|
| **FCFS** | 先来先服务 | 严格按请求**到达顺序**服务 | 公平、简单、**无饥饿** | 寻道距离长，可能来回"折腾" |
| **SSTF** | 最短寻道时间优先 | 每次选**离当前磁头最近**的请求 | 平均寻道短 | **可能饥饿**（远处请求长期得不到服务）；**不是最优** |
| **SCAN** | 电梯（扫描）算法 | 磁头**朝一个方向走到底**（到磁盘边界），沿途服务，再**反向** | 无饥饿，性能好 | 中间柱面被服务两次/两端等待不均 |
| **C-SCAN** | 循环扫描 | 只在**单方向上服务**，到端后**空跑回另一端**继续同向服务 | 各柱面等待时间**更均匀** | 回程空跑不算服务 |
| **LOOK** | — | SCAN 的改进：**只走到最远请求**就折返，不走到物理边界 | 少走冤枉路 | — |
| **C-LOOK** | — | C-SCAN 的改进：只走到单方向上**最远的请求**就跳回 | 少走冤枉路 | — |

> **记忆口诀**：
> - **FCFS** = "排队，来一个服务一个"；
> - **SSTF** = "就近原则，谁近先服务谁"；
> - **SCAN** = "电梯，一路走到底再反向"；
> - **C-SCAN** = "单行道，服务完一头、空车回另一头"；
> - **LOOK / C-LOOK** = "SCAN/C-SCAN 的聪明版，到最远请求就回头（Look 一下有没有请求了）"。

> **⚠️ 易错点（高频）**：
> 1. **SSTF 会"折返跑"**：它只看眼前最近，可能先往右再一路往左，导致总距离并非最优。**SSTF ≠ 最优算法**。
> 2. **SCAN/C-SCAN 要走到"端"**：端 = **物理边界**（0 或最大柱面）；**LOOK/C-LOOK 只走到最远请求**。这是最容易算错的一步，两者相差的距离 = `最远请求到端点的距离 × 2`（C-SCAN 只算单程）。
> 3. **C-SCAN 的回程不服务**：从一端跳回另一端时**不处理任何请求**，但**移动距离照算**。
> 4. 软考常考"平均寻道距离 = 总寻道距离 ÷ **请求总数**"（注意分母是请求个数，不是移动段数）。

### 3.2 完整手算例题（六种算法同一请求序列，必算 3 遍以上）

> **题目**：设磁盘共有 **200 个柱面**（编号 0–199），磁头初始位于柱面 **100**，磁头**向柱面号减小方向（朝 0）**移动。磁盘请求队列按到达顺序为：
> **108, 90, 88, 60, 130, 40, 160, 20**
>
> 分别用 FCFS、SSTF、SCAN、LOOK、C-SCAN、C-LOOK 算法给出磁头服务顺序，计算总寻道距离与平均寻道距离。

---

#### （1）FCFS（按到达顺序服务）

服务顺序 = 到达顺序：108 → 90 → 88 → 60 → 130 → 40 → 160 → 20

| 段 | 移动 | 距离 |
|----|------|------|
| 100 → 108 | 向右 | 8 |
| 108 → 90 | 向左 | 18 |
| 90 → 88 | 向左 | 2 |
| 88 → 60 | 向左 | 28 |
| 60 → 130 | 向右 | 70 |
| 130 → 40 | 向左 | 90 |
| 40 → 160 | 向右 | 120 |
| 160 → 20 | 向左 | 140 |

**总寻道距离 = 8+18+2+28+70+90+120+140 = 476**
**平均寻道距离 = 476 ÷ 8 = 59.5**

> 看出来了吗？磁头在 20~160 之间反复横跳，这就是 FCFS 的低效。

---

#### （2）SSTF（最短寻道时间优先）

每步从剩余请求中挑**离当前磁头最近**的：

| 步 | 当前 | 剩余请求中最近者 | 距离 | 累计 |
|----|------|-----------------|------|------|
| 1 | 100 | **108**（距 8；次近 90 距 10） | 8 | 8 |
| 2 | 108 | **90**（距 18；88 距 20） | 18 | 26 |
| 3 | 90 | **88**（距 2） | 2 | 28 |
| 4 | 88 | **60**（距 28） | 28 | 56 |
| 5 | 60 | **40**（距 20；20 距 40） | 20 | 76 |
| 6 | 40 | **20**（距 20） | 20 | 96 |
| 7 | 20 | **130**（距 110；160 距 140） | 110 | 206 |
| 8 | 130 | **160**（距 30） | 30 | 236 |

服务顺序：100 → 108 → 90 → 88 → 60 → 40 → 20 → 130 → 160
**总寻道距离 = 8+18+2+28+20+20+110+30 = 236**
**平均寻道距离 = 236 ÷ 8 = 29.5**

> **注意 SSTF 的折返**：磁头先向右到 108，再一路向左穿过起点到 20，最后又向右到 160。**它并不是最优的**——下面的 LOOK 算法比它还少走 16 个柱面。

---

#### （3）SCAN（电梯算法：朝一个方向走到底，再反向）

磁头朝 0 的方向走，先服务所有小于 100 的请求（从近到远：90, 88, 60, 40, 20），**走到物理边界 0**，再反向服务 108, 130, 160。

```
服务顺序：100 → 90 → 88 → 60 → 40 → 20 → [0] → 108 → 130 → 160
                                        ↑ 走到端点（无请求，空走）
```

| 段 | 移动 | 距离 |
|----|------|------|
| 100 → 90 | 向左 | 10 |
| 90 → 88 | 向左 | 2 |
| 88 → 60 | 向左 | 28 |
| 60 → 40 | 向左 | 20 |
| 40 → 20 | 向左 | 20 |
| 20 → 0 | 向左（空走到端点） | 20 |
| 0 → 108 | 向右 | 108 |
| 108 → 130 | 向右 | 22 |
| 130 → 160 | 向右 | 30 |

**总寻道距离 = 10+2+28+20+20+20+108+22+30 = 260**
**平均寻道距离 = 260 ÷ 8 = 32.5**

---

#### （4）LOOK（只走到最远请求就折返，不走到 0）

与 SCAN 唯一的区别：走到最小请求 **20** 就折返，**不去 0**。

```
服务顺序：100 → 90 → 88 → 60 → 40 → 20 → 108 → 130 → 160
                                       ↑ 直接折返
```

| 段 | 移动 | 距离 |
|----|------|------|
| 100 → 90 | 10 |
| 90 → 88 | 2 |
| 88 → 60 | 28 |
| 60 → 40 | 20 |
| 40 → 20 | 20 |
| 20 → 108 | 88 |
| 108 → 130 | 22 |
| 130 → 160 | 30 |

**总寻道距离 = 10+2+28+20+20+88+22+30 = 220**
**平均寻道距离 = 220 ÷ 8 = 27.5**

> **对比 SCAN**：260 − 220 = 40，正是 `20 → 0 往返 20×2 = 40`。**LOOK 永远 ≤ SCAN**。

---

#### （5）C-SCAN（单向服务：到端后空跑回另一端，继续同向）

磁头朝 0 走，服务 90, 88, 60, 40, 20，**走到边界 0**，**跳到另一端 199**（回程不服务），再继续**朝 0 的方向**服务 160, 130, 108。

```
服务顺序：100 → 90 → 88 → 60 → 40 → 20 → [0] → [199] → 160 → 130 → 108
                          ↑ 空走到端点        ↑ 空跳回另一端（不服务）
```

| 段 | 移动 | 距离 |
|----|------|------|
| 100 → 90 | 10 |
| 90 → 88 | 2 |
| 88 → 60 | 28 |
| 60 → 40 | 20 |
| 40 → 20 | 20 |
| 20 → 0 | 20（空走） |
| 0 → 199 | 199（空跳，不服务） |
| 199 → 160 | 39 |
| 160 → 130 | 30 |
| 130 → 108 | 22 |

**总寻道距离 = 10+2+28+20+20+20+199+39+30+22 = 390**
**平均寻道距离 = 390 ÷ 8 = 48.75**

> **⚠️ 关于 C-SCAN 的"回程距离"**：本题按严格 C-SCAN 定义，`0 → 199` 的跳回**计入总移动距离**。部分考题会把"空跑回程"视为零成本（只比较服务过程），则 C-SCAN 结果 = 390 − 199 = 191。**做题时看清题目口径**：题干说"磁头移动距离/寻道总距离"→ 全程计入；说"服务请求过程中的寻道距离"→ 可能不算回程。不确定时按**全程计入**作答，并在解答中写明口径。

---

#### （6）C-LOOK（只走到最远请求就跳回，继续同向）

与 C-SCAN 的区别：走到最小请求 20 就跳回**最远的未服务请求 160**，不去 0，也不去 199。

```
服务顺序：100 → 90 → 88 → 60 → 40 → 20 → [跳到 160] → 130 → 108
```

| 段 | 移动 | 距离 |
|----|------|------|
| 100 → 90 | 10 |
| 90 → 88 | 2 |
| 88 → 60 | 28 |
| 60 → 40 | 20 |
| 40 → 20 | 20 |
| 20 → 160 | 140（空跳，不服务） |
| 160 → 130 | 30 |
| 130 → 108 | 22 |

**总寻道距离 = 10+2+28+20+20+140+30+22 = 272**
**平均寻道距离 = 272 ÷ 8 = 34**

---

### 3.3 六种算法结果汇总（本例）

| 算法 | 服务顺序 | 总寻道距离 | 平均寻道距离 |
|------|---------|-----------|-------------|
| FCFS | 108,90,88,60,130,40,160,20 | **476** | 59.5 |
| SSTF | 108,90,88,60,40,20,130,160 | **236** | 29.5 |
| SCAN | 90,88,60,40,20,→0→,108,130,160 | **260** | 32.5 |
| **LOOK** | 90,88,60,40,20,108,130,160 | **220** ✅本例最优 | 27.5 |
| C-SCAN | 90,88,60,40,20,→0→199→,160,130,108 | **390** | 48.75 |
| C-LOOK | 90,88,60,40,20,→160,130,108 | **272** | 34 |

> **从这张表要读出三个结论**：
> 1. **FCFS 最差**（476），任何调度算法都比它强。
> 2. **SSTF（236）并不是最优**——本例中 LOOK（220）更短。SSTF 的"贪心"让它先去了 108，结果要折返。
> 3. **SCAN 与 LOOK、C-SCAN 与 C-LOOK 的差**全都来自"要不要走到端点"。记住：`SCAN − LOOK = 端点空走距离 × 2`。

## 四、文件逻辑结构（用户视角）

**逻辑结构**是文件在用户/程序员面前呈现的样子，与文件在磁盘上怎么存（物理结构）无关。

| 类型 | 含义 | 特点 | 典型 |
|------|------|------|------|
| **流式文件（无结构文件）** | 无结构的**字节序列**，文件就是一串字节 | 长度 = 字节数；想读哪读哪，但"记录"要程序自己切 | Unix/Linux 普通文件、文本文件 |
| **记录式文件（有结构文件）** | 由若干**逻辑记录**组成，每个记录是一个独立单位 | 便于以记录为单位检索、修改 | 数据库文件、学生档案 |

### 4.1 记录的成组与分解（易考小计算）

把若干逻辑记录**打包存入一个物理块**，叫**成组**；读出后再拆开，叫**分解**。

- **块因子 g**（每块能放的记录数）= `物理块大小 ÷ 记录长度`（**向下取整**）
- 成组后最后一块若没装满，产生**内部碎片**

> **例题**：物理块大小 512 B，逻辑记录长度 80 B。
> - 块因子 g = 512 ÷ 80 = 6.4 → **6 个记录成一块**（向下取整）。
> - 每块实际使用 6 × 80 = 480 B，**浪费 512 − 480 = 32 B**（内部碎片）。

> **⚠️ 易错点**：g 一定**向下取整**——放 7 个记录要 560 B > 512 B，放不下。

## 五、文件物理结构（磁盘视角，必考对比）

**物理结构**是文件在磁盘上的存放方式。三种基本结构：

### 5.1 对比表（必背）

| 对比项 | **连续分配** | **链接分配** | **索引分配** |
|--------|------------|------------|------------|
| 存放方式 | 文件占用**连续**的盘块 | 盘块**任意分散**，每块末尾存"下一块指针" | 盘块任意分散，另用一张**索引表**记录所有块号 |
| FCB 中存什么 | **首块号 + 文件长度** | **首块号**（+ 末块号） | **指向索引块的指针** |
| 随机存取 | ✅ **快**（直接算：第 i 块 = 首块 + i） | ❌ **慢**（必须沿指针从头遍历） | ✅ **快**（查索引表） |
| 文件动态增长 | ❌ 不方便（要找连续空间，产生**外部碎片**） | ✅ 方便（新块挂到链尾） | ✅ 方便（新块号加入索引表） |
| 可靠性 | 高 | 低（指针一旦损坏，链全断） | 较高 |
| 典型应用 | 早期系统、CD-ROM | FAT 文件系统 | ext2/3/4、UFS、NTFS |

> **记忆**：
> - **连续** = "整租一套房"——好找但搬家难；
> - **链接** = "租房链条，房东给你下一家地址"——好扩但要挨家找；
> - **索引** = "房东有一本通讯录（索引表）"——好找好扩，就是通讯录本身要占地方。

> **⚠️ 高频易错点**：
> - **连续分配**产生**外部碎片**（与动态分区一样）；**链接/索引分配**无外部碎片，但索引表本身占空间。
> - **链接分配**的随机存取是**不能**的（必须顺序沿指针走）——这是选择题最爱的陷阱。
> - **索引分配**的索引表放在**一个物理块（索引块）**里，FCB 只存指向它的指针。

### 5.2 连续分配的地址计算

> **例题**：文件 F 采用连续分配，其 FCB 记录首块号 = 20，文件共占 8 个盘块。求文件第 5 个盘块（从 0 编号）的物理块号。

**解**：物理块号 = 首块号 + i = 20 + 5 = **25**。

> **验证**：第 0 块→20，第 1 块→21，…，第 5 块→25，第 7 块→27（末块）。✅

### 5.3 链接分配的两种实现

| 类型 | 指针存放位置 | 特点 |
|------|------------|------|
| **隐式链接** | 指针存放在**每个数据块的末尾** | 实现简单；但读第 i 块必须从头读 i 块（慢） |
| **显式链接** | 指针集中存放在一张 **FAT 表**中（见第七节） | 整张表常驻内存，查链接快得多；**FAT 就是显式链接** |

## 六、索引文件（含多级索引与地址计算，必考）

### 6.1 一级索引

FCB 中存一个指向**索引块**的指针；索引块内是一张**数据块号表**：

```
   FCB ──▶ [ 索引块 ]  ┌────┬────┬────┬────┬…┬────┐
                       │块号│块号│块号│块号│…│块号│  → 各自指向一个数据块
                       └────┴────┴────┴────┴─┴────┘
   访问第 i 块：读索引块 → 取第 i 项 → 得数据块号 → 读数据块
```

- 一个索引块能存多少个块号？ = `索引块大小 ÷ 块号所占字节数`
- **一级索引可管理的文件最大长度** = `块号数 × 盘块大小`

> **例题（必算）**：某文件系统盘块大小为 **4 KB**，盘块号占 **4 字节**。求：
> （1）一个索引块可存放多少个盘块号？
> （2）一级索引可管理的文件最大长度？

**解**：
（1）4096 ÷ 4 = **1024 个盘块号**。
（2）1024 × 4 KB = 4096 KB = **4 MB**。

### 6.2 多级索引

当文件超过一级索引的容量时，让索引块指向**下一级索引块**：

```
   FCB ──▶ [一级索引块] ──▶ [二级索引块] ──▶ [数据块]
                     └──▶ [二级索引块] ──▶ [数据块]
```

**容量公式（以上述参数：4 KB 块、4 B 块号、1024 项/索引块）**：

| 级数 | 可管理的块数 | 可管理的文件最大长度 |
|------|------------|-------------------|
| 一级索引 | 1024 | 1024 × 4 KB = **4 MB** |
| 二级索引 | 1024 × 1024 = 2²⁰ | 2²⁰ × 4 KB = **4 GB** |
| 三级索引 | 1024³ = 2³⁰ | 2³⁰ × 4 KB = **4 TB** |

> **记忆规律**：每多一级，容量乘 1024（即 ×2¹⁰）。**一级 4MB、二级 4GB、三级 4TB**，一级跳一千倍。

### 6.3 混合多级索引（Linux ext2 风格，常考"读第 i 块要几次磁盘 I/O"）

一个 inode 中直接放若干**直接块指针**，再放一级、二级、三级间接指针：

```
   inode（FCB）
     ├── 10 个直接块指针      → 直接指向数据块        （1 次磁盘 I/O 读到数据）
     ├── 1 个一级间接指针     → 指向一个索引块        （2 次磁盘 I/O）
     ├── 1 个二级间接指针     → 指向"指向索引块的索引块" （3 次磁盘 I/O）
     └── 1 个三级间接指针                              （4 次磁盘 I/O）
```

**区域划分**（4 KB 块、4 B 块号）：

| 区域 | 覆盖的块号 | 覆盖的文件偏移 | 读数据需要的磁盘 I/O |
|------|-----------|---------------|--------------------|
| 直接（10 个） | 0 ~ 9 | 0 ~ 40 KB | 1 次 |
| 一级间接 | 10 ~ 1033 | 40 KB ~ 4 MB + 40 KB | 2 次 |
| 二级间接 | 1034 ~ 1049609 | ≈ 4 MB ~ 4 GB | 3 次 |
| 三级间接 | 1049610 ~ 更大 | ≈ 4 GB ~ 4 TB | 4 次 |

> **⚠️ 易错点**：题目问"读取某块数据需要访问几次磁盘"——**索引块也要算一次磁盘读**！一级间接 = 索引块 1 次 + 数据块 1 次 = **2 次**。

### 6.4 混合索引地址计算例题（必算）

> **例题**：文件系统盘块大小 4 KB，块号 4 B，inode 含 **10 个直接块 + 1 个一级间接 + 1 个二级间接 + 1 个三级间接**。现要访问文件的逻辑地址 **5 MB**（即 5242880 B）处。
> （1）该地址位于哪个盘块？块内偏移是多少？
> （2）该块落在哪种索引区域？
> （3）访问该数据块共需几次磁盘 I/O？

**解**：

（1）盘块号 = 5242880 ÷ 4096 = **1280**；块内偏移 = 5242880 mod 4096 = **0**。

（2）判断区域：
- 直接块覆盖块号 0~9 → 1280 不在其中；
- 一级间接覆盖块号 10 ~ 10+1024−1 = **10~1033** → 1280 不在其中；
- 二级间接覆盖块号 1034 起 → **1280 落在二级间接区域**。

二级间接区域内的序号 = 1280 − 10 − 1024 = **246**（即二级间接区域的第 246 个块，从 0 编）。
- 第一级索引项序号 = 246 ÷ 1024 = **0**（即二级间接指针指向的那张表里的第 0 项）；
- 第二级索引项序号 = 246 mod 1024 = **246**。

（3）访问路径：
```
   读【二级间接指针指向的一级索引块】(1 次)
      → 取第 0 项，得到【二级索引块】地址，读它 (1 次)
         → 取第 246 项，得到【数据块】地址，读它 (1 次)
```
共 **3 次磁盘 I/O**。

> **验证**：5 MB = 5 × 2²⁰ = 5242880 B；5242880 = 1280 × 4096 + 0 ✓。1280 落在 1034 之后 ✓。246 = 0 × 1024 + 246 ✓。

## 七、文件目录与 FAT

### 7.1 文件控制块（FCB）与目录

- **文件控制块（FCB）**：操作系统用来描述和管理文件的数据结构，是**文件存在的标志**。
- **FCB 的内容**：文件名 + 文件物理地址（首块号/索引指针）+ 文件类型 + 大小 + 创建时间 + 权限 + 属性等。
- **目录**：目录由**目录项**组成，每个目录项就是一个 FCB（或指向 inode 的指针）。**目录本身也是一种文件**。

| 目录结构 | 特点 | 缺点 |
|---------|------|------|
| **单级目录** | 全系统一张表，文件不能重名 | 重名冲突、检索慢 |
| **二级目录** | 主目录 + 各用户文件目录 | 解决重名，但不便分类 |
| **多级（树形）目录** | 层次结构，路径唯一 | 路径解析要多次读盘 |

> **⚠️ FCB vs inode（高频）**：
> - **FCB** 把文件名和属性、物理地址**都放在一起**；
> - **inode（索引节点）** 把文件名**分离**出去放在目录项里，inode 只存属性 + 物理地址（不含文件名）。同一个 inode 可以有**多个文件名（硬链接）**。

### 7.2 硬链接与软链接（符号链接）

| 类型 | 做法 | 删除原文件后 | 能否跨文件系统 |
|------|------|------------|--------------|
| **硬链接** | 多个目录项指向**同一个 inode**（inode 引用计数 +1） | **仍可访问**（计数 > 0，文件还在） | ❌ 不能（inode 是文件系统内部的） |
| **软链接（符号链接）** | 一个文件，其**内容是目标文件的路径字符串** | **失效**（路径悬空，成"野链接"） | ✅ 可以 |

> **记忆**：硬链接 = "同一套房挂两个门牌"（房子还在，门牌就能用）；软链接 = "一张写着地址的纸条"（房子拆了，纸条就是废纸）。

### 7.3 FAT（文件分配表）

**FAT = 显式链接的文件物理结构**：把所有盘块的"下一块指针"集中存放在一张表里，这张表就是 FAT。

```
   FAT 表（常驻内存或开机读入内存）：
   ┌──────┬────────────┐
   │ 盘块号│ 下一盘块号  │
   ├──────┼────────────┤
   │  0   │   ...      │
   │  1   │   5        │  ← 块 1 之后是块 5
   │  5   │   9        │
   │  9   │  -1        │  ← -1（全 1）= 文件最后一块
   │  3   │   0        │  ← 0 = 空闲块
   └──────┴────────────┘
```

| 要点 | 说明 |
|------|------|
| **表项数** = 盘块总数 | 每个盘块对应一项 |
| **特殊值** | **0** = 空闲块；**−1（0xFFFF…）** = 文件的最后一块 |
| **表项位数** | 由盘块总数决定：FAT12（12 位，4096 块）、FAT16（16 位）、FAT32（32 位） |
| **优点** | 指针在内存的 FAT 里，查链接**不必读数据块**，比隐式链接快得多 |
| **本质** | 链接式物理结构（显式），**不支持真正的随机存取**，但比隐式链接好很多 |

> **⚠️ 易错点**：FAT 的表项内容是**下一个盘块号**，不是文件名、不是索引。FAT 与"索引分配"是**两种不同**的物理结构：FAT 是**链接式**（显式），索引分配是**索引式**。

## 八、本章必背速记清单

1. 磁盘物理地址 = **（柱面号，磁头号，扇区号）**；扇区是磁盘读写的**最小单位**；柱面 = 所有盘面上半径相同的磁道集合。
2. **平均存取时间 = 平均寻道时间 + 平均旋转延迟 + 传输时间**；磁盘调度算法**只影响寻道时间**。
3. **转一圈 = 60 ÷ 转速**；**平均旋转延迟 = 半圈**。
4. 磁盘调度：**FCFS** 公平但慢；**SSTF** 就近但会饥饿且非最优；**SCAN** 走到底再反向；**C-SCAN** 单向服务、空跑回程；**LOOK/C-LOOK** 是只走到最远请求的改进版。
5. **SCAN − LOOK = 端点空走距离 × 2**；C-SCAN 的回程**不服务但计入距离**（看清题目口径）。
6. 平均寻道距离 = 总寻道距离 ÷ **请求个数**。
7. 文件逻辑结构：**流式（字节流）/记录式（记录集合）**；块因子 g = 块大小 ÷ 记录长度，**向下取整**。
8. 文件物理结构：**连续**（随机存取快、不便增长、外部碎片）；**链接**（便于增长、不能随机存取）；**索引**（随机存取 + 动态增长，索引表占空间）。
9. 连续分配：第 i 块的物理块号 = **首块号 + i**。
10. 索引块可存块号数 = **块大小 ÷ 块号字节数**；4 KB 块 + 4 B 块号 = **1024 项**。
11. **一级索引 4 MB、二级 4 GB、三级 4 TB**（4 KB 块、4 B 块号）。
12. 混合索引读数据所需磁盘 I/O：直接块 **1 次**、一级 **2 次**、二级 **3 次**、三级 **4 次**（索引块也要算）。
13. **FAT**：显式链接结构，表项存"下一块号"，**0 = 空闲，−1 = 文件末块**。
14. **FCB** 含文件名+属性+地址；**inode** 不含文件名；**硬链接**共享 inode（删原文件仍可用，不跨文件系统），**软链接**存路径（删原文件则失效，可跨文件系统）。

### 10.3 OS 三天必背结论清单（20 条）

**进程管理（Day 1）**
1. PCB 是进程**存在的唯一标志**；**资源分配单位 = 进程，CPU 调度单位 = 线程**。
2. **阻塞不能直接 → 执行**，必须「阻塞 → 就绪 → 执行」；P 操作失败 → **阻塞**，时间片用完 → **就绪**。
3. 线程共享代码/数据/堆/文件，**独享栈与寄存器**。
4. **SJF 平均等待时间最短**但长作业**饥饿**；RR 时间片过大 → 退化为 FCFS，过小 → 切换开销大。
5. P 减 V 加；生产者-消费者：`mutex=1, empty=n, full=0`，**资源量 P 在互斥量 P 之前**（否则死锁）。
6. 死锁四必要条件：**互斥、占有且等待、不可剥夺、循环等待**；银行家算法属于**死锁避免**。

**内存管理（Day 2）**
7. 页式：`P = LA ÷ S`，`W = LA mod S`，**物理地址 = 块号 × 页大小 + W**；段式：**物理地址 = 段基址 + W**（**页式乘、段式加**）。
8. 页大小是 2 的幂 → 二进制切位：低 log₂页大小 位 = 偏移，高位 = 页号。
9. **访存次数**：一级页表 2 次；二级 3 次；三级 4 次；**TLB 命中只 1 次**。
10. TLB = **相联存储器**实现的高速页表项缓存；EAT = h×(t1+t2) + (1−h)×(t1+2t2)。
11. 虚拟内存三特征：**多次性、对换性、虚拟性**；基础是**局部性原理**；缺页中断是**内部中断、指令执行期间**产生。
12. 置换算法：OPT 看未来（不可实现）、FIFO 看进入（**唯一会 Belady**）、LRU 看过去、Clock = LRU 近似。

**磁盘与文件（Day 3）**
13. 磁盘物理地址 = **(柱面号, 磁头号, 扇区号)**；扇区 = 最小读写单位；**调度算法只优化寻道时间**。
14. **Ta = 寻道 + 旋转 + 传输**；转一圈 = 60 ÷ 转速；**平均旋转延迟 = 半圈**。
15. **SSTF 会饥饿、且非最优**；**SCAN 走到端、LOOK 走到最远请求**；**C-SCAN 回程不服务**。
16. 文件物理结构：**连续 = 随机快 + 外部碎片**；**链接 = 好增长 + 不能随机**；**索引 = 随机 + 好增长**。
17. 索引块项数 = 块大小 ÷ 块号字节；**一级 4MB / 二级 4GB / 三级 4TB**（4 KB 块 + 4 B 块号）。
18. 混合索引读数据 I/O 次数：直接 1 次、一级 2 次、二级 3 次、三级 4 次（**索引块也算一次**）。
19. **FAT = 显式链接**，表项存下一块号，**0 = 空闲、−1 = 末块**。
20. **inode 不含文件名**；硬链接共享 inode（删原文件仍可用、不跨文件系统），软链接存路径（删原文件则失效）。
