# 答案解析

## 第一部分答案（1–20）

**1. B**
PCB（进程控制块）是进程存在的唯一标志，操作系统通过 PCB 感知进程的存在。程序、进程映像、线程都无法唯一标识进程。（知识点：进程与 PCB）

**2. B**
阻塞态不能直接进入执行态。等待的事件发生后，进程先由阻塞 → 就绪（重新排队），再被调度器选中后就绪 → 执行。故路径为「阻塞 → 就绪 → 执行」。（知识点：五状态模型与状态转换）

**3. B**
进程执行中主动请求 I/O（等待外部事件），由执行态 → 阻塞态。等 I/O 完成后才是阻塞 → 就绪。（知识点：执行 → 阻塞的触发条件）

**4. B**
时间片用完、进程被剥夺 CPU，由执行态回就绪态（它已经具备除 CPU 外的一切资源）。（知识点：执行 → 就绪的触发条件）

**5. B**
P 操作使 S<0 表示无资源可用，执行 P 操作的进程必须阻塞等待，转入阻塞态。（知识点：P 操作的语义；状态转换）

**6. B**
现代操作系统中，线程是处理机（CPU）调度的基本单位，进程是资源分配的基本单位。A 正好说反。（知识点：进程 vs 线程）

**7. C**
同一进程内的线程共享代码段、数据段、打开的文件等，但**各自拥有独立的栈和寄存器上下文**。（知识点：线程共享与独享资源）

**8. B**
线程切换不涉及地址空间（页表）切换，只需切换寄存器、栈等少量上下文，因此开销远小于进程切换。（知识点：线程轻量的原因）

**9. D**
同一进程内的线程共享地址空间，可直接读写共享变量通信；跨进程才需要管道、消息队列、信号量等 IPC 机制。（知识点：进程与线程通信方式）

**10. B**
进程撤销的第一步是撤销其 PCB，回收分配的资源（内存、I/O、文件等）。PCB 一旦撤销，进程在系统中即不存在。（知识点：进程终止与 PCB 回收）

**11. A**
FCFS 中，若一个长作业排在前，后面短作业都要等它完成，造成"护航效应"，平均等待时间长。B（长作业饥饿）是 SJF/优先级的问题。（知识点：FCFS 缺点）

**12. C**
SJF 使平均等待时间最短（可用拉格朗日/交换论证证明）。FCFS、RR 平均等待一般更长。（知识点：调度算法特点）

**13. B**
RR 时间片很大时，每个进程一次就能运行完，退化为 FCFS。（知识点：RR 时间片大小的影响）

**14. B**
SJF 一直优先短作业，长作业可能长期得不到 CPU，产生饥饿。可通过老化等手段缓解。（知识点：SJF 饥饿问题）

**15. B**
"老化（aging）"即随着进程等待时间增长逐步提高其优先级，防止低优先级进程饿死。（知识点：优先级调度的饥饿与老化）

**16. A**
运行时间排序 3、3、24。SJF 顺序为 P2(3)→P3(3)→P1(24)。
周转时间：P2=3−0=3，P3=6−0=6，P1=30−0=30；平均 = (3+6+30)/3 = 13。（详见笔记 4.4 节手算）

**17. C**
分时系统的核心要求是交互响应快、各用户公平获得 CPU，时间片轮转刚好满足。（知识点：RR 应用场景）

**18. B**
多级反馈队列为不同优先级队列设置不同时间片，进程随执行/等待动态升降队列，兼顾短作业响应与长作业吞吐。（知识点：多级反馈队列思想）

**19. C**
访问临界资源采用互斥，其他想访问同一资源的进程应挂起等待（阻塞），直到占用者释放（V 操作唤醒）。注意：这里说的是"等待临界资源"的进程，应阻塞而不是就绪。（知识点：临界区互斥语义）

**20. A**
互斥解决"多个进程对共享资源排他性访问"的竞争问题；同步解决"协作进程间执行先后顺序"的问题。B/C/D 均错误。（知识点：互斥与同步的区别）

## 第二部分答案（21–25）

**21. C**
信号量初值含义各异：互斥信号量初值通常为 1（表示临界资源可用一份）；资源信号量初值为资源数量 n；用于前驱/事件同步的信号量初值为 0。故"任意整数、视用途而定"最准确。（知识点：信号量初值）

**22. 生产者-消费者（标准答案）**

（1）三个信号量：

```
semaphore mutex = 1;   // 互斥信号量：保护缓冲区
semaphore empty = n;   // 资源信号量：空槽数，初值 = 缓冲区容量 n
semaphore full  = 0;   // 资源信号量：产品数，初值 = 0
```

（2）伪代码：

```
// 生产者
while(1){
    生产一个产品;
    P(empty);      // 申请空槽
    P(mutex);      // 进入缓冲区
    放入缓冲区;
    V(mutex);      // 离开缓冲区
    V(full);       // 产品数 +1，唤醒消费者
}

// 消费者
while(1){
    P(full);       // 申请产品
    P(mutex);      // 进入缓冲区
    取出产品;
    V(mutex);      // 离开缓冲区
    V(empty);      // 空槽 +1，唤醒生产者
    消费产品;
}
```

（3）若先 `P(mutex)` 再 `P(empty)`：当缓冲区满（empty=0）时，生产者先拿到 mutex 进入临界区后才发现无空槽而阻塞，且**不放回 mutex**；消费者想取产品需要先 `P(mutex)`，但 mutex 被生产者占着，消费者也无法进入 → 生产者等消费者释放空槽、消费者等生产者释放 mutex，形成**死锁**。故必须先 P 资源信号量、再 P 互斥信号量。

**23. 读者-写者（读者优先，标准答案）**

（1）信号量：

```
semaphore rw_mutex = 1;  // 读写共享数据的互斥锁（写者用它保证独占）
semaphore mutex    = 1;  // 保护 readcount 的互斥信号量
int readcount = 0;       // 当前读者计数
```

（2）伪代码：

```
// 读者
void reader(){
    P(mutex);
        readcount++;
        if(readcount == 1) P(rw_mutex);  // 第一个读者锁资源，挡写者
    V(mutex);
    ...读数据...
    P(mutex);
        readcount--;
        if(readcount == 0) V(rw_mutex);  // 最后一个读者解锁，放行写者
    V(mutex);
}

// 写者
void writer(){
    P(rw_mutex);   // 写者独占
    ...写数据...
    V(rw_mutex);
}
```

（3）机理：只有**第一个进入的读者**会执行 `P(rw_mutex)` 锁住资源，后续读者只需 `readcount++` 后直接读，不经过 rw_mutex，因此可以**并发读**；只有**最后一个离开的读者**才 `V(rw_mutex)` 释放资源，此时写者才能进入。`mutex` 仅用来保证对 `readcount` 的修改是原子互斥的。

**24. 两人取物（盒容量 1）**

（1）只需 2 个信号量即可（因为盒容量为 1，缓冲区本身天然互斥，无需额外 mutex）：

```
semaphore empty = 1;  // 盒子空槽数（初始为空）
semaphore full  = 0;  // 盒子中产品数
```

（2）伪代码：

```
// 生产者
while(1){
    生产产品;
    P(empty);   // 盒子空才放（empty=0 表示已满，阻塞）
    放入盒子;
    V(full);    // 产品 +1
}

// 消费者
while(1){
    P(full);    // 有产品才取（full=0 表示空，阻塞）
    取出产品;
    V(empty);   // 空槽 +1
    消费产品;
}
```

> 说明：因为盒子只能放 1 件，"放"和"取"本身就互斥（empty/full 一个为 1 时另一个必为 0），所以不需要额外的 mutex。这是容量为 1 的特殊情形，体现"资源信号量初值 = 资源数"的思想。

**25. 前驱关系 S1 → S2**

（1）一个同步信号量，初值为 0：

```
semaphore s = 0;  // 表示"事件 S1 是否已发生"
```

（2）伪代码：

```
// P1
S1;
V(s);   // 发出"我已完成 S1"的信号

// P2
P(s);   // 等待 S1 完成（s<0 则阻塞）
S2;
```

> 机理：若 P2 先执行到 `P(s)`，s 由 0 减到 −1 < 0，P2 阻塞；P1 执行完 S1 后 `V(s)` 使 s 回到 0 并唤醒 P2 继续执行 S2。反之若 P1 先执行 `V(s)`，s 变为 1，P2 的 `P(s)` 把 s 减回 0 直接通过。两种情况都保证了 S1 在 S2 之前完成。
> 这是**PV 操作实现"前驱/先后顺序"同步的最小范例**，各种复杂同步大题都是由"资源信号量 + 前驱信号量"组合而来。
