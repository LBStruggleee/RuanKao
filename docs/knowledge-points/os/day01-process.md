## 一、进程的基本概念

### 1.1 什么是进程

**进程**（Process）是**可并发执行的程序在某数据集合上的一次运行活动**，是系统进行**资源分配和调度的基本单位**。

关键词记忆：**进程 = 程序 + 数据 + 进程控制块（PCB）**。程序是静态的，进程是动态的。

| 对比项 | 程序 | 进程 |
|--------|------|------|
| 性质 | 静态的指令集合 | 动态的执行过程 |
| 持久性 | 永久存在（存于磁盘） | 暂时的、有生命期 |
| 并发 | 不能并发执行 | 可以并发执行 |
| 组成 | 只有代码 | 程序段 + 数据段 + PCB |
| 唯一性 | 一份程序可对应多个进程 | 一个进程唯一对应一个执行实例 |

### 1.2 进程控制块（PCB）

**PCB（Process Control Block）是进程存在的唯一标志**。操作系统**感知进程的存在靠的是 PCB**，而不是程序本身。

PCB 通常包含四类信息：

| 类别 | 内容 |
|------|------|
| 进程标识符 | 进程 ID、父进程 ID |
| 处理机状态 | 程序计数器 PC、各寄存器内容（保存现场、恢复现场用） |
| 进程控制信息 | 进程状态、优先级、程序/数据地址、同步与通信信息、资源清单 |
| 进程调度信息 | 队列指针等 |

> 记忆：**"进程实体 = 程序段 + 数据段 + PCB"**，其中 PCB 是灵魂。

## 二、进程的五状态模型（高频！）

### 2.1 五种状态

进程在其生命周期中会经历以下状态：

| 状态 | 含义 |
|------|------|
| **新建（创建）态** | 进程刚被创建，PCB 已建立但尚未就绪 |
| **就绪（Ready）态** | 已获得除 CPU 之外的所有资源，只等 CPU 分配 |
| **执行（运行 Running）态** | 正在 CPU 上执行 |
| **阻塞（等待 Blocked）态** | 因等待某事件（I/O、信号量等）而暂停执行 |
| **终止（退出）态** | 进程执行完毕，系统回收资源 |

> **三状态模型**是简化版本：就绪、执行、阻塞。**五状态模型**在三状态基础上加了「新建」「终止」。软考常要求区分，注意题目问的是哪个模型。

### 2.2 状态转换图（必背）

```
       新建
        │
        ▼
  ┌──────────┐     被调度(dispatch)     ┌──────────┐
  │  就绪     │ ───────────────────────▶ │  执行     │
  │  Ready    │ ◀─────────────────────── │ Running   │
  └──────────┘     时间片用完(超时)      └──────────┘
        ▲                                    │     │
        │                                    │     │ 等待某事件(发生I/O请求)
        │  被唤醒(wakeup)                    │     ▼
        │  (等待的事件发生)                  │  ┌──────────┐
        │                                    │  │  阻塞     │
        │                                    │  │ Blocked   │
        └────────────────────────────────────┘  └──────────┘
                                                 │
                                                 ▼
                                              终止
```

### 2.3 状态转换的触发条件（易错点，必记）

| 转换 | 触发事件 |
|------|----------|
| 新建 → 就绪 | 系统允许接收新进程（创建完成） |
| 就绪 → 执行 | **进程被调度程序选中（获得 CPU）** |
| 执行 → 就绪 | **时间片用完**，或被更高优先级进程抢占 |
| 执行 → 阻塞 | **进程等待某事件**（如请求 I/O、P 操作失败） |
| 阻塞 → 就绪 | **等待的事件发生**（如 I/O 完成、被 V 操作唤醒） |
| 执行 → 终止 | 进程正常结束或异常退出 |

> **⚠️ 核心易错点**：
> 1. **阻塞态不能直接进入执行态**，必须**先回到就绪态**（因为阻塞态没有 CPU，也不具备被调度资格，事件发生后要先排队进就绪队列）。
> 2. **就绪态不能直接进入阻塞态**（就绪态的进程还没有 CPU，谈不上"等待事件"）。
> 3. **执行态能进入就绪态和阻塞态两个分支**：时间片用完→就绪；等待事件→阻塞。
> 4. 题目常考"X 到 Y 是否合法"，用上面这张表对照即可。

## 三、进程与线程（高频！）

### 3.1 线程的定义

**线程（Thread）**是**进程中能够独立执行的一个执行单元**，是**处理机调度和分派的基本单位**（注意：CPU 调度的基本单位是**线程**，资源分配的基本单位是**进程**）。

一个进程至少包含一个线程（主线程）。

### 3.2 进程与线程对比（必背表）

| 对比维度 | 进程 | 线程 |
|----------|------|------|
| **资源分配单位** | ✅ 是（独立地址空间、独立资源） | ❌ 否（共享所属进程的资源） |
| **调度单位** | 传统 OS 中是 | ✅ 是现代 OS 的基本调度单位 |
| **独立性** | 独立地址空间，互不干扰 | 共享地址空间 |
| **通信方式** | 需要 IPC（管道、消息队列、共享内存、信号量） | 直接读写共享变量（同一进程内） |
| **切换开销** | 大（要切换地址空间/页表） | 小（只切换寄存器和栈） |
| **并发性** | 进程间并发 | 进程间 + 线程间均可并发 |
| **崩溃影响** | 一个进程崩溃不影响其他进程 | 一个线程崩溃**可能导致整个进程崩溃**（共享地址空间） |
| **创建/销毁开销** | 大 | 小 |

### 3.3 常见考点速记

- 引入线程后，**进程只作为资源分配单位**，**线程作为 CPU 调度单位**。
- 同一进程内的线程共享：**代码段、数据段、打开的文件、堆**；独享：**栈、寄存器、程序计数器（各自）**。
- 线程状态也可分就绪/执行/阻塞，但不存在"新建/终止"的系统级干预差别（理解即可，不必深究）。

## 四、进程调度算法（必考计算题！）

### 4.1 调度层次

| 层次 | 别称 | 频率 | 作用 |
|------|------|------|------|
| 高级调度 | 作业调度 / 长程调度 | 低 | 从外存后备队列选作业调入内存，建立进程 |
| 中级调度 | 内存调度 / 中程调度 | 中 | 进程在内存与外存（挂起）间交换，缓解内存紧张 |
| 低级调度 | 进程调度 / 短程调度 | 高（s 级） | 从就绪队列选进程分配 CPU（**我们下面讨论的都是这个**） |

### 4.2 五种调度算法

#### （1）先来先服务 FCFS（First Come First Served）
- 按到达顺序排队，先到的先执行。
- **非抢占式**。
- 优点：简单、公平。缺点：**对短作业不利，平均等待时间长**，可能出现"护航效应"（长作业阻塞在前的短作业）。

#### （2）短作业优先 SJF / 最短剩余时间优先 SRTF
- 选取**估计运行时间最短**的作业/进程。
- SJF 非抢占；SRTF 是抢占版（新到更短作业可抢占）。
- 优点：**平均等待时间最短**。缺点：**长作业可能饥饿（饿死）**，需要"老化"救济。

#### （3）优先级调度
- 按优先级高低分配 CPU，分**抢占式**和**非抢占式**。
- 缺点：**低优先级可能饥饿**，可通过**老化（aging，随等待时间提升优先级）**解决。

#### （4）时间片轮转 RR（Round Robin）
- 就绪队列按 FCFS 排队，每个进程分一个**时间片（固定 q）**，用完未结束则回到队尾。
- 用于**分时系统**。
- 关键结论：**时间片过大 → 退化为 FCFS；时间片过小 → 上下文切换开销过大**。
- 平均等待时间通常比 SJF 长，但公平、响应性好。

#### （5）多级反馈队列（综合，最常用）
- 多个优先级不同的就绪队列；高优先级队列时间片小，低优先级时间片大；进程从一个队列降到更低的队列，直到在底层按 RR 执行。
- 兼顾了**响应时间**和**周转时间**，是较完善的调度算法。

### 4.3 调度性能指标（必会计算）

| 指标 | 定义 | 公式 |
|------|------|------|
| **周转时间** | 从提交到完成 | = 完成时间 − 到达时间 |
| **带权周转时间** | 周转时间 / 运行时间 | = 周转时间 ÷ 运行时间 |
| **平均周转时间** | 各进程周转时间之和 / 进程数 | |
| **平均带权周转时间** | 各带权周转时间之和 / 进程数 | |
| **平均等待时间** | 各进程等待时间（= 开始执行 − 到达时间）之和 / 进程数 | |

> 考试往往给一张"进程 + 到达时间 + 运行时间"表，要求按某算法求**平均周转时间 / 平均等待时间**。**必须画时间轴（甘特图）手算**，不要只背公式。

### 4.4 例题（手算示范）

> 三个进程到达时间与运行时间如下，分别求 FCFS 和 SJF 的**平均周转时间**。

| 进程 | 到达时间 | 运行时间(ms) |
|------|---------|-------------|
| P1 | 0 | 24 |
| P2 | 0 | 3 |
| P3 | 0 | 3 |

**FCFS（顺序 P1→P2→P3）：**

```
时间轴: |----P1(24)----|--P2(3)--|--P3(3)--|
时间点:  0             24        27        30
```

| 进程 | 完成时间 | 周转时间 |
|------|---------|---------|
| P1 | 24 | 24 − 0 = 24 |
| P2 | 27 | 27 − 0 = 27 |
| P3 | 30 | 30 − 0 = 30 |

平均周转时间 = (24 + 27 + 30) / 3 = **27 ms**。

**SJF（顺序 P2→P3→P1）：**

```
时间轴: |--P2(3)--|--P3(3)--|----P1(24)----|
时间点:  0         3         6             30
```

| 进程 | 完成时间 | 周转时间 |
|------|---------|---------|
| P2 | 3 | 3 |
| P3 | 6 | 6 |
| P1 | 30 | 30 |

平均周转时间 = (3 + 6 + 30) / 3 = **13 ms**。

**结论**：SJF 平均周转时间（13）远优于 FCFS（27）。这就是"SJF 平均等待时间最短"的直观来源。

## 五、信号量与 PV 操作（科目二高频大题！）

### 5.1 为什么要同步：临界资源与临界区

- **临界资源**：一次只允许一个进程使用的资源（如打印机、共享缓冲区）。
- **临界区**：进程中访问临界资源的代码段。
- 临界区访问原则：**互斥进入、有空让进、有限等待、让权等待**。

### 5.2 信号量（Semaphore）

**信号量**是一个记录型数据结构，核心是一个**整型变量 S** + 一个**等待队列**。通过 S 的加减和队列实现资源的"记账"：

| 操作 | 别称 | 动作 |
|------|------|------|
| **P 操作** | wait / down | S = S − 1；若 S < 0，则**该进程阻塞**并进入信号量的等待队列 |
| **V 操作** | signal / up | S = S + 1；若 S ≤ 0，则**从等待队列唤醒一个进程**（转入就绪） |

**P、V 操作必须成对出现，且是原子操作（不可中断）。**

> **⚠️ 记忆口诀**：
> - **P** = Proberen（荷兰语"测试"，减）→ **"要资源、先 P"**。
> - **V** = Verhogen（荷兰语"增加"，加）→ **"用完了、再 V"**。
> - **P 是"申请/消耗"，V 是"释放/产生"**。

### 5.3 信号量的两种用途

| 用途 | 信号量初值 | 含义 |
|------|-----------|------|
| **互斥信号量（mutex）** | 通常为 1 | 保证同一时刻只有一个进程进入临界区 |
| **资源/同步信号量（empty/full）** | 为可用资源数 n，或为 0 | 表示某种资源的剩余数量或事件是否发生 |

> **如何区分**：互斥量初值 = **1**，PV 出现在**同一进程内**（P 和 V 夹住临界区）；资源信号量初值 = **n 或 0**，P 和 V 通常**分别出现在不同进程**里（一个进程 P，另一个进程 V）。

### 5.4 经典模型一：生产者-消费者问题（必会写代码）

**场景**：生产者往大小为 n 的缓冲区放产品，消费者从缓冲区取产品。要求：缓冲区满则生产者不能放，空则消费者不能取；同一时刻一个进程访问缓冲区。

**信号量设计（三件套）：**

```
semaphore mutex = 1;   // 互斥信号量：保护缓冲区这种临界资源
semaphore empty = n;   // 资源信号量：缓冲区空槽数量（初值 = 缓冲区大小 n）
semaphore full  = 0;   // 资源信号量：缓冲区已有产品数量（初值 = 0）
```

**生产者进程：**

```
while(true){
    生产一个产品;
    P(empty);      // ①申请一个空槽（没有空槽则阻塞等待）
    P(mutex);      // ②申请进入缓冲区（互斥）
    把产品放入缓冲区;
    V(mutex);      // ③释放缓冲区
    V(full);       // ④产品数量 +1（唤醒等待产品的消费者）
}
```

**消费者进程：**

```
while(true){
    P(full);       // ①申请一个产品（没有产品则阻塞等待）
    P(mutex);      // ②进入缓冲区（互斥）
    从缓冲区取出产品;
    V(mutex);      // ③释放缓冲区
    V(empty);      // ④空槽数量 +1（唤醒等待空槽的生产者）
    消费产品;
}
```

> **⚠️ 经典易错点（务必理解）**：
> **`P(empty)` 必须在 `P(mutex)` 之前，`P(full)` 必须在 `P(mutex)` 之前。**
> 顺序若颠倒（先 P(mutex) 再 P(empty)），会产生**死锁**：
> 生产者拿到 mutex 进入缓冲区后发现 empty=0（缓冲区满）而阻塞，却**不肯释放 mutex**；
> 消费者要取产品必须先 P(mutex)，但 mutex 被生产者占着，导致**生产者等消费者、消费者等生产者**——死锁。
> 反过来 "先申请资源、再申请互斥" 就不会：即使资源不够，也没占用 mutex，别人还能进入释放资源。

### 5.5 经典模型二：读者-写者问题

**场景**：多个读者可以同时读；写者与任何读者/写者都互斥（写时不能读、不能写）。**允许多读者同时读，但同一时刻至多一个写者。**

**写者优先 or 读者优先**是两种策略，考试最常见的是**读者优先**：

```
int readcount = 0;             // 当前读者数量
semaphore rw_mutex = 1;        // 写者互斥信号量（读/写共享资源的访问锁）
semaphore mutex = 1;           // 保护 readcount 的互斥信号量

// 读者进程
void reader(){
    P(mutex);                  // 保护 readcount 的修改
        readcount++;
        if(readcount == 1)
            P(rw_mutex);       // 第一个读者到来，锁住资源，挡住写者
    V(mutex);

    读取数据;

    P(mutex);
        readcount--;
        if(readcount == 0)
            V(rw_mutex);       // 最后一个读者离开，释放资源，允许写者进入
    V(mutex);
}

// 写者进程
void writer(){
    P(rw_mutex);               // 写者要独占，直接申请 rw_mutex
    写入数据;
    V(rw_mutex);
}
```

> **核心思路记忆**：
> - `rw_mutex` 是"**读写全局锁**"，写者直接 P/V 它，实现写互斥。
> - 读者通过 `readcount` 计数：**第一个进 → P(rw_mutex)**（挡住写者）；**最后一个出 → V(rw_mutex)**（放行写者）。
> - `mutex` 只用来保护 `readcount` 这个共享变量的读写。
> - **多读者可同时读**的奥妙：只有第一个读者 P(rw_mutex)，后续读者直接读，不经过 rw_mutex。

### 5.6 PV 操作大题答题模板（科目二通用套路）

看到 PV 大题，按以下 4 步走（**步骤分就是这样拿的**）：

**第 1 步：找临界资源** → 每个临界资源配一个**互斥信号量**（初值 1）。
**第 2 步：找资源/同步约束** → 每种"资源"配一个**资源信号量**（初值 = 该资源数量；若表示"事件发生与否"，初值 0）。
**第 3 步：写每个进程的操作序列**：**先 P 资源信号量，再 P 互斥信号量；进入临界区；先 V 互斥信号量，再 V 相应的资源信号量**。
**第 4 步：检查**：
- P、V 是否成对；
- 互斥量的 P、V 是否在同一进程内（夹住临界区）；
- 资源量的 P、V 是否在不同进程内对应；
- 会不会死锁（资源量 P 是否在互斥量 P 之前）。

> 口诀：**"资源在前、互斥在后；谁进谁 P、谁出谁 V；成对出现、原子操作。"**

## 六、死锁（配合进程同步一起记，常与 PV 关联出题）

### 6.1 死锁的四个必要条件

1. **互斥**：资源一次只能被一个进程独占。
2. **占有且等待（请求与保持）**：进程已持有资源，又等待新资源，且不释放已持有的。
3. **不可剥夺（不可抢占）**：进程已获得的资源不能被强行夺走，只能自己释放。
4. **循环等待**：若干进程之间形成首尾相接的资源等待环。

> **四个条件缺一不可**：破坏其中任意一个，即可防止死锁。

### 6.2 死锁的处理

| 策略 | 做法 | 例子 |
|------|------|------|
| **预防** | 破坏四条件之一 | 资源有序分配（破坏循环等待） |
| **避免** | 动态判断资源分配是否安全 | **银行家算法**（安全状态判断） |
| **检测** | 允许发生，检测后处理 | 资源分配图、死锁解除 |
| **消除/恢复** | 撤销进程、剥夺资源 | |

### 6.3 死锁资源分配的一个结论（易考）

设每个进程需要 k 个同类资源，共有 n 个进程：

- 不发生死锁的**最少资源数** = `n × (k − 1) + 1`（最坏情况每人拿 k−1 个，还差的那个资源一给谁，谁就能完成并释放）。

> 例：3 个进程，每个最多需要 3 台打印机，则至少需要 `3 × (3−1) + 1 = 7` 台打印机才不会死锁。

### A.1 树遍历（树/二叉树四种遍历）

| 遍历 | 递归顺序 | 记忆 |
|------|---------|------|
| 前序（先根） | 根 → 左 → 右 | 根在最前 |
| 中序 | 左 → 根 → 右 | 根在中间（**BST 输出有序**） |
| 后序 | 左 → 右 → 根 | 根在最后（**删除树/计算树高用**） |
| 层序 | 逐层从左到右 | 用**队列**实现（BFS） |

> **重难点：由两个遍历序列确定唯一二叉树**——**必须有中序**。
> 前序 + 中序 或 后序 + 中序 → 可唯一确定；**前序 + 后序无法唯一确定**（因为无法区分左右子树边界）。
>
> 例：前序 `ABDEC`，中序 `DBEAC`。由前序知 A 为根；中序中 A 左边 `DBE` 是左子树、右边 `C` 是右子树；递归还原。

### A.2 图算法

| 算法 | 用途 | 时间复杂度 | 关键点 |
|------|------|-----------|--------|
| DFS | 深度遍历 | 邻接表 O(V+E) | 递归/栈 |
| BFS | 广度遍历 | 邻接表 O(V+E) | 队列 |
| **Prim** | 最小生成树 | O(V²)（朴素） | 从点出发，适合**稠密图** |
| **Kruskal** | 最小生成树 | O(E log E) | 从边出发，适合**稀疏图**，需并查集判环 |
| **Dijkstra** | 单源最短路 | O(V²)（朴素） | **不能有负权边** |
| Floyd | 全源最短路 | O(V³) | 三重循环，可带负权（无负环） |

### A.3 排序稳定性

> **稳定排序**：关键字相等时，排序前后的相对次序不变。

| 排序 | 平均 | 最坏 | 空间 | 稳定性 |
|------|------|------|------|--------|
| 冒泡 | O(n²) | O(n²) | O(1) | ✅ **稳定** |
| 直接插入 | O(n²) | O(n²) | O(1) | ✅ **稳定** |
| 归并 | O(nlogn) | O(nlogn) | O(n) | ✅ **稳定** |
| 基数 | O(d(n+k)) | O(d(n+k)) | O(n+k) | ✅ **稳定** |
| 简单选择 | O(n²) | O(n²) | O(1) | ❌ 不稳定 |
| 快速 | O(nlogn) | O(n²) | O(logn) | ❌ 不稳定 |
| 希尔 | 依赖增量 | O(n²) | O(1) | ❌ 不稳定 |
| 堆 | O(nlogn) | O(nlogn) | O(1) | ❌ 不稳定 |

> 口诀：**"快些（快速）选、简单选、希尔、堆"不稳定**；稳定的有**冒泡、插入、归并、基数**。
> 记忆技巧：不稳定的大多是"跳跃式交换"的（快排、选择、希尔、堆）；稳定的多是"相邻交换/顺序合并"的（冒泡、插入、归并、基数）。

### A.4 哈希冲突处理

| 方法 | 做法 | 特点 |
|------|------|------|
| **开放地址法**（线性探测） | 冲突就往后找下一个空位 `H+i` | 会产生"聚集"（堆积），查找退化为顺序 |
| **开放地址法**（二次探测） | `H + i²` 探测 | 减少堆积 |
| **链地址法（拉链法）** | 每个桶挂链表 | 不会堆积，装填因子 >1 也可 |
| **再哈希法** | 冲突用第二个哈希函数 | |

- 装填因子 α = 表中已有记录数 / 表长。α 越大，冲突概率越大，ASL（平均查找长度）越长。
- 哈希查找 ASL 只取决于装填因子 α，与记录个数 n 无直接线性关系（理想 O(1)）。

### A.5 时间复杂度速记

`O(1) < O(logn) < O(n) < O(nlogn) < O(n²) < O(n³) < O(2ⁿ) < O(n!)`

- 折半查找：O(logn)；顺序查找：O(n)。
- 快速/归并/堆排序平均：O(nlogn)；冒泡/插入/选择：O(n²)。
- 二叉树相关：平衡树 O(logn)，退化链表最坏 O(n)。
- 递归复杂度：可用**主定理**或展开法（如 T(n) = 2T(n/2) + n → O(nlogn)，归并排序）。
