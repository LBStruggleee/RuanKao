### 【问题1】（8 分）填充 C 代码空（1）〜（4）

> **答案（原文）**：
> （1）`d[0][j] = j`
> （2）`str1[i – 1] == str2[j – 1]`
> （3）`d[i – 1][j – 1] + 1`
> （4）`d[len1][len2]`

**丢分点解析**（状态转移如何映射到代码）：

先把二维数组 d 的含义钉死：**`d[i][j]` = 把 str1 的前 i 个字符变成 str2 的前 j 个字符
所需的最少操作次数**。整段代码就是这个递推式的"自底向上填表"，四个空分别对应
**两类边界 + 字符比较 + 三种操作取最小 + 最终答案**。

- **空（1）`d[0][j] = j`（列边界）**：
  紧邻的上一段已给出 `for (i = 0; i <= len1; i++) { d[i][0] = i; }`——
  这是**行边界**："str1 的前 i 个字符变成空串，只能删除 i 次，代价 i"。
  空 (1) 所在循环是 `for (j = 0; j <= len2; j++)`，**结构完全对称**：
  "空串变成 str2 的前 j 个字符，只能插入 j 次，代价 j" → `d[0][j] = j`。
  - **易错点**：误填 `d[j][0] = j`（下标写反）；或受行边界影响写成 `d[0][j] = i`（循环变量混用）。
  - **记忆法**：**"谁的前缀长度就是谁的下标，值就是那个长度"**——`d[0][j]` 里
    str1 长度 0、str2 长度 j，值为 j。

- **空（2）`str1[i – 1] == str2[j – 1]`（字符比较）**：
  双重循环 `i` 从 1 到 len1、`j` 从 1 到 len2 遍历所有"非空"子问题。
  若两串当前末字符**相等**，则不用任何操作，`d[i][j] = d[i - 1][j - 1]`（继承左上角）。
  - **下标减 1 的原因**：`d` 的下标是"前缀长度"（从 0 计），而字符数组的下标是"字符位置"
    （从 0 计）——长度 i 的前缀，其末字符是 `str1[i-1]`。**这是本题最高频的丢分点**：
    漏掉 `-1` 写成 `str1[i] == str2[j]` 会导致越界且语义错误。
  - **易错点**：把 `==` 写成 `!=`（则 if 分支语义反转，相等时反而走 else）；
    用 `diff` 变量拼接（题目声明了 `diff` 但代码直接写比较式，按上下文填比较式即可）。

- **空（3）`d[i – 1][j – 1] + 1`（替换操作的代价）**：
  else 分支里，`temp = min(d[i - 1][j] + 1, d[i][j - 1] + 1)` 已经给出两种操作：
  - `d[i-1][j] + 1` = **删除 str1 末字符**（str1 少一个，代价 +1）；
  - `d[i][j-1] + 1` = **插入一个字符到 str2 末位**（str2 少一个，代价 +1）。
  - 缺的第三种 = **把 str1 末字符替换成 str2 末字符**：两个末字符同时消掉，
    代价 = `d[i-1][j-1] + 1`。三者再取一次 min，即 `min(temp, d[i-1][j-1] + 1)`。
  - **易错点**：漏掉 `+ 1`（替换本身要算 1 次操作）；误写成 `d[i-1][j-1]`（与"相等时
    继承左上角"混淆——相等时 +0，不等时 +1）。

- **空（4）`d[len1][len2]`（最终答案）**：
  问题问的是"str1 整体变成 str2 整体"，即前缀长度分别取到最大值 → 右下角格子。
  - **易错点**：写成 `d[len1-1][len2-1]`（混淆"长度"与"下标"）；
    写成 `d[N][N]`（N 是数组容量 100，不是串长）。

**状态转移总览（对照代码读两遍）**：

```text
d[i][0] = i                              （行边界：全删除）
d[0][j] = j                              （列边界：全插入）       ← 空(1)
if str1[i-1] == str2[j-1]:               （末字符相等）           ← 空(2)
    d[i][j] = d[i-1][j-1]                （继承左上角，+0）
else:
    d[i][j] = min( d[i-1][j]   + 1,      （删除）                 
                  d[i][j-1]   + 1,      （插入）
                  d[i-1][j-1] + 1 )     （替换）  ← 空(3)
```

**知识点**：【科目二·试题四】动态规划——序列 DP（编辑距离），边界 + 状态转移 + 三操作取小

### 【问题2】（4 分）设计策略与时间复杂度

> **答案（原文）**：（5）动态规划法　（6）`O(mn)` 或 `O(m * n)`

**丢分点解析**：

- **（5）动态规划法**：判断依据三件套——① 用二维数组 d **记录子问题最优解**；
  ② 问题具有**最优子结构**（大问题的最优解由子问题最优解构成）；
  ③ 代码**自底向上填表**（两层循环从小到大填 d）。
  - **易错点**：答"分治法"（分治是自顶向下分解+合并，且子问题独立；本题子问题重叠、
    需要记录中间结果，这是 DP 区别于分治的关键）；答"贪心法"（贪心不回溯、不保证全局最优）。
- **（6）O(mn)**：填表是 `(len1+1) × (len2+1)` 的双重循环，每格 O(1) → O(mn)。
  题目用 m、n 表示两串长度，照题意作答。
  - **易错点**：写成 `O(n²)`（没注意两串长度不同、题目指定了 m/n 两个符号）；
    写成 `O(n)` 或 `O(m+n)`。

**知识点**：【科目二·试题四】算法设计策略判别（DP 特征）+ 复杂度分析

### 【问题3】（3 分）手算编辑距离

> **答案（原文）**：（7）`4`

**丢分点解析**（按代码逻辑手算，A="CTGA"、B="ACGCTA"）：

- A 的前缀长度 i ∈ [0,4]（5 行），B 的前缀长度 j ∈ [0,6]（7 列），先填边界：
  第 0 行 `d[0][j] = j` → `0,1,2,3,4,5,6`；第 0 列 `d[i][0] = i` → `0,1,2,3,4`。
- 逐格套用空 (2)(3)（`C/T/G/A` 对 `A/C/G/C/T/A`）：

| i＼j | 0 | 1(A) | 2(C) | 3(G) | 4(C) | 5(T) | 6(A) |
|------|---|------|------|------|------|------|------|
| 0 | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
| 1(C) | 1 | 1 | 1 | 2 | 3 | 4 | 5 |
| 2(T) | 2 | 2 | 2 | 3 | 4 | 3 | 4 |
| 3(G) | 3 | 3 | 3 | 2 | 3 | 4 | 4 |
| 4(A) | 4 | 3 | 3 | 3 | 4 | 4 | **4** |

- 右下角 `d[4][6] = 4` 即答案。**一种最少 4 步的操作序列**（验证用）：
  `CTGA` → 删 C 得 `TGA` → 插 A 得 `ATGA` → 改 G→C 得 `ATCA` → 插 G 得 `ACGCTA`。
- **易错点**：只凭直觉猜（"看起来差 4 个字符"）；画表时行/列与字符串对错位；
  填表顺序错（应**从左到右、从上到下**，因为每格依赖左、上、左上三个已填格子）。

**知识点**：【科目二·试题四】DP 表的手工模拟（阅卷按结果给分，建议画表后保留草稿）

### 【问题1】（8 分）填充 C 代码空（1）〜（4）

> **答案（原文）**：
> （1）`j = i + p`
> （2）`k < j`
> （3）`cost[i][k] + cost[k + 1][j] + seq[i] * seq[k + 1] * seq[j + 1]`
> （4）`trace[i][j] = tempTrace`

**丢分点解析**（区间 DP 如何映射到三重循环）：

先钉死含义：**`cost[i][j]` = 连乘 A(i+1) *…* A(j+1) 的最优（最少乘法）代价**；
`trace[i][j]` = 对应的最优断点 k。循环结构是典型的**区间 DP**：
外层 `p` = 区间长度（矩阵个数，从 2 到 n），中层 `i` = 区间起点，内层 `k` = 枚举断点。

- **空（1）`j = i + p`（区间终点）**：
  区间从 i 出发长度 p，终点 `j = i + p`。验证：`p=1` 时 `j=i+1`（两个矩阵 A(i+1)*A(i+2)，
  恰是长度 2 的区间），且代码里有 `i < n - p` 保证 `j = i + p ≤ n - 1`（不越界）。
  后面 `cost[i][j] = tempCost;` 也用到了 j，说明 j 必须在此空先算出来。
  - **易错点**：写成 `j = i + p - 1`（把"长度"与"跨度"差 1 搞混——区间 [i..j] 含 j-i+1 个
    元素，长度 p 时 j = i + p - 1 还是 i + p 取决于"长度"定义；本题 `p` 是矩阵个数、
    `cost[i][i]=0` 对角线为长度 1，故长度 p 的区间是 [i..i+p-1] 还是 [i..i+p]？
    用 `i < n - p` 的边界核对：i 最大为 n-p-1，若 `j = i+p` 则 j ≤ n-1 ✓；
    若 `j = i+p-1` 则 j ≤ n-2，最后一个区间取不到 n-1，故本题答案为 `j = i + p`）。

- **空（2）`k < j`（断点枚举上界）**：
  断点 k 把连乘 A(i+1)…A(j+1) 分成 **左段 A(i+1)…A(k+1)** 与 **右段 A(k+2)…A(j+1)**。
  k 从 i 开始，最多到 j-1（保证右段至少有一个矩阵）。`k < j` 等价于 `k <= j - 1`。
  - **易错点**：写成 `k <= j`（右段为空，`cost[k+1][j]` 里 k+1 > j，语义错误）；
    写成 `k < n`（与终点 j 无关）。

- **空（3）`cost[i][k] + cost[k + 1][j] + seq[i] * seq[k + 1] * seq[j + 1]`（合并代价）**：
  三部分：左段最优代价 + 右段最优代价 + **左右段相乘的乘法次数**。
  维数序列 `seq[]` 里，矩阵 A(t) 是 `seq[t-1] * seq[t]`。左段 A(i+1)…A(k+1) 的结果是
  `seq[i] * seq[k+1]` 行列？——逐步核对：左段第一个矩阵 A(i+1) 的行数是 `seq[i]`，
  左段最后一个矩阵 A(k+1) 的列数是 `seq[k+1]`，故左段结果矩阵为 `seq[i] × seq[k+1]`；
  右段 A(k+2)…A(j+1) 的结果是 `seq[k+1] × seq[j+1]`。两矩阵相乘
  （左列 = 右行 = `seq[k+1]`）的乘法次数 = `seq[i] * seq[k+1] * seq[j+1]`。
  - **下标记忆法**：合并代价的三项维数**首尾相接**——`seq[i]`（左段行）→
    `seq[k+1]`（左段列=右段行）→ `seq[j+1]`（右段列），中间项是断点处共享的维数。
  - **易错点**：写成 `seq[i] * seq[k] * seq[j]`（k 与 k+1 混淆——断点 k 的"列维数"
    是 `seq[k+1]`，因为 A(k+1) 的列在 `seq[k+1]`）；漏掉前两项的 cost 递推。

- **空（4）`trace[i][j] = tempTrace`（记录最优断点）**：
  与上一行 `cost[i][j] = tempCost;` 完全对称——内层循环找到更小的 temp 时，
  把 `tempCost` 与 `tempTrace` 一起更新，循环结束后一并写回二维数组。
  - **易错点**：写成 `trace[i][j] = k`（循环外引用循环变量 k，此时 k 已不指向最优断点；
    `tempTrace` 才是"更新发生时"记下的最优 k）；位置写错（应在对 k 的循环**结束后**赋值）。

**区间 DP 骨架（对照代码读两遍）**：

```text
for 每个单矩阵: cost[i][i] = 0                      （对角线初始化）
for p = 区间长度 2..n:                              （外层：规模）
    for i = 起点 0..n-p-1:
        j = i + p                                   （终点）      ← 空(1)
        for k = i..j-1:                             （断点）      ← 空(2)
            temp = cost[i][k] + cost[k+1][j]
                   + seq[i]*seq[k+1]*seq[j+1]       （合并代价）  ← 空(3)
            if 更小: 记下 tempCost, tempTrace
        cost[i][j]  = tempCost
        trace[i][j] = tempTrace                     （保存断点）  ← 空(4)
```

**知识点**：【科目二·试题四】动态规划——区间 DP（矩阵连乘），断点枚举 + 维数下标偏移

### 【问题2】（4 分）设计策略与时间复杂度

> **答案（原文）**：（5）动态规划　（6）`O(n³)`

**丢分点解析**：

### 【问题3】（3 分）最优计算顺序与乘法次数

> **答案（原文）**：
> （7）`A1 * （（A2 * A3） * A4）` 或 `A1 * （A2 * A3 * A4）` 或：`A1 （（A2 A3） A4）` 或 `A1 （A2 A3 A4）`
> （8）`5375`

**丢分点解析**（维数序列 seq = {15, 5, 10, 20, 25}，即 A1:15×5，A2:5×10，A3:10×20，A4:20×25）：

- 乘法次数公式（【说明】(1)）：`A(a×b) * A(b×c)` 需 `a*b*c` 次乘法，结果为 `a×c`。
- **5 种括号化逐一计算**：

| 计算顺序 | 乘法次数计算 | 合计 |
|----------|--------------|------|
| `A1*((A2*A3)*A4)` | A2*A3: 5×10×20=1000 →5×20；(5×20)*A4: 5×20×25=1000 →5×25；A1*(5×25): 15×5×25=1875 | **5375** |
| `A1*(A2*(A3*A4))` | A3*A4: 10×20×25=5000 →10×25；A2*(10×25): 5×10×25=1250 →5×25；A1*(5×25): 1875 | 8125 |
| `((A1*A2)*A3)*A4` | A1*A2: 15×5×10=750 →15×10；*A3: 15×10×20=3000 →15×20；*A4: 15×20×25=7500 | 11250 |
| `(A1*A2)*(A3*A4)` | 750 + 5000 + (15×10)*(10×25): 15×10×25=3750 | 9500 |
| `(A1*(A2*A3))*A4` | A2*A3: 1000 →5×20；A1*(5×20): 15×5×20=1500 →15×20；*A4: 7500 | 10000 |

- 最小值 **5375**，对应 `A1*((A2*A3)*A4)`（答案也接受不写最内层括号的简写）。
- **易错点**：
  - 只算了一种顺序就下结论（本题必须枚举全部 5 种，或按 DP 表回溯）；
  - 维数取错——A1 是 15×5（不是 5×15），`seq[0]=15, seq[1]=5`；
  - 忘记"结果矩阵的维数"会随结合方式变化（左结合到右结合中间结果维数不同，这是
    "不同顺序计算量不同"的根本原因）。

**知识点**：【科目二·试题四】最优解的构造与手工验算（括号化枚举 + 乘法次数公式）

### 逐空丢分点解析（模式角色如何映射到代码）

先把享元模式的**两个状态**分清——这是本题代码的全部逻辑基础：
- **内部状态（可共享）**：棋子**颜色** `m_color`——一盘棋只有黑白两种，可共享；
- **外部状态（不共享）**：棋子**位置** `m_pos`——每颗棋子位置不同，由 `PiecePos` 单独封装。

- **空（1）`public abstract void draw()`（抽象享元的操作声明）**：
  `Piece` 是抽象享元，两个具体子类 `BlackPiece`、`WhitePiece` **都已实现**了
  `public void draw() {…}`。父类里必须有一个**与子类签名一致**的抽象方法。
  - 三个得分要素：**访问修饰符 `public`**（子类 draw 是 public，父类抽象方法不能更窄）、
    **`abstract` 关键字**（在抽象类中声明无实现的方法）、**返回类型 + 方法名 + 参数列表**
    （`void draw()`，无参）。
  - **易错点**：漏 `abstract`（写成 `public void draw();`——在抽象类中带分号的无方法体
    方法虽也能编译，但题目明确考"抽象声明"，且缺 abstract 语义不完整）；
    漏 `public` 只写 `abstract void draw()`（子类是 public，父类缩小访问范围不合法）；
    误加参数（如 `draw(PiecePos pos)`，与子类签名不符）。

- **空（2）`Piece`（泛型容器的元素类型）**：
  棋盘用一个 `ArrayList` 收集所有已落棋子，黑子白子要放进同一个集合，
  元素类型必须是它们的**共同父类 `Piece`**。
  - **判定链**：`m_arrayPiece.add(piece)` → `piece` 是 `BlackPiece` 或 `WhitePiece`
    → 集合元素类型须能同时容纳两者 → `Piece`。
  - **易错点**：填 `BlackPiece`（放不进白子）；填 `PieceColor`（那是颜色枚举，不是棋子）；
    漏掉泛型语法写成裸 `ArrayList`。

- **空（3）`Piece`（局部变量类型）**：
  `SetPiece` 里同一个变量 `piece` 在 if 分支被赋为 `BlackPiece`、在 else 分支被赋为
  `WhitePiece`，声明类型必须是共同父类 `Piece`（多态）。
  - **与空（2）的关联**：正因为 `piece` 是 `Piece` 类型，`m_arrayPiece`（`ArrayList<Piece>`）
    才能 `add(piece)`。两空答案相同、理由不同：(2) 是集合元素类型，(3) 是多态变量类型。
  - **易错点**：填 `Object`（过宽，丢失"棋子"语义，且后续 `piece.draw()` 依赖 Piece 类型
    才能调用 draw）；填具体子类名（另一分支无法赋值）。

- **空（4）（5）`piece.draw()`（落子后绘制）**：
  两个分支结构完全对称——获取棋子 → 打印落子位置 → **调用棋子的绘制方法**。
  `piece` 声明为 `Piece`，`draw()` 是 `Piece` 的（抽象）方法，此处通过多态调用
  实际子类的实现。
  - **易错点**：写成 `BlackPiece.draw()` / `WhitePiece.draw()`（静态方式调用，
    且签名应为对象方法调用）；漏掉 `.` 或 `()`；只在 if 分支写、漏掉 else 分支（两个空
    写法相同，都要填）。

**享元模式角色 → 代码对照表**：

| 模式角色 | 本题代码 | 识别要点 |
|----------|----------|----------|
| 抽象享元 Flyweight | `abstract class Piece` | 内部状态 `m_color` + 抽象操作 (1) |

# 试题 D：2022 年上半年 下午试题五（备忘录模式，C++）

| （5） | `originator->saveStateToMemento()` | 同上 |
| （6） | `originator->saveStateToMemento()` | 同上 |

---

### 逐空丢分点解析（模式角色如何映射到代码）

备忘录模式三角色（【说明】已直接给出）：**Memento**（封装要恢复的状态）、
**Originator**（创建并在 Memento 中存储状态）、**CareTaker**（负责从 Memento 恢复状态）。
填空全部是"三角色之间怎么传状态"。

- **空（1）`Memento(state)`（发起人 → 备忘录：存状态）**：
  方法签名 `Memento saveStateToMemento()` 要求**返回一个 Memento 对象**；
  `Memento` 的构造函数是 `Memento(string state)`。把发起人的当前状态打包成备忘录，
  即构造一个用 `this->state`（等价 `getState()`）初始化的 Memento 返回。
  - **三种等价写法**：`Memento(state)` / `Memento(this->state)` / `Memento(getState())`
    （后者利用本类的 `getState()`，语义最清晰）。
  - **易错点**：只写 `state`（返回类型是 Memento，不能返回 string）；
    写成 `new Memento(state)`（方法返回值类型是 `Memento` 不是 `Memento*`，
    `main` 中 `careTaker->add(...)` 接收的是对象不是指针，直接返回对象即可）。

- **空（2）`Memento.getState()`（备忘录 → 发起人：取状态）**：
  方法 `getStateFromMemento(Memento Memento)` 的形参**也叫 Memento**（与类名同名，
  系原卷写法），`Memento.getState()` 中的 `Memento` 指**形参对象**。
  把形参备忘录里存的状态取出，赋给 `this->state`，即完成"恢复"。
  - **易错点**：写成 `state.getState()`（混淆成员与形参——等号左边的 `state` 是成员，
    右边要从形参备忘录取）；误认为 `Memento` 指类名而无法组织表达式。
  - 【存疑：原卷形参名与类名同名（`Memento Memento`），按原卷转录；
    作答时 `Memento.getState()` 指形参对象调用其 getState() 方法。】

- **空（3）`void add(Memento state)`（管理者：存备忘录）**：
  方法体 `mementoList.push_back(state);` 说明：方法名是 `add`（由 `main` 中
  `careTaker->add(...)` 确定），形参名是 `state`（方法体里 push 的就是它），
  形参类型是 `Memento`（容器是 `vector<Memento>`），无返回值 → `void`。
  - **得分要素**：`void` + `add` + `Memento state` 三件套。
  - **易错点**：漏 `void`；形参类型写成 `string`（容器收的是 Memento 对象）；
    方法名写成 `save` 之类（要与 `main` 的调用一致）。

- **空（4）`Memento get(int index)`（管理者：取备忘录）**：
  方法体 `return mementoList[index];` 返回的是 `Memento` 对象；方法名 `get`
  （由 `careTaker->get(0)` 确定）；形参是 `int index`（下标）。
  - **易错点**：返回类型写成 `void` 或 `int`（要返回 Memento）；
    形参名写成 `i`（方法体用的是 `index`，需保持一致）。

- **空（5）（6）`originator->saveStateToMemento()`（客户端：发起人存档）**：
  `main` 的流程：`setState("State #2")` → `add(...)` 把当时状态存档；
  `setState("State #3")` → `add(...)` 再存档。`add` 的形参是 `Memento`，
  所以实参必须是"发起人打包出的备忘录" → 调用 `originator->saveStateToMemento()`。
  - **两个空写法相同**（一次存 State #2、一次存 State #3，都是"取发起人当前状态"）。
  - **指针调用语法**：`originator` 是 `Originator*`（指针），成员访问用 `->`（不是 `.`）。
  - **易错点**：用 `.` 而非 `->`；写成 `originator->getState()`（返回 string，
    无法作为 `add` 的 Memento 实参）；只填一个空。

**运行结果对照（验证三个角色协作无误）**：

```text
Current State：State #4        ← setState("State #4") 后的当前状态
First saved State：State #2    ← get(0) 取回第 0 个备忘录（State #2 时存的）
Second saved State：State #3   ← get(1) 取回第 1 个备忘录（State #3 时存的）
```

**备忘录模式角色 → 代码对照表**：

| 模式角色 | 本题代码 | 职责 |
|----------|----------|------|
| Memento（备忘录） | `class Memento` | 封装 `string state`；只能构造时写入、`getState()` 读出 |
| Originator（发起人） | `class Originator` | `setState/getState`；`saveStateToMemento()` 存档(1)、`getStateFromMemento()` 恢复(2) |
| CareTaker（管理者） | `class CareTaker` | `vector<Memento>` 列表；`add()` 存(3)、`get()` 取(4) |
| Client（客户端） | `main` | 发起人状态变更 → 存档(5)(6) → 事后取回恢复 |

## 高频丢分点 Top（做完后对照回填到 `patterns-algo-notes.md`）

1. **下标 ±1**：DP 中"前缀长度下标"与"数组字符位置"差 1（试题 A 空 (2) 的 `str1[i-1]`；
   试题 B 空 (3) 的 `seq[k+1]`）——下午卷算法题第一丢分大户。
2. **边界/初始化对称**：看到一个边界已给出，对称的那个就是空（试题 A 空 (1)）。
3. **区间 DP 的长度-跨度换算**：`j = i + p` 还是 `j = i + p - 1`，用循环边界条件核对
   （试题 B 空 (1)）。
4. **答案格子定位**：最终返回的是"规模最大"那一格，不是 n-1 也不是 N（试题 A 空 (4)）。
5. **抽象方法声明三要素**：访问修饰符 + `abstract` + 子类一致签名（试题 C 空 (1)）。
6. **多态类型选择**：能同时容纳多个子类的类型是**共同父类**，不要写具体子类或 Object
   （试题 C 空 (2)(3)）。
7. **方法签名反推**：管理者类的方法名/参数/返回类型由**方法体用到的变量**与
   **main 中的调用**共同锁定（试题 D 空 (3)(4)）。
8. **形参与类名同名**：`Memento.getState()` 指形参对象，不要被同名干扰（试题 D 空 (2)）。
9. **指针成员访问符**：C++ 中指针调方法用 `->`，Java 用 `.`（试题 D 空 (5)(6)）。
10. **复杂度漏数循环层数**：区间 DP 是三重循环 → O(n³)（试题 B 空 (6)）。
11. **手算题只算一种**：矩阵连乘要枚举全部括号化，或画 DP 表回溯（试题 B 空 (7)(8)）。
