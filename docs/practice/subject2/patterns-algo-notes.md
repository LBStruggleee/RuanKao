# 一、设计模式大题识别速查表（试题五/六）

> 试题五（C++）与试题六（Java）是**选答题**（二选一），每年考 **2 个模式**：
> 一个在试题五、一个在试题六，通常**同一年两个试题考不同模式**。
> 题目结构固定：【说明】描述场景 + 类图 + 完整代码挖 4~6 个空，15 分全在空上。
> **识别是第一步**：从【说明】的场景关键词 1 秒锁定模式，再按"角色结构 → 代码特征"
> 逐空对应。下表按"场景关键词 → 模式"整理，覆盖 2020–2023 真题考过的全部模式。

## 1.1 场景关键词 → 模式映射（秒选表）

## 1.2 高频模式：意图 + 角色结构 + 代码特征

### 享元模式（Flyweight）— 2021下 Java 围棋

- **意图**：运用共享技术有效地支持大量细粒度对象的复用，降低内存占用。
- **核心思想**：**内部状态（可共享，如颜色）与外部状态（不共享，如位置）分离**。
- **角色结构**：

| 角色 | 职责 | 本题对应 |
|------|------|----------|
| 抽象享元 Flyweight | 声明共享对象的接口 | `abstract class Piece` |
| 具体享元 ConcreteFlyweight | 实现接口，存储内部状态 | `BlackPiece`、`WhitePiece` |
| 享元工厂 FlyweightFactory | 创建/管理共享对象（查缓存返回） | `PieceBoard` 的获取逻辑 |
| 非享元 UnsharedFlyweight | 外部状态，不可共享 | `PiecePos`（位置） |
| 客户端 Client | 组合内部/外部状态使用 | `PieceBoard.SetPiece` |

- **代码特征（填空高频位置）**：
  - 抽象享元里的**抽象方法声明**（与所有具体子类签名一致）；
  - 工厂/容器里装共享对象的**泛型集合元素类型**（共同父类）；
  - 局部变量用**父类类型**（多态）指向不同具体子类；
  - 通过父类引用**调用共享对象的方法**。
- **严格享元的工厂代码骨架（补充识记，本题未完整出现）**：
  ```java
  class PieceFactory {
      private static final Map<PieceColor, Piece> pool = new HashMap<>();
      public static Piece getPiece(PieceColor color) {
          if (!pool.containsKey(color))
              pool.put(color, color == BLACK ? new BlackPiece(...) : new WhitePiece(...));
          return pool.get(color);   // 同色复用已有对象 ← 享元本质
      }
  }
  ```

### 备忘录模式（Memento）— 2022上 C++/Java 状态撤销

- **意图**：在不破坏封装的前提下，捕获并保存一个对象的内部状态，以便以后恢复。
- **角色结构**：

| 角色 | 职责 | 2022上对应 |
|------|------|------------|
| 发起人 Originator | 持有当前状态；创建备忘录存状态、从备忘录恢复 | `Originator` |
| 备忘录 Memento | 封装发起人的内部状态（只能构造写入、getter 读出） | `Memento` |
| 管理者 Caretaker | 保存备忘录集合，按索引存取（不修改内容） | `CareTaker` |

- **代码特征（填空高频位置）**：
  - 发起人"存档"方法：`return new Memento(this->state);`（把状态打包成备忘录返回）；
  - 发起人"恢复"方法：`this->state = memento.getState();`（从备忘录取回）；
  - 管理者的 `add(Memento)` / `get(int)` 方法签名（由方法体与 main 调用反推）；
  - 客户端：状态变更后 `careTaker->add(originator->saveStateToMemento())`。
- **记忆口诀**：**发起人存进备忘录、管理者只搬运、恢复时再取回**。

### 外观模式（Facade）— 2022下 Java/C++ 医院接待

- **意图**：为子系统中的一组接口提供一个一致的界面（统一入口），使子系统更易使用。
- **角色结构**：**外观类 Facade**（接待员）持有一组**子系统类**（挂号 Registry、门诊 Doctor、
  取药 Pharmacy）的引用，对外暴露一个简单方法，内部依次调用子系统。
- **代码特征**：
  - 子系统共享同一接口（如 `Disposer` 的 `dispose(Patient)`）；
  - 外观类构造时或方法内 `new` 出各子系统并**依次调用**；
  - 客户端只与 Facade 交互（填空常考外观方法内的调用链与客户端的 Facade 实例化）。

### 策略模式（Strategy）— 2023上 Java 区间格式打印

- **意图**：定义一系列算法，把它们各自封装成可互换的策略类，使算法变化不影响客户端。
- **角色结构**：**策略接口**（`PrintStrategy` 的 `doPrint`）+ **具体策略**（逗号/点号/横线三种
  格式）+ **环境类**（`Interval` 持有一个策略引用，`printIntervals` 时委托给策略）。
- **代码特征**：
  - 环境类方法体只有一句：`strategy.doPrint(this);`（委托）；
  - 工厂/switch 方法：`case COMMA: st = new PrintIntervalsComma();`（按类型造策略）。

### 中介者模式（Mediator）— 2020下 Java 支付整合

- **意图**：用一个中介对象封装一组对象的交互，使各对象不需要显式互相引用（解耦多对多）。
- **角色结构**：**中介者接口**（`WebServiceMediator`）+ **具体中介者**（持有各同事对象引用，
  在 `buy` 里按规则转发）+ **同事类**（`WebService` 抽象 + `Amazon`/`Ebay` 具体同事，
  各持中介者引用，交互时 `mediator.buy(money, this)` 转交给中介者）。
- **代码特征**：同事类的方法体就是一句 `mediator.xxx(...)`（把交互委托给中介者）。

### 组合模式（Composite）— 2021上 Java 层叠菜单

- **意图**：将对象组合成树形结构以表示"部分-整体"层次，使客户端统一对待单个对象与组合对象。
- **角色结构**：**抽象构件 Component**（菜单项与子菜单的共同接口，含 add/remove/getElement）+
  **叶子 Leaf**（`MenuItem`，方法返回 false/null）+ **组合 Composite**（`Menu`，内部一个
  `List<MenuComponent>` 递归聚合）。
- **代码特征**：组合类里有 `List<构件类型>` 成员；递归打印方法对子节点递归调用自身。

### 观察者模式（Observer）— 2023上 试题三问题3（UML 结合考）

- **意图**：定义对象间一对多依赖，当一个对象状态改变时，所有依赖它的对象自动得到通知。
- **角色结构**：**主题 Subject**（维护观察者列表、attach/detach/notify）+ **观察者 Observer**
  （update 接口）+ **具体主题/具体观察者**。
- **答题模板**（试题三常考"选模式 + 解释原因"，3 分）：
  > 观察者模式适合当一个对象的状态发生改变时，所有依赖于它的对象都得到通知并被自动更新。
  > 本需求中"……"是主题状态，"……"是观察者，当……发生时自动通知所有……，故选观察者模式。

## 1.3 设计模式填空通用三招

> 不管考哪个模式，填空的位置只有三类。按下列三招逐空定位：

**第 1 招：抽象方法看子类签名**
- 抽象类/接口里的空，**把所有具体子类已实现的方法签名抄一遍**，取交集即答案。
- 注意三要素：**访问修饰符**（不窄于子类）+ `abstract`/无方法体 + **返回类型+方法名+参数表**。

**第 2 招：容器/变量类型取共同父类**
- `ArrayList<？>` 的元素类型、`？ piece = null;` 的局部变量类型——
  若同一变量/集合要装多个具体子类，类型填**它们的共同父类（或接口）**，不填具体子类。

**第 3 招：方法签名由"方法体 + 调用处"反推**
- 空在方法声明处时：方法体里用了 `state`、`index` 等名字 → 形参名/类型确定；
  `main`/其他类里 `xxx->add(...)`、`xxx.get(0)` → 方法名、参数个数、返回类型确定；
  方法体 `return mementoList[index];` → 返回类型 = 容器元素类型。
- 调用处填空：看返回类型需要什么（`add(Memento)` 需要一个 Memento 对象 →
  只能是 `originator->saveStateToMemento()`）。

## 1.4 语言细节对照（Java vs C++）

| 考点 | Java | C++ | 易错 |
|------|------|-----|------|
| 抽象方法 | `public abstract void draw();`（接口方法默认 public abstract） | `virtual void draw() = 0;`（纯虚函数） | C++ 用 `= 0`，不是 `abstract` |
| 对象创建 | `new X()` 返回引用 `X x = new X();` | `X x;` 或 `X* p = new X();` | C++ 指针 vs 对象语义不同 |
| 成员访问 | 引用用 `.`：`x.draw()` | 指针用 `->`：`p->draw()`；对象用 `.` | **指针调方法必须 `->`** |
| 泛型集合 | `ArrayList<Piece>` | `vector<Memento>` | C++ 是 `vector<类型>` |
| 继承 | `class A extends B` | `class A : public B` | C++ 有访问限定符 |
| 实现接口 | `class A implements B` | `class A : public B`（纯虚基类） | C++ 无 `implements` 关键字 |

> 💡 **选语言学**：Java 语法更"直白"（abstract/new/extends），C++ 要注意
> `->`、`= 0`、`: public`。若两种语言都不排斥，**建议选 Java（试题六）**——
> 填空更少踩语言细节的坑；若 C++ 更熟，注意指针与对象的区别。

# 二、算法填空答题策略（试题四，C 语言）

> 试题四固定考**一个完整 C 算法的 4~8 个空**，15 分。
> 结构：【说明】（算法思想 + 递归式/公式）+ 变量说明 + 代码 + 问题1 填空（8 分）+
> 问题2 策略/复杂度（2~4 分）+ 问题3 手算实例（3~5 分）。

## 2.1 填空四步法（通用）

**第 1 步：读【说明】，一句话写下"这个算法在算什么"**
- 例：编辑距离 = "把 str1 变成 str2 的最少操作次数"；矩阵连乘 = "n 个矩阵相乘的最少乘法次数"。
- **写下每个二维数组/变量的含义**（题目在变量说明里给了，抄在草稿纸上）：
  `d[i][j]`、`cost[i][j]`、`trace[i][j]` 分别是什么？——**填空全部在操作这些下标上**。

**第 2 步：标出循环不变量（每层循环在干什么）**
- 把每层循环的"语义"写在旁边：外层 = 子问题规模、中层 = 起点、内层 = 决策（断点/字符比较）。
- **循环边界条件就是高频空位**：`for (i = ?; i < n - p; i++)`、`while (k < j)`。

**第 3 步：从边界/已知反推空位**
- **对称法**：题目已给出的一个边界/分支，对称的那个就是空（编辑距离的行边界给出、
  列边界是空）；
- **赋值链法**：空在 `xxx = ?` 的右边，看左边变量被谁用 → 反推表达式
  （`cost[i][j] = tempCost` 已给出，紧邻的 `trace[i][j] = ?` 与之对称）；
- **公式法**：【说明】给的递归式/算例，把数字代进去验算空位
  （矩阵连乘的算例 `5*100*8 + 5*8*50` 直接对应空 (3) 的结构）。

**第 4 步：代入实例自检**
- 用【问题3】的小数据手算一遍填空后的代码，看能否得到题目的已知结果/合理结果。
- 检查**下标越界**（`i-1`、`k+1` 是否在合法范围）与**类型匹配**。

## 2.2 DP 题专属：状态转移三件套

下午卷试题四的 **DP 题占绝对多数**（2021下 编辑距离、2021上 三角剖分、2022上 矩阵连乘）。
所有 DP 填空都是三件套之一：

| 三件套 | 代码位置 | 反推方法 |
|--------|----------|----------|
| **① 初始化（边界）** | 算法开头的 for 循环 | 看已给出的对称边界；"空串/单元素/长度 1"的答案恒定（0、i、j） |
| **② 状态转移（主递推）** | 双重/三重循环体 | 三种操作/决策的代价并列取 min/max，缺哪项补哪项 |
| **③ 结果返回** | 函数末尾 return | 取"规模最大"那一格（`d[len1][len2]`、`cost[0][n-1]`） |

**DP 识别特征（问题 2 策略题必背）**：
1. 用表格（一维/二维数组）**记录子问题的解**；
2. 具有**最优子结构**（大问题最优解 = 子问题最优解的组合）；
3. **自底向上**填表（从小规模循环到大规模）；
4. 有**重叠子问题**（区别于分治：分治的子问题独立、不记忆）。

**复杂度口诀**：**填表格子数 × 每格决策数**。
- 双重循环 + 每格 O(1) → O(n²)（编辑距离 O(mn)）；
- 三重循环（多一层枚举断点）→ O(n³)（矩阵连乘、三角剖分）。

## 2.3 常考算法骨架清单（排序/查找/树/DP/贪心/图）

> 虽然近年试题四以 DP 为主，但大纲覆盖下列全部骨架。每类给出**代码骨架 + 最常挖空位置**，
> 遇到同类题直接套。

### 动态规划（最高频）
- **一维序列型**（编辑距离、最长公共子序列 LCS、最长递增子序列 LIS）：
  ```c
  for (i = 0; i <= len1; i++) d[i][0] = i;      /* 行边界 ← 高频空 */
  for (j = 0; j <= len2; j++) d[0][j] = j;      /* 列边界 ← 高频空 */
  for (i = 1; i <= len1; i++)
      for (j = 1; j <= len2; j++)
          if (str1[i-1] == str2[j-1])           /* 字符比较，下标 -1 ← 高频空 */
              d[i][j] = d[i-1][j-1];
          else
              d[i][j] = min(d[i-1][j]+1, d[i][j-1]+1, d[i-1][j-1]+1);  /* 三操作取小 ← 高频空 */
  return d[len1][len2];                          /* 结果 ← 高频空 */
  ```
- **区间型**（矩阵连乘、凸多边形三角剖分）：
  ```c
  for (i = 0; i < n; i++) cost[i][i] = 0;        /* 对角线 */
  for (p = 1; p < n; p++)                        /* 区间长度 */
      for (i = 0; i < n - p; i++) {              /* 起点 */
          j = i + p;                             /* 终点 ← 高频空 */
          for (k = i; k < j; k++) {              /* 断点 ← 高频空 */
              temp = cost[i][k] + cost[k+1][j] + 合并代价;  /* ← 高频空 */
              if (更小) { cost 更新; trace 记录; }
          }
          cost[i][j] = tempCost; trace[i][j] = tempTrace;   /* ← 高频空 */
      }
  ```
  **合并代价的维数口诀**：`seq[起点] * seq[断点+1] * seq[终点+1]`，首尾相接。

### 排序
- **希尔排序**（2020下）：步长序列 `delta[i] = n/2, n/4, …, 1`；每组内**直接插入排序**。
  挖空点：步长递推 `k /= 2`、步长循环条件、组内插入的 `data[j+dk] = t`。
- **堆排序**（2022下）：`Heapify` 调堆 + 交换堆顶到末尾。挖空点：父子比较条件
  `R[j] > R[j+1]` 选大孩子、`Heapify(R, 1, i-1)` 的规模参数。
- **稳定性/复杂度**（问题 2 常考）：希尔、堆、快排**不稳定**；直接插入、冒泡、归并**稳定**。

### 查找
- 二分查找：`mid = (low + high) / 2`；`low = mid + 1` / `high = mid - 1`（注意 +1/-1 防死循环）。

### 树的遍历
- 递归框架：`if (root == NULL) return; 遍历(root->left); 遍历(root->right);`
- 挖空点：**终止条件**、**递归调用的子节点**（如 `print_triangle(S[i][j]+1, j)`）。

### 图遍历
- DFS/BFS：邻接表/邻接矩阵；挖空点：访问标记数组、邻接点推进 `p = p->nextarc`、
  递归调用 `DFS(G, p->adjvex)`、计数 `count++`。（2023上 试题四考了 DFS 计连通分量，
  但题目文本在本地源缺失，未入选本专项。）

### 贪心
- 排序 + 每步取局部最优（活动安排、部分背包）。挖空点：排序比较函数、选择条件。

## 2.4 算法题得分技巧汇总

| 技巧 | 说明 |
|------|------|
| 先写变量含义 | 把【说明】/变量说明里的 `d[i][j]`、`cost[i][j]` 含义抄在草稿上，所有空都围绕它 |
| 找对称 | 已给出的边界/赋值，对称的那个极可能是空 |
| 代入算例 | 【说明】的算例数字是免费的自检数据（矩阵连乘 5375 就这么验出来的） |
| 注意 ±1 | "前缀长度下标" vs "数组位置"、`k` vs `k+1`——第一丢分大户 |
| 写全语法 | 空要补完整语句（分号、等号、`->`/`.`），不要只写表达式片段 |
| 手算保留草表 | 问题 3 的手工模拟要画表，阅卷按结果给分，草表能复核 |
| 策略题背特征 | "表格记录 + 最优子结构 + 自底向上" → 动态规划；复杂度数循环层数 |

# 三、高频丢分点清单（做完 4 题后对照回填）

## 3.1 算法填空（试题四）高频丢分点

1. **下标 ±1**：DP 中"前缀长度"与"数组字符位置"差 1（`str1[i-1]`、`seq[k+1]`）。
2. **边界对称没看出来**：一个边界已给出、另一个对称的是空，却去硬推。
3. **区间 DP 长度-跨度换算**：`j = i + p` 还是 `j = i + p - 1`，未用循环边界核对。
4. **结果格子定位错**：返回 `d[len1-1][len2-1]` 或 `d[N][N]`（应为 `d[len1][len2]`）。
5. **三操作漏一项或漏 +1**：替换操作漏 `+ 1`，或只写两项。
6. **断点枚举上界错**：写成 `k <= j`（右段为空）。
7. **复杂度漏数循环层数**：区间 DP 是三重循环 → O(n³)，常误答 O(n²)。
8. **策略错答成分治/贪心**：看到"递归""分解"就答分治，忽略"表格记录 + 重叠子问题"。
9. **手算题只算一种情况**：矩阵连乘未枚举全部括号化；DP 表行列与字符串对错位。
10. **空填成"半句"**：缺分号、缺等号左边、`->` 与 `.` 混用（C++ 题）。

## 3.2 设计模式（试题五/六）高频丢分点

1. **抽象方法签名与子类不一致**：漏 `abstract`、漏 `public`、加错参数。
2. **容器/变量类型填具体子类**：应填共同父类（`Piece`），却填 `BlackPiece` 或 `Object`。
3. **方法签名反推不全**：漏 `void`、返回类型错、形参名与方法体不一致。
4. **形参与类名同名被绕晕**：`Memento.getState()` 指形参对象，非类名。
5. **指针/引用成员访问符混用**：C++ 指针用 `.` 而非 `->`。
6. **调用处填错方法**：需要 Memento 对象却调用返回 string 的 `getState()`。
7. **只填一个空**：两个分支对称的空（如 `piece.draw()` 出现两次）漏填一个。
8. **模式识别错误**：把"状态变化通知"的观察者场景错认为中介者；把"共享对象"的
   享元场景错认为工厂。**先用 1.1 秒选表锁定模式再动笔**。
