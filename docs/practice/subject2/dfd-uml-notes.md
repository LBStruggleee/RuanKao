# 一、DFD 答题模板（试题一，15 分）

> 试题一固定考数据流图，题目结构高度套路化：
> 【说明】列 4–6 项功能 → 给上下文图（图1-1）+ 0 层图（图1-2）→
> 问题1 填外部实体（3–5 分）→ 问题2 填数据存储（3–5 分）→
> 问题3 补缺失数据流（4–5 分）→ 问题4 加工逻辑描述/加工分解（2–3 分）。
> 按下列 **四步** 顺序作答，每步对应一个问题，稳拿 12 分以上。

## 第 1 步：外部实体识别法（对应问题1）

**核心口诀：找"人"、找"设备"、找"外部系统"；排除"数据"、排除"系统自己"。**

- **什么是外部实体**：向系统提供输入、或接收系统输出的、系统**之外**的人、设备、外部系统。
  在上下文图中画成方框，在 0 层图中沿图形边缘出现。
- **三条识别线索**：
  1. 【说明】功能句中的**动作发出者**（"管理员对……设置"→ 管理员）；
  2. 【说明】中的**被动接收方**（"向检测设备发送控制指令"→ 检测设备）；
  3. 【说明】中的**外部角色名词**（"传感器上传……"→ 传感器）。
- **必须排除**：
  - 系统处理的数据内容（产品、图像、农作物、订单……）——这些是数据流名称，不是实体；
  - 系统自身（"智能检测系统""智慧农业平台"本身）；
  - 系统内部生成的信息（检测结果、分析结果——这些进数据存储）。
- **答题规范**：题目要求"使用说明中的词语/语句"，**必须照抄【说明】原词**
  （"检测业务员"不能写成"业务员"；"农业专家"不能写成"专家"）。
- **检查**：上下文图与 0 层图的实体集合必须**完全一致**（实体守恒）。

## 第 2 步：数据存储定位法（对应问题2）

**核心口诀：找"存储、保存、记录、维护、设置、写入、读取"等动词，被存储的名词即存储名。**

- **什么是数据存储**：系统内部保存的数据，0 层图中画成双横线（或圆柱）`D1、D2…`。
- **定位法**：
  1. 逐句扫【说明】，每出现一个"存储/保存/记录/维护"动作，就对应一个存储；
  2. 被存储的名词 + "表/信息表/文件/记录"后缀即存储名；
  3. 存储个数 = 【说明】中不同存储对象的个数（数"存储"出现的次数可快速核对）。
- **注意"合并存储"**：功能 (1) 若写"对检测标准和监控规则等基础信息设置"，
  则"检测标准""监控规则"合并为一个存储"基础信息表"，不要拆成两个。
- **命名规范**：后缀灵活（表/信息表/文件/记录均可给分），**核心词必须来自【说明】**。

## 第 3 步：数据流平衡检查（对应问题3，最高频丢分点）

**三条平衡规则**（逐条套用）：

### 规则 1：守恒规则（加工平衡）

每个加工必须同时满足：
- **有输入、有输出**——有输入无输出（"黑洞"）、有输出无输入（"奇迹"）都是错误；
- **输入足以产生输出**——输入数据必须能支撑输出数据（"输入不足以产生输出"）。

**作答动作**：把 0 层图中每个加工的已有输入/输出列成清单，逐一与【说明】的功能描述对照，
缺哪条输入/输出，就回【说明】找原词补上。

### 规则 2：父子图平衡

上下文图 ↔ 0 层图之间、父加工 ↔ 子加工（0 层↔1 层）之间：
- 子图的输入数据流集合 = 父图中对应加工的输入数据流集合；
- 子图的输出数据流集合 = 父图中对应加工的输出数据流集合；
- 名称可以合并或分解，但**数据必须守恒**（不能多、不能少）。

### 规则 3：无悬空流

- 每条数据流必须**一端连加工**（另一端连外部实体或数据存储）；
- **禁止**：外部实体 ↔ 外部实体直接相连、数据存储 ↔ 数据存储直接相连。

### 三类常见错误（背诵点，原题原文表述）

> 1、**加工有输入但是没有输出**
> 2、**加工有输出但是没有输入**
> 3、**加工的输入不足以产生输出**

这三句是 2021 下半年试题一问题 4 的官方答案原文，几乎每份真题的分解题都按此给分，
务必**逐字记忆**，遇到"分解时需要注意哪些错误"直接默写。

### 补数据流的实战要点

- **区分实时流与存储读取**（核心难点）：带"**历史 / 批量 / 记录 / 已存**"字样的输入，
  只能来自**数据存储**（`D→P`），不能从采集加工直接来（`P→P`）。
  例：智慧农业平台"历史监测信息"必须是 `D2→P3`，不能是 `P2→P3`。
- **同名数据流可流向多个加工**：同一份数据被多个加工读取时，**每条都要单独画**。
  例："监控处理规则"分别流向 `P3`（监测分析）和 `P4`（判定），画了一条不等于画了两条。
- **数据流名称用名词短语**（"监控规则""分析结果"），**不用动词**（"监控""分析"）。
- **答案三要素写全**：数据流名称 + 起点 + 终点，缺一不可；编号用图中的 `E/D/P` 编号。

## 第 4 步：加工逻辑描述 / 加工分解（对应问题4）

### 结构化语言（描述加工逻辑）

**三层结构，照【说明】逐句翻译**：

```text
顺序结构：   接收到 XX / 对 XX 进行 YY
选择结构：   IF 条件 THEN 动作1 ELSE 动作2 ENDIF
循环结构：   WHILE 条件 DO 动作 ENDDO      （或 DO ... WHILE ...）
```

- **得分点**：① 有接收输入语句；② 有主处理动作；③ 有 IF 条件分支；
  ④ 说明处理结果的组成（输出包含什么）。
- **易错点**：写成自然语言段落（无结构化关键字不得分）；漏掉结果组成。

### 加工分解（子加工切分）

- **切分法**：把【说明】中该功能段的**动词短语序列**切成子加工，每个子加工一个动词核心。
  例："对实时监测信息进行监测分析，将分析结果进行可视化并进行存储、远程控制，
  对历史监测信息进行综合统计和预测，将预测信息进行可视化和存储"
  → 4 个子加工：① 监测分析实时监测信息；② 分析结果可视化、存储、远程控制；
  ③ 综合统计和预测历史监测信息；④ 预测信息可视化、存储。
- **检查**：分解后子加工的输入集合 = 父加工输入集合，输出集合 = 父加工输出集合（父子图平衡）。

## DFD 得分技巧汇总

| 技巧 | 说明 |
|------|------|
| 照抄原词 | 问题 1/2/3 的名称一律用【说明】原词，不要自创 |
| 后缀灵活 | 存储名后缀"表/信息表/文件/记录"均给分，核心词对即可 |
| 先列清单 | 问题 3 先把每个加工的已有输入/输出列清单，再找缺腿的 |
| 实体守恒 | 上下文图与 0 层图实体必须一致 |
| 三要素全 | 补数据流必须写"名称 + 起点 + 终点" |
| 结构化关键字 | 问题 4 必须有 IF/THEN/ENDIF 等关键字 |

# 二、UML 答题模板（试题三，15 分）

> 试题三固定考 UML：一般给【说明】+ 用例图（图3-1）+ 类图（图3-2）。
> 问题 1 填参与者/用例/关系（6–8 分）→ 问题 2 填类名或属性（4–6 分）→
> 问题 3 填关系/属性解释/设计模式（2–4 分）。

## 类图填空三招（核心方法）

### 第 1 招：名词找类

- 【说明】中**带英文括号注**的核心名词几乎都是类名（"房产（Property）""学术资源（Resoure）"）；
- "**X 包括 A、B、C**"或"**X 分为 A 和 B 两类**"句式 → 一个泛化层级：
  X 是父类，A/B/C 是子类（图中表现为多条 `--|>` 空心三角箭头指向 X）；
- 图中**已给名的类**（如"镜像数据库、会议集、期刊"）是定位线索，不填，用于判断泛化结构。

### 第 2 招：动词找方法

- 【说明】中的**动词短语** = 类的方法：
  "浏览、检索、下载"（数字图书馆）→ 资源类或用户类的方法；
  "添加、修改、删除、排序、打印"（地址簿）→ 管理类的方法。
- 方法名用【说明】原动词或其英文括号注（"按照资源的题名检索（SearchByTitle）"→ `SearchByTitle`）。

### 第 3 招：关键词判关系

| 【说明】中的关键词 | UML 关系 | 符号 |
|--------------------|----------|------|
| "分为……两类 / 包括 A、B、C" | 泛化（继承） | 空心三角实线箭头，子类→父类 |
| "由……组成 / 包含"（可分离） | 聚合 | 空心菱形，整体→部分 |
| "由……组成 / 包含"（生命周期相同） | 组合 | 实心菱形，整体→部分 |
| "记录……关系 / 关联类阐述两者关系" | 关联（可带关联类） | 实线，可有多重性 |
| "调用 / 使用 / 依赖"（临时） | 依赖 | 虚线箭头 |
| "实现接口" | 实现 | 空心三角虚线箭头 |

**关联类属性判定**：关联类的属性 = 描述**两者关系本身**的属性，**不是**任一类的自身属性。
例：房产—经纪的关联类 `AgentList`，属性是"经纪负责该房产的起始/终止时间"，
而不是经纪的姓名/住址（那些是 Agent 类的属性）。

## 类间六关系：符号与代码级判别

| 关系 | UML 符号 | 代码级特征 | 记忆口诀 |
|------|----------|------------|----------|
| 泛化 Generalization | 空心三角 **实线** 箭头，子→父 | `class 子类 extends 父类` | "is-a"，继承 |
| 实现 Realization | 空心三角 **虚线** 箭头 | `class X implements 接口` | "实现接口" |
| 关联 Association | 实线（可有箭头/多重性） | 成员变量持有对方引用 | "has-a"，长期持有 |
| 聚合 Aggregation | **空心菱形**，整体→部分 | 部分可独立存在（外部传入/集合） | "整体与部分可分离" |
| 组合 Composition | **实心菱形**，整体→部分 | 部分随整体创建/销毁（构造里 new） | "整体与部分同生共死" |
| 依赖 Dependency | 虚线箭头 | 局部变量 / 方法参数使用 | "临时使用" |

**聚合 vs 组合的快速判别**：看部分能否脱离整体单独存在——
能单独存在（班级与学生）→ 聚合；不能单独存在（汽车与发动机，汽车报废发动机也报废）→ 组合。

## 用例图三关系

| 关系 | 符号与方向 | 内涵 | 判别口诀 |
|------|------------|------|----------|
| 包含 `<<include>>` | 虚线箭头，**基用例 → 被包含用例** | 多个用例的**共同行为**被抽取成独立用例；执行基用例**必然**执行它 | "必然发生、公共抽取" |
| 扩展 `<<extend>>` | 虚线箭头，**扩展用例 → 基用例** | 异常行为/可选分支抽象成扩展用例；**特定条件下才**执行 | "条件触发、可选异常" |
| 泛化 generalize | 空心三角实线，子用例→父用例 | 子用例是父用例的特化（参与者之间也可泛化） | "特殊化" |

**常考场景对照**：
- "修改房产信息"必然触发"审批授权" → **include**；
- "删除房产信息"只在"公司确定不再销售"时发生，扩展"归档" → **extend**；
- 按题名检索/按作者检索/按来源检索 都是"检索资源"的特化 → **泛化**。

## 属性提取：父类共性 vs 子类特性

- **父类属性** = 【说明】中"**系统中存储了每个 XX 的……**"后面的共有属性；
- **子类属性** = 【说明】中"**对于 XX，还需记录……**"后面的特有属性；
- **不要**把子类属性填进父类（"会议名称"不能进父类"学术资源"）；
- **不要**在子类里重复填父类已有的属性。

## 顺序图 / 状态图 / 活动图读图要点（备考点）

虽然试题三以用例图+类图为主，但上午卷与部分大题会涉及其他图：

- **顺序图（Sequence Diagram）**：
  - 横轴 = 对象（生命线 Lifeline），竖轴 = 时间（自上而下）；
  - 对象生命线上的**竖直长矩形** = 激活期（执行期）；
  - **实心三角箭头** = 同步消息，**开放箭头** = 异步消息，**虚线箭头** = 返回；
  - 自调用 = 自指的弧形箭头。
- **状态图（State Diagram）**：
  - 圆角矩形 = 状态；实心圆点 = 初始状态；牛眼（圆中套圆） = 终止状态；
  - 箭头 = 状态迁移，标签格式 `事件[条件]/动作`。
- **活动图（Activity Diagram）**：
  - 圆角矩形 = 活动；菱形 = 判断（guard 条件）/ 合并；
  - 粗实线 = 并发分叉（fork）/ 汇合（join）；泳道（swimlane）= 责任划分；
  - 实心圆点 = 起点，牛眼 = 终点。

## UML 得分技巧汇总

| 技巧 | 说明 |
|------|------|
| 优先用英文原名 | 类名用【说明】括号注里的英文（如 Property）；中文通常也给分 |
| 先定父类再定子类 | 看到 `--|>` 结构先定位"X 包括 A、B"句式 |
| 关联类只填关系属性 | 不是任何一方的自身属性 |
| include/extend 看必然性 | 必然发生 = include；条件可选 = extend |
| 设计模式答机制 | 不只写模式名，必须答"该模式如何满足需求" |

# 三、设计模式题速查（试题三问题3 常考）

> 试题三最后一问常给一个"新需求"，问"增加哪种设计模式 + 解释原因"。
> 记住下列**题干特征词 → 模式**映射，秒选：

| 题干特征词 | 设计模式 | 一句话解释 |
|------------|----------|------------|
| "状态变化时通知所有关注者" | **观察者**（Observer） | 一对多依赖，状态变化自动通知全部依赖者 |
| "多种格式/算法可互换" | **策略**（Strategy） | 将算法封装成独立类，可相互替换 |
| "统一接口封装多个子系统" | **外观**（Facade） | 为复杂子系统提供一致的高层接口 |
| "减少创建对象的数量、节省内存" | **享元**（Flyweight） | 共享细粒度对象，降低内存占用 |
| "撤销/恢复到原先状态" | **备忘录**（Memento） | 保存对象状态以便恢复 |
| "层叠菜单 / 树形结构 / 部分-整体" | **组合**（Composite） | 统一对待单个对象与组合对象 |
| "多对象交互由中介协调" | **中介者**（Mediator） | 用中介对象封装一组对象的交互 |
| "动态地给对象增加职责" | **装饰**（Decorator） | 包装对象以扩展功能（比继承更灵活） |

**解释题万能模板**（以观察者为例，照抄结构换词）：

> **XX 模式**适合……（该模式的标准定义）。本需求中"……"对应模式的……角色，
> "……"对应……角色，当……发生时……，故选择 XX 模式。

## 试题三（UML）高频考点

| 考点 | 出现频率 | 备注 |
|------|----------|------|
| 类图类名（泛化层级） | **每年必考** | 5–8 分，"X 包括 A、B、C"句式 |

| 用例的参与者 / 用例名 | 高频 | 5–7 分，从【说明】动作提取 |
| include / extend 关系 | 高频 | 判别口诀：必然 vs 条件 |

| 顺序图 / 状态图 / 活动图读图 | 偶考于上午 | 读图要点见上文 |

## 交叉高频丢分点（做完 4 题后回填对照）

1. 加工"有输出无输入"时漏补输入流（数据流平衡）
2. "历史/批量"输入误走加工→加工，应是存储→加工
3. 同名数据流被多个加工读取时只画一条
4. 关联类属性误填为类的自身属性
5. 父类属性与子类属性互相串填
6. include/extend 混淆（必然 vs 条件）
7. 结构化语言写成自然语言段落（无关键字）
