## 二、逐题解析（含知识点归属）

> 格式：`答案 | 【科目】知识点 | 解析`

**1. A**｜【计算机基础】指令寻址方式
**立即寻址**操作数直接包含在指令中，取操作数不需要额外访存，最快；**寄存器寻址**操作数在寄存器中，需一次寄存器读取，次之；**直接寻址**操作数地址在指令中，需按地址访问内存，最慢。速度序：立即 > 寄存器 > 直接，选 A。

**2. D**｜【计算机基础】总线分类
**PCI** 是目前微型机上广泛采用的**并行内总线**（局部总线，连接 CPU 与高速外设）；**SCSI**（小型计算机系统接口）是一条**并行外总线**。故 D 正确，A/B/C 均把传输方式（并行/串行）或总线位置（内/外）说错。
> ⚠️ **分歧题**：信管网给 C（SCSI 是"串行内总线"）。但软考达人解析原文即"SCSI 是一条并行外总线"，且 SCSI 并行传输是基本常识，信管网的 C 与其自身解析矛盾，本题取 D。

**3. A**｜【计算机基础】I/O 控制方式
**中断方式**下外设准备数据时 CPU 可做其他工作、完成后中断通知，可实现外设与 CPU 并行工作；**DMA 方式**下整块数据的传送由 DMAC 控制、CPU 仅在传送开始与结束干预，并行性更好。二者都可实现外设与 CPU 并行工作，A 正确。B 错：中断方式每传送一个字（节）都要 CPU 干预一次；C 错：DMA 传输速度快于程序中断方式；D 错：程序中断方式需要 CPU 保护现场。

**4. C**｜【计算机基础】中断系统
**中断向量**用来保存各中断源的中断服务程序的**入口地址**。CPU 响应中断时，由中断控制器确定中断号，再查中断向量表取得服务程序入口地址并转入。被选中设备地址、数据起始地址、主程序断点地址均不是中断向量内容。

**5. B**｜【计算机基础】存储器
**DRAM**（动态随机存取存储器）靠电容存储电荷，因漏电需**定时刷新**保持数据。SRAM 用触发器存储不需刷新；FLASH、EEPROM 均为非易失性存储器，不需刷新。

**6. B**｜【计算机基础】浮点数表示
（【存疑：图形复原】格式：阶符 1 位｜阶码 4 位补码｜数符 1 位｜尾数 10 位原码）"1 0001 0 0000000001" 分段：阶符=1、阶码=0001 → 合成 5 位补码 **10001 = −15**；数符=0（正）；尾数=0000000001，原码且**允许非规格化** → 尾数值 = **2⁻¹⁰**。故该浮点数 = **2⁻¹⁵ × 2⁻¹⁰**，选 B。（若把阶码只取 0001=+1 而丢掉阶符会误得 −1；若把尾数按规格化当作 1−2⁻¹⁰ 会误选 C/D。）

**7. C**｜【网络·信息安全】病毒防治
防止计算机病毒最直接有效的策略是**安装并及时升级防病毒软件**（针对病毒本身）。防火墙用于防范网络访问与攻击；入侵监测系统用于监测入侵行为；定期备份数据是容灾恢复手段，不能"防止"病毒感染。

**8. C**｜【网络·信息安全】加密算法
**AES**（高级加密标准）是**分组加密**（对称密钥）算法，以 128 位分组进行加密/解密，支持 128/192/256 位密钥，基于排列与置换运算迭代。公钥加密是非对称算法（如 RSA）；流密码是逐位加密（如 RC4）；消息摘要不可逆（如 MD5/SHA）。

**9. A**｜【网络】应用层协议
**SSH**（安全外壳）、**Telnet**、**RFB**（远程帧缓冲，VNC 底层协议）都可用于远程登录或远程控制。**IGMP**（Internet 组管理协议）运行在主机与组播路由器之间、用于管理组播组成员，与远程登录/控制无关，选 A。

**10. C**｜【网络·信息安全】防火墙
包过滤防火墙工作在**网络层**，检查 IP 数据报文（源/目的 IP 地址、协议号、端口号等）以决定放行或丢弃。检查应用层数据属于应用层网关/代理防火墙；物理层与链路层设备不检查报文内容。

**11. B**｜【网络·信息安全】防火墙区域划分
按受保护程度从低到高：**外网（Internet）→ DMZ（非军事区，放置对外服务）→ 内网**。DMZ 的存在使外网不能直接访问内网，故 B 正确。

**12. C**｜【知识产权】软件著作权法律体系
构成我国保护计算机软件著作权的两个基本法律文件是**《中华人民共和国著作权法》**和**《计算机软件保护条例》**（后者是前法的特别法规）。我国没有《软件法》，也没有《中华人民共和国版权法》（版权即著作权）。

**13. B**｜【知识产权】委托开发软件的著作权归属
《计算机软件保护条例》：委托开发的软件，其著作权归属由委托人与受托人**签订书面合同**约定；**没有签订书面合同或合同未约定的，著作权由受托人享有**。X 公司是受托开发方（受托人），故 X 公司享有著作权，选 B。

**14. A**｜【知识产权】侵权复制品的善意取得
《计算机软件保护条例》第 30 条：软件复制品的**善意持有人**（不知道也没有合理理由知道是侵权复制品）**不承担赔偿责任**；但知道后**应当停止使用、销毁**该侵权复制品；若停止使用并销毁将造成**重大损失**，可以**向著作权人支付合理费用后继续使用**。鸿达公司是善意持有人，知道后其使用仍属侵权，但支付合理费用后可继续使用，选 A。
> ⚠️ **分歧题**：信管网给 B（须承担赔偿责任）。但 B 与第 30 条"善意持有人不承担赔偿责任"直接相悖；2021 上半年同题型（卷 2 第 14 题）官方答案同为"支付合理费用后可以继续使用"，本题取 A。

**15. B**｜【软件工程】分层 DFD
构造分层 DFD 的注意事项：适当命名各数据流/加工/数据存储/外部实体、**画数据流而不画控制流**、避免一个加工有过多的数据流、分解尽可能均匀、先考虑确定状态忽略琐碎细节、随时准备重画。DFD 只描述数据流，**不表示控制流**，故"图中要表示出控制流"不属于其注意事项，选 B。

**16. C**｜【软件工程】模块化设计原则
模块划分应使模块**规模适中**——并非越小越好（模块过小会增加模块数量、接口与调用开销）。A（模块相对独立）、B（低耦合）、D（扇入扇出合理：高层小扇出、中层较少扇出、底层高扇入）均为正确原则。

**17. A**｜【软件工程】风险监测
风险监测的目的：**评估所预测的风险是否发生**、**保证正确实施了风险缓解步骤**、**收集用于后续风险分析的信息**。风险只能识别、评估、减轻、规避或转移，**不可能被"消除"**，故"消除风险"不是风险监测的目的，选 A。

**18. B**｜【软件工程】AOE 网与关键路径
（【存疑：图形复原】边集见 questions 文件）从源点 A 到汇点 L 的最长路径（关键路径）长度为 **20**，有三条：A→B→D→I→J→L、A→B→D→I→J→K→L、A→E→G→H→K→L。各活动是否在关键路径上：**BD 在**（关键边）、**GH 在**（A→E→G→H→K→L 上）、**KL 在**（关键边）；而 **BI 不在**（经 BI 到 I 仅 3+6=9 < 10，被 A→B→D→I=10 覆盖），选 B。

**19. B**｜【软件工程】活动松弛时间（总时差）
（【存疑：图形复原】）用 Ve/Vl 法复算：Ve(B)=3、Ve(E)=4、Ve(I)=10、Ve(G)=7；Vl(I)=10、Vl(G)=7。松弛时间 = Vl(终点) − Ve(起点) − 活动时长：
- **BI**：Vl(I) − Ve(B) − 6 = 10 − 3 − 6 = **1**
- **EG**：Vl(G) − Ve(E) − 3 = 7 − 4 − 3 = **0**
故"1 和 0"，选 B。

**20. C**｜【数据结构】表达式二叉树
（【存疑：图形复原】树结构见 questions 文件）对二叉树按中序遍历（左—根—右）并按运算符优先级补括号：根为 `*`，左子树为 `a`，右子树为 `−`（其左为 `/`（被除数 b、除数 c），右为 d）⇒ **a \* (b/c − d)**，选 C。（A 漏了括号变成 (a\*b/c)−d；B 把 `/` 的范围错配；D 把 `−` 的两个操作数颠倒。）

**21. B**｜【软件工程·程序设计语言】编译过程与符号表
**符号表**用于在编译过程中记录源程序各个符号（标识符、常量、标号等）的名字、类型、作用域、存储分配等信息，以辅助**语义正确性检查**（如类型匹配、变量先声明后使用）与**代码生成**。决策表用于表示加工逻辑/测试用例；广义表是链式数据结构；索引表是查找结构。

**22. D**｜【软件工程·程序设计语言】有限自动机
（【存疑：图形复原】NFA 结构见 questions 文件）S0 上有标记 0、1 的自环，可接收任意由 0/1 组成的前缀；要到达终态 S3 必须依次走过 S0 —1→ S1 —0→ S2 —1→ S3，即串的**末尾必须是 "101"**，选 D。（自环可匹配任意前缀，故"不能包含连续 0/1""必须以 101 开头"都不正确。）

**23. B**｜【操作系统】进程状态转换
P1 释放扫描仪 → 等待扫描仪的 **P4 获得资源，由"等待"转为"就绪"**（单处理机下不能直接转为"运行"，排除 C）。P1 释放的是扫描仪，**而它仍持有打印机且尚未运行完毕，故 P1 仍处于"运行"状态**——释放资源既不会使进程阻塞（排除 A：只有申请资源未果才会阻塞），也不会让它退回就绪队列（排除 D：FCFS 为非抢占式，无调度事件触发 P1 让出 CPU）。P2 仍未分到 CPU，保持"就绪"；P3 等待的打印机未被释放，仍"等待"。故四进程状态为**运行、就绪、等待、就绪**，选 B。
> ⚠️ **分歧题**：信管网与部分知识点汇总给 **A**（P1 变为"等待"）。但"释放资源后进入等待"找不到任何使之阻塞的等待条件，违背三态模型转换规则。**官方题解**给出 B：P1 还有打印机未运行完成，应仍处于运行状态；P2 未分配到 CPU 仍就绪；P3 无打印机资源释放仍等待；P4 因扫描仪释放由等待变就绪。本题取 **B**。

**24. D**｜【操作系统】前驱图与 PV 操作
（【存疑：图形复原】前趋图与程序骨架见 questions 文件）按"前趋有多少后继，执行后做多少个 V；后继有多少前趋，执行前做多少个 P"：P2 有 1 个前趋（P1）→ 空①=**P(S1)**；P2 有 2 个后继（P3、P4）→ 空②=**V(S2)V(S3)**，选 D。

**25. B**｜【操作系统】前驱图与 PV 操作
P3 有 1 个后继（P5）→ 执行后空③=**V(S4)**；P4 有 1 个前趋（P2）→ 执行前空④=**P(S3)**，选 B。

**26. A**｜【操作系统】前驱图与 PV 操作
P5 有 1 个后继（P6，经 S6）→ 执行后空⑤=**V(S6)**；P6 有 2 个前趋（P4 经 S5、P5 经 S6），程序中已给出 `P(S6)`，故空⑥补另一个等待 **P(S5)**，选 A。

**27. D**｜【操作系统】磁盘旋转调度
（【存疑：图形复原】记录排布表见 questions 文件）旋转 10ms/周、10 块/周 → 每块读取 1ms。处理每个记录 1ms 读 + 2ms 处理 = 3ms，期间磁头转过 3 块。顺序处理时，处理完 R1 后磁头位于 R4 开始处，下一个要读的 R2 需等待磁盘再转近一圈（8 块 = 8ms）才能到达磁头下。故除第一个记录外，其余 9 个记录各花 8+1+2 = 11ms，总时间 = **3 + 9×11 = 102ms**，选 D。

**28. A**｜【操作系统】磁盘旋转调度（优化）
对存储顺序作优化排列，使处理完上一个记录时下一个要处理的记录**正好转到磁头下**，则每个记录只花 1ms 读 + 2ms 处理 = 3ms，10 个记录共 **10×3 = 30ms**（即磁盘转过三圈），选 A。

**29. D**｜【软件工程】增量模型
增量模型的优点：能早期投入计划（A）、第一个可交付版本所需时间少成本低（B）、以增量方式开发小系统风险小（C）。其**不足**恰恰是：需要管理多个增量版本，**系统管理成本高、配置与集成复杂**，故"系统管理成本低、效率高、配置简单"不是增量模型的优点，选 D。

**30. D**｜【软件工程】敏捷统一过程（AUP）

**58. B**｜【数据结构】循环队列
顺序（数组）队列若不移动元素，随着入队/出队交替进行，front 指针不断后移，会出现"尾指针已到数组末端、而数组前部仍有空闲"的**假溢出**。循环队列把存储空间首尾相接成环，入队时尾指针、出队时头指针均通过取模运算在环上回绕，**入队与出队都不需要移动队列中的其他元素**即可复用出队腾出的空间——这正是循环队列区别于普通顺序队列的核心优点，选 B。

A（路由协议通过执行路由算法完成路由选择）、B（动态路由协议分为距离向量路由协议与链路状态路由协议）、D（路由器之间通过路由协议学习网络拓扑结构）均正确。C"路由协议是允许让数据包在主机之间传送信息的一种协议"**错误**：路由协议是**路由器之间**交换路由信息、维护路由表的协议，而"在主机之间传送数据包"是 IP 等可路由协议（routed protocol）的职责，选 C。

**71. A**｜【英语】上下文：DevOps 与软件工程师的区别
后文明确对比：软件工程师"focus on how well the computer software fits the needs of the client"（关注软件如何满足客户需求），而 DevOps 工程师"a broader focus"（关注面更广，含开发、部署与云上运维），两者的最大区别在于**关注点（focus）**，且 focus 在下文原句复现，选 A。（process 流程、goal 目标、function 功能均未在文中得到对应支撑。）
> ⚠️ **分歧题**：信管网给 C（goal）。但短文以 "focus" 与 "broader focus" 直接对比两者的职责差异，取 A。

**72. D**｜【英语】上下文：DevOps 的职责
"a broader focus that includes software development, how the software is deployed and providing （72） support through the cloud"——与开发（development）、部署（deployment）并列的是云上**运营支持（operational support）**，选 D。（developing、deploying 为动名词，与 "providing … support" 的搭配不当；training 培训与文意无关。）

**73. B**｜【英语】上下文：软件的持续运行
"while the software is continually （73）"——continually（持续地）修饰形容词作表语，表示软件**持续运行/保持可用**的状态，选 **functional**（运行正常的、在起作用的）。developed（已开发的）、constructed（已构建的）是已完成动作的过去分词，不表"持续"状态；secure（安全的）与 continually 搭配不合语境。

**74. C**｜【英语】上下文：DevOps 的持续自动化
DevOps 工程师管理软件的构建、部署与运营，将其作为一个**持续自动化的过程（a continuous automated process）**——这正是 DevOps 的 CI/CD（持续集成/持续交付）内涵；短文开篇即以 "a **continuous** simplification process" 定义 DevOps，"continuous" 与后文呼应，选 C。（single 单一的、whole 整体的、independent 独立的，均不能体现 DevOps 的"持续"特征。）

**75. B**｜【英语】上下文：工作流整合
"manage the workflow to （75） software to smoothly function with automated processes"——DevOps 工程师管理工作流，以使软件**整合（integrate）**到自动化流程中并顺畅运行（integrate … with … 是固定搭配），选 B。（develop 开发、analyse 分析、maintain 维护均不能与 "with automated processes" 构成"使软件与自动化流程协同"之意。）
