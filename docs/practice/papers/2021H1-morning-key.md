## 二、逐题解析（含知识点归属）

> 格式：`答案 | 【科目】知识点 | 解析`

**1. A**｜【计算机基础】CPU 组成
**程序计数器（PC）**存放将要执行的下一条指令在内存中的地址。指令寄存器（IR）存放当前正在执行的指令；主存地址寄存器（MAR）存放 CPU 当前访问的内存单元地址；状态条件寄存器（PSW）存放程序状态字（标志位与控制位）。

**2. D**｜【计算机基础】CISC 与 RISC
RISC 的主要特点：**使用简单指令、长度固定**、**大量通用寄存器**、**硬布线（组合逻辑）控制**、**适合流水线**；CISC 指令复杂、长度可变、寄存器较少、**普遍采用微程序（微码）控制**。故 D 正确，A、B、C 均说反了。

**3. B**｜【计算机基础】输入/输出控制方式
DMA（直接存储器存取）传送时，DMAC 接管**系统总线**，在内存与外设之间直接交换数据，**每传送一个数据占用一个总线周期**（一个 DMA 周期相当于一次总线读/写周期）。
> ⚠️ **分歧题**：部分资料（如希赛 qicoder）给 C 存储周期，理由"传送时间只与内存相关"，该说法不完整——DMA 传送的是"经总线的一次访存"，占用的是总线周期。信管网、软考达人、rkpass、腾讯云题库均给 **B**，本题取 B。

**4. C**｜【计算机基础】存储体系
闪存是**非易失性**存储器（掉电不丢失，A 对）；以**块**为单位擦除（B 对）；在嵌入式系统中可代替 ROM（D 对）。但闪存**不能按字节改写**、写入前需先擦除整块，速度与随机访问能力不适合替代 RAM/主存，故"常用来代替主存"错误，选 C。

**5. C**｜【计算机基础】磁盘
磁盘**旋转等待时间**（寻道完成后等待目标扇区转到磁头下）与转速成反比，转速提高一倍则旋转等待时间**减半**，C 正确。平均寻道时间由磁头移动决定、与转速无关（B 错）；平均存取时间 = 寻道时间 + 旋转等待时间 + 传输时间，由于寻道时间不变，存取时间不会恰好减半（A 错）；数据传输速率确实会随转速提高，但本题官方答案为 C（最直接、确定的定量关系）。

**6. B**｜【计算机基础】中断与异常
**中断**来自处理器**外部**（I/O 完成、DMA 传送结束、外部信号等）；**异常**来自处理器**内部**（除数为 0、缺页、地址越界、非法指令等）。故"DMA 传送结束"为中断、"除运算时除数为 0"为异常，选 B。

**7. C**｜【网络·信息安全】安全协议
**SSH**（Secure Shell）是**安全的远程登录协议**，在传输层对数据加密并可端口转发。TLS 是传输层安全协议（用于加密应用层数据，本身不是远程登录协议）；TCP 是传输层协议；TFTP 是简单文件传输协议（基于 UDP，不安全）。

**8. B**｜【网络·信息安全】攻击类型
**拒绝服务（DoS / DDoS）**的首要目标是使被攻击对象**耗尽资源或过载，不能继续提供服务**（破坏可用性）。跨站脚本（XSS）攻击用户浏览器窃取信息；信息篡改破坏完整性；口令猜测以冒充合法用户。

**9. B**｜【网络·信息安全】加密算法
**RSA** 是非对称加密算法（公钥加密/私钥解密，可用于加密与数字签名）。DES、AES 均为**对称**加密算法；MD5 是**报文摘要**算法（不可逆，不是加密算法）。

**10. D**｜【网络·信息安全】SQL 注入
SQL 注入通过在输入中嵌入恶意 SQL 片段，欺骗后端数据库执行，其**首要目标是获得（绕过认证获取）对数据库的访问权限**并窃取/篡改数据。破坏 Web 服务是 DoS 的目标；攻击用户浏览器是 XSS 的目标。

**11. A**｜【网络·信息安全】网络层安全
**IPSec** 工作在**网络层（IP 层）**，为 **IP 数据报**提供加密（ESP）与认证（AH）服务。HTTPS 是应用层（HTTP over TLS）；TLS 位于传输层之上为应用层加密；PP2P 不是加密协议。

**12. D**｜【知识产权】软件著作权保护范围
软件著作权保护**源程序、目标程序、软件文档**。**开发软件所用的思想、处理过程、操作方法或数学概念等不受保护**（思想与表达二分法），故"开发软件所有的操作方法"不受保护，选 D。

**13. D**｜【知识产权】商标注册
商标法：两个或两个以上申请人在同一种或类似商品上以**相同或近似**商标申请注册的，**初步审定并公告申请在先**的；**同日申请**的，初步审定并公告**使用在先**的。甲、乙于**同日（2020-07-07）**分别申请"宏达""鸿达"（两商标读音近似、商品类似），乙第一次使用"鸿达"（2019-05）**早于**甲使用"宏达"（2019-07），故乙的"鸿达"能获准注册，选 D。

**14. B**｜【知识产权】侵权复制品的善意取得
《计算机软件保护条例》第 30 条：软件复制品的**善意持有人**（不知道也没有合理理由知道是侵权复制品）**不承担赔偿责任**；但知道后**应当停止使用、销毁**该侵权复制品；若停止使用并销毁将造成**重大损失**，可以**向著作权人支付合理费用后继续使用**。故 C 企业的使用行为仍属侵权，但支付合理费用后可继续使用，选 B。

**15. C**｜【软件工程】数据字典与加工逻辑
加工逻辑用于**描述输入数据流变换为输出数据流的加工规则**（可用结构化语言、判定树、判定表表示），它规定"做什么"而非"如何实现"，**不需要给出具体的数据结构和算法实现**，故 C 的说法不正确。A、B、D 均为正确叙述。

**16. B**｜【软件工程】模块设计原则
模块的**作用范围**（受该模块内一个判定影响的模块集合）应当**限制在其控制范围**（该模块本身及其下属模块）**之内**，这样判定结果的传递路径最短、模块耦合最低。若作用范围超出控制范围，判定结果要绕过层级传递，导致高耦合。

**17. D**｜【软件工程】AOE 网与关键路径
关键路径是从源点到汇点的**最长路径**，其长度即最短工期。本图最长路径为 **A-D-F-H-J，长度 48 天**，故选 D。（【存疑：图形复原】顶点 A～J 的活动图见原卷 PDF 第 5 页。）

**18. B**｜【软件工程】总时差
"晚 16 天开始不影响工期"即该活动的**总时差 ≥ 16 天**。各活动总时差：**AC=8 天、BE=21 天、FI=14 天、HJ=0 天（关键活动）**。只有 **BE 的总时差 21 ≥ 16**，晚 16 天开始仍在时差范围内，不影响总工期，选 B。（【存疑：图形复原】）

**19. B**｜【软件工程】风险管理
风险是**可能发生、可能带来损失**的事件；可以**预测**风险、通过**干预减少损失**，但**无法完全避免**（"能预测到就能避免"错误地把风险当作确定事件）。故 B 的叙述不正确。

**20. A**｜【数据结构】表达式后缀式
`a∗(b+c/d)−e`：先算最内层 `c/d` → 后缀 `cd/`；再 `b + c/d` → `bcd/+`；再 `a ∗ (...)` → `abcd/+∗`；最后 `− e` → **`abcd/+∗e−`**。后缀式 = 对表达式树做后序遍历，操作数在前、操作符跟在其两个操作数之后。

**21. B**｜【软件工程·程序设计语言】编译过程
**语义分析**阶段进行**静态语义检查**（类型一致性检查、变量作用域与唯一性检查等）。词法分析识别单词（token）；语法分析检查语法结构（是否符合文法）；目标代码生成已处于编译后端。

**22. A**｜【软件工程·程序设计语言】Java 语言特征
Java 采用**即时编译（JIT）**（① 对）：先将源码编译为字节码，运行时由 JIT 把热点代码编译为本地码；Java 对象在**堆空间**分配（③ 对），由 GC 自动回收；Java **不**做静态优化编译（② 错），基本类型变量在栈上但**对象不在栈空间**分配（④ 错）。故 ①③，选 A。

**23. B**｜【软件工程】云计算部署模型
云基础设施**为某个客户单独构建和使用**属于**私有云**。公有云面向公众；社区云由有共同需求的多个组织共享；混合云是上述两种或多种的组合。

**24. B**｜【操作系统】位示图
磁盘物理块数 = 2048GB ÷ 8MB = 2048×1024 MB ÷ 8 MB = **262144 = 2¹⁸** 块。位示图每块用 1 bit 记录，共需 **2¹⁸ bit**。字长 128 bit，则所需字数 = 2¹⁸ ÷ 2⁷ = **2¹¹ = 2048** 个字，选 B。

**25. A**｜【操作系统】页面置换（改进型 Clock）
被淘汰页必须**在内存**：由页面变换表，在内存的是页 **0、2、4**。三者**访问位均为 1**，第一轮扫描找不到访问位为 0 的页，将访问位清零后第二轮优先淘汰**修改位为 0** 的页——页 0 的修改位为 0（页 2、页 4 修改位为 1），故淘汰**页 0**，选 A。（【存疑：图形复原】页面变换表见原卷 PDF 第 6 页。）

**29. D**｜【软件工程】螺旋模型
螺旋模型将**风险分析**引入瀑布模型（A 对），把开发划分为若干**螺旋周期**，每个周期大致经历瀑布式阶段（B 对），适合**大规模、复杂、高风险**项目（C 对）。螺旋模型本身**不强调快速提供初始版本**（快速提供初始版本让用户测试是**原型模型/增量模型**的特点），故 D 的陈述不正确。

**30. C**｜【软件工程】螺旋模型
螺旋模型**支持需求动态变化**（A 对）、**要求开发人员具备风险分析能力**（B 对）、过多迭代会**增加成本、延迟提交**（D 对）。由于每个周期都要进行风险分析，**开发成本较高**，"开发成本低"不正确，选 C。

**31. D**｜【软件工程】耦合性
**内容耦合**是最强的耦合：一个模块**直接访问另一模块的内部数据**，或**通过非正常入口转入另一模块内部**。数据耦合通过参数传递数据（最弱）；公共耦合共享全局数据结构；外部耦合访问同一外部环境（如同一外部设备/文件）。

**32. C**｜【软件工程】详细设计
**详细设计**的主要任务：为每个模块设计**算法**、**数据结构**、**数据库的物理（存储）结构**、模块的详细处理流程等。**模块之间的接口设计**属于**概要设计**（总体设计）阶段的任务，选 C。

**33. B**｜【软件工程】软件文档
文档是软件产品的重要组成部分（A 对），编制文档在软件开发中占有突出地位、工作量很大（C 对），高质量文档对软件效益有重要意义（D 对）。文档**对开发活动同样重要**（需求、设计、测试、评审均以文档为依据），"只对维护有用、对开发意义不大"不正确，选 B。

**34. A**｜【软件工程】白盒测试·路径覆盖
路径覆盖要求所选用例覆盖程序中**所有可执行路径**。该流程图共有 **3 条可执行路径**，每条路径需一个用例，故至少 **3** 个测试用例，选 A。（【存疑：图形复原】流程图见原卷 PDF 第 9 页。）

**35. D**｜【软件工程】软件可维护性公式
**可维护性** = **1/（1+MTTR）**（MTTR 越小越易维护）。对比：**可靠性** = MTTF/（1+MTTF）；**可用性** = MTBF/（1+MTBF)（MTBF = MTTF + MTTR）。A 是可靠性公式，C 是可用性公式变形，B 无意义。

**36. C**｜【软件工程】软件维护类型
**完善性（改善性）维护**：为**改进性能、增加新功能、提升效率或可维护性**而修改软件。本题"修改索引方法以更快得到搜索结果"属于提高性能的完善性维护。正确性维护改错误；适应性维护适应环境变化；预防性维护为提高可维护性而主动修改。

**37. A**｜【软件工程】面向对象分析（OOA）
OOA 的活动顺序通常为：**认定对象 → 组织对象（建立对象间关系/分类结构）→ 描述对象间的相互作用 → 确定对象的操作**。B、C、D 混入了"定义属性""识别包"等其他活动或打乱了顺序。

**38. C**｜【软件工程】面向对象设计原则
**接口分离原则（ISP）**：**不应该强迫客户依赖于他们不用的方法**——接口属于客户（使用者），不属于它所在的类层次结构；应使用多个专门的接口而非单一臃肿接口。这常与"依赖于抽象、不依赖于具体（DIP）"配合使用。单一责任（SRP）强调一个类只有一个变化原因；开放—封闭（OCP）强调对扩展开放、对修改封闭；里氏替换（LSP）强调子类型必须能替换父类型。

**39. C**｜【软件工程】面向对象
Bird 是 Parrot 的**父类**：Parrot 对象可以当作 Bird 看待（"is-a"），但 **Bird 对象不能当作 Parrot 看待**（父类不具有子类特有的成员），故 C 的叙述不正确。cat、bird、parrot 均可直接或间接视为 Animal 的对象（A、B、D 正确）。

**40. D**｜【软件工程】面向对象
**多态**：同一消息（方法调用）发送给不同对象，各对象按自身类型产生不同的行为（Animal 的 move() 在 Bird、Cat、Parrot 中有各自的实现）。封装是隐藏内部细节；继承是子类复用父类成员；消息传递是对象间通信机制。

**41. B**｜【软件工程·UML】状态图建模对象
UML 状态图用于对**反应型对象**（reactive object）建模——其行为由外部事件驱动、在有限状态间转换的对象（如电梯、订票机、协议实体）。状态图描述该对象在其生命周期中经历的状态、转换、事件与动作。

**42. B**｜【软件工程·UML】状态转换触发条件
从**组合状态 C**（其内部含子状态 A、B）到 D 的转换，其触发条件是**一旦状态 A 和 B 的所有动作完成**（即组合状态内部的迁移完成、do 活动结束），才能发生 C→D 的转换，选 B。（【存疑：图形复原】状态图见原卷 PDF 第 11 页。）

**43. D**｜【软件工程·UML】状态图基本概念
**状态由事件触发**的说法错误：**状态转换（迁移）由事件触发**，状态本身是对象在生命周期中的一种条件/情形（被进入和退出，而非被"触发"）。A（动作可在状态内或转换时执行）、B（事件发生且无监护条件则离开当前状态、终止 do 活动）均正确；C 中 `when(b=5)` 在 UML 中表示**变化事件**（change event，条件为真时触发），若按原卷写"时间事件"则也不准确，但本题官方答案为 D。

**44. A**｜【软件工程·设计模式】命令模式
题干即命令模式的定义："**将一个请求封装为一个对象**，从而可用不同的请求对客户进行参数化；对请求排队或记录请求日志，以及支持可撤销的操作"，即 **Command（命令）模式**。观察者用于一对多通知；状态用于状态驱动行为；中介者用于解解对象间直接通信。（【存疑：图形复原】类图见原卷 PDF 第 12 页。）

**45. A**｜【软件工程·设计模式】命令模式的角色
**Command（此处为 Operation）** 是抽象命令，**声明执行操作的接口**（execute）。SellOperation/BuyOperation/ViewOperation 是**具体命令**（实现接口、绑定接收者）；**Broker 是调用者（Invoker）**；**Stock 是接收者（Receiver）**，真正执行业务。

**46. D**｜【软件工程·设计模式】模式分类
命令模式属于**行为型对象**模式（关注对象间职责分配与请求的处理顺序，封装请求为对象）。创建型关注对象创建；结构型关注对象组合。

**47. B**｜【软件工程·设计模式】命令模式适用场景
命令模式适用于：需要**抽象出执行的动作（请求）以参数化某对象**时（把"做什么"封装成命令传给调用者）；需要支持**撤销/恢复**、**请求排队**或**记录日志**时。A 是观察者适用场景；C 是状态模式适用场景；D 是中介者模式适用场景。

**48. A**｜【软件工程·程序设计语言】文法与语法树
由文法（E→E+T|T，T→F∗T|F，F→id），∗ 的优先级高于 + 且左结合：`a+b∗c∗d` 的推导为 E ⇒ E+T ⇒ a + T ⇒ a + T∗F ⇒ a + T∗d ⇒ a + F∗d ⇒ a + b∗d... 更严格地，`b∗c∗d` 由 T ⇒ T∗F 链式产生，故语法树**根为 +，左子树为 a，右子树为 ∗（其左子树为 b∗c 的 ∗ 结点、右子树为 d）**。四个选项中只有 A 与该结构相符，选 A。（【存疑：图形复原】四个图形选项见原卷 PDF 第 13 页，D 选项原卷标注"暂无"。）

**49. D**｜【软件工程·程序设计语言】有限自动机
据原卷 DFA 图与公开解析：该自动机为**非确定的有限自动机**（状态转换存在不确定性），且它**不能识别以 bab 结尾**的串，选 D。（【存疑：图形复原】DFA 图见原卷 PDF 第 13 页。）

**50. C**｜【软件工程·程序设计语言】传值与传引用
`foo(5)`：形参 x（值）=5，局部 `a=2`。调用 `hoo(a, x)`：hoo 的 `&x` 是**引用**，绑定到 foo 的 a（初值 2）；hoo 的 y 是**值**，=5。
hoo 内：`y = y+10` → y=15（局部副本，不影响 foo 的 x）；`x = y - x` → 引用的 a = 15 - 2 = **13**。
返回后 `print(a, x)` 输出 **13, 5**，选 C。（【存疑：代码为图片，排版依据原卷文字层复原，见 PDF 第 14 页。】）

**51. D**｜【数据库】E-R 图转关系模式
**多对多（\*:\*）联系**必须**转换成一个独立的关系模式**，其属性包含两端实体的主键（作外键）及联系自身的属性，主键为两端实体主键的组合。1:1 与 1:\*（或 \*:1）联系可合并到某一端实体对应的关系中，不必独立。（【存疑：图形复原】E-R 图见原卷 PDF 第 14 页。）

**52. C**｜【数据库】函数依赖与候选码
求属性闭包：A→B、B→DH，得 A⁺={A,B,D,H}，缺 C、E，故 A 不是候选码；C→E，C⁺={C,E}，缺 A、B、D、H，C 也不是。**AC**：A⁺C⁺={A,B,C,D,E,H}=U，且去掉 A 或 C 均不再闭包为 U（A、C 互不可达），故 **AC 是唯一候选码**，选 C。

**53. D**｜【数据库】传递依赖与冗余依赖
**传递依赖**：A→B 且 B→DH（B 不决定 A），故 **A→D** 为传递依赖；同理 **A→H** 也可由 A→B→H 推出（传递依赖）。**冗余依赖**：F 中已显式给出 **A→H**，但它可由 A→B、B→DH（含 B→H）推出，故 **A→H 是冗余函数依赖**。综合为"存在传递依赖 A→D 和 A→H，并且还存在冗余函数依赖"，选 D。

**54. C**｜【数据库】关系代数
最外层先按"销售部 1"筛员工：对 **E** 的第 3 个属性（部门名）做选择。字符串常量须加引号 → **σ3='销售部1'(E)**，选 C。（A、B 缺引号；B、D 操作关系 C 错误。）

**55. B**｜【数据库】关系代数

**57. C**｜【数据结构】栈与队列
入栈序 a,b,c,d,e,f，出队序 b,d,f,e,c,a。模拟：a,b 入栈 → 弹 b；c,d 入栈 → 弹 d；e,f 入栈 → 栈内为 a,c,e,f → 弹 f,e,c,a。**S 中元素最多为 4 个，此时栈底到栈顶为 a, c, e, f**，选 C。
（验证：出队序 b,d,f,e,c,a 正由该栈操作序列产生——弹 b 前入 a,b；弹 d 前入 c,d；之后入 e,f，依次弹 f、e、c、a。）

**58. B**｜【数据结构】二叉树
结点数固定时，**完全二叉树**的高度（深度）**最小**：n 个结点的完全二叉树高度为 ⌊log₂n⌋+1，这是所有 n 结点二叉树中的最小高度（除最下层外各层均填满）。二叉排序树、线索二叉树形态可退化成链（高度可达 n）；最优二叉树（哈夫曼树）优化的是带权路径长度而非高度。

**59. B**｜【数据结构】数组与稀疏矩阵
稀疏矩阵的压缩存储常用**三元组顺序表**（线性表存储非零元的行、列、值）与**十字链表**（按行、列建立链表）。二维数组是稀疏矩阵的普通（非压缩）存储；邻接矩阵用于图；双向链表、索引顺序表不是稀疏矩阵的压缩存储方式。

**60. D**｜【数据结构】哈希表·线性探查
线性探查法在发生冲突时顺序向后探测。查找 e 成功且与多个关键字比较时，这些关键字位于 e 的起始位置之后连续的槽中，**第一个关键字可以不是 e 的同义词**——它可能是因冲突被"顺延"过来的其他关键字的同义词或普通元素。
> ⚠️ **分歧题（构造反例证明）**：取 m=5，依次插入 1, 6, 2, 7。H(1)=1→槽1；H(6)=1 冲突→槽2；H(2)=2 冲突→槽3；H(7)=2 冲突→槽3(2)→槽4。查 e=7：从槽2 起，依次比较 **6、2、7** 才找到。其中 **6%5=1 ≠ 7%5=2**，即 6 **不是** 7 的同义词。故"都是 e 的同义词"（信管网答案 C）错误，**D** 正确。

**61. C**｜【数据结构】排序
第一趟结束后能确定某个元素最终位置的排序：
- **冒泡排序**：一趟后最大（小）元素"沉底"到最终位置 ✓；
- **简单选择排序**：一趟选出的最小（大）元素放入最终位置 ✓；
- **堆排序**：初始建堆并调整后，堆顶元素到位 ✓；
- **快速排序**：一趟划分后基准元素到达最终位置 ✓。
**直接插入排序**（一趟只把一个元素插入前部有序区，后续还可能移动）与**归并排序**（一趟只保证段内有序）都不能确定最终位置。故 ②③④⑤，选 C。

**62. C**｜【数据结构】堆
对 A=(2,8,7,1,3,5,6,4)（下标 1..8）自第 ⌊n/2⌋=4 个结点起向前调整（大顶堆）：
- 调整 1（A[4]=1，子 4）：1<4 → 交换 → (2,8,7,**4**,3,5,6,1)
- 调整 7（A[3]=7，子 5、6）：7 最大，不动
- 调整 8（A[2]=8，子 4、3）：8 最大，不动
- 调整 2（A[1]=2，子 8、7）：2<8 → 与 8 交换 → (8,2,7,4,3,5,6,1)；继续调整 2 的子树：A[2]=2，子 4、3，2<4 → 交换 → **(8,4,7,2,3,5,6,1)**
结果为大顶堆 **(8,4,7,2,3,5,6,1)**，选 C。（大顶堆满足任一非叶结点 ≥ 其孩子：8≥4,7；4≥2,3；7≥5,6。）

**63. A**｜【数据结构】分治法时间复杂度
该分治策略把规模 n 分为两个 n/2 的子问题，并花 O(n) 时间处理跨中点的合并（最大子段和的三种情形：全在前半段、全在后半段、跨中点）。故递推式 **T(n) = 2T(n/2) + O(n)**，由主定理（a=2, b=2, f(n)=O(n)=Θ(n^log₂2)）属 **case 2**，得 **T(n) = O(nlgn)**，选 A。
> ⚠️ **分歧题**：信管网答案 B（O(n²)）错误——那是不做分治的朴素枚举复杂度；分治法每层 O(n)、共 O(lgn) 层。

**64. C**｜【数据结构】算法设计策略
问题具有**最优子结构**（最优解包含子问题的最优解）与**重叠子问题**（子问题被反复求解）两个性质，正是**动态规划**的适用特征（自底向上/记忆化存储子问题解，避免重复计算）。分治要求子问题独立；贪心需贪心选择性质；回溯是穷举解空间。

**65. D**｜【数据结构】算法设计策略
以**广度优先**方式搜索解空间（状态空间树）的策略是**分支限界法**（常配合剪枝/限界函数求最优解）。深度优先搜索解空间是**回溯法**；动态规划与贪心不是解空间搜索策略。

**66. D**｜【网络】IPv6
IPv6 地址长度为 **128 bit**（16 个字节，写作 8 组 4 位十六进制数，如 2001:db8::1）。IPv4 为 32 bit。

**67. A**｜【网络】应用层协议
在地址栏输入 `www.abc.com`，浏览器默认用 **HTTP**（端口 80）访问该网站。DNS 负责把域名解析为 IP 地址（是解析过程的参与者，但浏览器发出的应用层请求是 HTTP）；TCP 是传输层协议；FTP 是文件传输协议。

**68. A**｜【网络】电子邮件协议
**SMTP**（简单邮件传输协议）用于**客户端向邮件服务器发送**邮件（端口 25，加密版 SMTPS 端口 465）。POP3（端口 110）与 IMAP4（端口 143）用于从服务器**接收/读取**邮件；MIME 是邮件内容格式扩展（支持附件、多语言），不是收发协议。

**69. B**｜【网络】网络命令
`ipconfig /flushdns` 清除本地 **DNS 解析缓存**。`/release` 释放（DHCP 租约的）IP 地址；`/displaydns` **显示**（不清除）DNS 缓存内容；`/registerdns` 向 DNS 服务器重新注册本机的名称与地址。

**70. B**｜【网络】网络系统设计
网络设计目标（低成本、高性能、高可靠、高安全等）相互制约、不可能全部最优。本题官方答案取 **B**：在网络系统中**可用性/可靠性（最短的故障时间）优先级最高**，设计时应优先保证最短的故障时间（故障时间越长，业务损失越大）。故"尽量让最短的故障时间目标达到最优"最为合理。

**71. C**｜【英语】上下文：设计模式引言（GoF《设计模式》原文）
"设计面向对象软件很难，而设计**可复用的（reusable）**面向对象软件就更难了。" 与后文 "a reusable and flexible design..." 呼应。runnable（可运行的）、right（正确的）、pertinent（相关的，前文已出现）均不合语境。

**72. B**｜【英语】上下文：设计的通用性
"你的设计应当针对手头的问题，但又要足够**通用（general）**，以便应对未来的问题与需求变化。" clear（清晰）、personalized（个性化）、customized（定制化）与"应对未来问题"相悖。

**73. D**｜【英语】上下文：新手的状态
" Meanwhile new designers are **overwhelmed**（不知所措/应接不暇）by the options available..." overwhelmed by... 是标准搭配（被大量选择压倒）。excited（兴奋）、surprised（惊讶）不合"退回到非面向对象老办法"的语境。
> ⚠️ 原卷 D 选项印刷为 "Foverwhelmed"，应为 "overwhelmed"，据语义与 GoF 原书选 D。

**74. D**｜【英语】上下文：复用解决方案
"他们复用过去行之有效的解决方案。当找到一个好的**解决方案（solution）**时，就一次又一次地使用它。" tool（工具）、component（构件）、system（系统）在文中指代不明，solution 与 "solutions that have worked for them" 直接呼应。

**75. A**｜【英语】上下文：模式的反复出现
"因此，你会在许多面向对象系统中发现**反复出现的（recurring）**类与通信对象的模式。" recurring patterns（反复出现的模式）正是"设计模式"的定义性表述。right（正确的）、experienced（有经验的）、past（过去的）均不能表达"模式反复出现"的含义。
