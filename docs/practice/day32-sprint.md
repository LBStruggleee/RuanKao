### 卡③加密算法参数（数字必须精确）

| 算法 | 有效密钥长度 | 分组长度 | 轮数 | 结构 / 特点 |
|------|------------|---------|------|-------------|
| **DES** | **56 位**（输入 64 位，其中 8 位是奇偶校验） | **64 位** | 16 轮 | Feistel 网络；**已被破解**，不再用于新系统 |
| **3DES** | **112 位**（2 密钥）或 **168 位**（3 密钥，3×56） | **64 位** | 48 轮（3×16） | EDE（加密-解密-加密）；DES→AES 的过渡，安全但慢 |
| **AES** | **128 / 192 / 256 位** | **128 位（固定！与密钥长度无关）** | **10 / 12 / 14 轮** | SP 网络（**不是** Feistel）；当前国际主流 |
| **SM4** | 128 位 | 128 位 | 32 轮 | SP 网络；**国密**（WAPI 无线安全） |

**摘要算法（输出长度必背）**：**MD5 = 128 位**（已破解，仍用于文件完整性校验）／**SHA-1 = 160 位**（已不安全）／**SHA-256 = 256 位**（当前主流）／SHA-512 = 512 位／SM3 = 256 位（国密）。

**非对称三巨头**：**RSA** 1024/2048/4096 位，数学基础 = **大整数因子分解困难**，慢、只加密小数据或签名；**ECC** 160–256 位，椭圆曲线离散对数，**短密钥同等安全**（256 位 ECC ≈ 3072 位 RSA）；**DSA 只能签名不能加密**；**Diffie-Hellman 只能交换密钥不能加密**。

**两个规模数字**：对称加密 n 人两两通信需 **n(n−1)/2** 个密钥；非对称只需 **2n** 个（每人一对）。

**四条高频易错**：① **AES 分组固定 128 位**，不随密钥变（"AES 分组可以是 192/256"是错的）；② **3DES 密钥是 112 或 168 位**，不是 3×64=192；③ **数字签名不提供机密性**（报文仍是明文）；④ HTTPS **握手用非对称、通信用对称**。
*（出处：`day06-security.md §2.1、§3.2、§6.2、§十`）*

> 🙋 **自测方式**：遮住右列，逐算法口述"密钥/分组/轮数"；单独问"MD5 摘要长度""AES-192 几轮""3DES 三密钥多长"要能秒答。

### 卡④范式定义一句话版（大题 + 选择通用）

| 范式 | 一句话定义 | 破坏它的是什么 |
|------|-----------|---------------|
| **1NF** | 每个属性都是**原子的**，不允许"表中有表" | 属性非原子（存了集合/子表） |
| **2NF** | 消除**非主属性对候选码的部分依赖**（单属性码自动满足） | 存在真子集 W，使 W → 非主属性 |
| **3NF** | 消除**非主属性对候选码的传递依赖** | 存在 X→Y→Z 且 Y↛X 的链条 |
| **BCNF** | 每个**非平凡函数依赖的左部都包含候选码**（"决定者必须是码"） | 存在左部不含码的依赖 |

**三条配套结论**：① 包含关系 **1NF ⊇ 2NF ⊇ 3NF ⊇ BCNF**；② **3NF 不蕴含 BCNF**（经典反例：R(A,B,C)，F={AB→C, C→B}，候选码 AB 与 AC，全主属性，是 3NF 但 C→B 左部不含码，不是 BCNF）；③ **分解动作**：部分依赖 W→Y ⇒ 拆出 **(W, Y)**；传递依赖 X→Y→Z ⇒ 拆出 **(Y, Z)**；分解到 3NF 能同时**无损连接 + 保持依赖**，分解到 BCNF 保无损但不一定保持依赖。

**考场三条快解**：候选码是**单属性** → 不可能有部分依赖；**没有非主属性**（全主属性）→ 直接是 3NF，只剩 BCNF 要查；F 中每个依赖左部都是候选码 → 直接是 BCNF。
*（出处：`day08-er.md §3.1、§3.3、§3.5`）*

> 🙋 **自测方式**：遮住中间列，看着 1NF/2NF/3NF/BCNF 口述定义；再口述"3NF 为什么不蕴含 BCNF"的那个反例。

### 卡⑤设计模式意图一句话（15 个常考模式 + 中介者）

> 分类速记：**创建型"工抽单建原"**（工厂方法、抽象工厂、单例、建造者、原型）／**结构型"适装外组享桥代"**／**行为型"观状策命备职中模迭访解"**。★ = 常考 15 个。

| 模式 | 分类 | 场景关键词（看到就选它） | 意图一句话 |
|------|------|--------------------------|-----------|
| **工厂方法** | 创建型 | "由子类决定""创建接口" | 定义创建对象的接口，**让子类决定**实例化哪一个类（创建与使用分离） |
| **抽象工厂** | 创建型 | "产品族""一系列相关产品""不同平台/主题" | 创建**一族相关或相互依赖**的产品，不指定具体类（产品族整体替换） |
| **单例** | 创建型 | "只能有一个""唯一实例""全局" | 保证一个类**只有一个实例**，提供全局访问点 |
| **建造者** | 创建型 | "分步骤""复杂对象构建""相同过程不同结果" | 将**复杂对象的构建与它的表示分离**，同样的构建过程可创建不同表示 |
| **适配器** | 结构型 | "转换接口""兼容""已有类复用" | 把一个接口**转换**成客户希望的另一个接口，使不兼容的类能一起工作 |
| **装饰** | 结构型 | "动态增加""透明包装""比子类更灵活" | **动态地**给对象增加额外职责，避免子类膨胀 |
| **外观** | 结构型 | "统一接口""统一入口""一站式" | 为子系统中的一组接口提供一个**一致的界面**，简化调用 |
| **组合** | 结构型 | "树形结构""层叠菜单""部分-整体" | 把对象组合成**树形结构**，统一对待单个对象与组合对象 |
| **享元** | 结构型 | "共享""节省内存""大量相同对象" | 运用**共享**技术支持大量细粒度对象复用，降低内存占用（内部状态共享、外部状态作参数） |
| **观察者** | 行为型 | "通知""订阅""状态变化时自动更新" | 定义**一对多**依赖，一方状态变化时所有依赖它的对象**自动收到通知** |
| **状态** | 行为型 | "随状态改变行为""消除 if-else 分支" | 允许对象在**内部状态改变时改变行为**，用状态对象替代庞大的条件分支 |
| **策略** | 行为型 | "可互换""多种方式""算法变体" | 把一系列算法各自**封装成可互换**的策略类，使算法变化独立于客户端 |
| **命令** | 行为型 | "封装请求""排队执行""撤销重做" | 把**请求封装为对象**，使请求可排队、记录日志、支持撤销 |
| **备忘录** | 行为型 | "撤销""恢复""历史版本""存档" | 在不破坏封装性的前提下**捕获并保存**对象内部状态，以便以后**恢复** |
| **职责链** | 行为型 | "层层审批""逐级处理""传递请求" | 使多个对象都有机会处理请求，请求**沿链传递直到被处理**，发送者与接收者解耦 |
| **中介者**（上午高频） | 行为型 | "封装一系列对象交互""中介协调""解耦多对多" | 用一个**中介对象封装一组对象的交互**，使各对象不需要显式地互相引用 |

**两对易混辨析**：**策略 vs 状态**——策略是客户端**主动选**算法、策略间互不感知；状态是状态对象在 handle 完后**自动切换**到下一状态。**观察者 vs 中介者**——观察者是"一方变，多方被通知"（一对多）；中介者是"多对象互不直接引用、全找中介中转"（星型结构）。
*（出处：`day20-design-patterns.md §2.1、§2.2`）*

### 卡⑥维护四类型与占比（场景题必考）

| 维护类型 | 目的 | 触发场景（题干长这样） | 占比 |
|---------|------|----------------------|:----:|
| **完善性维护** | 增加新功能、改进性能、提升体验 | "用户要求增加一个统计报表""加快查询速度" | **~50%（最大头）** |
| **适应性维护** | 适应**外部环境变化**（不改功能） | "操作系统/数据库升级后系统不能运行""税率政策调整" | ~25% |
| **改正性维护**（纠错性） | 改正**交付后发现的错误** | "系统计算结果偶发出错"（交付时就有 bug） | ~20% |
| **预防性维护** | 主动改进以提高**可维护性**、防患未然 | "重构老旧代码、补充文档以降低未来风险" | ~5% |

**判别两步法**：系统本身有错 → 改正性；环境变了 → 适应性；用户想要更多 → 完善性；为未来买保险 → 预防性。
**两条最高频陷阱**：① "增加报表功能" → **完善性**（不是适应性）；② "升级 OS 后不能运行" → **适应性**（不是改正性，交付时本就是好的）。
**一条附结论**：维护是软件生命周期中**时间最长、花费最大**的阶段。
*（出处：`day12-process.md §1.4`、`day13-test.md §八`）*

> 🙋 **自测方式**：遮住"占比"列默背四个数字（50/25/20/5）；遮住类型列，由场景反推维护类型。

### 卡⑧必背公式（计算题主力，逐条默写）

| 考点 | 公式 |
|------|------|
| **Cache 命中率** | **h = N_c / (N_c + N_m)**（分母是**总访存次数**） |
| **Cache 平均访问时间** | **t_a = h·t_c + (1 − h)·t_m**（软考默认公式） |
| **Cache 加速比 / 效率** | **S = t_m / t_a（>1）**；**e = t_c / t_a ≤ 100%**；记 **e = S / r** 交叉验证，r = t_m / t_c |
| **Cache 反求命中率** | **h = (t_m − t_a) / (t_m − t_c)** |
| **流水线周期** | **Δt = max(t₁, …, t_k)**（最长段决定节拍） |
| **流水线总时间** | **T = Σt + (n − 1)·Δt**（等长段简化为 **T = (k + n − 1)·Δt**） |
| **流水线加速比 / 吞吐率 / 效率** | **S = n·Σt / [Σt + (n−1)·Δt]**（等长段 **S = kn/(k+n−1)**）；**TP = n / T**；**TP_max = 1/Δt**；等长段 **E = n/(k+n−1)** |
| **子网划分 5 步** | 网络地址 = **IP AND 掩码**；广播地址 = 网络地址 + 块大小 − 1；**可用主机 = 2^h − 2**（h = 32 − 前缀 n）；子网数 = 2^b（b = 借用位数）；块大小 = 256 − 掩码值所在段 |
| **前缀对照** | /30→2、/29→6、/28→14、/27→30、/26→62、/25→126、/24→254 |
| **路由聚合（CIDR）** | 合并 **2^k 个连续网络，前缀减 k**（4 个 /24 → /22） |
| **关键路径（AOE 网）** | **ve(源点) = 0，ve(v) = max{ve(u) + w(u,v)}**（顺着取最大）；**vl(汇点) = ve(汇点)，vl(v) = min{vl(w) − w(v,w)}**（逆着取最小）；关键路径 = **最长路径**，其长度 = **最短完成时间**；关键活动满足 **ve = vl**（缓冲为 0） |
| **McCabe 圈复杂度** | **V(G) = E − N + 2 = P + 1 = 区域数 + 1**（注意常数是 **+2**）；V(G) = 独立路径数 = 基本路径测试最少用例数；McCabe 建议 **V(G) ≤ 10** |
| **总线带宽** | **带宽 = 工作频率 × 总线宽度 / 8**（MB/s；复用总线要扣除地址占用时间） |
| **风险暴露** | **RE = P × L**（概率 × 损失） |
| **缺页率** | 缺页率 = 缺页次数 / 总访问次数 |

**两条公式类易错**：① 不等长段流水线用 **T = Σt + (n−1)Δt**（不是 k·Δt + (n−1)Δt）；② 加速比 S 可以 >1、效率 e 一定 ≤100%——"加速比往大看（相对慢主存），效率往小看（相对快 Cache）"。
*（出处：`day11-cache.md §2.4`、`day10-cpu.md §4`、`day05-tcp.md §八`、`day13-test.md §7.1、§9.2`）*

> 🙋 **自测方式**：遮住右列，在白纸上把 Cache 四式、流水线五式、子网划分五步、ve/vl 递推、V(G) 三式**全部默写一遍**（今天必须写一遍，光看不算会）。

### 卡⑨白盒覆盖标准六级（排序与定义都要背）

| 强度顺序（弱→强） | 标准 | 一句话定义 |
|------------------|------|-----------|
| ① | **语句覆盖** | 每条**语句**至少执行一次（最弱） |
| ② | **判定覆盖**（分支覆盖） | 每个判定的**每个分支（真/假）**至少执行一次 |
| ③ | **条件覆盖** | 每个基本**条件**的真/假至少执行一次 |
| ④ | **判定-条件覆盖** | 既满足判定覆盖又满足条件覆盖 |
| ⑤ | **条件组合覆盖** | 每个判定内**所有条件的各种取值组合**至少执行一次 |
| ⑥ | **路径覆盖** | 程序中**所有可能执行路径**至少执行一次（最强） |

**三条反直觉结论（常考）**：① **条件覆盖不保证判定覆盖**（两者互不包含，所以才需要"判定-条件覆盖"）；② **条件组合覆盖可能漏路径**；③ **路径覆盖也可能漏条件组合**——末两级严格来说"不可比"，但**选择题一律按上面 ①<②<③<④<⑤<⑥ 作答**（这是官方表述）。

**配套两条**：**判定覆盖 ⊇ 语句覆盖**（反之不成立）；基本路径测试四步 = 画 CFG → 算 V(G) → 找 V(G) 条独立路径 → 每条路径设计一个用例（**独立路径数 ≠ 全部路径数**）。

**黑盒三方法**：等价类划分（**有效可合并、无效必须逐个单独测**）、边界值分析（取 **min−1, min, min+1, max−1, max, max+1** 六个点，不是只取 min/max）、因果图（最终转判定表）。
*（出处：`day13-test.md §5、§6、§7`）*

> 🙋 **自测方式**：遮住右列，把六级排序与定义逐条口述；再答"条件组合覆盖一定覆盖所有路径吗？"

### 卡⑩附加卡：耦合七级 / 内聚七级 / 测试阶段依据

| 考点 | 内容 |
|------|------|
| **耦合七级（低→高，越好越低）** | 无直接耦合 < 数据耦合 < 标记耦合 < 控制耦合 < 外部耦合 < 公共耦合 < 内容耦合。口诀：**"无直数标控外公内"** |
| **内聚七级（低→高，越好越高）** | 偶然 < 逻辑 < 时间 < 过程 < 通信 < 顺序 < 功能。口诀：**"偶逻时过通顺功"** |
| **过程 vs 顺序内聚** | 前者输出**不是**后者输入 → 过程内聚；**是**输入 → 顺序内聚（最高频易错） |
| **标记 vs 数据耦合** | 传整个数据结构（对方只用一部分）→ 标记；传简单值 → 数据 |
| **外部 vs 公共耦合** | 共享**程序之外**的约定（同一文件/设备）→ 外部；共享**程序之内**的公共数据区（全局变量）→ 公共 |
| **四个测试阶段的依据文档** | 单元测试 ← **详细设计**；集成测试 ← **概要设计**；系统测试 ← **需求规格说明书 SRS**；验收测试 ← 用户需求/合同 |
| **集成测试两策略** | **自顶向下打桩**（Stub 模拟下层）；**自底向上写驱动**（Driver 模拟上层）。口诀："顶→桩、底→驱动" |
| **面向对象设计七原则** | **单开里接依**（SRP/OCP/LSP/ISP/DIP，即 SOLID）+ **迪米特法则**（最少知识）+ **合成复用**（组合优于继承）；**开闭是核心目标**，其余是实现手段 |

*（出处：`day13-test.md §1–4`；注：`quick-reference.md` 里耦合只列了常用 5 级，本文用 `day13-test.md` 的完整 Myers 七级为准。）*

> 🙋 **自测方式**：遮住右列，正背/倒背耦合七级与内聚七级口诀；口述四个测试阶段各依据哪份文档。
