## 一、试题一：DFD 答题模板（15 分）

> 题目套路：【说明】列 4-6 项功能 → 给上下文图（图1-1）+ 0 层图（图1-2）→
> 问题1 填外部实体 → 问题2 填数据存储 → 问题3 补缺失数据流 → 问题4 加工逻辑描述/分解。
> **按四步顺序作答，每步对应一个问题，稳拿 12 分以上。**

### 四步法

| 步 | 对应问题 | 核心口诀 |
|----|----------|----------|
| 1 | 外部实体 | 找"人"、找"设备"、找"外部系统"；排除"数据"、排除"系统自己" |
| 2 | 数据存储 | 找"存储/保存/记录/维护/写入/读取"等动词，被存储的名词即存储名 |
| 3 | 补数据流 | 数据流平衡三规则（见下） |
| 4 | 加工逻辑 | 结构化语言三层结构 / 加工分解切动词短语 |

### 数据流平衡三规则（问题 3 最高频丢分点）

1. **守恒规则**：每个加工有输入且有输出，且输入足以产生输出。
2. **父子图平衡**：子图输入/输出集合 = 父图对应加工的输入/输出集合（数据守恒，可合并分解但不能多不能少）。
3. **无悬空流**：每条数据流必须一端连加工；禁止实体↔实体、存储↔存储直连。

**三类常见错误（官方答案原文，逐字背，遇"分解注意哪些错误"直接默写）**：
① 加工有输入但是没有输出；② 加工有输出但是没有输入；③ 加工的输入不足以产生输出。

### 补数据流要点

- 带"**历史/批量/记录/已存**"字样的输入只能来自**数据存储**（`D→P`），不能是 `P→P`。
- **同名数据流被多个加工读取时，每条都要单独画**（画了一条不等于画了两条）。
- **答案三要素**：数据流名称 + 起点 + 终点，缺一不可；编号用图中的 `E/D/P` 编号。

### 得分技巧

照抄原词 / 存储名后缀灵活（表/信息表/文件/记录均给分）/ 问题 3 先列每个加工的输入输出清单再找缺腿的 / 上下文图与 0 层图实体必须守恒 / 问题 4 必须有 IF-THEN-ENDIF 等结构化关键字。

> 详见 `dfd-uml-notes.md`（含 2020 下/2021 下真题例句与完整得分技巧表）

## 二、试题二：数据库设计答题模板（15 分）

> 题目套路：【需求分析结果】列 3-5 个实体及属性 → 【概念模型设计】给不完整 E-R 图 →
> 【逻辑结构设计】给不完整关系模式 → 问题1 补联系 → 问题2 填属性空 →
> 问题3 主键外键 → 问题4 扩展设计（m:n 变化/规范化分解）。

### E-R 三步法

| 步 | 动作 | 找什么句式 |
|----|------|-----------|
| 1 | 需求→实体 | "XX 信息包括：……"（被描述的主体是实体） |
| 2 | 实体→联系 | **量词句**："一个/一名/多张/只属于/至少有" |
| 3 | 联系/实体→属性 | 属性挂在拥有它的实体上，关系属性挂联系上 |

### 联系类型判定口诀（核心）

> **两端都唯一 → 1:1；一端唯一一端不唯一 → 1:n；两端都不唯一 → m:n**
>
> "唯一" = 该端实体对象在这个联系中只出现一次。判别动作：把需求里的量词逐对写成
> "X 端：唯一 / Y 端：不唯一"的对照，再套口诀。
>
> ⚠️ "经理""主管"**不是独立实体**，是职员的**岗位**——把岗位画成新实体是最常见错误。

### E-R → 关系模式转换规则（直接决定问题 2/3/4 的分）

| 联系类型 | 转换规则 |
|----------|----------|
| 1:1 | 把任一端主键放另一端（可两端都放） |
| 1:n | **把 1 端主键放进 n 端关系模式**（最高频考点） |
| m:n | **必须转成独立关系**，主键 = 两端主键的组合 |

### 关系模式填空两类缺项（都要填！）

1. **需求属性清单里有、模式里缺的属性**（对照"XX 信息包括"逐项排查）；
2. **1:n 联系的 1 端主键**（作为外键放进 n 端）。

> 例：2021 下试题二维修单 (d) = **车牌号 + 员工号**（车牌号是需求清单缺项，员工号是 1:n 转换项）。

### 主键 / 外键判定

- **主键**：看"XX 号唯一标识……每一个元组"那句（没明说时用自然唯一标识，如车牌号）；
- **外键**：关系模式中引用别的关系主键的属性——**填空时新加进去的属性，到主外键题里也要算外键**。

### 规范化题模板（数据冗余题，背熟套话）

> 存在**数据冗余、修改异常、插入异常、删除异常**等问题。
> 应将关系模式分解为：模式1（…）+ 模式2（…）。

### SQL 考法（上午卷为主，下午备考点）

四类考法：CREATE TABLE（含主外键约束 FOREIGN KEY … REFERENCES）/ SELECT（JOIN 连接、子查询、GROUP BY 分组聚合）/ GRANT·REVOKE（权限）/ CREATE VIEW。
> 详见 `database-notes.md`（每类配真题例句：2023 上 GRANT / 2017 上 分组聚合 / 2019 下 等价连接）

## 三、试题三：UML 答题模板（15 分）

> 题目套路：【说明】+ 用例图（图3-1）+ 类图（图3-2）→
> 问题1 填参与者/用例/关系 → 问题2 填类名或属性 → 问题3 填关系/属性解释/设计模式。

### 类图填空三招

| 招 | 内容 |
|----|------|
| 名词找类 | 【说明】中带英文括号注的核心名词几乎都是类；"X 包括 A、B、C"或"X 分为 A 和 B 两类"→ 一个泛化层级（X 父类，A/B/C 子类） |
| 动词找方法 | 动词短语 = 类的方法；方法名用【说明】原动词或其英文括号注 |
| 关键词判关系 | 见下表 |

### 类间六关系（符号 + 代码级判别）

| 关系 | UML 符号 | 代码级特征 | 口诀 |
|------|----------|-----------|------|
| 泛化 | 空心三角**实线**箭头，子→父 | `extends` | is-a，继承 |
| 实现 | 空心三角**虚线**箭头 | `implements` | 实现接口 |
| 关联 | 实线（可有多重性） | 成员变量持有引用 | has-a，长期持有 |
| 聚合 | **空心菱形**，整体→部分 | 部分可独立存在（外部传入） | 整体与部分可分离 |
| 组合 | **实心菱形**，整体→部分 | 部分随整体创建/销毁（构造里 new） | 同生共死 |
| 依赖 | 虚线箭头 | 局部变量/方法参数 | 临时使用 |

**聚合 vs 组合**：部分能否脱离整体单独存在——能（班级与学生）→ 聚合；不能（汽车与发动机）→ 组合。

### 用例图三关系

| 关系 | 方向 | 判别口诀 |
|------|------|----------|
| `<<include>>` | 基用例 → 被包含用例 | **必然发生**、公共抽取 |
| `<<extend>>` | 扩展用例 → 基用例 | **条件触发**、可选异常 |
| 泛化 | 子用例 → 父用例 | 特殊化 |

**记方向**：include 箭头从"必然触发的用例"指向"被抽取的公共用例"；extend 箭头从"可选/异常用例"指向"基用例"——**两者方向相反**。

### 属性提取

- 父类属性 = "系统中存储了每个 XX 的……"后面的共有属性；
- 子类属性 = "对于 XX，还需记录……"后面的特有属性；
- 关联类属性 = 描述**两者关系本身**的属性（如"经纪负责该房产的起止时间"），**不是**任一类的自身属性。

### 试题三问题 3 常考：设计模式速选

| 题干特征词 | 模式 | 一句话 |
|------------|------|--------|
| 状态变化通知关注者 | 观察者 | 一对多依赖，自动通知 |
| 多种格式/算法可互换 | 策略 | 算法封装成类可替换 |
| 统一接口封装多子系统 | 外观 | 高层一致接口 |
| 减少对象数量省内存 | 享元 | 共享细粒度对象 |
| 撤销/恢复原状态 | 备忘录 | 保存状态以便恢复 |
| 层叠菜单/树形/部分-整体 | 组合 | 统一对待单个与组合对象 |
| 多对象交互由中介协调 | 中介者 | 封装一组对象交互 |
| 动态增加职责 | 装饰 | 包装扩展功能 |

**解释题万能模板**：XX 模式适合……（标准定义）。本需求中"…"对应……角色，"…"对应……角色，当……发生时……，故选 XX 模式。

> 详见 `dfd-uml-notes.md`（含顺序图/状态图/活动图读图要点）

## 四、试题四：算法填空答题模板（C 语言，15 分）

### 填空四步法

1. **读【说明】理清算法目标**（输入是什么、输出是什么、策略是什么）；
2. **读代码标循环不变量**（每层循环在干什么、数组含义）；
3. **从边界条件反推空位**（i 从 0 还是 1？j < n 还是 <= n？）；
4. **代入小例子验证**（手算一个 3×3 或 n=3 的例子，空位对不对一下就出来）。

### DP 题专属：状态转移三件套

1. **定义状态**：`D[i][j]` / `m[i][j]` 的含义；
2. **写状态转移方程**：由左/上/左上推出（序列型），或按区间长度枚举断点（区间型）；
3. **定边界与遍历序**：`D[0][j]`、`D[i][0]` 初值；外层枚举什么、内层枚举什么。

> 序列型例：编辑距离（2021 下试题四）；区间型例：矩阵连乘（2022 上试题四，枚举断点 k，`m[i][j] = min(m[i][k]+m[k+1][j]+代价)`）。

### 常考算法骨架清单

| 类别 | 核心结构 |
|------|----------|
| 动态规划（最高频） | 双重循环 + 状态转移 + 边界初始化 |
| 排序 | 快排划分（双边/单边指针）、归并合并 |
| 查找 | 二分（循环条件与 mid 取整）、哈希冲突处理 |
| 树的遍历 | 递归先/中/后序（栈的压入顺序） |
| 图遍历 | DFS 栈/递归、BFS 队列 + visited 标记 |
| 贪心 | 排序 + 单向扫描 + 局部最优策略 |

### 得分技巧

算法空写出**数组下标或变量名**也能拿分；不会做就先把循环结构与变量声明抄进空位，再按小例子推。

> 详见 `patterns-algo-notes.md`（含 Java vs C++ 语言细节对照）

## 五、试题五/六：设计模式答题模板（C++ / Java 二选一，15 分）

### 大题三步法

1. **读【说明】定位场景关键词判模式**（用本文 §三的速选表或 `patterns-algo-notes.md` 的秒选表）；
2. **对照类图找角色对应**（谁是 Abstraction / ConcreteSubject / FlyweightFactory …）；
3. **依多态与继承关系填代码空**（抽象类定义接口、具体类实现接口、客户端面向抽象编程）。

### 填空通用三招

- **招 1**：抽象类/接口中的**方法签名**空 → 抄【说明】里的动词或类图中的方法名；
- **招 2**：子类/具体实现类中的**方法体**空 → 调用被聚合的成员对象的方法（委托），或返回自身状态；
- **招 3**：客户端/调用处空 → **面向抽象类型声明变量**（`Abstraction abs = new ConcreteImpl()`）。

### Java vs C++ 细节对照

| 点 | C++ | Java |
|----|-----|------|
| 抽象接口 | 纯虚函数 `virtual void f() = 0` | `interface` 或抽象类 `abstract` |
| 继承 | `class A : public B` | `class A extends B` |
| 实现接口 | `class A : public Iface` | `class A implements Iface` |
| 对象持有 | 指针 `Iface* obj` + `new` | 引用 `Iface obj` + `new` |
| 内存管理 | 析构函数 `virtual ~A()` | 无（GC） |

### 高频模式角色结构（考前默写）

- **工厂方法**：Product（抽象产品）/ ConcreteProduct / Factory（抽象工厂，声明 Create）/ ConcreteFactory（实现 Create 返回 ConcreteProduct）
- **观察者**：Subject（attach/detach/notify）/ ConcreteSubject（状态）/ Observer（update）/ ConcreteObserver
- **策略**：Strategy（算法接口）/ ConcreteStrategyA、B / Context（持有 Strategy 引用，调用其方法）
- **享元**：Flyweight（共享状态接口）/ ConcreteFlyweight / FlyweightFactory（维护共享对象池）
- **备忘录**：Originator（创建/恢复备忘录）/ Memento（保存状态）/ Caretaker（保管备忘录）

> 详见 `patterns-algo-notes.md`（7 个高频模式的意图+角色结构+代码特征，附 2020-2023 考频）

## 六、高频丢分点总表（做完真题后对照回填）

| 题型 | 高频丢分点 |
|------|-----------|
| DFD | 加工"有输出无输入"漏补输入流；"历史/批量"输入误走 P→P（应 D→P）；同名数据流被多加工读取只画一条；结构化语言写成自然语言（无关键字）；分解三错误背不全 |
| E-R | 联系类型判错（量词句没逐对对照）；关系模式填空**漏属性**（需求清单缺项 + 1:n 主键两项都要填）；把岗位/经理画成独立实体；填空新加的属性到主外键题漏算外键；m:n 忘转独立关系；规范化题套话写不全 |
| UML | 聚合/组合/关联判错；关联类属性误填类的自身属性；父类与子类属性互相串填；include/extend 混淆（必然 vs 条件，箭头方向相反）；类名不用【说明】英文原名 |
| 算法 | 循环边界差 1；DP 状态转移方程推不出（没先手算小例子）；数组下标写错（0 基 vs 1 基没看清） |
| 设计模式 | 模式判错（场景关键词没记住）；角色结构默写不出（谁继承谁、谁聚合谁）；方法签名空不照【说明】原动词；客户端空不用抽象类型声明 |
